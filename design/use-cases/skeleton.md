# Скелетон (Skeleton)

> **Контракт поведения компонента.** Нормативный документ контура `design/`:
> человек (владелец) читает его, чтобы понимать гарантии компонента; агент
> приводит реализацию к контракту. Расхождение кода с контрактом — задача
> на рефакторинг, а не правка контракта «под код». Источник истины по фактам:
> `crates/canvas-ui/src/component/skeleton.rs`. Актуализировано: 2026-10-10
> (волны T/C/L, issue #47).

## 1. Назначение
Заглушка «места под контент» при загрузке: серые блоки по форме будущего
контента. Спека Wave C (`docs/dev-researches/ui-kit-deep-review-2026-10.md`
§5.3.8): «Загрузка схем, поиск, explain — показывают пустоту». Отличия:
spinner/progress (`../use-cases/progress.md`) показывают ход процесса;
skeleton — структуру ожидаемого результата. Не контрол и не поверхность:
рисуется внутри панели потребителя.

## 2. Анатомия и размеры
| Pattern | Блоки |
|---|---|
| TextLines { count, row_h } | count строк высотой row_h с зазором gap; последняя — 70% ширины |
| Card { w, h } | header (h·0.2) + 3 строки (высота header·0.6, третья — 60% ширины) + footer (40% × header·0.5) — 5 rect'ов |
| Table { rows, cols } | сетка rows×cols: cell_w = (slot.w − gap·(cols−1))/cols, cell_h аналогично |

Зазор между блоками — параметр `gap` потребителя, значения — шкала S1
(`../rules/03-spacing-radius.md`: SPACING_S 6 / SPACING_SM 8).

## 3. Токены (слоты KitPalette)
Модуль возвращает только геометрию и фазу — цвет блоков не назначен: решение
за потребителем на базе слота K2 (`../rules/10-components.md` §K2, базовый
кандидат — control_fill); alpha-ступени — только через `tint()` (K2.2).
Прямые rgb/alpha-литералы вне K2.2 запрещены (П4).

## 4. Состояния
Состояний ST1 нет (не контрол). Анимация — pulse: `skeleton_alpha(time_ms)`
с периодом 1500 мс, alpha = 0.04 + 0.08·(0.5 + 0.5·sin(phase·2π)) → диапазон
[0.04, 0.12]; комментарий модуля: «Pulse-анимация (M3 shimmer): alpha
0.04 ↔ 0.12, period 1500ms». `time_ms` — от потребителя (`anim.rs`):
dt-детерминизм M2 (`../rules/06-motion.md`), таймеров кит не хранит (M3.5);
`SkeletonLayout.phase` модуль ставит 0.0 — фазу заполняет потребитель.

## 5. Взаимодействие
- Не интерактивен (decoration, ST6 `../rules/08-states.md`): hit-зон нет,
  клики и наведение проходят к контейнеру.
- Замещает контент ровно на время загрузки; замена skeleton → реальный
  контент — мгновенная (M3.3).
- Скролл родителя двигает заглушку как обычный контент.

## 6. Граничные случаи
- TextLines не клампится по высоте слота: y растёт как i·(row_h + gap) —
  выход за слот возможен, контроль за потребителем.
- Table при экстремальном cols: cell_w может стать ≤ 0 — клампа нет.
- count = 0 / rows = 0 → пустой `rects` (ничего не рисуется).
- Долгая загрузка: pulse не сообщает прогресс; при известном ходе —
  переключение на progress (`../use-cases/progress.md`).

## 7. Где в коде
`crates/canvas-ui/src/component/skeleton.rs` — `skeleton_layout`,
`skeleton_alpha`, `SkeletonPattern`; тесты паттернов/диапазона alpha — в
модуле. Фасад — `crates/canvas-ui/src/kit.rs` (117). Потребителей в
`crates/canvas-app` нет; секции витрины в `crates/canvas-app/src/kit_ui.rs`
нет — долг K1.1/K4.

## 8. Что меняется при правке файла
- Паттерны/пропорции блоков → модуль + его юнит-тесты.
- Период/амплитуда pulse (1500 мс, 0.04–0.12) — вне шкалы M1: правка через
  `../rules/06-motion.md` и `design/tokens/motion.json`, не локальная
  константа.
- Назначение слота для блоков → K2.1 одновременно: KitPalette + мост +
  таблица K2.
- Появление потребителей → секция витрины в той же волне (K4).
