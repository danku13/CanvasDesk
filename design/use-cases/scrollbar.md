# Скроллбар (ScrollBar)

## 1. Назначение
Прокрутка переполненных списков/панелей: галерея схем (видимое окно строк),
дропдауны, docs viewer, настройки.

## 2. Анатомия и размеры
| Параметр | Значение |
|---|---|
| Ширина трека | SCROLLBAR_WIDTH 4 (docs viewer: 6) |
| Мин. длина кноба | SCROLLBAR_KNOB_MIN 20 |
| Длина кноба | viewport/content × трек (пропорция) |
| Радиус кноба | RADIUS_CHIP 6 (капсула) |
| Зазор трека до контента | 2–4 px |

## 3. Токены
Трек — прозрачный (не рисуется как полоса), кноб — control_fill hover →
control_hover_fill. Активный (drag) кноб — accent. Никаких стрелок-кнопок.

## 4. Состояния
Скрыт / виден / drag. Автопоявление только при переполнении; исчезает при
достаточной высоте контента.

## 5. Взаимодействие
- **Drag кноба** — прямое скроллирование (пропорционально).
- **Колесо** над списком — скролл без наведения на кноб (шаг = строка × 3).
- **Клик по треку** — страница вверх/вниз (не «к краю»).
- Клавиатура: ↑/↓ — по строкам, PgUp/PgDn — по страницам (в рамках
  keyboard-scope поверхности).

## 6. Граничные случаи
- Контент чуть больше вьюпорта: кноб не мельче SCROLLBAR_KNOB_MIN 20.
- Списки с фиксированной видимой высотой (галерея ROW_H 56 × N): скролл
  целыми строками, «полустроки» не показываются.
- Тонкий кноб (4 px) трудно попасть: drag-зона кноба расширяется до 12 px
  (hit ≥ визуал, A3), трек-клик — по всей ширине полосы.

## 7. Где в коде
`canvas-ui/src/kit.rs` — scroll_bar (813–830), SCROLLBAR_* (157–159);
docs viewer — `docs_ui.rs` (293–303, ширина 6, close 26); списки контекстных
меню — list_rows + ScrollState (app.rs).

## 8. Что меняется при правке файла
Ширины/мин. кноб → SCROLLBAR_* в kit.rs. Шаг колеса — константы поверхности.
Расширение hit-зоны — A3 (не ломает «hit ≥ визуал»).
