## 2. Код-причины (точная механика)

### L1 — сайдбар математически не помещается при любом окне

```
PANEL_MAX            = 900×640            (kit_ui.rs:57)
панель = min(640, viewport.h − SPACING_XL)                 → 640 при вьюпорте ≥ 664
окно сайдбара = 640 − 2·SPACING_LG(12) − 30(шапка) − 12(SECTION_GAP) − 32(DEMO_TOOLBAR_H)
             = 542px
потребность   = 26 секций×20(DEMO_NAV_ROW_H) + 5 групп×18(DEMO_NAV_GROUP_H) = 610px
дефицит       = 68px  ⇒  Тултип + Снекбар + Поповер (60px) не помещаются ВСЕГДА
```

- `kit_ui.rs:756-757` — комментарий «компактный список … ≈ 610px, окно ≥ 640px» **ошибочен**: нужно ~718px высоты панели (610 + 30 + 12 + 32 + 24).
- `kit_ui.rs:765-767` — `break` молча останавливает наполнение: секции исчезают из навигации, но остаются в контенте (реестр полный) — расхождение «навигация ↔ контент».
- На скриншоте видна «сирота»: группа «Фидбек» с единственным «Тост», далее пусто до кромки.

### L2 — усечение по символам вместо TextMeasurer

`kit_ui.rs:3287-3292`:

```rust
// Сайдбар узкий — укорачиваем до ~36 символов (без замера: метки
// секций длинные; v1 — грубое усечение, документировано в D7).
if title.chars().count() > 36 {
    title = format!("{}…", title.chars().take(35).collect::<String>());
}
```

Двойная ошибка:
1. **Порог по счёту, не по ширине**: доступно `DEMO_SIDEBAR_W − 8(item inset) − 8(label inset) = 184px`; 36 символов кириллицы при 11px ≈ 230–250px → строка всё равно шире ректа.
2. **Эллипсис рендерится за клип-кромкой**: «…» стоит на позиции 36, рект клипает на ~28–29 символах → эллипсис невидим, текст обрезан жёстко посреди слова. Видно на скриншоте: «Текстовое поле (TextField: каретка ..» — эллипсис срезан до двух точек.

При этом в той же сигнатуре `gallery_layout_impl` уже есть `m: &mut TextMeasurer, fs: &mut cosmic_text::FontSystem` — измеритель доступен, но для сайдбара не использован (в отличие от Table/row_guides/auto_width в том же файле).

### L3 — state-гуттер AS-IS унаследован TO-BE без адаптации

В AS-IS `STATE_LABEL_W = 84` — колонка слева для меток состояний (Hover/Pressed) при полной ширине панели; заголовки секций на `content.x` читались нормально. В TO-BE контент сдвинут на 212px (сайдбар 200 + gap 12), заголовки остались на `content.x` — теперь это полоса 268..358, визуально сросшаяся с переполненным сайдбаром. Заголовок слева, его контент справа (358+) — разрыв выравнивания «заголовок ↔ контент» 90px.

## 3. Почему issue #27 (LAY-W1..W12) это не покрыло — системные причины

1. **`kit_ui.rs` в allowlist lay7-гейта.** Файл исключён из скана `y +=`; Wave D добавила в него ~1800 строк нового ручного layout-кода (тулбар с фиксированными ширинами чипов, сайдбар с `break`) — гейт молчал. Это та же болезнь, что подтверждённый P1-2 LAY-VERIFY (35 639 строк вне скана), но через allowlist.
2. **G4-линт `kit_demo` не проверяет текст.** `lint_kit_demo_tobe` (`app/ui_layout_lint.rs:265`) открывает максимальный кадр и валидирует overlaps/viewport по хитам реестра. Инварианта «строка влезает в свой рект» нет ни в одном гейте.
3. **Усечение по символам — нарушение собственного принципа «ширины — измеренные»**, закреплённого в kit_ui (row_guides, Table::guides_with, auto_width.rs), но новый код Wave D написан вне этой системы.
4. **Golden-тест легализовал дефект.** `tobe_demo_layout_structure` (`kit_ui.rs:5560+`): ассерт `sidebar_items.len() >= 20` при 26 секциях кодифицирует обрезание как норму («Feedback-хвост за краем… задокументировано в D7»). TDD зафиксировал баг-поведение. При этом в `docs/interface-objects/kit-demo-v1.md` ограничение **не описано** — ссылка теста на D7 пуста.
5. **Константная математика не пересчитана при добавлении тулбара.** PANEL_MAX.y = 640 подобран под AS-IS-линейку; TO-BE добавил 44px (тулбар 32 + gap 12) сверху, не тронув PANEL_MAX — сайдбар потерял 44px и перестал влезать даже теоретически.

## 5. Вывод

Дефекты скриншота — не регрессия LAY-волны (те поверхности админки/панелей, что прошли W1–W12, на скриншоте не участвуют), а **зона, куда улучшения #27 физически не дотянулись**: витрина была и остаётся в allowlist lay7, её новые TO-BE-зоны написаны вручную вне Column/Row-скелета и измерителя ширин, а структурный тест закрепил обрезание как норму. Оба P1 (L1, L2) воспроизводятся при любом размере окна и любом языке — это не «узкое окно», а архитектурный дефект v1, честно зафиксированный в тест-комментарии, но не в доке D7 и не видимый из гейтов.
