# 11 — Раскладки (layouts) и адаптивность

> Единственный норматив раскладок UI (закрытие пробела аудита 2026-10:
> layout-правил в этой папке не было — фрагменты жили в П7/П10 и S6).
> Источники: `canvas-ui/src/layout.rs` + `layout/{flex,scene}.rs`
> (FR-053/FR-062/FR-068/FR-074), ADR-0013/0014/0015, `docs/ui-kit.md` §4/§6,
> CR-014 (web-оболочка), FR-097 (тач-цели), FR-099 (safe-area).
> Семантика примитивов — современные web-стандарты: CSS Flexbox (§9.7),
> CSS Grid (§11.5–11.8), container-based раскладка, `clamp()`, aspect-ratio,
> sticky, `@media`/`pointer: coarse`, safe-area. Правило видит код, а не
> переписывает его (I-1): значения уже равны текущим константам.

## LAY1. Слот — единственный источник геометрии

Раскладка immediate-mode от слота родителя: потребитель каждый кадр передаёт
слот (родительский rect) и список детей — примитивы возвращают вычисленные
rect'ы. Ничего не хранится и не рисуется между кадрами (D2, ADR-0013).

- **LAY1.1** Геометрия любого ребёнка выводится из слота родителя, а не из
  вьюпорта напрямую. Вьюпорт входит в раскладку только двумя путями: как
  корневой слот поверхности и как брейкпоинт деградации (LAY8). «Вёрстка от
  окна» в глубине дерева запрещена — она невосприимчива к перемещению
  поверхности и ломает линт G4.
- **LAY1.2** Ввод = тому, что видно (П5): hit-rect'ы строятся из **тех же**
  результатов раскладки. Второй, «ручной» расчёт геометрии для хитов
  запрещён — расхождение draw/hit не ловится линтом и всегда рано или поздно
  расходится.
- **LAY1.3** Каскад координат: World px — канвас (масштабируется зумом),
  screen/ui px — хром (панели, HUD; П11). Примитивы `canvas_ui::layout`
  работают в ui px; смешивание масштабов внутри одного дерева раскладки
  запрещено.

## LAY2. Примитивы и их web-эквиваленты

Выбор примитива — по таблице. Новая раскладка обязана выражаться этими
примитивами; «ручная» арифметика `x += w + gap` вне `layout/` запрещена
(исключение — `Custom`, LAY5).

| Примитив (`canvas_ui::layout`) | Web-эквивалент | Применение |
|---|---|---|
| `Row { gap, main, cross, policy }` | `display:flex; flex-direction:row` | тулбары, ряды контролов, чип-строки |
| `Column { gap, main, cross }` | `display:flex; flex-direction:column` | панели (шапка→тело→футер), формы |
| `Child::fixed(w, h)` | фиксированный flex-item (`flex: 0 0 auto`) | кнопки, поля, константные блоки |
| `Child::flexible(w, h, grow)` | `flex-grow` при `flex-basis` = базовый размер | заполнители свободного места |
| `Child::spacer(len)` / `MeasuredItem::Spacer` | фиксированный gap-блок | именованные распорки скелета |
| `MainAlign::{Start, SpaceBetween, End}` | `justify-content` | прижать ряд к правому краю, распределить |
| `CrossAlign::{Start, Center, End}` | `align-items` | вертикаль центров контролов разной высоты |
| `RowPolicy::Wrap` | `flex-wrap: wrap` | чипы категорий, теги, фильтры |
| `grid_cells(slot, cols, rows, row_h, gap)` | `grid-template-columns` (равные явные) | витрины, галереи карточек |
| `stack(slot, size, HAlign, VAlign)` | absolute-центр / прижатие фикс-блока | модалки по центру, empty-карточки |
| `constrain(min, max, desired)` | `clamp()` (min приоритетнее max) | размеры модалок и панелей |
| `pad(slot, EdgeInsets)` | `padding` | внутренние поля контейнеров |
| `MeasuredItem::Text { pad_x, min_w, max_w, h }` | `width: max-content` + явные min/max | авто-размер от текста (чипы, кнопки) |

Правило выбора: две оси — `Row`/`Column`; регулярная сетка — `grid_cells`;
наложение/центрирование — `stack`; ограничение размера — `constrain`;
внутренние поля — `pad`. Комбинация покрывает все регулярные раскладки кита;
`SceneNode` (LAY5) — когда нужен percent/aspect/sticky.

## LAY3. Политики переполнения главной оси

Переполнение никогда не маскируется молча (класс CR-015). Три именованные
политики `RowPolicy`:

| Политика | Web-аналог | Семантика |
|---|---|---|
| `Fit` (default) | `overflow: visible` | дети занимают слот; перелив за слот виден и ловится линтом G4 |
| `SqueezeTail` | именованная деградация (НЕ `flex-shrink` — расхождение C3 задокументировано) | каждый ребёнок получает `min(desired, остаток)`; хвост сжимается до нулевой ширины и не пикается (half-open hit) |
| `Wrap` | `flex-wrap: wrap` | не влез в строку — перенос; высота строки = max высот детей строки; строки ниже слота не маскируются (ловит G4) |

- **LAY3.1** `Fit` — по умолчанию и всегда, когда переполнение — дефект
  контента, а не ожидаемое поведение. Молчаливый срез узкого слота
  (`break`/`take`-клампы) запрещён линтом G5.
- **LAY3.2** `SqueezeTail` — только для баров с якорем слева, где правый хвост
  (чипы, подсказки) семантически вторичен: what-if бар, ряды статусов.
  Политика приоритетна над flex-факторами: `grow` детей при ней игнорируется.
- **LAY3.3** `Wrap` — для наборов однородных чипов/тегов. Число видимых строк
  определяет ВЫСОТА слота, а не параметр политики; перелив строк за нижний
  край — сигнал дефекта (G4), не маскируется.
- **LAY3.4** Усечение текста — только явное: `max_w` в `MeasuredItem::Text`
  + ellipsis/clip потребителем. Молчаливый кламп ширины в остаток слота
  запрещён (G5, П6).

## LAY4. Flex-факторы (распределение свободного места)

`Child.grow` — доля свободного места слота (после фиксированных детей,
базовых размеров flex-детей и зазоров), распределяемая пропорционально
коэффициентам — дословный CSS flexbox §9.7 «Resolving Flexible Lengths»
при `flex-basis` = базовый размер; `FlexLayoutEngine` additionally приводит
главные размеры к целой px-сетке по `round_layout` taffy (допуск ≤ 0.5 ui px,
задокументирован в тестах).

- **LAY4.1** На каждую главную ось — максимум один grow-ребёнок-заполнитель
  (аналог `flex: 1` spacer). Несколько grow-детей с разными коэффициентами —
  только когда доли осмысленны (панели 2:1), не «чтобы как-то растянулось».
- **LAY4.2** Приоритеты (пинены тестами): `SqueezeTail` > распределение `grow`;
  при Σgrow > 0 свободное место съедается grow-детьми — `SpaceBetween`/`End`
  деградируют к базовому зазору/прижатию (документировано, не дефект).
- **LAY4.3** `grow = 0` — байт-в-байт прежнее фиксированное поведение
  (инвариант «только добавление» FR-062). Существующие раскладки не
  меняют ни одного rect'а при добавлении flex-факторов.

## LAY5. Grid и расширенная сцена (SceneNode)

Два уровня выразительности. Эскалация — по необходимости, без переписывания
потребителей (контракт FR-068 §Контракт-1: сигнатуры примитивов стабильны).

**Уровень 1 — примитивы (по умолчанию):** `Row`/`Column`/`grid_cells`/
`stack`/`constrain`/`pad`. `grid_cells` — равные явные колонки row-major
(направляющие ширины задаются вызовом).

**Уровень 2 — сцена `SceneNode` (FR-074, возможности за пределами примитивов):**

| Возможность | Web-аналог | Когда |
|---|---|---|
| `SceneDim::Percent` | `%` от content-box родителя | доли ширины/высоты |
| `SceneDim::Fill` | `flex: 1` / `align-self: stretch` | гибкие треки сцены |
| `aspect` | `aspect-ratio` | превью, миникарта, иконочные слоты |
| `ScenePosition::Absolute` | `position: absolute` (от border-box родителя) | оверлеи внутри контейнера |
| `ScenePosition::Fixed` | `position: fixed` (от корневого слота) | тултипы, дропдауны у края |
| `ScenePosition::Sticky { top, left }` | `position: sticky` (каждая ось независима) | шапки таблиц при прокрутке |
| `SceneOverflow::Hidden` | `overflow: hidden` (rect'ы не меняет; клип — `PaintItem::ClipRect`, FR-056) | окна списков, скролл-контейнеры |
| `SceneNode::offset` | scroll content-shift | прокрученные контейнеры |
| Grid-треки `Auto/Length/Percent/Fill/MinMax{min,max}` + `span` | CSS Grid §11.5–11.8 (`minmax()`, `fr`, авторасчёт по max-content span-1 ячеек) | нерегулярные сетки, masonry-lite |

- **LAY5.1** Правило эскалации: примитивы покрывают потребность — сцена не
  используется. Сцена используется, когда нужен percent/aspect/sticky/авто-
  треки/minmax/scroll-offset. Экзотика вне обеих моделей (полярные координаты
  wheel-меню — см. «Исключения», drop-сетки) — `Custom(rect)`
  **с комментарием-обоснованием** (ловится grep-аудитом G8).
- **LAY5.2** Перед расширенными политиками потребитель проверяет маску
  `LayoutFeatures` движка (`FLEX_GROW/FLEX_SHRINK/FLEX_BASIS/FLEX_WRAP/
  GRID_2D/AUTO_SIZE/OVERFLOW_CLIP/PERCENT/ASPECT_RATIO/STICKY`) — код не
  должен молча предполагать возможность, которой у движка нет.
- **LAY5.3** `SqueezeTail` — НЕ `flex-shrink`: это именованная деградация
  (LAY3.2). CSS-семантика flex-shrink движком не предоставляется; потребность
  в ней — сигнал пересмотреть раскладку (фиксированный хвост → Wrap).

## LAY6. Измеренный текст в раскладке

Ширины для раскладки — только через `TextMeasurer` (П6): реальный шейпинг
cosmic-text, та же пара (семейство, вес), что у рендера.

- **LAY6.1** Авто-размер текстового ребёнка — `MeasuredItem::Text`:
  ширина из измерения, `pad_x` — суммарный горизонтальный пад (бит-в-бит
  ≡ проводке `Fixed { w: width_of + pad_x }` — чип/кнопка без ручного
  замера), `min_w` — пол ширины (короткая подпись поднимается до минимума),
  `max_w` — единственный кламп (G5), `h: Some(константа)` — явная высота
  дизайн-константой (чип `CHIP_HEIGHT`), `None` — измеренная (кегль·фактор
  строки).
- **LAY6.2** Ручные посимвольные ширины (`chars.len() × константа`) и
  «на глаз» фиксированные ширины под конкретную строку запрещены — ломаются
  на первой локализации (RU/EN прогоняется линтом G4).
- **LAY6.3** Замер выполняется ДО backend'а у всех движков (в сигнатуре
  `lay_out_measured`) — результат не зависит от выбора backend'а.

## LAY7. Зазоры и поля — только из шкал

- **LAY7.1** `Row.gap`/`Column.gap` и `EdgeInsets` — значения только шкалы
  S1 (`SPACING_S 6 / SM 8 / MD 10 / LG 12 / XL 24`); литеральные зазоры в
  вызовах запрещены (аудит G5/G8). Полшага (7, 9, 11) не существует.
  Нейтральный нулевой зазор `gap: 0.0` — не член шкалы S1; он разрешён
  только как задокументированное исключение «ритм без зазора»
  (см. «Исключения»).
- **LAY7.2** Правило выбора: внутренние зазоры контролов — S/SM; паддинг
  контейнеров — MD/LG; воздух от краёв вьюпорта — LG/XL (пары
  «поверхность ↔ край» — таблица S4).
- **LAY7.3** Вертикальный зазор в `Column` — `MeasuredItem::Fixed
  { w: 0.0, h: <зазор> }`, не `Spacer`: распорка в колонке места по главной
  оси не занимает (пин тестом `measured_column_matches_manual_fixed_oracle`).

**Исключения (документированные отклонения от LAY7.1):** палитра команд
(`crates/canvas-app/src/palette.rs`) — `PAL_GAP 5 / PAL_DROP_PAD 5 /
PAL_DROP_GAP 3 / PAL_CAPTION_PAD 2` — значения заморожены CSS-прототипом
F-7.9 (плотность списка; микрозначения ниже шкалы). Каждая константа в коде
помечена комментарием со ссылкой на этот пункт. Новые off-scale значения
без внесения в этот список запрещены.

## LAY8. Адаптивность: вьюпорты, брейкпоинты, деградация

Порядок деградации при сужении слота/окна — строго именованный:

1. **Fluid** — grow-дети и `Fill`/percent-треки сжимаются первыми
   (свободное место кончается);
2. **Именованная политика** — `SqueezeTail`/`Wrap` на главной оси; ellipsis
   на тексте (LAY6.1);
3. **Деградация поверхности** — `DegradationPolicy::HideBelow { min_w, min_h }`
   (П10): окно меньше минимума → поверхность скрывается ЦЕЛИКОМ, не
   сжимается в нечитаемую кашу (what-if бар < 900×600);
4. **Промежуточных ступеней нет** — «полускрытые», полупрозрачные и
   «сжатые до нечитаемости» состояния запрещены.

- **LAY8.1** Канонические вьюпорты гейтов: **1280×800 / 1024×640 / 800×560**
  (линт G4: 0 пересечений интерактивных rect'ов разных поверхностей одной
  полосы, 0 выходов за вьюпорт, 0 текстовых переливов; × RU/EN). Web-аудит
  оболочки — дополнительно 7 вьюпортов 375–1920 (CR-014).
- **LAY8.2** DOM-оболочка: `@media (max-width: 1199px)` — тулбар в левый
  нижний угол; `@media (pointer: coarse)` — тач-цели. GPU-UI эквивалент
  брейкпоинта — `HideBelow` в `SurfaceRegistry` (LAY8, п.3); брейкпоинт
  обязан быть зарегистрирован там же, где рисуется поверхность, а не в теле
  отрисовки.
- **LAY8.3** Тач-цели: на coarse-указателе hit-rect дотягивается до
  **44 лог. px** по обеим осям (`MIN_TOUCH_TARGET`, FR-097), центрированно,
  с клампом в контейнер; визуал не меняется, десктоп бит-в-бит прежний.
  Новая интерактивная зона < 44 px обязана пройти через hit-only расширение.
- **LAY8.4** Safe-area: DOM-оболочка — `viewport-fit=cover` +
  `max(8px, env(safe-area-inset-*))` на прижатых элементах (FR-099).
  GPU-панели держат поля от краёв ≥ 8–16 px (S4), чтобы notch/жест-бар не
  перекрывал контент; проброс env() в GPU-UI — только через новый
  AppEvent-канал (решение владельца), не через CSS-парсинг в рантайме.

## LAY9. Движки вёрстки и паритет

- **LAY9.1** Единый контракт — `trait LayoutBackend`: `lay_out_row/column/
  measured/grid` + маска `features()`. Потребитель пишет
  `Row { .. }.lay_out(slot, &children)` и не знает, кто считает rect'ы;
  явный выбор — `lay_out_with(backend, …)` (пилотные поверхности, тесты).
- **LAY9.2** `default_backend()` → `FlexLayoutEngine` (собственный движок,
  zero-dep инвариант G7, ADR-0015); `pilot_backend()` → `NativeBackend`
  (перенос примитивов 1:1, оракул старой семантики). taffy вырезан (W4);
  возврат внешнего движка — только через ADR.
- **LAY9.3** Задокументированные расхождения семантик (не дефекты):
  `SqueezeTail` ≠ `flex-shrink` (C3); `MainAlign::End` при переполнении —
  unsafe-выталкивание за начальный край (без fallback); rounding on freeze
  ≤ 0.5 ui px. Новый backend обязан воспроизводить политику `SqueezeTail`
  дословно (§Контракт-4 FR-068) и проходить общие golden-эталоны.
- **LAY9.4** Оракулы web-паритета — HTML5 demo-goldens
  (`canvas-ui/tests/html5_demos.rs`, 15 эталонов: sticky-header, grid-12-col,
  masonry-lite, aspect-ratio, modal-fixed-clip, … + 5 CanvasDesk-специфичных).
  Новый CSS-паттерн в ките: сначала эталон в html5_demos (дамп rect'ов),
  затем использование в потребителе. Изменение эталона — осознанный PR
  с diff (регенерация `CANVAS_UI_UPDATE_HTML5=1`).

## LAY10. Гайдлайны: типовые каркасы

Проверенные паттерны поверх примитивов (соответствуют 15 golden-эталонам):

- **Панель** — `Column`: `PanelHeader` (фикс. высота S3) → тело (grow 1 или
  окно `list_rows` + `SceneOverflow::Hidden`) → футер/действия (фикс).
  Зазор — SPACING_SM/MD, пад контейнера — SPACING_LG (S1).
- **Тулбар/строка действий** — `Row { gap: SPACING_SM, main: End }`: слева
  контент, справа действия; прижатие к правому краю — `MainAlign::End`,
  не «распорка + SpaceBetween».
- **Форма/настройки** — `Column` фиксированных строк: label (измеренный) +
  контрол; перекрёстное выравнивание разновысоких контролов —
  `CrossAlign::Center`; разделители секций — `Spacer(SPACING_MD)`.
- **Модалка** — `stack(центр)` + `constrain(min, max)`: фиксированные
  границы от шкал, центрирование от слота вьюпорта; затемнение —
  `stage_dim` (L4-полоса).
- **Витрина/галерея** — `grid_cells` с направляющими ширинами от
  `RowGuides`/измерения; перенос «лишних» карточек — новая строка сетки,
  не обрезка.
- **Строка чипов** — `Row { policy: Wrap, gap: SPACING_S }`; выбор чипа —
  ChipStrip (K1), не ручные чипы.

**Анти-паттерны (запрещены):**

- ручная арифметика `x += w + gap` вне `layout/` без `Custom`-обоснования;
- молчаливые клампы/срезы (`take(`, `break`-клампы, посимвольные ширины) —
  G5;
- вёрстка от вьюпорта в глубине дерева (LAY1.1);
- своя скролл-модель (`offset + ручной кламп`) мимо `ScrollState` (K3);
- зазоры/высоты вне шкал S1/S3;
- flex-факторы при `SqueezeTail` (игнорируются политикой — LAY3.2);
- второй расчёт геометрии для хитов (LAY1.2);
- fit-переполнение «спрятанное» под клип (`SceneOverflow::Hidden`) вместо
  исправления политики: клип — для окон списков, не для маскировки дефекта.

## LAY11. Чек-лист новой раскладки

Перед пушем новой поверхности/панели:

1. Слот приходит от родителя (LAY1.1), вьюпорт — только корневой?
2. Каждый контейнер выражен примитивом LAY2 / сценой LAY5 / `Custom`
   с обоснованием?
3. Зазоры и паддинги — из шкал S1/S4, высоты — из S3?
4. Весь текст — измеренный (`MeasuredItem`/`TextMeasurer`), клампы явные?

Перечень ИСЧЕРПЫВАЮЩИЙ: ниже — все задокументированные отклонения
поверхностей от буквы правил LAY1–LAY11, принятые владельцем по итогам

правило видит код, а не переписывает его: исключение фиксирует существующее
осознанное решение, а не санкционирует будущую самодеятельность. Якоря —
имена функций/констант/структур + файл; номера строк не фиксируются
(файлы растут), сверка — grep-ом по текущему HEAD. Новое исключение

- **Explain, tidy-дерево.** Раскладка дерева объяснения (колонка = уровень,
  ряд = порядок листьев, безье между портами — FR-083) — алгоритм одного
  объекта, а не каркас поверхности: кит «список однородных строк + скролл»
  здесь неприменим, что зафиксировано в шапке модуля. Граница: хром окна
  (шапка, крошки, футер) остаётся на kit/примитивах (FR-060); через тот же
  путь вправо идёт только новый алгоритмический лейаут того же класса.
- **Docs, GFM.** `layout_page`/`layout_table` рендерят вшитый контент
  (`user-docs/`): геометрия — чистая функция от ширины контента и замера
  (LAY6 соблюдён), отступы — на шкале `tokens::SPACING_*`; UI-обвязка
  просмотрщика (док, меню «?», скролл) — kit. Граница: контент-рендер
  расширяется свободно, UI-каркас поверх него — нет.
- **Wheel-меню.** Полярные координаты — канонизированный escape-hatch
  (LAY5.1, G8): геометрия считается чистой функцией `wheel_geometry` для И
  рендера, И hit-теста (LAY1.2 — один источник), рисуется специализированным
  SDF-проходом — карточный пайплайн дуг не рисует. Новая «экзотика» — только
  тем же путём: чистая функция + комментарий-обоснование.
- **`gap: 0.0`.** Допустим ТОЛЬКО как осознанный нулевой зазор — «ритм без
  зазора», когда шаг композиции несут высоты строк/распорки (стопки строк,
  таблицы без лишнего воздуха; в `stage.rs` — инвариант `sync_scroll`).
  0 не входит в S1 и не может читаться как «зазор забыли выбрать»; в
  неочевидных местах — комментарий в коде.
- **`row_gap: 2.0`.** Значение живёт только в демо-секциях Table
  UI-консоли: витрина демонстрирует параметр `TableOpts.row_gap`, поэтому
  число — часть демо-контракта, а не шкалы. В прод-поверхности переносить
  запрещено; прод-ритм таблиц — `row_gap: 0.0` (см. выше) или зазор S1.
- **Hairline 2–4 px.** Микрозначения ниже минимума S1 (6): инсеты плотности
  (подсветка строки, стык колонок, пад чипа-полосы, кламп kit-viewport) и
  исторические надбавки линейки витрины. Граница: новый hairline-зазор в
  прод-раскладке не вводится — либо токен S1, либо правка этого раздела;
  существующие значения миграцией не меняются (утроение микроотступа, пины).
- **Пады 14–16 px.** Значения между ступенями S1 12 и 24 — «дыра» шкалы для
  падов контейнеров: миграция 14/16 → 24/12 меняет плотность устоявшихся
  поверхностей без выигрыша. Новые пады контейнеров — MD/LG (LAY7.2), не 14/16.
- **Поля 20–40 px.** Внешние поля окон и клампы к вьюпорту: S1 кончается на
  XL 24, значения 26–40 недостижимы, 20/22 — между 12 и 24. Новые значения
  вне {6, 8, 10, 12, 24} запрещены без правки этого раздела; производные
  суммы (2×пад рендера) считаются от источника и не мигрируют.
- **Метрики элементов.** Пад чипа и шаги строк текста — размер/шаг элемента,
  а не зазор между блоками: правило шкалы зазоров к ним по природе
  неприменимо (смежные текстовые метрики вроде `TITLE_LINE_H 17` — вне
  LAY7). Новый зазор между блоками, оформленный «метрикой», — обход этого
  раздела, а не исключение.
