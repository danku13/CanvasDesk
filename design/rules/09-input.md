# 09 — Адекватность поведения input-модулей

> Норматив аудита 2026-10-09 (волна «input-адекватность»): единая модель поля,
> клавиатурный контракт, видимость каретки, выделение, состояния, семантика
> типов, IME/web-паритет, запрет дублей. Код модели —
> `crates/canvas-ui/src/component/text_field.rs` (`TextFieldModel`,
> `TextFieldAction`, `text_field()`), маппер клавиш — app-слой
> (`canvas_app::app::input::text_field_action`). Источники: `00-principles.md`
> (П4/П5/П6), `08-states.md` (ST1/ST2), `use-cases/text-field.md`.

## IN1. Единая модель поля — kit `TextFieldModel`

Любое текстовое поле UI приложения (поиск, фильтры, настройки, чат-агент,
инлайн-правки) держит текст/каретку/селекцию в `TextFieldModel` кита.
Позиции — в СИМВОЛАХ (`chars().count()`), не в байтах (П6).

Запрещено:

- собственные структуры «строка + курсор» (`SearchInput`, `filter: String` +
  `cursor: usize`, `EditField { text: String }`) — дубли эвристик каретки,
  исторически ломавшиеся на кириллице;
- `String::push`/`pop()` как модель ввода — каретка «всегда в конце» без
  возможности клика/стрелок адекватностью не является;
- байтовые индексы каретки.

## IN2. Клавиатурный контракт (редакторский минимум однострочного поля)

Поле обязано обрабатывать ОДИН и тот же набор клавиш — через kit-действия
`TextFieldAction` + `TextFieldModel::apply` (headless-тестируемо), а не
собственными match-блоками:

| Клавиша | Действие |
|---|---|
| Печатные символы / IME-коммит | `Insert` (замещает селекцию) |
| Space | `Insert(" ")` — Space это Named-клавиша winit, ветка Character его не видит |
| Backspace / Ctrl+Backspace | `Backspace` / `BackspaceWord` |
| Delete / Ctrl+Delete | `Delete` / `DeleteWord` |
| ← / → (±Shift) | `CaretLeft/Right { extend }` |
| Ctrl+← / Ctrl+→ (±Shift) | `CaretWordLeft/Right { extend }` |
| Home / End (±Shift) | `Home` / `End` |
| Ctrl+A (латиница/кириллица/control-код) | `SelectAll` |
| Ctrl+C / Ctrl+X / Ctrl+V | `Copy` / `Cut` / `Paste` → эффекты потребителю (буфер — на стороне app: кит zero-dep) |

Семантика без селекции: `Copy`/`Cut` — весь текст (конвенция однострочных
полей чата/фильтра); `BackspaceWord`/`DeleteWord` — эвристика слова
(whitespace + ASCII-пунктуация — разделители). Ctrl/Alt+символ, не попавший
в таблицу, НЕ вставляется в поле (уходит хоткей-лестнице).

Enter/Esc — семантика потребителя (submit/cancel), в `apply` не входят.

## IN3. Каретка всегда видна (скролл-вслед)

Если текст шире поля: при фокусе показывается окно текста, следующее за
кареткой (`TextFieldLayout.scroll_x`, Clip-политика — см.
`use-cases/text-field.md` §6); ellipsis не применяется к активному вводу.
Литералы-каретки `format!("{}|")` в тексте ЗАПРЕЩЕНЫ — каретка рисуется
из `TextFieldLayout.caret_x` (1.5 px, слот `accent`, паттерн агент-панели).

## IN4. Выделение

Shift-стрелки/Shift+Home/End расширяют селекцию (anchor/head в символах);
подложка селекции — accent α0.25 под текстом (фон до текста, границы по
замеру префиксов тем же кеглем). Печать/Backspace/Delete замещают селекцию.

## IN5. Мышь

- Клик по полю — фокус + каретка по месту клика (`caret_index_at_x`,
  символьная позиция с учётом `scroll_x`).
- Двойной клик — выделение слова (план v2), drag-селекция — v2.
- Hit-зона поля = rect поля из той же layout-функции (П5).

## IN6. Состояния поля (по ST1/ST2)

Normal / Focused (рамка accent, каретка видна) / Disabled (текст
`control_disabled_text`, ввод игнорируется, busy-статус потребителя) /
Error (рамка слота `control_danger`, рисует потребитель — валидация).
Hover-заливки у поля нет (поле идентифицируется фокусом).

## IN7. Семантика типов полей

| Тип | Обязательные свойства | Примеры экрана |
|---|---|---|
| text | placeholder, скролл-вслед, полный клавиатурный контракт | поля настроек (URL, модель) |
| password (маска) | `mask_char: Option<char>` в layout — глифы заменяются на маску, модель хранит исходник; каретка/селекция работают по маске | API-ключи (LlmSettings) |
| search/filter | + живой фильтр без Enter, сброс выделения/скролла строк при правке, placeholder | Ctrl+F, палитра Ctrl+P, галерея Ctrl+T |
| chat-input | + Enter=send, busy→Disabled, цитирование placeholder'ом сценария | агент-панель Ctrl+I |

`max_chars` (политика модели `TextFieldModel.max_chars`) — жёсткий потолок
`Insert` (клампит вставку до лимита; backspace/delete не ограничиваются).
Multiline-поле/number-spinner/select — вне экранов продукта; вводятся только
при появлении экрана-потребителя (принцип «не спекулировать компонентами»).

## IN8. IME/web-паритет

Каждый активный текстовый приёмник обязан:
1) присутствовать в `App::text_input_active()` (web-шим держит фокус
виртуальной клавиатуры);
2) присутствовать в `App::insert_committed_text` (маршрут Ime::Commit);
3) приоритет приемников фиксирован: настройки-поле → редактор заметки →
поиск → палитра → агент-панель → инлайн-правки. Отсутствие приёмника в
маршруте = на web/mobile ввод молча теряется (найденный дефект агент-панели).

## IN9. Никаких дублей — kit everywhere

Новый текстовый приёмник = `TextFieldModel` + app-маппер
`text_field_action()` + рендер через `kit::text_field()`. Копировать
клавиатурные match-блоки запрещено; расхождение контракта между полями —
дефект, а не фича. Существующие дубли мигрируются на кит (волна
«input-адекватность» 2026-10-09: SearchInput, галерея, палитра, настройки,
explain-инлайн, агент-панель).

## IN10. Достаточность набора кита

Минимально достаточный состав input-модуля кита: `TextFieldModel`
(текст/каретка/селекция/словесные операции/max_chars) + `TextFieldAction`/
`TextFieldEffect` (клавиатурная семантика) + `text_field()` layout
(placeholder/ellipsis/скролл-вслед/маска/caret_x) + `caret_index_at_x`
(клик) + `TextField`-компонент (контейнер/фокус/состояния). Достаточность
проверена аудитом экранов: все текстовые входы приложения покрываются
типами IN7; недостающее на момент аудита — реализовано этой волной.
