# Шаблоны архитектурных нод

Шаблон — готовая роль для ландшафта сервиса (балансировщик, кэш, БД,
очередь…). Вместо того чтобы каждый раз писать формулу с нуля, вы выбираете
роль — на канвасе появляется заметка с **Numi-листом параметров** (`rps =
1000 rps`, `servers = 2`) и **формулой** (например, `mm1($rps, $service_rate,
$servers)`). Нода считается как обычная Numi-заметка: меняете параметр —
итог пересчитывается сразу, и если нода соединена value-связями, пересчитывается
весь downstream (см. [Расчёты и поток значений](calculations.html)).

## Как создать ноду из шаблона

- **Палитра** — постоянный левый док (в стиле Miro), виден всегда: поиск по
  имени/описанию, фильтры-чипы категорий, список шаблонов с иконками.
  - **Клик** по шаблону — нода в центре viewport.
  - **Drag-and-drop** — перетащите карточку в нужную точку канваса:
    под курсором следует полупрозрачный призрак, отпускание создаёт ноду в
    этой точке.
  - `Ctrl+P` — фокус в поиск палитры (когда док свёрнут — разворачивает);
    `Esc` — свернуть док в полосу-ручку слева (клик по ручке разворачивает
    обратно). Состояние (развёрнут/свёрнут) запоминается между запусками.
- **Радиальное меню** — `Shift+клик` по пустому месту: внешнее кольцо —
  категории, внутренние кольца — шаблоны выбранной категории. Клик по
  шаблону создаёт ноду в точке клика. `Esc` или клик заметно в стороне —
  закрыть меню.
- **MCP** — AI-клиент вызывает `template_instantiate {id, x, y, params}`.

После создания нода связана с шаблоном (id + версия хранятся в
`.canvas`-файле), но живёт своей жизнью: правка параметров — это правка
текста ноды, никаких скрытых состояний.

## Что «знает» шаблон: манифест

Каждый шаблон описан манифестом `template.json`. Поля, которые учитывает
приложение:

| Поле | Что это | Как используется |
|---|---|---|
| `id` | Уникальный идентификатор (`com.canvasdesk.lb`) | Связь ноды с шаблоном, MCP, override |
| `name_en` / `name_ru` | Двуязычное имя | UI показывает русское имя, MCP — оба |
| `version` | Semver (`1.0.0`) | Кнопка «Обновить до vX.Y.Z» у устаревших нод |
| `category` | Категория (`backend`, `network`, `custom`) | Кольца wheel, чипы палитры, цвет полосы ноды |
| `description` | Описание (рус/англ) | Поиск в палитре, MCP |
| `params` | Список параметров | Numi-лист в тексте ноды (см. ниже) |
| `expr` | Формула с `$параметрами` | Итог — в футере карточки и в value-потоке |
| `color` | Цвет категории `#RRGGBB` | Полоса в шапке шаблонной ноды |
| `icon` | Ключ квад-иконки (`lb`, `db`, `cache`…) | Иконка в шапке ноды, wheel и палитре |

## Доменные типы параметров

У каждого параметра манифеста есть тип — он говорит, **что учитывается** и
в каких единицах параметр ожидает значения:

| Тип | Размерность | Типовые единицы | Примеры |
|---|---|---|---|
| `rate` | скорость (req/время) | `rps`, `req/s` | `1000 rps`, `0.5 rps` |
| `time` | время | `ms`, `s`/`sec`, `min`, `h` | `50 ms`, `168 h` |
| `count` | штуки (безразмерное) | — | `2`, `3 replicas` |
| `bytes` | объём | `B`, `KB`, `MB`, `GB` | `8 KB`, `64 KB` |
| `percent` | доля/процент | `%` | `85 %` |
| `scalar` | безразмерный коэффициент | — | `0.85` (hit rate) |

Дополнительно параметр может задавать:

- **`default`** — стартовое значение при создании ноды (в единице
  параметра);
- **`unit`** — единица по умолчанию (`ms`, `rps`, `KB`…); число без
  единицы трактуется в этой единице;
- **`min` / `max`** — границы разумных значений; выход за границу не
  запрещён, но подсвечивается при валидации манифеста (для MCP —
  предупреждение).

Единицы в параметрах — те же, что и во всей Numi-алгебре CanvasDesk:
`1 sec + 500 ms` конвертируется автоматически, деление сокращает
размерность (`100 req / 2 sec → 50 req/s`). Полный список единиц — в
[Расчётах](calculations.html#что-можно-в-выражениях).

## Параметры на ноде

Текст шаблонной ноды — обычный Numi-лист присваиваний:

```
rps = 1000 rps
service_rate = 1200 rps
servers = 2
```

- **Правка**: двойной клик по ноде — редактируете как обычный текст;
  значения параметров синхронизируются в `canvasdesk.template`, итог
  формулы и downstream пересчитываются live.
- **Ссылки на параметры в формуле** — `$rps`, `$servers` (синтаксис
  `$имя`). Имена вида `$in`, `$1`…`$N` заняты входами value-потока.
- **Итог формулы** — в футере карточки; он же уходит дальше по
  value-связи (`$in` у приёмника).
- **Перегрузка**: если по формуле ρ ≥ 1 (очередь растёт неограниченно), в
  футере — красная диагностика «перегрузка: ρ = … ≥ 1». Это не ошибка
  ввода, а сигнал узкого места.

## Встроенная библиотека (15 шаблонов)

**Backend — 10:**

| Шаблон | Формула (суть) | Что считается |
|---|---|---|
| Балансировщик нагрузки | `mm1($rps, $service_rate, $servers)` | время ответа кластера M/M/c |
| API-шлюз | `mm1($rps, 1 req / ($latency_budget − $auth_overhead))` | бюджет латентности минус аутентификация |
| Кэш (Redis) | `mm1($qps × $hit_rate, 1 req / $eviction_latency)` | нагрузка с учётом hit rate |
| БД SQL (мастер) | `mm1($qps, 1 req / $query_time, $replicas)` | запись, μ из времени запроса |
| БД SQL (реплика) | `mm1($qps, 1 req / $query_time, $replicas)` | пул читателей; `lag` — справочный |
| Очередь (Kafka) | `mm1($produce_rate / $partitions, $partition_consume)` | партиция как канал обслуживания |
| Воркер | `mm1($tasks_per_sec, 1 req / $processing_time, $workers)` | пул воркеров M/M/c |
| CDN | `mm1($rps × (1 − $cache_hit), 1 req / $origin_latency)` | промахи уходят в origin |
| Хранилище (S3) | `mm1($requests_per_sec, 1 req / $latency)` | латентность запроса; размер объекта — справочный |
| Сервис аутентификации | `mm1($rps, 1 req / $token_verify)` | верификация токенов; `cache_ttl` — справочный |

**Network — 5:**

| Шаблон | Формула (суть) | Что считается |
|---|---|---|
| HTTP-эндпоинт | `mm1($rps, 1 req × $max_connections / $timeout)` | пул соединений; `keepalive` — справочный |
| gRPC-сервис | `mm1($rps, 1 req / $timeout)` | латентность вызова; окно стрима — справочное |
| WebSocket | `mm1($connections × $messages_per_sec, $handler_rate)` | агрегированный поток сообщений |
| GraphQL | `mm1($rps × $avg_complexity, 1 req / $resolver_time)` | сложность запроса умножает нагрузку |
| TCP-балансировщик | `mm1($connections_per_sec, $server_rate, $servers)` | L4-балансировка соединений |

Имена двуязычные: интерфейс показывает русское, MCP отдаёт оба. «Справочные»
параметры (lag, retention, keepalive) в формулу не входят — они для
контекста и what-if прикидок.

## Свой шаблон

1. Создайте ноду из любого шаблона (или обычную Numi-заметку) и доведите
   параметры/формулу до нужного вида.
2. Выделите её → палитра под выделением → **«Действия» → «Сохранить как
   шаблон»**.
3. Манифест запишется в `~/.canvasdesk/templates/<id>/template.json` и
   сразу появится в палитре `Ctrl+P`, wheel-меню и MCP (`source: custom`).

- **Override**: custom-шаблон с тем же `id`, что и встроенный, перекрывает
  его (удобно для правки дефолтов под свою команду).
- **Перенос/шаринг**: скопируйте папку `~/.canvasdesk/templates` на другую
  машину (или в репозиторий команды).
- **Удаление**: удалите папку шаблона; операция файловая, мимо undo.

## Обновление до новой версии

Если версия шаблона в реестре новее, чем у ноды, в палитре выделения
появляется группа **«Шаблон» → «Обновить до vX.Y.Z»**. При обновлении:

- значения существующих параметров **сохраняются**;
- новые параметры получают дефолты из манифеста;
- формула заменяется на формулу новой версии (старый итог пересчитается
  автоматически).

## MCP

| Инструмент | Что делает |
|---|---|
| `template_list` | все шаблоны: id, имена (рус/англ), категория, версия, параметры, `source: builtin\|custom` |
| `template_instantiate {id, x, y, params}` | создаёт ноду; `params` переопределяют дефолты (число — в единице параметра манифеста) |

## Ограничения и нюансы

- Шаблонная нода — обычная text-нода с расширением `canvasdesk.template`:
  Obsidian Canvas переживает round-trip (расширение сохраняется как
  неизвестное поле), формулы в Obsidian не считаются.
- Поток значений — DAG: циклы запрещены, при попытке замкнуть value-связь
  будет предложена обычная контрольная связь.
- Undo работает для создания ноды из шаблона и правки параметров; запись
  и удаление custom-шаблона — файловые операции, мимо undo.
