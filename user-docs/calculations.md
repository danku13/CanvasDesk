# Расчёты и поток значений

CanvasDesk умеет считать прямо на канвасе: пишете формулы «человеческим
языком» в заметках (стиль Numi), соединяете ноды связями-потоками — и всё
пересчитывается мгновенно, как таблица.

## Numi-формулы в заметке

Любая строка заметки вида `имя = выражение` становится вычисляемой:

```
rps = 1000
latency = 50 ms
replicas = 3

cpu_per_request = 0.5 ms × 1000 rps / 3 replicas
total = sum(20 ms, latency) × 2
```

Под текстом появится строка результата (последнее утверждение). Ошибочная
строка подсвечивается красным с подсказкой — остальные строки продолжают
считаться. Строки без присваивания тоже вычисляются (`2 + 2` покажет `4`);
блоки кода в тройных кавычках и обычный текст без формул игнорируются.

### Что можно в выражениях

- **Числа**: `5`, `3.14`, суффиксы `1k`, `2M`.
- **Единицы**: время `ms`, `s`/`sec`, `min`, `h`/`hour`; счёт `req`;
  скорость `rps`/`req/s`; объём `B`, `KB`, `MB`, `GB`; деньги `$`/`usd`;
  проценты `%`. Составные единицы поддержаны: `ms·req/s`.
- **Операторы**: `+ − * / × · ⋅ ✕ ⨯ ÷`, скобки, унарный минус;
  неявное умножение (`5 ms`, `$5`), `x`/`х` как умножение (`35 x 20` = 700).
- **Функции**: `sum(...)`, `avg(...)`, `max(...)`, `min(...)`,
  `percentile(p, ...)`.
- **Теория очередей (FR-015)**: `mm1(λ, μ[, c])`, `mmc(λ, μ, c)`,
  `utilization(λ, μ[, c])`, `littles_law(λ, W)`, `erlang_c(λ, μ, c)` —
  см. раздел «Расчёт пропускной способности» ниже.
- **Переменные**: латиница и кириллица (`х = 200`), хвостовое присваивание
  `expr = name`.
- Сложение требует одной размерности (`1 sec + 500 ms == 1.5 sec` —
  конвертируется автоматически); деление сокращает единицы
  (`100 req / 2 sec == 50 req/s`).

Явная формула всей ноды (удобно для MCP/AI-агентов) — расширение
`canvasdesk.expr` в `.canvas`-файле; она имеет приоритет над текстом.

### Автодополнение формул (FR-021)

Пока каретка стоит на вычисляемой строке (присваивание, `= …` или
выражение), рядом с ней открывается popup подсказок — варианты
отфильтрованы по набираемому префиксу:

- **Функции** с сигнатурой (`mm1(λ, μ[, c])`, `sum(x, …)`) — вставляются
  с открывающей скобкой;
- **Единицы** (`ms`, `sec`, `rps`, `KB`, `%`…) — после числа или числа с
  пробелом (`50 ` → весь список единиц);
- **Переменные** строки — заведённые присваиваниями выше по тексту;
- **`$`-ссылки** — после `$`: `$in` и `$1`..`$N` по фактическим
  value-входам ноды, параметры шаблона (`$rps`…) у шаблонных нод.

Клавиши: `↑`/`↓` — выбор, `Enter`/`Tab` — принять (заметка не
фиксируется, можно продолжать набор), `Esc` — закрыть подсказки.
Обычный текст без формул подсказок не вызывает — автодополнение не
мешает прозе.

## Поток значений между нодами

Связи бывают двух типов:

- **Контрольная** (обычный drag от порта) — просто визуальная связь.
- **Поток значений** (**Shift + drag** от порта или палитра связи →
  «Поток») — бирюзовая линия, передающая значение ноды-источника дальше.

Значение ноды — её последняя вычисленная формула. В заметке-приёмнике
входящие значения доступны как:

- `$in` — единственное входящее value-ребро;
- `$1`, `$2`, … `$N` — входящие value-рёбра по порядку.

Пример: три заметки, соединённые value-связями `A → B → C`:

```
A:  rps = 1000
B:  total = $in × 2        → 2000
C:  per_node = $in / 3     → 666.67
```

Меняете формулу в A — B и C пересчитываются **сразу** (в пределах кадра),
включая лейблы value-рёбер: связь покажет `label · 1000 rps`.

### Построчные точки выхода (FR-025, фича-флаг)

По умолчанию value-связь уносит значение ноды ЦЕЛИКОМ (последняя
формульная строка). В настройках, группа «Связи и порты», есть флаг
**«Точки выхода строк»** (по умолчанию выключен):

- при включении у каждой строки с результатом появляется кружок-порт на
  правом краю заметки — на уровне этой строки (проза — без порта);
- **финальная строка** (значение ноды) — бирюзовый кружок, промежуточные —
  серо-голубые;
- drag от кружка строки всегда создаёт value-связь, несущую значение
  именно этой строки: в приёмнике `$in` будет `1000 rps`, если потянули
  от строки `rps = 1000`, а не от итога;
- у **шаблонной ноды** — кружок у каждой строки листа параметров плюс
  бирюзовый кружок у футера (формула шаблона и есть итог): строка
  `rps = 1000` отдаёт `1000 rps`, футер — результат формулы шаблона;
- кружки сидят на самом краю ноды: захват работает с любой стороны
  кружка (в том числе с наружной, за пределами карточки);
- удалите строку-исток или она станет прозой/ошибкой — приёмник тихо
  получит «вход отсутствует» (нумерация `$1..$N` не съезжает);
- выключенный флаг прячет порты и возвращает прежнее поведение, но уже
  созданные построчные связи продолжают переносить значения строк.

В `.canvas` построчный исток хранится полем `fromLine` ребра — старые
файлы (без него) читаются как раньше, значение ноды целиком.

### Проливание в параметры шаблонных нод (FR-029)

Шаблонные ноды считают формулу по **именованным параметрам** (`$rps`,
`$servers`…), а value-связь по умолчанию кладёт значение в позиционные
слоты `$1..$N` — параметр остаётся со своим локальным значением, и
«пролить» нагрузку из ноды в ноду без правки формулы было нельзя.
FR-029 вводит **адресацию рёбер портами**:

- `fromOutput` — именованный **выход истока**: у шаблонной ноды это
  секция `outputs` манифеста (например, у CDN — `origin_rps`, у
  балансировщика — `out_auth`/`out_feed`/`out_media`); у текстовой ноты —
  **любая переменная Numi-листа** (`peak_rps = 1389 rps` — адресуйте
  `peak_rps`; имя живёт при добавлении строк выше, связь не рвётся);
- `toParam` — **вход параметра приёмника**: значение ребра подставляется
  в `$<имя>` шаблонной ноды-приёмника, **перекрывая** локальное значение
  параметра («проливание сильнее дефолта»), сама формула и текст ноды не
  меняются.

Так собирается цепочка «Трафик → CDN → Балансировщик → сервисы → БД»:
одна правка `dau` в ноде «Трафик» (`node_edit` MCP или редактор) меняет
все downstream-значения без правки формул и связей.

Правила:

- ребро с `toParam` не занимает позиционный слот `$1..$N`;
- несколько рёбер в один параметр — побеждает последнее по порядку рёбер,
  `flow_recalc` отмечает узел предупреждением (строгая проверка —
  `graph_validate`, FR-032);
- сломанная адресация (удалили переменную/строку) — тихая деградация:
  параметр возвращается к локальному значению;
- ИИ-агенту: `template_list` показывает `outputs` каждого шаблона,
  `edges_list` — существующие связи с адресацией, `flow_recalc` —
  значения + именованные выходы + построчные значения каждой ноды.

### Правила и ограничения

- Граф потока — **DAG**: циклы запрещены. При попытке замкнуть value-связь
  появится диалог с предложением создать обычную контрольную связь.
- Ошибка в одной ноде (например, удалили источник) не валит граф: downstream
  получит красную пометку «вход отсутствует», пока цепочку не починят.
- Значения — runtime: в `.canvas`-файле хранятся только формулы и топология,
  как в электронной таблице.
- `$5` без входящих value-рёбер — деньги (5 долларов); в ноде с входами
  целое `$N` — ссылка на вход, для денег пишите `5 usd`.

## Расчёт пропускной способности (FR-015)

В формулы встроены функции теории массового обслуживания — ландшафт
сервиса можно не только рисовать, но и считать:

| Функция | Возвращает | Пример |
|---|---|---|
| `mm1(λ, μ[, c])` | среднее время пребывания заявки в системе W (сек) | `mm1(1000 rps, 1200 rps)` → `0.005 sec` (5 мс) |
| `mmc(λ, μ, c)` | то же для M/M/c (Erlang-C) | `mmc(1000 rps, 600 rps, 3)` → `0.002 sec` |
| `utilization(λ, μ[, c])` | коэффициент загрузки ρ (доля) | `utilization(1000 rps, 400 rps, 3)` → `0.83 %` |
| `littles_law(λ, W)` | среднее число заявок в системе L = λ·W | `littles_law(1000 rps, 5 ms)` → `5 req` |
| `erlang_c(λ, μ, c)` | доля заявок, ожидающих в очереди | `erlang_c(1000 rps, 600 rps, 3)` → `0.3 %` |

Здесь λ — скорость прибытия (например, `1000 rps`), μ — скорость
обслуживания одной единицы (сервера), c — число серверов (по умолчанию 1).

- **Перегрузка** (ρ ≥ 1) — красная строка «перегрузка: ρ = 2 ≥ 1 — очередь
  растёт неограниченно»: это диагностика узкого места, а не ошибка ввода.
- Время — в секундах (`0.005 sec`); умножайте (`× 1000 ms`) при желании
  перевести. Итог можно передавать дальше value-связью: `mm1($in, 1200 rps)`.
- Пример ландшафта: gateway с `mm1($in, 2000 rps, 2)`, за ним DB с
  `mmc($in, 600 rps, 3)` — меняете вход, оба пересчитываются live.
- **Индикаторы узких мест (FR-016)**: включите оверлей **Ctrl+B** — ноды
  с расчётами получат цветную рамку и бейдж (`83% · W: 120 ms`,
  `OVERLOAD 223%`) прямо из посчитанных ρ/W: жёлтая ≥ 70 %, красная
  ≥ 90 %, перегрузка ρ ≥ 1 — видна с любого зума (см.
  [Объекты интерфейса](interface.html)). Шаблонные ноды отдают ρ
  именованным выходом `utilization` — вручную ничего считать не нужно.

## Финансовые функции (FR-027)

Для расчётов юнит-экономики и продуктовой аналитики в формулы встроены 4
доменные функции — расширение FR-015. Используются в шаблонах `com.canvas
desk.ue-npv` и `com.canvasdesk.ue-cagr` (для NPV/CAGR), доступны и в
обычных Numi-заметках.

| Функция | Возвращает | Пример |
|---|---|---|
| `npv(rate, *cf)` | скаляр (USD/исходная единица) — NPV серии потоков | `npv(0.1, -100000, 40000, 50000, 60000)` → чистая приведённая стоимость проекта |
| `cagr(begin, end, periods)` | скаляр (доля) — годовой темп роста | `cagr(100000, 200000, 3)` → `0.2599` (≈26% в год) |
| `irr(*cf)` | скаляр (доля) — внутренняя норма доходности | `irr(-1000, 500, 600, 200)` → `0.1635` (≈16.35% IRR) |
| `cohort_ltv(arpu_m0, margin, r_d1, r_d7, r_d30, months)` | скаляр (USD) — LTV когорты через retention-кривую | `cohort_ltv(20, 0.8, 0.4, 0.25, 0.1, 12)` → LTV при типичной кривой SaaS |

Здесь `rate` — ставка дисконтирования (скаляр, доля 0..1), `cf1..cfN` —
денежные потоки (USD), `begin`/`end` — начальное/конечное значение
(например, MRR), `periods` — число лет, `arpu_m0` — ARPU нулевого месяца,
`r_d1`/`r_d7`/`r_d30` — retention в дни 1/7/30 (доли 0..1).

- **IRR** требует, чтобы потоки имели разный знак (хотя бы один
  отрицательный — инвестиция). Если все потоки одного знака — `BadCall`.
  Метод — Newton-Raphson с начальной догадкой 10%, лимит 100 итераций.
- **cohort_ltv** — линейная интерполяция retention между точками d0=1,
  d1, d7, d30 + экспоненциальное затухание после d30 (r_d30^(d/30)).
  Параметр `margin` ограничен 0..1, `months` — целое неотрицательное.
- Все 4 функции можно передавать дальше value-связями: `npv($in, 50000,
  60000, 70000)` (где `$in` — ставка из другой ноды).
- Пример ландшафта: `ue-cac` (CAC = 50) → value-связь → `ue-ltv-cac`
  (формула `$ltv / $cac`, итог = 6.4) → overlay FR-016 показывает здоровье
  юнит-экономики.

## Шаблоны архитектурных нод (FR-018/019/020)

Вместо того чтобы каждый раз писать формулы с нуля, ноду можно создать из
**шаблона**: в палитре слева (постоянный док; `Ctrl+P` — фокус в поиск;
drag-and-drop карточки — вставка в точку канваса) или в радиальном меню
`Shift+клик` по пустому месту (кольцо категорий → кольца шаблонов). Нода
создаётся с готовым Numi-листом параметров (`rps = 1000 rps`, `servers = 2`)
и формулой (например, `mm1($rps, $service_rate, $servers)`); итог формулы —
в футере карточки и в потоке значений.

> Подробно — в отдельной странице [Шаблоны нод](templates.html): что
> учитывает манифест, доменные типы параметров (rate/count/time/bytes/
> percent/scalar) и единицы, каталог 45 встроенных шаблонов (инфраструктура,
> юнит-экономика, продуктовая аналитика), свой шаблон и обновление версий.

- **Параметры редактируются как обычный Numi-текст**: двойной клик по ноде,
  меняете `rps = 2000 rps` — формула и downstream пересчитываются live.
- **Высота карточки подстраивается под переносы**: длинное значение параметра
  переносится на несколько рядов — нода вырастет ровно по реальным метрикам
  шрифта (высота тела измеряется теми же встроенными шрифтами, что и рендер),
  итог формулы останется строкой под текстом, а не налезет на него (CR-012).
- **45 встроенных шаблонов** в трёх категориях: инфраструктура — 15
  (балансировщик, API-шлюз, кэш, master/replica БД, очередь, воркер, CDN,
  хранилище, аутентификация; HTTP, gRPC, WebSocket, GraphQL, TCP-балансировщик),
  юнит-экономика — 18 (CAC, LTV, MRR/ARR, runway, NPV…) и продуктовая
  аналитика — 12 (retention, воронка, NPS…). Имена двуязычные (рус/англ).
- **Свой шаблон**: выделите шаблонную ноду → палитра → «Действия» →
  **«Сохранить как шаблон»**. Манифест сохраняется в
  `~/.canvasdesk/templates/<id>/template.json` и появляется в палитре,
  wheel-меню и MCP. Папку можно переносить между машинами (шаринг —
  копирование папки).
- **Обновление**: если версия шаблона в реестре новее, чем у ноды
  (linked-связь), в палитре выделения появляется группа **«Шаблон» →
  «Обновить до vX.Y.Z»**. Значения параметров сохраняются; новые параметры
  получают дефолты. Custom-шаблон с тем же id, что и встроенный,
  перекрывает его (override).
- **MCP**: `template_list` — все шаблоны с пометкой `source: builtin|custom`;
  `template_instantiate {id, x, y, params}` — создание ноды с
  переопределениями (число — в единице параметра манифеста).

## Undo и безопасность

Любая правка формулы, тогл потока, закрепление портов и раскладка — один
undo-шаг (**Ctrl+Z**). Live-пересчёт downstream сам по себе не «undo-ится» —
он просто следствие изменения исходников.

## Сценарии использования

- **Ландшафт сервиса**: ноды = gateway/queue/replica/DB, рёбра = поток
  запросов, в каждой ноде — параметры. Сразу видно, где узкое место.
- **Сметы и бюджеты**: валюты, проценты, `sum()` по веткам.
- **What-if (в планах, FR-017)**: подстановка значений сверху и пересчёт
  сценария.
