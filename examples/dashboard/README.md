# Repo Dashboard — пример виджета с сетью (T22-C)

Мини-дашборд репозитория: звёзды/форки/issues через `fetch` к
`https://api.github.com`. Демонстрирует работу с внешней сетью —
единственным permission, которое надо запрашивать осознанно.

Две линии защиты, обе видны на этом примере:

1. **Хост**: без `"network"` в `widget.json` внешние
   `WebResourceRequested` блокируются пустым 403 (SPEC §7.6).
2. **CSP самого виджета**: `connect-src 'self' https://api.github.com` —
   fetch идёт только на явно перечисленный origin.

Задача виджета при отказе — деградировать с понятной ошибкой
(красная панель с подсказкой), не падать и не зависать.

## Демонстрация отказа

1. `npm run pack`, перетащите `dist-widget/` на канвас → установится с
   permission `network`, данные загрузятся.
2. Удалите `"network"` из `public/widget.json`, запустите `npm run pack`
   снова, перетащите новую версию на канвас → «Обновить» (версия выше) →
   `fetch` получит 403, виджет покажет панель ошибки с объяснением.
3. В standalone (`npm run dev`) сеть идёт напрямую из браузера —
   хост-фильтры не участвуют.

## Сборка

```
npm install
npm run typecheck
npm run pack      # → dist-widget/
```

## Что демонстрирует

| Приём | Где в коде |
|---|---|
| permission `network` | `public/widget.json` |
| CSP для fetch | `connect-src` в `index.html` |
| обработка 403-отказа хоста | `load()` → ветка `response.status === 403` |
| обработка сетевого исключения | `catch` → панель ошибки |
| refresh по кнопке | обработчик `#refresh` |

API GitHub без токена лимитирован (60 запросов/час с IP) — для демо
достаточно; свой токен добавляется заголовком `Authorization`.
Справочник — `docs/WIDGETS.md`.
