# Демо-стенд: от нуля до записи скриншотов и GIF за ~10 минут

Рабочий рецепт подготовки среды для записи демонстраций CanvasDesk под Linux
без sudo и без GPU. Всё проверено живьём при записи демо FR-013 (numi-вычисления
в текстовых нодах): Xvfb + software Vulkan (lavapipe) + XTEST-автоматизация.
Артефакты снимаются с реально запущенного приложения — ничего не дорисовывается.

Инструкция адресована агенту, который готовит стенд в одноразовой песочнице
(окружение теряется между сессиями — этот документ гарантирует, что всё
восстанавливается по одному файлу за минимум шагов).

> **Автоматизированная альтернатива:** [docs/demo-environment.md](demo-environment.md) —
> стенд `scripts/demo/` одним прогоном (xdotool-драйвер, env.sh bootstrap
> без ручных шагов, готовый конвейер GIF/MP4 + скриншоты, референсный
> сценарий FR-013/FR-014). Для типового демо быстрее он.

---

## 1. Что уже должно быть в песочнице (проверить одной строкой)

```bash
which Xvfb ffmpeg && python3 -c "import Xlib; print('python-xlib OK')" && cargo --version
```

| Компонент | Роль | Если нет |
|---|---|---|
| `Xvfb` | виртуальный X-сервер (окно приложения) | обычно предустановлен |
| `ffmpeg` | запись GIF (x11grab) и одиночных кадров | обычно предустановлен |
| `python-xlib` | XTEST-автоматизация ввода | `pip install python-xlib` |
| rustup/cargo stable | сборка | `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs \| sh -s -- -y` (см. `docs/ENVIRONMENT.md` §4) |

Всё остальное доставается **без sudo** (§3).

## 2. Карта стенда

```
~/demo-stand/                     # всё non-sudo окружение (пути в lvp.json — абсолютные!)
├── xkb/usr/lib/x86_64-linux-gnu/ # libxkbcommon-x11, libxcb-xkb, libxkbcommon
└── mesa/                         # lavapipe (software Vulkan)
    ├── lvp.json                  # свой ICD-манифест (путь к .so — абсолютный)
    └── usr/lib/x86_64-linux-gnu/libvulkan_lvp.so

<репо>/scripts/xdemo.py           # автоматизация ввода (XTEST): печать, клики, зум, пан
<репо>/examples/demo-numi.canvas  # эталонная демо-сцена (шаблон для новых сцен)
/tmp/demo-live.canvas             # РАБОЧАЯ КОПИЯ сцены (приложение пишет автосейв!)
/home/z/my-project/download/<demo>/  # артефакты (в репозиторий НЕ коммитятся)
```

## 3. Окружение без sudo: lavapipe + xkb (5 минут, один раз на песочницу)

```bash
STAND=$HOME/demo-stand && mkdir -p $STAND && cd $STAND

# xkb — без них winit не поднимет X11-контекст
apt-get download libxkbcommon-x11-0 libxcb-xkb1 libxkbcommon0
mkdir -p xkb && for f in libxkb*.deb libxcb*.deb; do dpkg -x "$f" xkb/; done

# lavapipe — software Vulkan, wgpu работает без GPU
apt-get download mesa-vulkan-drivers
mkdir -p mesa && dpkg -x mesa-vulkan-drivers_*.deb mesa/
cat > mesa/lvp.json <<EOF
{
  "ICD": {
    "api_version": "1.3.305",
    "library_path": "$STAND/mesa/usr/lib/x86_64-linux-gnu/libvulkan_lvp.so"
  },
  "file_format_version": "1.0.0"
}
EOF
# ВАЖНО: library_path обязан быть абсолютным — поэтому $STAND разворачивается в heredoc.

# лоадер Vulkan (если его нет в системе)
ldconfig -p | grep -q libvulkan.so.1 || { apt-get download libvulkan1 && mkdir -p vk && dpkg -x libvulkan1*.deb vk/; }
```

Профиль окружения (класть в начало **каждой** шелл-сессии/скрипта, работающего со стендом):

```bash
export STAND=$HOME/demo-stand
export DISPLAY=:99
export LD_LIBRARY_PATH=$STAND/xkb/usr/lib/x86_64-linux-gnu${VKPATH:+:$VKPATH}
export VK_ICD_FILENAMES=$STAND/mesa/lvp.json
# если качали libvulkan1 — добавить: export LD_LIBRARY_PATH=$LD_LIBRARY_PATH:$STAND/vk/usr/lib/x86_64-linux-gnu
```

## 4. Сборка и запуск (2–3 минуты на тёплой машине)

```bash
cd <репо>
cargo build --release -p canvas-app        # тянет core/render/shell/widgets автоматически
```

Если песочница убивает долгие процессы — собирать по крейтам короткими
командами в порядке зависимостей: `canvas-core` → `canvas-render` →
`canvas-shell` → `canvas-app` (каждая команда сама подтянет готовые депы).

```bash
Xvfb :99 -screen 0 1600x1000x24 -nolisten tcp &   # виртуальный дисплей
sleep 1

# КОПИЯ сцены — приложение автосейвит открытый файл при выходе!
cp examples/demo-numi.canvas /tmp/demo-live.canvas
./target/release/canvasdesk /tmp/demo-live.canvas &
sleep 3

python3 scripts/xdemo.py resize 1600 1000 0 0   # WM нет: окно по умолчанию 800x600
python3 scripts/xdemo.py focus                  # ОБЯЗАТЕЛЬНО до любого ввода!
```

Смок-проверка, что рендер поднялся (иначе стенд не готов):

```bash
ffmpeg -y -f x11grab -video_size 1600x1000 -i :99 -frames:v 1 /tmp/smoke.png
```

На кадре должно быть окно приложения с нодами сцены. Ошибки вида
`Failed to create surface`/`vkCreateInstance` — проблема с §3 (пути в
`lvp.json`, `LD_LIBRARY_PATH`), а не с приложением.

## 5. Автоматизация ввода — `scripts/xdemo.py`

XTEST через python-xlib. Переменная `DISPLAY` должна указывать на `:99`.

| Команда | Действие |
|---|---|
| `resize W H [X Y]` | размер/позиция окна приложения (без WM иначе никак) |
| `focus` | отдать клавиатуру приложению — **после каждого запуска и ресайза** |
| `click X Y [N]` | клик; `N=2` — двойной клик = **вход в редактирование ноды** |
| `type "TEXT"` | посимвольная печать; `\n` внутри текста = Shift+Enter (новая строка) |
| `key KEYSYM` | одиночная клавиша (`Return`, `End`, …) |
| `wheel X Y N [1]` | колесо в точке; `N>0` вверх, `N<0` вниз; `1` = зажать Ctrl → **зум к курсору** |
| `drag X1 Y1 X2 Y2 [btn]` | перетаскивание; `btn=2` — средняя кнопка = **пан канваса** |
| `move X Y` | переместить курсор |

Скорость «живой» печати: `XDEMO_CHAR_DELAY` (сек между символами, по умолч.
0.012) и `XDEMO_LINE_DELAY` (сек между строками, по умолч. 0.4).

### Семантика редактора ноды (canvas-render/src/edit.rs)

| Ввод | Результат |
|---|---|
| одиночный клик | выделение ноды |
| **двойной клик** | вход в редактирование текста |
| **Enter** | commit — фиксация текста и пересчёт выражений |
| **Shift+Enter** | новая строка внутри редактирования |
| клик мимо ноды | commit текущего редактирования |
| средняя кнопка / обычное колесо | пан канваса |
| **Ctrl+колесо** | зум к курсору |

### Ограничение печати

`type` умеет latin1 и словарные символы (`=+-*/().,:_$%!`). **Кириллицу
клавиатурой не набрать** — национальный текст класть в сцену заранее
(см. §6), на камеру печатать латиницу/цифры.

## 6. Демо-сцена

Формат — Obsidian-совместимый JSON `.canvas`: узлы `{id, type:"text", text,
color, x, y, width, height}`, рёбра `edges`. Пример-шаблон —
`examples/demo-numi.canvas`: смета с кириллической переменной «итого»,
единицы измерения, кейс с ошибкой (`c = a + b`, `a` не объявлена), пустая
нода под live-набор на камеру.

Правила сцены:

1. **Текст нод — сырой, с обычными `=`**. Бэкслеши и markdown-экранирование
   в файл не писать (это внутренняя каноника сессии).
2. Результаты выражений **не сериализуются** — считаются на лету при
   load/commit/undo/MCP. Поэтому сцена весит копейки и не протухает.
3. Работать только с **копией** (`cp` в `/tmp`): приложение при выходе
   перезапишет открытый файл автосейвом вместе с набранным на камеру.
4. Для каждого нового демо — копия шаблона с переименованными `id` нод
   (стабильные id упрощают повторные прогоны автоматизации).

## 7. Запись

### GIF «живой набор» (главный артефакт)

```bash
# запись сама завершится через -t секунд; x11grab пишет весь виртуальный экран
ffmpeg -y -f x11grab -framerate 15 -video_size 1600x1000 -i :99 -t 30 /tmp/raw.mp4 &
sleep 1
python3 scripts/xdemo.py click 950 620 2                      # вход в пустую ноду
python3 scripts/xdemo.py type "vm = 40
db = 25
vm + db
vm + db / 2"
sleep 2
# постобработка: кроп до окна + палитра (без неё GIF выцветший и тяжёлый)
ffmpeg -y -i /tmp/raw.mp4 -vf "crop=1600:1000:0:0,fps=15,palettegen" /tmp/pal.png
ffmpeg -y -i /tmp/raw.mp4 -i /tmp/pal.png \
  -lavfi "crop=1600:1000:0:0,fps=15[x];[x][1:v]paletteuse" demo.gif
```

Кроп-прямоугольник берите по фактическому окну (`xdemo.py resize` запоминает
позицию; курсор в кадре — часть истории, не мешает).

### Одиночные кадры

```bash
ffmpeg -y -f x11grab -video_size 1600x1000 -i :99 -frames:v 1 01_overview.png
# кадр «крупным планом»: зум к точке, затем кадр
python3 scripts/xdemo.py wheel 800 500 -6 1                    # 6 щелчков Ctrl+колеса
ffmpeg -y -f x11grab -video_size 1600x1000 -i :99 -frames:v 1 02_zoom.png
```

Для тултипов ошибки: двойной клик в строку с ошибкой, навести курсор
(`xdemo.py move`) на `!`-бейдж, выдержать паузу ~1 с, снять кадр.

## 9. Грабли (всё — реальные, из первого прогона)

| Симптом | Причина / лечение |
|---|---|
| Клавиатура игнорируется | нет `focus` — вызывать после запуска и после каждого `resize` |
| Колесо панит вместо зума | зум только с третьим аргументом `1` (Ctrl); обычное колесо — пан |
| Кириллица не печатается | ограничение `type` (latin1) — текст класть в сцену заранее |
| Сцена «испортилась» после записи | автосейв при выходе; работать на копии, эталон в `examples/` |
| Формулы не считаются, мусор в тексте | в `.canvas` попало markdown-экранирование `\=` — в файле только сырой `=` |
| `vkCreateInstance failed` | не подхватился lavapipe: проверить абсолютный путь в `lvp.json` и `VK_ICD_FILENAMES` |
| winit падает на старте | нет xkb-библиотек в `LD_LIBRARY_PATH` (§3) |
| Сборка обрывается посреди | песочница убивает долгие процессы — собирать по крейтам (§4) |
| Окно маленькое, декораций нет | WM нет — только `xdemo.py resize W H X Y` |
| ffmpeg пишет пустые кадры | неверный `-video_size`/экран не `:99` — сверить с `Xvfb -screen` |

## 11. Воспроизведение исторического демо FR-013

Материалы: README с расшифровкой кадров лежит рядом с артефактами демо
(агентский каталог `download/canvasdesk-demo/`), сцена — `examples/demo-numi.canvas`.
Сценарий записи: двойной клик в пустую ноду → набор листа `deploy`/`db` →
результаты появляются live → commit кликом мимо → кадр; затем зум к ноде
ошибки → тултип. Автоматизация — §5, постобработка — §7.
