## Описание (What)

Пользователь запросил механизм авто позиционирования **связанных карточек** —
карточек, соединённых связями (edges). Уточнение владельца: это
**авто-раскладка** — команда, которая раскладывает цепочки и ветки связанных
нод автоматически по рёбрам. Поддерживаемые схемы: **tree горизонтально**
(корень слева, ветви вправо), **tree вертикально** (корень сверху), **radial**
(корень в центре, ветви по кругу). Выявил пользователь.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| `node` | Позиции связанных нод изменяются командой | `docs/interface-objects/node.md` §4 |
| `edge` | Рёбра следуют за перемещёнными концами (пересчёт геометрии) | `docs/interface-objects/edge.md` |
| `group` | Дети групп перемещаются вместе с группой (инвариант translate_group) | `docs/interface-objects/node.md` §2 |
| Undo/автосейв | Раскладка — один undo-шаг + `mark_dirty` | FR-006, `docs/SPEC.md` §9 |
| Меню | Новый пункт «Выровнять связанные ▸» | FR-009 |

## Анализ (Root Cause)

Отсутствует в текущей реализации — перечислено то, на чём строить:

- **Нет модуля раскладки** ни в `canvas-core`, ни в `canvas-app`. Ближайшие
  блоки: `spatial.rs` (rstar-индекс для hit-test, не раскладка),
  `edgegeom.rs` (геометрия линии связи, не позиции нод).
- **Обход «связанных» уже реализован** как образец: `focus_set`
  (`crates/canvas-core/src/focus.rs:56-97`) — 1-hop окрестность ноды по
  инцидентности рёбер (по `id`, не по индексам; сортировка+дедуп). Раскладка
  — тот же обход в глубину/ширину с накоплением позиций.
- **Пакетное перемещение — прецедент:** `translate_group`
  (`crates/canvas-core/src/model.rs:425-439`) — чистая функция модели,
  сдвигающая группу и детей одним вызовом.
- **Анимация готова:** `crates/canvas-render/src/animate.rs` —
  `ease_out_cubic` (18), `Flight` (26-79, 300 мс), `pulse_alpha`;
  плавный переход позиций реализуется по образцу `Flight`.
- **Undo готов:** snapshot-механика FR-006 — раскладка обязана быть одним
  шагом (снапшот до применения).
- Точки входа команды: меню ноды (FR-009 «Настройки/Выровнять связанные ▸»)
  и/или хоткей (координация с FR-004).

## Требуемые изменения (Changes)

1. `canvas-core` (новый модуль, например `layout.rs`): чистая функция
   `plan_related_layout(canvas, seed: usize, mode: LayoutMode) -> Vec<(usize, [f32; 2])>`
   - `LayoutMode::{TreeHorizontal, TreeVertical, Radial}`;
   - обход от семени по `canvas.edges` (по `id`, паттерн `focus_set`),
     защита от циклов (`visited`);
   - учёт `node.width/height` + зазоры-константы (в `ui` рядом с
     `GROUP_PADDING`);
   - дерево: глубина = уровень; radial: угол по номеру ветви, радиус по
     глубине;
   - детерминизм (сортировка соседей по id) — тестируемость без GPU.
2. `canvas-app`: применение плана — позиции нод через мутацию модели +
   `SpatialIndex` перестройка + `invalidate_node_caches` (паттерн
   `delete_selected`, `main.rs:1158-1180`) + `mark_dirty`; один undo-шаг.
3. Команда: пункт меню ноды «Выровнять связанные ▸ (горизонтально /
   вертикально / радиально)»; опционально хоткей (FR-004).
4. `canvas-render` (опционально v1): плавная анимация перехода позиций
   (~200–300 мс, `ease_out_cubic`) — по образцу `Flight`; без анимации —
   мгновенная раскладка (не блокирует CR).
5. Дети групп при раскладке: перемещать вместе с группой (инвариант
   `translate_group`) либо исключать поддеревья групп из плана — решение
   в анализе реализации.

## Открытые вопросы дизайна

- Глубина охвата: только 1-hop соседи или всё дерево достижимости от семени?
- Что делать с нодами, не связанными с семенем: не трогать (предложено).
- Конфликт с ручной расстановкой: команда перезаписывает позиции —
  предупреждать (HUD-строка) или достаточно undo?
- Виджет-ноды в плане: двигать (live-HWND синхронизируется камерой — ок).

## Проверка (Verification)

- Цепочка a–b–c + ветвление b–d: «Выровнять связанные (горизонтально)» →
  a слева, b по центру, c/d справа, без пересечений bbox; рёбра соединяют
  порты корректно (`edgegeom` пересчитался).
- Radial: соседи по кругу вокруг семени, глубина 2 — на большем радиусе.
- `Ctrl+Z` возвращает все исходные позиции одним шагом; автосейв срабатывает.
- Ноды без связей с семенем не сдвинулись.
- Группа в плане едет вместе с детьми (тест по образцу
  `translate_group_moves_children_once`, `model.rs:511`).
- Юнит-тесты чистой функции: детерминизм, отсутствие пересечений на
  фиксированной сцене, защита от циклов (a↔b), невалидный seed — пустой план.

## История изменений (Changelog)

- `2026-09-15` — агент: документ создан по запросу пользователя с уточнением
  (авто-раскладка: tree-H/tree-V/radial), статус `выявлено`; зафиксированы
  строительные блоки (`focus_set`, `translate_group`, `animate.rs`, undo
  FR-006) и открытые вопросы.
- `2026-09-15` — агент: реализация v1, статус `в работе` (до ручной
  приёмки). `canvas-core` (новый модуль `layout.rs`): чистая функция
  `plan_related_layout(canvas, seed, mode)` с `LayoutMode::
  {TreeHorizontal, TreeVertical, Radial}`; обход — BFS от семени по рёбрам
  со ЗНАКОВОЙ глубиной (исходящие рёбра — дети справа/снизу, входящие —
  родители слева/сверху: пример проверки «a слева, c/d справа» выполняется;
  открытый вопрос «глубина охвата» — всё дерево достижимости). Детерминизм
  (соседи по `id`, BTree-структуры), защита от циклов, зазоры
  `LEVEL_GAP`/`SIBLING_GAP`/`RADIAL_RING_STEP`. Группы в плане едут вместе
  с геометрическими детьми (решение открытого вопроса — вариант
  «перемещать вместе», дельта распространяется на подгруппы). Семя не
  двигается (якорь). Применение: `canvas-app::apply_related_layout` — один
  undo-шаг + точечный spatial.update + mark_dirty. Точка входа — подменю
  «Настройки ▸» (FR-009): «Выровнять связанные: горизонтально/вертикально/
  радиально». Анимация перехода — не делалась (v1 — мгновенно). Тесты:
  цепочка+ветвление по всем схемам, отсутствие пересечений, циклы,
  невалидный seed, детерминизм, группа+дети.
