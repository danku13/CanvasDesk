# CR-027: Ctrl+Enter не расширяет высоту ноды (сообщение владельца 2026-10-08) — расследование

- **Статус:** не воспроизводится на 59991c5 (пиксель-валидация живого Pages); требуется уточнение сценария владельцем
- **Тип:** CR (дефект-репорт)
- **Приоритет:** высокий (блокирует приёмку волны W1/W2 владельцем)
- **Владелец:** danku13 (симптом), агент (расследование)
- **Источник:** сообщение владельца в сессии 2026-10-08: «ctrl + enter почему-то перестал расширять высоту ноды, следующие строки уезжают за clipping зону»
- **Связанные:** CR-019…CR-026 (волна, слитая в 59991c5), FR-100 (web-клавиатура, W4), CR-028 (найденный попутно web-DPI дефект)

## Симптом (What)

В редакторе заметки Ctrl+Enter (новая строка) не увеличивает высоту карточки; строки ниже каретки уходят за зону клиппинга текста.

## Расследование (Root Cause Analysis)

### 1. Кодовые пути фита верифицированы тестами — дефекта в них не найдено

- Клавиатурный путь: `map_key` (edit.rs:327-335) — Ctrl+Enter → `Action::Enter`; маршрут Editor-ветки (input.rs:505-574) — `session.apply` + `fit_note_size` — без изменений волной.
- Математика `fit_note_size` (app.rs:2449-2521): `max(GFM-мера, раскладка буфера)` — скретч-тест на реальных функциях (`crates/canvas-render/tests/fit_note_repro.rs`) подтверждает рост: нода «ровно под контент» (116) + 2 строки → needed 140 (растёт).
- Слой сессии: `content_size_px` измеряет переполнение без клипа (тесты edit.rs `content_size_tracks_lines`), зелёные.
- Дельта волны (47274e5..59991c5) в render: markdown (CR-019), row_grid/text/renderer (CR-020, аддитивно), cards/theme (CR-026, блендинг) — клавиатурный/фит-путь не трогает; canvas-scene волной не менялась.

### 2. Живая репродукция на Pages = сборка владельца (59991c5, деплой 2026-10-08 09:44)

Headless-chromium (playwright, WebGL2-fallback), скрипты `scripts/fit_height_repro.mjs`, `scripts/fit_numi_repro.mjs`:

| Сценарий | Результат |
|---|---|
| Проза, 8 строк через Ctrl+Enter (DPR 1) | Кромка растёт +20 px/строку (497→585), textBelow=0, после коммита стабильна |
| Numi-лист с юнитами («a = 10 rub» × 8, сценарий приёмки CR-019) | Кромка растёт +26 px/ряд (497→567), значения считаются, textBelow=0 |
| Ctrl+Enter | Строка вставляется, редактор не закрывается (кадры repro_out_debug d4/d5) |
| Зум канваса ≠ 1 (3 шага колеса) | Фит работает (рост ~13 px/строку на экране), textBelow=0 |

Вывод: на сборке 59991c5 при DPR 1 симптом не воспроизводится ни на прозе, ни на Numi+юнитах.

### 3. Задокументированный смежный дефект платформы (не объясняет симптом полностью)

UR-001-02 (FR-100, волна W4 — НЕ реализована): winit 0.30.13 web-backend шлёт `KeyboardInput` раньше `ModifiersChanged` (window_target.rs:148-166) и стирает модификаторы при blur (86-99). Первая Ctrl-комбинация после смены фокуса приходит с пустыми модификаторами: Ctrl+Enter обрабатывается как plain Enter → **Commit** (редактор закрывается, строки нет). Поле `KeyEvent` модификаторов не несёт (event.rs:523-598) — компенсация возможна только в web-слое (план D1(б): canvas-web/ime.rs).

## Открытые вопросы владельцу

1. Платформа сборки, где замечено: web (Pages) или нативный билд? Браузер/ОС?
2. Воспроизводится ли на НОВОЙ пустой заметке (двойной клик → текст) или только на заметке из handtest.canvas (какой — текст/геометрия)?
3. Shift+Enter в той же ноде — строка вставляется и карточка растёт?
4. Был ли открыт попап подсказок (FR-021) в момент Ctrl+Enter? При открытом попапе Enter/Tab принимают подсказку — это существующий контракт FR-021, Ctrl не проверяется (input.rs:479-484) — кандидат в ревизию FR-100.
5. Масштаб ОС/браузера (DPR): при DPR ≠ 1 найден отдельный дефект указательного ввода — CR-028.
