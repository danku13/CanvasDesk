- **Тип:** FR (Feature Request)

## Описание (What)

В репозитории есть пользовательская документация — `user-docs/` (7 страниц:
index, quick-start, interface, hotkeys, calculations, templates, faq) — но из
приложения доступа к ней нет: единственный способ прочитать её — открыть файлы
на GitHub. План публикации на GitHub Pages (`user-docs/README.md`) требует
сети, включения Pages, нового крейта `webbrowser`, и версия страниц может
расходиться с версией запущенного бинарника.

Требуется: (1) кнопка **«?»** рядом с кнопкой настроек ⚙ — тот же кластер
летающих кнопок, тот же `button_corner` из настроек; (2) клик по «?» открывает
**меню помощи** с подменю разделов документации (паттерн
`ContextMenu.submenu`) и пунктом «Пройти онбординг» (FR-028); (3) выбор раздела
открывает **встроенный просмотрщик** — док-панель с рендером markdown силами
своего же GFM-конвейера (`gfm.rs`), страницы вшиты в бинарник на этапе сборки
(`include_str!`). Без сети, без внешних зависимостей, без изменений схемы
`config.toml`.

## Исследование бест-практик (Research)

Источники:

- **VS Code Welcome page** — документация живёт внутри приложения в
  скроллируемой панели: заголовок, оглавление-ссылки, разделы; никаких
  переходов в браузер для базовых сценариев. Паттерн «панель-док» уже освоен
  проектом в FR-024 (левый док палитры шаблонов).
- **Obsidian Help vault** — справка поставляется файлами в комплекте и
  открывается тем же движком, что и контент пользователя: единый рендерер =
  единый внешний вид. Для CanvasDesk аналог — переиспользование `gfm.rs`
  (блоки) + `inline_segments` (жирный/ссылки) вместо нового markdown-движка.
- **HIG «Help menu»** — помощь открывается из предсказуемого места рядом с
  настройками; иконка «?» — устоявшееся обозначение (Nielsen Norman Group,
  «Help and Documentation»): точка входа должна быть видимой, а не спрятанной
  в контекстном меню.
- **Встраивание доков в бинарник** — `include_str!` компил-тайм: отсутствие
  файла = ошибка сборки (доки не «забыть»); размер 7 страниц ≈ 35 КБ текста
  (шрифты уже вшиты — 1.4 МБ, прирост незаметен). GitHub Pages остаётся
  опциональным веб-зеркалом (README обновить, не удалять инструкцию).
- **GFM-таблицы** — `hotkeys.md` содержит 50 строк-таблиц, `templates.md` — 42,
  `index.md` — 15, `calculations.md` — 7: без таблиц просмотрщик бесполезен для
  половины страниц. Таблицы GFM (`| a | b |` + разделитель `| --- |`) —
  добирается в `gfm.rs` флагом, чтобы поведение заметок не изменилось.

Применение к CanvasDesk: правый док (зеркально палитре шаблонов FR-024 —
панели не конфликтуют), меню «?» — screen-space колонка с подменю по образцу
контекстного меню и dropdown FR-026, рендер — те же квады + screen-тексты, что
у панели настроек.

## Анализ (Root Cause — чего нет в коде)

Встроенного доступа нет — новая функция. Точки опоры:

- **Кластер из двух кнопок.** `ui::button_rect(corner, viewport)`
  (`crates/canvas-app/src/lib.rs:132`) — ⚙; `ui::theme_button_rect`
  (`lib.rs:146-153`) — тема, смещение внутрь экрана на
  `SETTINGS_BUTTON + SETTINGS_GAP` (тест `theme_button_next_to_settings_button`
  `lib.rs:2230` — образец для `help_button_rect` и его теста на 4 углах).
  Кластер перемещается целиком настройкой `button_corner` (FR-026, группа
  «Приложение»).
- **Нет меню помощи.** Контекстное меню канваса `CanvasMenuItem`
  (`lib.rs:960-987`) не содержит «Документация»; но готовый паттерн подменю —
  `ContextMenu.submenu / Submenu / SubmenuEntry / SubmenuAction`
  (`lib.rs:185-215`), а кламп колонки к окну — `settings_ui::dropdown_layout`
  и `hints_ui::popup_layout` (`hints_ui.rs:254`).
- **Нет просмотрщика.** Существующие панели непрокручиваемые и фикс-размерные:
  хоткеи F1 (`HOTKEYS_*`, `lib.rs:340-397`), настройки (`settings_ui.rs`),
  палитра шаблонов (`template_ui.rs:81,287` — левый док). Ни одна не скроллит
  контент и не рендерит блочный markdown в screen-space.
- **GFM без таблиц.** `Block` (`canvas-render/src/gfm.rs:32-47`): Heading /
  Paragraph / List / Quote / Code / Rule — таблиц нет, при этом 4 из 7 страниц
  доков табличные. Ссылки уже парсятся: `inline_segments` (`gfm.rs:344`),
  флаг `link` сегмента (`gfm.rs:54`), тест `inline_segments_link`
  (`gfm.rs:695-714`) — но клика по ссылкам нет нигде (в заметках они только
  рендерятся).
- **Доки не вшиты.** `user-docs/*.md` не участвуют в сборке; front matter
  (`---\ntitle: …\n---`) не срезается ничем — нужен `strip_front_matter`.
- **Первый экран канваса пуст** для новой аудитории — вход в доки через «?»
  закрывает и это (связь с FR-028: финальная карточка онбординга указывает на
  «?»).

## Требуемые изменения (Changes)

### 1. Чистый модуль `docs_ui.rs` (образец `settings_ui`/`hints_ui`)

- Модель страниц: `DOCS_PAGES: &[DocsPage]` — `DocsPage { id: &'static str,
  title: &'static str, body: &'static str }`, значения —
  `include_str!("../../user-docs/index.md")` и остальные 6 (manifest-директория
  `canvas-app` → путь `../../user-docs/…`). Front matter срезается
  `strip_front_matter(md) -> (&str title, &str body)` (const-функция не
  требуется — значения статик-массива).
- Модель ссылок: `LinkTarget { Page(&'static str), External }` — маппинг
  относительных `*.html` из тела страниц на `id` вшитых страниц; внешние
  `http(s)://` — `External` (v1 не кликабельны).
- Геометрия: `viewer_rect(viewport) -> [f32; 4]` — правый док на всю высоту,
  ширина `DOCS_PANEL_WIDTH = 480.0`, кламп к узким окнам (минимум — весь
  viewport при 320×240); шапка (title + ×) и футер-подсказка — фиксированные
  зоны, контент — между ними.
- Раскладка контента: `layout_page(page, width) -> PageLayout` — блоки GFM
  (`parse_blocks_opts(body, Tables)` + `inline_segments`) → вектор строк
  `DocRow { y, spans, kind }` с переносами по ширине; таблица — строки ячеек
  колонок фиксированных пропорций (v1: выравнивание влево, без «умной»
  ширины колонок — по максимальной ширине ячейки колонки с клампом к панели).
- Скролл: `ScrollState { offset: f32, max_offset: f32 }` — `max_offset =
  max(0, content_height − viewport_height)`; колесо над панелью меняет offset,
  кламп; справа аффорданс-скроллбар (квад по пропорции offset/max).
- Хит-тесты: `link_at(layout, scroll, point) -> Option<LinkTarget>`,
  `close_hit(point) -> bool` — чистые, с тестами.

### 2. Таблицы GFM в `gfm.rs` (флаг, без регрессии заметок)

- `Block::Table { header: Vec<String>, rows: Vec<Vec<String>> }` — парсинг:
  строка с `|`, следующая строка-разделитель `| --- | :--- |…` → таблица;
  ячейки — сплит по `|` с тримом; без разделителя — обычный Paragraph (как
  сейчас).
- Сигнатура: `parse_blocks_opts(text, tables: bool)`; существующая
  `parse_blocks(text)` (`gfm.rs:226`) делегирует с `tables = false` — **поведение
  заметок и `.canvas`-текста не меняется** (регрессионный тест: тексты с `|`
  дают те же блоки, что до изменения). Просмотрщик вызывает с `true`.
- Рендер таблиц — только в `docs_ui` (в `text.rs::shape_body` таблицы не
  заводим: заметка с `|` рендерится как раньше).

### 3. Кнопка «?» в кластере

- `ui::help_button_rect(corner, viewport) -> [f32; 4]` — третья кнопка кластера:
  смещение от `theme_button_rect` внутрь экрана по горизонтали на
  `SETTINGS_BUTTON + SETTINGS_GAP` (зеркально для правых углов — образец
  `theme_button_rect`, `lib.rs:146-153`); тест смежности на 4 углах (образец
  `lib.rs:2230`).
- Кластер управляется существующей настройкой `button_corner` («Приложение»,
  FR-026) — `config.toml` не меняется; перемещение угла переносит все три
  кнопки.

### 4. Меню помощи (клик по «?»)

- Колонка screen-space у кнопки (кламп к окну — паттерн FR-026
  `dropdown_layout`): «Документация ▸» (открывает подменю — паттерн
  `ContextMenu.submenu`, `lib.rs:195-215`) и «Пройти онбординг» (FR-028; в
  отсутствие FR-028 — пункт не активен/скрыт, реализация в FR-028).
- Подменю «Документация ▸»: Главная / Быстрый старт / Объекты интерфейса /
  Горячие клавиши / Расчёты и поток значений / Шаблоны нод / FAQ — 7 пунктов из
  `DOCS_PAGES` (инвариант полноты: пункт ↔ страница, без пропусков и дублей).
- Esc — двухэтапный (подменю → меню → закрыто), семантика FR-026; клик вне —
  закрыть меню.

### 5. Рендер и ввод (просмотрщик)

- Рендер: квады + screen-тексты (паттерн `settings_overlay`); шапка — заголовок
  раздела и ×; контент — `DocRow` со смещением `-offset`; внутренние ссылки —
  акцентный цвет + подчёркивание, внешние — обычный текст (курсор не меняется);
  скроллбар справа; фон панели `palette.menu_fill` поверх затемнения канваса
  (паттерн FR-022).
- Ввод: клик «?» → меню; клик по разделу → открыть просмотрщик на странице;
  колесо над панелью → скролл; клик по внутренней ссылке → переход на страницу
  (offset = 0); × / Esc / клик вне панели → закрыть. Открытие просмотрщика
  закрывает меню «?» (одна «панель помощи» активна).

### 6. Совместимость

- Схема `config.toml` — без изменений; `SETTINGS_GROUPS`/`SETTINGS_ROWS` FR-026
  не трогаются (кнопка «?» — не строка настроек, а элемент кластера).
- `parse_blocks` для заметок — идентичное поведение (флаг таблиц по умолчанию
  выключен); тесты `gfm_body_smoke` / `text_body_smoke` остаются зелёными.
- `user-docs/README.md`: раздел «Канонические URL» пометить как опциональное
  веб-зеркало; основной доступ — меню «?» (обновить «Рекомендуемые точки
  подключения»: F1 → `hotkeys` страница просмотрщика и т.д.).

## Архитектура тестируемости (инварианты FR-027)

1. **Инвариант полноты меню:** пункты подменю ↔ `DOCS_PAGES` биективно — каждая
   страница достижима, лишних пунктов нет (юнит-тест).
2. **Инвариант парсинга:** все 7 страниц парсятся `parse_blocks_opts(_, true)`
   без паник; front matter срезан; `title` не пуст (smoke-тест).
3. **Инвариант ссылок:** каждая внутренняя ссылка каждой страницы резолвится в
   существующий `id` (линк-чек тест — сломанная ссылка в доках падает в CI, а
   не у пользователя).
4. **Инвариант скролла:** `offset ∈ [0, max(0, content − viewport)]` после
   любого колеса (тест на граничных значениях).
5. **Инвариант клампа:** меню/подменю и панель целиком внутри окна на 4 углах
   кластера и окне 320×240 (паттерн теста FR-026).
6. **Инвариант регрессии заметок:** `parse_blocks` (без таблиц) на текстах с
   `|` выдаёт те же блоки, что до изменения (фикстюры до/после).

## Открытые вопросы дизайна

- **Хоткей «?»** (`Shift+/` — раскладкозависим; `F2`?) — v2; v1 только клик.
- **Внешние ссылки** — v1 не кликабельны; v2 — «открыть в браузере» (крейт
  `webbrowser`, только с согласия владельца) или копирование в буфер.
- **Поиск по документации** (строка в шапке) — вне скоупа, отдельный FR.
- **Ширина панели резиновая** (drag края) — v2; v1 фиксированная с клампом.
- **Скриншоты/иллюстрации в страницах** — формат не поддерживает картинок;
  если понадобятся — отдельный FR (вшивание PNG + рендер в screen-space).

## Проверка (Verification)

### Юнит-тесты (docs_ui)

- Полнота меню ↔ страницы; порядок стабилен.
- Front matter срезан у всех страниц; `title` соответствует оглавлению.
- Линк-чек: все внутренние ссылки всех страниц → существующие `id`.
- `viewer_rect`: кламп на 320×240 (панель не шире окна); правый док на
  широком окне.
- `ScrollState`: кламп offset после «перемотки» за границы; `max_offset = 0`
  для короткой страницы.
- `link_at` вне строк / по внешней ссылке — None / не кликабельно.

### Юнит-тесты (gfm)

- `parse_blocks_opts(_, true)`: таблица 2×3 из фикстуры → `Block::Table` с
  ожидаемыми ячейками; разделитель без `|` после `|`-строки — Paragraph.
- Регрессия: `parse_blocks` (флаг выкл) на текстах с `|` — блоки идентичны
  сохранённым до изменения (golden-фикстуры).
- Таблица с `:---:` в разделителе парсится (выравнивание v1 игнорирует).

### Ручная приёмка

- Кнопка «?» видна рядом с ⚙ и темой во всех 4 углах; смена угла в настройках
  переносит кластер целиком.
- Клик «?» → меню; «Документация ▸» → подменю 7 разделов; выбор «Горячие
  клавиши» → панель с таблицей хоткеев; скролл колесом; клик по ссылке
  «Расчёты» внутри страницы → переход; Esc закрывает панель.
- У нижнего края на окне 320×240 панель не выходит за окно.
- Колесо над канвасом при закрытой панели — зум как обычно (скролл не
  перехватывается).
