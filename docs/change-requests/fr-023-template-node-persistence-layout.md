# FR-023: Шаблонные ноды — сохранение свойств после редактирования + вёрстка карточки

- **Статус:** выполнено (v1)
- **Тип:** FR (Feature Request — дефект сохранения свойств + вёрстка; по классификации владельца оформлен как FR)
- **Приоритет:** критично (потеря данных настроек ноды)
- **Владелец:** агент (анализ + реализация)
- **Источник:** сообщение пользователя (сессия 2026-09-16): «нужно переработать расширенную логику шаблонных нод так, чтобы они не теряли свои свойства после редактирования. Сейчас если шаблонную ноду отредактировать, то она теряет цвет, иконку и финальную расчетную единицу (обычно это sec). Нужно улучшить вёрстку ноды, выставить адекватные отступы для заголовка и увеличить его шрифт на 10-20% относительно шрифта основного текста, для результатов вычислений шаблонных нод надо так же дополнительное место внизу ноды».
- **Связанные задачи:** FR-018 (шаблонные ноды, снапшот `canvasdesk.template`), FR-013 (`canvasdesk.expr`, строка результата), FR-019 (Template update), FR-020 (params_from_text)
- **Создан:** 2026-09-16
- **Обновлён:** 2026-09-16 (создан, реализация)
- **Документ-шаблон:** `docs/change-requests/cr-template.md`

---

## Описание (What)

Две группы изменений.

**1. Сохранение свойств.** После commit-правки текста шаблонной ноды она
теряла цветную полосу категории, квад-иконку и итог формулы шаблона
(например, `sec` из `mm1($rps, $service_rate, $servers)`). Причина —
дефект `Node::set_expr(None)`: при очистке `canvasdesk.expr` объект
`canvasdesk` удалялся целиком, если в нём не было виджет-полей
(`widgetId`/`props`), — проверка не учитывала `template`. Путь правки
(`finish_editing`) вызывает `set_expr(split_formula_lines(&text))` ДО
синхронизации параметров; для шаблонного листа
(`rps = 1000 rps\n…`) `split_formula_lines` возвращает `None`, и весь
снапшот шаблона стирался. Дополнительно: правка текста, в которой
пользователь удалил/переименовал строку параметра, вытесняла параметр
целиком — формула шаблона теряла переменную и итог (единицу) исчезал
уже из-за ошибки вычисления.

**2. Вёрстка карточки.** Заголовок карточки набран тем же кеглем, что и
тело (13 world px против 14 тела — заголовок МЕНЬШЕ текста), отступы
минимальные (8 px); у шаблонной ноды под строкой результата не
резервируется место (резерв включается только для программного итога
MCP-expr), поэтому итог налезает на последнюю строку параметров.

## Влияние (Impact)

| Объект | Что меняется |
|---|---|
| `canvas-core/src/model.rs` | `set_expr(None)` больше не стирает `canvasdesk.template` (условие очистки учитывает `template.is_none()`) |
| `canvas-core/src/templates.rs` | `TemplateRef.name: Option<String>` — снимок отображаемого имени (заголовок ноды переживает переименование шаблона в реестре); `merge_params(base, fresh)` — слияние параметров правки текста с прежними |
| `canvas-app/src/main.rs` | `finish_editing` — слияние параметров вместо замены; шаблонным нодам резерв футера результата всегда; авто-высота при инстанциации |
| `canvas-render/src/cards.rs` | `HEADER_HEIGHT` 28 → 34 (под кегль 16); `title_for` — у шаблонной ноды заголовок = имя шаблона из снапшота |
| `canvas-render/src/text.rs` | `TITLE_FONT_SIZE` 13 → 16 (+14 % к телу 14 — вилка владельца 10–20 %), `TITLE_LINE_HEIGHT` 18 → 22, `TITLE_PADDING` 8 → 12 |

## Анализ (Root Cause)

1. `model.rs:266-274` — ветка `None` в `set_expr` удаляет `canvasdesk`
   при `widget_id.is_none() && props.is_empty()`, не проверяя
   `template`; `finish_editing` (`main.rs:1726`) зовёт `set_expr(None)`
   для шаблонного текста до чтения `node.template()` — снапшот погибал
   в первом же стейтменте.
2. `set_template_params(params_from_text(text))` — полная замена карты
   параметров; строка, не распознанная как присваивание (удалена,
   переименована, временно сломана пользователем), исчезала из карты, и
   `mm1($rps, …)` падал с «неизвестная переменная» — строка результата с
   единицей `sec` пропадала.
3. Вёрстка: `TITLE_FONT_SIZE = 13 < BODY_FONT_SIZE = 14` — заголовок
   иерархически главнее, а набран мельче; `fit_note_size` резервирует
   футер только для `node.expr().is_some() && !has_line_results`
   (программный итог), шаблонные ноды (итог — ВСЕГДА, text.rs:1255)
   резерв не получали.

## Требуемые изменения (Changes)

1. **`crates/canvas-core/src/model.rs`** — условие очистки:
   `ext.widget_id.is_none() && ext.props.is_empty() && ext.template.is_none()`.
   Тесты: `set_expr(None)` сохраняет template; `set_template(None)`
   сохраняет expr (симметрия уже верна — фиксируется тестом).
2. **`crates/canvas-core/src/templates.rs`**
   - `TemplateRef.name: Option<String>` (+ `to_json`/`from_json`,
     опционально — старые `.canvas` читаются); `instantiate` пишет
     `display_name()` манифеста;
   - `pub fn merge_params(base, fresh) -> BTreeMap` — свежие значения
     правки текста перекрывают прежние, отсутствующие в тексте
     сохраняются (формула остаётся вычислимой).
3. **`crates/canvas-app/src/main.rs`**
   - `finish_editing`: `merge_params(node.template_params(),
     params_from_text(&text))`;
   - `fit_note_size`: для шаблонной ноды резерв
     `RESULT_LINE_HEIGHT + 2` всегда (итог показывается всегда);
   - `fit_template_node_height(&mut node)` — высота по числу строк
     параметров (шапка + тело + футер результата); вызов в GUI- и
     MCP-путях инстанциации (новая нода сразу влезает без правки).
4. **`crates/canvas-render/src/cards.rs` / `text.rs`** — кегль/отступы
   заголовка (см. Impact), `title_for`: template-имя → прежний фолбэк
   (первая строка текста).

## Архитектура тестируемости (инварианты)

1. Правка текста шаблонной ноды (та же последовательность вызовов, что
   в `finish_editing`) сохраняет `template()`: id/version/expr/icon/
   color/name — тест в `canvas-core` и интеграционный в app.
2. Удаление строки параметра НЕ ломает формулу: merge оставляет прежнее
   значение, итог (единица `sec`) вычисляется.
3. `title_for` шаблонной ноды = имя из снапшота; у ноды без имени в
   снапшоте (старый файл) — прежнее поведение (первая строка).
4. Геометрия заголовка: `TITLE_FONT_SIZE` ∈ [1.1, 1.2] ×
   `BODY_FONT_SIZE` (вилка владельца) — тест-инвариант в text.rs.
