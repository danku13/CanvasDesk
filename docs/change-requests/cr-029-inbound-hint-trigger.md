# CR-029: Автодополнение входящих значений иногда не отрабатывает при вставке/вводе

- **Статус:** реализовано (код+тесты), ожидает приёмки владельца
- **Тип:** CR
- **Приоритет:** важно
- **Владелец:** агент (анализ и реализация)
- **Источник:** сообщение владельца со скриншотом (сессия 2026-10-09): «не понятно, почему иногда не отрабатывает автодополнение при вставке входящих значений»
- **Связанные задачи:** FR-021 (popup подсказок Numi-ввода), FR-101 (подсказки входов по имени), CR-023 (разовое автодополнение — подавление токена); user-docs/calculations.md
- **Создан:** 2026-10-09
- **Обновлён:** 2026-10-09

## Описание

При сборке выражения из входящих значений ноды (строки «Нода . поле» в теле ноды) popup автодополнения иногда не появляется — ни при наборе префикса, ни при вставке (Ctrl+V) имени входящего значения. Владелец отметил это на ноде «Корзина за вычетом всех скидок и купонов» с входами «Скидка . скидка», «Корзина . sum», «Купон . купон»: для «Купон.купон» подсказка по «К» приходит, для «Корзина.sum» по «Корз» — нет. Выявил пользователь.

## Анализ (Root Cause)

Классы «молчания» попапа, воспроизведённые тестами на стенде `suggest_stub_app` (App без рендера, канвас-фикстура):

1. **Триггер только по имени поля (главная причина).** `hint_items` (`crates/canvas-app/src/hints_ui.rs`, обе ветки — `$`-токен и идентификатор) матчит входы исключительно по `inbound.name` — имени поля qualified-ключа («sum», «купон», «скидка»). Имя объекта («Корзина») в матче не участвует: ввод «Корз» не находит «Корзина.sum». У «Купон.купон» и «Скидка.скидка» имя объекта совпадает с именем поля — триггер «работает иногда», что и наблюдал владелец. Вид строк входов в теле ноды («Корзина . sum») подталкивает вводить именно имя ноды.
2. **CR-023-подавление переживает явную вставку.** `HintPopup::sync` (`hints_ui.rs`) держит попап закрытым, пока токен перед кареткой совпадает с подавленным (после принятия подсказки или Esc). Ветка `KeyCommand::Paste` (`crates/canvas-app/src/app/input.rs:477`) вызывала `update_hints` без снятия подавления — вставка значения сразу после принятия того же значения (или Esc) оставляла попап закрытым несмотря на непустой список вариантов (подтверждено тестом: `open=false`, `items=[Купон.купон]`).
3. **Вставка с хвостовым переводом строки** (скопированный текст часто несёт «\n»): каретка уходит на новую пустую строку, префикс каретки — `Prose`, гейт `expr::line_kind` в `update_hints` (`crates/canvas-app/src/app/overlays.rs:2084`) сбрасывает попап. Это семантика пустой строки (подсказывать нечего — вставленное значение уже полное), зафиксирована тестом как документированное поведение, правка не требуется.

Дополнительно проверено и НЕ является дефектом: чистая вставка qualified-имени («Купон.купон») открывает попап (`insert_text` + `update_hints` в Paste-ветке корректны); вставка с пробелами вокруг точки («Купон . купон») — открывает; вставка второго входа после принятия первого — открывает.

Ручная приёмка (владелец):
1. Нода с входом «Корзина . sum» (латинское поле): набрать «итог = Корз» → попап предлагает «Корзина.sum»; набрать «итог = $Корз» → то же.
2. Принять подсказку (Enter), затем сразу вставить (Ctrl+V) значение с тем же хвостом → попап открывается.
3. Регресс: «итог = К» → «Купон.купон» и «Корзина.sum» в попапе, «Купон.купон» выше (матч по полю приоритетнее).

WASM L2 (браузерный стенд) не прогонялся — в среде нет Chromium/Xvfb (как и в сессии UR-001). Изменение — логика подсказок/вставки без затрагивания раскладки и рендера; инструкция для ручной web-проверки: открыть web-версию, повторить шаги 1–3 в редакторе ноды.
