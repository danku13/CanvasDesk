## Описание (What)

При сборке выражения из входящих значений пользователь набирает qualified-путь «Объект.Поле» (FR-050 Р-6) — тот самый вид, в котором строки входов отображаются в теле ноды («Корзина . sum»). До FR-102 точка обрывала токен подсказок (`token_before_caret` игнорирует `.`): после неё попап предлагал переменные листа (пустой токен) либо матч по имени входа без учёта набранного объекта — контекст пути не использовался. Требуется: ввод «Объект.» открывает попап с ПОЛЯМИ этого объекта; дописываемый хвост («Объект.пол») фильтрует список; принятие вставляет только имя поля — дописывает набираемый путь, а не задваивает объект.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| `hint_items` | Новая завершающая ветка «после точки»: поля объекта из qualified-ключей входящих value-рёбер | FR-021 (v3), FR-101 |
| `token_before_caret` | Без изменений — точка по-прежнему обрывает токен; контекст объекта восстанавливается отдельно (`dot_field_context`) | FR-021 |
| Семантика «токен после точки» | Матч по имени входа (CR-029/FR-101) больше не подмешивается внутрь набираемого пути — старое поведение предлагало «Корзина.» + ввод «с» → «Скидка.скидка» (полный qualified на хвост пути — битая вставка) | CR-029 (тесты обновлены) |
| Вставка подсказки | Только имя поля: «Корзина.s» + принятие «sum» → «Корзина.sum» (замена `replace_token_before_caret` — хвост после точки) | user-docs/calculations.md |

## Анализ (Root Cause)

1. **Точка — не часть токена.** `token_before_caret` (`crates/canvas-app/src/hints_ui.rs`) собирает токен из букв Unicode/цифр/`_`/`$`; `.` обрывает. Для «Корзина.s» токен — «s», для «Корзина.» — пустой: контекст объекта до точки терялся, ветки полей в `hint_items` не существовало.
2. **Грамматика qualified-пути — точка вплотную.** `try_qualified`/`dot_field_starts` (`crates/canvas-core/src/expr.rs`, FR-050 Р-6): путь собирается только из `Объект.Поле` без пробелов; «Объект .» — не начало qualified. Значит контекст полей однозначно восстанавливается из префикса перед кареткой: токен после точки + идентификатор непосредственно перед точкой. Число перед точкой («2.» — семантика дробного числа) и `$`-токен («$имя.» — валюта/параметр FR-013) контекстом полей не являются.
3. **Источник полей — входящие qualified-ключи.** `HintContext.inbounds` (FR-101) содержит ровно те ссылки, которые резолвятся в этой ноде: «Нода.поле» адресных рёбер и спиллов (`flow::source_line_name` + `dataref::qualified_obj_name`). Поля объекта = поля `qualified`-ключей с совпадающим объектом; больше ничего подсказывать нельзя (чужие ноды не резолвятся).

## Проверка (Verification)

Автоматические гейты (зелёные на момент коммита):
- `cargo test -p canvas-app --lib` — 623 ok (5 новых FR-102 + обновлённые cr029_*);
- `cargo fmt --check` — ok; `cargo clippy -p canvas-app --all-targets -- -D warnings` — ok;
- `scripts/wasm_gate.sh --check` — ok.

Ручная приёмка (владелец):
1. Нода с входом «Корзина . sum»: набрать «итог = Корзина.» → попап предлагает «sum» (деталь — источник); набрать «итог = Корзина.su» → список сжат до «sum».
2. Принять «sum» (Enter) → строка «итог = Корзина.sum» — объект не задвоен.
3. Регрессы: «итог = 2.» — попап полей не открывается (прежнее поведение); «итог = $Профиль.» — без полей; «Корзина .» (пробел перед точкой) — без полей; «итог = Корз» — прежние подсказки по имени объекта (CR-029) работают.

WASM L2 (браузерный стенд) не прогонялся — в среде нет Chromium/Xvfb; изменение — логика подсказок без затрагивания рендера/раскладки.
