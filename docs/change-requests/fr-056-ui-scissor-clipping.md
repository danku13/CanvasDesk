# FR-056: Scissor-клиппинг рендера (F-5 PRD-0009) — клип-бакеты полос + закрытие G7-остатка (замер wasm)

- **Статус:** ✅ выполнено (волна 2 UI kit; сливается первым из волны — до FR-059/060)
- **Тип:** FR
- **Приоритет:** критично
- **Владелец:** не назначен (любой агент — права на файлы см. отдельный раздел)
- **Источник:** PRD-0009 §8 (F-5 must), §12 (R-1), §15 (G5/G7 — остаток после FR-055); сессия 2026-09-23 «оформить доработки кита как перечень FR для разных агентов»
- **Связанные задачи:** PRD-0009; FR-051 (UiFrame — clip обязателен), FR-052 (ScreenBand-полосы), FR-055 (scissor отложен — G7-остаток); потребители — FR-059/FR-060
- **Создан:** 2026-09-23
- **Обновлён:** 2026-09-23

## Описание
Системного клиппинга нет: `rg "scissor"` по `crates/canvas-render/src` даёт **0 совпадений** — контент удерживается ручными клампами в потребителях (`take`/`break`-срезы, clamp к краю окна). Каркас U1/U2 уже подготовил данные: `SurfaceFrame.clip` обязателен (`canvas-ui/src/frame.rs:41–50`), полосы рендера `ScreenBand` существуют (`renderer.rs:138`), но рендер клип **не исполняет**. Требуется: scissor-бакеты по клип-регионам полос (квады) + `TextBounds`-клип текстов + замер wasm-прироста ≤ 100 КБ (остаток G7, отложен при FR-055 на «следующую web-сборку»). Выявлено агентом при гэп-анализе переноса кастомного UI на кит.

## Влияние
| Объект | Что меняется | Где в документации |
|---|---|---|
| `renderer` (canvas-render) | `ScreenBand` получает клип; отрисовка полосы — под scissor | PRD-0009 §8 F-5, §7 рендер-строка |
| `text` (canvas-render) | тексты полосы — `TextBounds` = клип полосы | PRD-0009 §8 F-5 |
| `app` — сборка полос | в `ScreenBand` кладётся `surface.clip` | `docs/interface-objects/surface-registry.md` |
| Потребители (FR-059/060) | после включения можно удалять ручные клампы (G5 расширяется на волны миграции) | PRD-0009 §15 G5 |

## Анализ
- `crates/canvas-render/src/renderer.rs:1318–1326` — `band_ranges` собираются по полосам, scissor не ставится; квады рисуются диапазонами одним проходом.
- `crates/canvas-render/src/renderer.rs:138–150` — `ScreenBand { layer, instances, texts }` — поля клипа нет.
- `crates/canvas-ui/src/frame.rs:41–50` — `SurfaceFrame.clip` обязателен (F-5 precursor) — данные уже есть, рендер их игнорирует.
- Тексты: glyphon поддерживает прямоугольный `TextBounds` на текст — клип текста делается локально в `text.rs` без новых зависимостей (G7).
- Риски: R-1 (draw-calls) — бакет = полоса поверхности (O(клип-регионов слоя), не O(элементов)); смоук fps SPEC §6.3 до/после.

## Требуемые изменения
| Что | Где | Как |
|---|---|---|
| Клип в полосе | `renderer.rs` (`ScreenBand`) | поле `clip: UiRect` (логические px); см. замороженный контракт |
| Scissor-бакеты | `renderer.rs` (исполнение полос, ~1318–1346) | перед отрисовкой диапазона квадов полосы — `set_scissor_rect(физ. клип, scale_factor, кламп к вьюпорту)`; один switch на полосу, после — полный rect |
| Клип текстов | `text.rs` (`band_group`) | `TextBounds` текстов полосы = клип полосы (scissor на текст не тратится) |
| Сборка | `app.rs` (только места формирования `ScreenBand`/полос) | в полосу кладётся `clip` соответствующей `SurfaceFrame` |
| Замер wasm (G7-остаток) | `scripts/wasm_gate.sh` (запуск) + worklog | размер бина до/после (вывод wasm-bindgen/wasm-opt), запись в worklog; прирост ≤ 100 КБ |

## Замороженные контракты (остальные агенты кодируют против них)
```rust
// canvas-render::renderer.rs — расширение существующей структуры
pub struct ScreenBand<'a> {
    pub layer: UiLayer,
    /// Клип-прямоугольник поверхности в логических (экранных) px.
    /// Рендер конвертирует в физические (scale_factor) и клампит к вьюпорту.
    pub clip: UiRect,
    pub instances: &'a [CardInstance],
    pub texts: /* фактический тип текстов полосы — как сегодня */,
}
// Инвариант «0 визуальных изменений»: клип поверхности = её видимая область,
// канонические состояния канваса не меняются (G3 z-тесты зелёные без правок).
// Инвариант R-1: один set_scissor_rect на полосу-бакет, не на элемент.
```

## История изменений
- `2026-09-23` — агент: создан документ (постановка волны 2 кита, FR-056), статус «выявлено»; контракты заморожены, права на файлы разведены для параллельной реализации.
- `2026-09-23` — агент: **реализовано** (ветка `feature/fr-056-ui-scissor-clipping`). Код: `renderer.rs` — `ScreenBand.clip: UiRect` + чистая `band_scissor_rect(clip, scale_factor, viewport) → Option<[u32;4]>` (ceil лево/верх, floor право/низ, кламп к вьюпорту, `None` — пустое пересечение) + исполнение в цикле полос (один `set_scissor_rect` на полосу, после — полный вьюпорт; пустой клип — полоса не рисуется) + 5 юнит-тестов; `text.rs` — `clip_text_bounds` (пересечение `TextBounds` текста со scissor-бакетом полосы, та же конверсия; текст за клипом не готовится) + 3 теста; `app.rs` — сборка полос кладёт `clip = вьюпорт` (сужение per-surface — волны FR-059/060). Инварианты CR соблюдены: scissor не расширяет видимое (тест-свойство на 5 scale_factor), R-1 (один switch на полосу), G3 z-тесты зелёные без правок, 0 новых зависимостей. Гейты: fmt/clippy/test --workspace/wasm_gate/mcp_wasm_gate — зелёные. **Замер G7 (до/после, trunk release, оба без wasm-opt): 10 849 931 → 10 853 951 байт wasm (прирост +4 020 б ≈ 3,9 КБ ≤ 100 КБ — G7-остаток закрыт); gzip 4 101 849 → 4 103 930.** Документация: PRD-0009 §15/§16, ui-kit.md §6 (scissor-политика), surface-registry.md §2 п.5, index-cr-fr.md, worklog.
