# CR-032: Онбординг — адаптивный масштаб поверхности (×вьюпорт) и адекватность иллюстраций

- **Статус:** реализовано (S1–S2: код+тесты; ожидает приёмки владельца)
- **Источник:** UR-003 — обратная связь владельца по онбордингу
  (`docs/user-reporting/ur-003-onboarding-surface-scale.md`, скриншот 2K)
- **Затрагивает:** FR-028 (онбординг), CR-031 (S2 — вёрстка 50/50,
  onboarding_art), docs/interface-objects/onboarding.md

## What

- **S1. Адаптивный масштаб поверхности.** Карточка тура растёт с окном:
  `onboarding_scale(viewport) = clamp(min(vw/1280, vh/720), 1.0, 3.0)` —
  на 2K (2560×1440) ровно ×2 (1440px, «минимум в 2 раза»), на 4K — ×3
  (2160px), ноутбучные/узкие окна — прежнее поведение (×1, кламп по слоту).
  Один коэффициент масштабирует ВЕСЬ контент: кегли (13/18 → 26/36 на 2K),
  межстрочные, паддинги, футер, кнопки, CTA-опции, прогресс-точки, зону
  опций и иллюстрации (`card_scale(card_w)` — производная от фактической
  ширины карточки; единый источник для раскладки, рендера, ввода и реестра).
- **S2. Иллюстрации — валидность и адекватность.** Сцены
  `onboarding_art` переведены на полностью масштабируемые метрики
  (фикс-пиксельные размеры элементов ×k), композиция центрируется по
  вертикали, высоты элементов — доли слота с k-минимумами (не пустует).
  Автотесты: валидность (все примитивы внутри зоны, без вырожденных),
  пропорциональность (кадр при ×k == кадр ×1, растянутый k:1 — ловит
  забытые фикс-пиксели), заполнение (bbox сцены ≥80% ширины / ≥55% высоты
  внутренней зоны на всех 8 шагах).

## Impact

На 2K/4K онбординг читаем и соразмерен экрану (площадь поверхности ×4/×9);
иллюстрации заполняют свой слот вместо пустыни со снежинками фиксированного
размера; узкие окна и стресс-вьюпорты — бит-в-бит прежнее поведение (×1).
