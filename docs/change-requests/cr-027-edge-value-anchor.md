## Описание (What)

На основном канвасе value-связь (data-ребро: бирюзовый поток значений, от построчного порта или от значения ноды) геометрически стартует из **семантической** точки — центра стороны ноды-истока (`port_point`, синие кружки сторон). Визуально линия «от значения» отрывается не от той точки, к которой прикреплена семантически: бирюзовый кружок data-порта строки (FR-025) стоит у ряда значения, а линия начинается выше/ниже — у центра стороны. На скриншоте владельца рёбра `Товар → Корзина` и `Цена → Корзина` начинаются от синей точки стороны, хотя несут значения `Товар.qty`/`Цена.price` и должны выходить из бирюзовых data-точек соответствующих строк.

Требуется: если ребро идёт **от значения** — его исток якорится в data-точке этого значения (построчный порт строки / футер шаблонной ноды), а не в семантической точке стороны. Контрольные рёбра (`flow = control`) остаются на семантических точках сторон.

## Анализ (Root Cause)

Геометрия связей основного канваса — `canvas-core/src/edgegeom.rs`: `edge_curve` → `bezier_between(from, from_side, to, to_side)` → `p0 = port_point(node, side)` — **всегда** центр стороны, независимо от `from_line`/`from_output`/`FlowKind`. Построчные data-порты считаются только для отрисовки кружков (`canvas-render/src/text.rs::line_ports` из кэша раскладки) и для drag'а нового ребра (`line_port_at`), но в геометрию существующих рёбер не попадают: core не знает вертикалей строк, а рендер/приложение не подставляют их в кривую. Эталон решения существует в stage-срезе: `canvas-core/src/bundles.rs::stage_edge_anchor_points` («точки выходов/входов — к строкам, на которых значения», решение владельца 2026-09-22) — но он оперирует приблизительными метриками stage, а на основном канвасе точные вертикали даёт кэш раскладки рендера.

## Решение

1. **Core** (`edgegeom.rs`): явные якоря концов `EdgeAnchors { from, to }` + anchored-варианты чистых функций (`edge_curve_anchored`, `edge_polyline_anchored`, `edge_endpoint_anchored`, `edge_midpoint_anchored`, `distance_to_edge_anchored`, `edge_at_anchored`). Старые сигнатуры — делегирование с `EdgeAnchors::NONE` (прежнее поведение; headless-потребители — MCP, тесты — без изменений). Нормаль контроля якоренного конца — `nearest_side(node, anchor)`.
2. **Резолв якоря истока** (`canvas-render/src/text.rs`, кэш раскладки — точные вертикали строк):
   - `from_line = Some(i)` → порт строки с `source_line == i`; строки нет (проза/без результата/вне диапазона) → фолбэк;
   - `from_output = Some(name)` → шаблонная нода: порт футера; текстовая: последняя строка присваивания с этим именем;
   - прочие value-рёбра (`flow = value` без адресации) → **финальный** порт значения ноды (последняя формульная строка; у шаблона — футер);
   - якорь не резолвится (нет кэша — нода вне экрана, нет портов, висячее ребро) → прежняя точка стороны (плавная деградация).
3. **Условие якорения**: `from_line.is_some() || from_output.is_some() || flow_kind() == Value`. Контрольные рёбра — без изменений. Закрепление стороны (`pin`) не трогаем: при резолве якоря он перекрывает пин визуально, данные `from_side` сохраняются (фолбэк при пропаже кэша).
4. **Консистентность** (визуал = hit-test = хэндлы = лейблы): рендер и `canvas-app` резолвят якоря из одного кэша раскладки; все потребители геометрии основного канваса переведены на anchored-варианты. Миникарта (силуэт «центр—центр») и headless-MCP — без изменений (деградация допустима).

## Открытые вопросы

- Входы текстовых нод (столбец «Входящие значения») не имеют data-точек на левом краю — приёмник остаётся на семантической точке; для шаблонных нод (`toParam`) есть якоря параметров (FR-050 Н2) — отдельный CR, если владелец захочет зеркальное якорение приёмника.
- Пучок (FR-042, вес ≥ 2) на основном канвасе рисуется одной агрегированной линией по доминанте — строковые якоря разных рёбер пучка визуально схлопываются в якорь доминанты (веер со строками есть только в stage-срезе).
