## Описание (What)

Палитра шаблонов (Ctrl+P) сейчас — **модальная** панель: открывается по Ctrl+P,
закрывается Esc и кликом мимо (`main.rs:5823`), а в закрытом состоянии недоступна.
Пользователь требует паттерн Miro: палитра как **постоянно видимый левый док** —
шаблон под рукой в любой момент, без запоминания горячих клавиш. Управление —
**мышью**: drag-and-drop карточки шаблона в нужную точку канваса (вставка сейчас
всегда в центр viewport, `main.rs:5814-5816`) и дабл-клик по карточке для вставки
в центр viewport. Клавиатурный сценарий (Ctrl+P → поиск → Enter) сохраняется.

## Исследование бест-практик (Research)

Источники:

- Miro: левый тулбар/доки board-инструментов видны постоянно; панель шаблонов
  открывается из тулбара и остаётся доступной, пока пользователь работает с
  доской; вставка — drag-and-drop из панели в точку доски
  (https://help.miro.com — Templates / Template picker).
- Figma: левый док (слоёв/компонентов) не модален — клик по канвасу не закрывает
  док, док перекрывает канвас своей полосой, взаимодействие с канвасом мимо
  дока работает как обычно.
- FR-024 уже перенёс визуальный стиль (левый док во всю высоту, шапка, поиск,
  чипы, секции, карточки) — этот FR меняет **режим присутствия** (модал →
  закреплённый док) и добавляет **мышиные жесты вставки**.

Применимое к CanvasDesk:

| Паттерн Miro/Figma | Статус до | Решение FR-030 (в момент решения — FR-025) |
|---|---|---|
| Док виден постоянно | модальная панель (Ctrl+P, клик мимо закрывает) | признак `pinned`: по умолчанию открыт; Ctrl+P — фокус в поиск, не тогл «закрыть» |
| Клик по канвасу не закрывает док | клик мимо закрывает (`main.rs:5823`) | клик мимо панели проходит в канвас; панель не закрывается |
| Кнопка сворачивания дока | нет (Esc только) | кнопка ««» в шапке дока: свернуть/развернуть; Esc — то же |
| Drag-and-drop шаблона в точку канваса | нет — вставка в центр viewport | drag карточки → ghost-подложка под курсором → отпускание вставляет в точку |
| Дабл-клик по карточке — вставить | одиночный клик вставляет в центр | дабл-клик — вставка в центр; одиночный клик — выбор/фокус строки (см. открытый вопрос) |
| Клавиатурный сценарий Ctrl+P → Enter | есть | сохранить: Ctrl+P фокусирует поиск панели |

## Анализ (Root Cause — что отсутствует)

- Панель модальна по построению: `TemplatePanel { open: bool }`
  (`template_ui.rs:81-96`), клик мимо — `self.template_panel.close()`
  (`main.rs:5823-5825`), Esc — `close()` (`main.rs:3085-3090`), Ctrl+P — тогл
  open/close (`main.rs:5480-5492`). Признака «закрепленный док» и «свёрнут»
  нет.
- Drag-and-drop из панели отсутствует: есть только клик по строке →
  `instantiate_template_at(&manifest, viewport_center)` (`main.rs:5810-5817`).
  Ghost-подложка для перетаскивания уже есть на канвасе: `drop_ghost`
  (`cards.rs:847`) — переиспользуется для drag-превью.
- Дабл-клик: обработчик кликов панели (`main.rs:5782-5828`) не различает
  одиночный/двойной клик.
- Отсутствует: состояние collapsed, drag-состояние палитры (индекс строки +
  смещение курсора), пересчёт screen→world для точки вставки (есть
  `viewport_center_world`, обратное преобразование — в camera).

## Требуемые изменения (Changes)

1. **`crates/canvas-app/src/template_ui.rs`**
   - `TemplatePanel { open → mode: DockMode }`, `enum DockMode { Expanded,
     Collapsed }`; `toggle_collapse()`, `focus_search()`;
   - `panel_layout` — в свёрнутом режиме панель не рендерится (или рисуется
     только полоса-ручка 24 px с кнопкой «»»); геометрия без изменений в
     развёрнутом;
   - тесты: дефолт — Expanded; collapse/expand round-trip; геометрия
     не зависит от режима.
2. **`crates/canvas-app/src/main.rs`**
   - старт: панель развёрнута по умолчанию (первый запуск); состояние
     (развёрнута/свёрнута) сохранять в сессии;
   - клик по канвасу при развёрнутой панели: хиты чипов/строк обрабатываются
     как раньше, мимо панели — **клик уходит в канвас**, панель не закрывается
     (убрать `close()` в `main.rs:5823-5825`);
   - кнопка сворачивания в шапке (`lay.header_rect` справа, 22×22): клик —
     Collapsed; повторный (полоса слева) — Expanded;
   - drag: нажатие в `row_rects` с движением > threshold (4 px) входит в
     drag-режим панели — под курсором `drop_ghost`, подложка панели на время
     drag полупрозрачная; отпускание → `instantiate_template_at(manifest,
     camera.screen_to_world(cursor))`; без движения (> threshold) — обычный
     клик (выбор строки);
   - дабл-клик по карточке → вставка в центр viewport (существующее
     поведение одиночного клика — см. открытый вопрос ниже);
   - Ctrl+P: при развёрнутой панели — фокус в поиск (очистка/выделение
     фильтра), при свёрнутой — Expanded + фокус; Esc — Collapsed.
3. **Документация** — `user-docs/interface.md` (палитра-постоянный док,
   drag-and-drop, дабл-клик), `user-docs/hotkeys.md` (Ctrl+P — фокус поиска,
   Esc — свернуть палитру); FR-024 — закрыть пункт «drag-and-drop v2».
4. **Блокеры приёмки** — дефекты вёрстки палитры из CR-011 (строки на футер,
   чипы по байтам, хардкод цветов) должны быть исправлены: постоянный док
   делает их видимыми всегда.

## Проверка (Verification)

- Первый запуск: палитра развёрнута слева; клики по канвасу работают, палитра
  не закрывается; кнопка ««» сворачивает док в полосу, повторный клик
  разворачивает.
- Drag карточки «Database Primary» в правый нижний угол канваса → нода
  появляется в точке отпускания (ghost следовал за курсором); связи/undo —
  один undo-шаг на вставку.
- Дабл-клик по карточке → вставка в центр viewport.
- Ctrl+P → фокус в поиске (курсор в поле фильтра); ввод фильтрует список;
  Enter вставляет выбранный шаблон в центр viewport.
- Esc → док сворачивается; Ctrl+P при свёрнутом — разворачивает.
- Клавиатурная навигация (стрелки/Enter) — без регрессий (сценарий FR-024).
- Гейты: `cargo fmt --check`, `clippy --workspace -- -D warnings`,
  `cargo test --workspace` — зелёные; юнит-тесты режима DockMode и
  screen→world точки вставки.

## Открытые вопросы дизайна

- Одиночный клик по карточке: реализован вариант v1 — одиночный клик
  (без движения) вставляет в центр viewport, как и раньше; drag — в точку
  курсора. Переход на «клик = выбор, дабл-клик = вставка» — v2 (требует
  различения одиночного/двойного клика в обработчике панели).
- Скролл списка колесом мыши — изначально вне скоупа; ревизия
  2026-09-16: колесо над flyout свёрнутой полосы прокручивает список
  (см. Changelog).

## История изменений (Changelog)

- `2026-09-16` — агент: правка 3 — «мёртвый Esc» по развёрнутому доку без
  клавиатурного фокуса. Регрессия ревизии: дефолт свёрнутости сделал
  массовым мышиный путь разворачивания (клик по полосе/шеврону → `expand()`,
  `focused = false`, чтобы не отнимать клавиатуру у канваса), а Esc жил
  только в `on_template_panel_key` под гейтом `open && focused` — в общей
  Esc-цепочке transient-ов ветки для развёрнутого дока не было. Добавлена
  ветка в цепочку (main.rs, Esc-цепочка, после flyout-ветки): `open` →
  `close()` + `persist_palette_dock()`. Сфокусированная панель по-прежнему
  закрывается раньше по коду (гейт выше цепочки) — дублирования нет.
  Контракт `expand() → open без фокуса; close() → !open` зафиксирован в
  `panel_dock_mode_focus_lifecycle`.
- `2026-09-16` — агент: ревизия по скриншоту пользователя (сессия
  2026-09-16): палитра ПРИМАРНО СВЁРНУТА. Свёрнутая ручка-уголок заменена
  вертикальной полосой категорий (`dock_strip_layout`): полоса у левого
  края, центрирована по вертикали, клампится отступами к окну; внизу —
  шеврон «развернуть док» (клик по шеврону или по полосе мимо строк →
  `expand()`). Наведение на строку категории раскрывает flyout справа от
  полосы (`flyout_layout`): ширина = `PANEL_WIDTH − 40` (минимум 260),
  высота по числу шаблонов с клампом к окну, вертикальный центр — строка
  категории, строки обрезаются видимым окном по `scroll_top` — items не
  вылезают за область видимости. Hover-механика — `StripHover` (своя
  реализация по механике `PaletteHover`): intent 150 мс, grace 300 мс,
  пин по клику (WAI-ARIA menu button), удержание внутри flyout, смена
  категории сбрасывает скролл. Колесо над flyout прокручивает список
  (`scroll_by` с клампом к `max_scroll`), над полосой — глотается; полоса
  и flyout добавлены в `cursor_over_screen_surface` (канвас не
  панорамируется). Строки flyout — drag-and-drop/клик через тот же
  `PanelDrag` (ghost-превью общее для обоих режимов). Esc гасит flyout.
  Дефолты: `TemplatePanel::new().open = false`,
  `Settings::template_palette_open = false` (serde default; конфиги,
  где состояние сохранено, уважаются). Развёрнутый док (Ctrl+P) — без
  изменений поведения. Тесты: переписан
  `panel_collapse_button_and_strip_geometry` (центровка, кламп),
  `panel_dock_mode_focus_lifecycle` (дефолт свёрнутости);
  новые `strip_layout_clamps_to_window_bottom`,
  `flyout_layout_clamps_height_and_scroll`,
  `flyout_layout_few_items_centers_on_row`,
  `strip_hover_*` (state machine: intent/grace/пин/смена категории/
  скролл-кламп); `settings::partial_config_uses_defaults` — дефолт
  свёрнутости. Доки: `user-docs/templates.md`, `user-docs/hotkeys.md`.
- `2026-09-16` — агент: реализовано, статус `выполнено`. Вместо enum
  `DockMode` — флаги `TemplatePanel { open, focused }` (те же состояния,
  меньше трения с существующим кодом): `open` = развёрнут док (дефолт
  true), `focused` = клавиатурный фокус (только тогда панель перехватывает
  клавиши). Клик мимо панели — фокус снимается, клик уходит в канвас, док
  не закрывается. Кнопка «‹» (`collapse_rect` в `PanelLayout`) и
  полоса-ручка (`collapsed_strip_rect`) — единые rect'ы для рендера и
  hit-test. Drag-and-drop: `PanelDrag { index, press, active }` (порог
  4 px), инстанциация на отпускании (клик → центр viewport, drag →
  world-точка курсора), ghost-превью — `drop_ghost` (Т9) в screen-space.
  Ctrl+P: свёрнутый → `open()` (фокус + чистый фильтр), развёрнутый →
  `focus_search()` (фильтр сохраняется); обработчик панели Ctrl+P не

  (canvas-core, serde default true) → `config.toml`. Тесты:
  `panel_dock_mode_focus_lifecycle`, `panel_collapse_button_and_strip_geometry`,
  `panel_drag_threshold`. Доки: `user-docs/templates.md` (палитра-док,
  drag-and-drop), `hotkeys.md` (Ctrl+P), `calculations.md`, `node.md`
  (строка FR-030, в момент решения — FR-025). Зависимость: дефекты вёрстки палитры исправлены в
  CR-011 (строки на футер, чипы, палитурные заливки).
- `2026-09-16` — агент: документ создан по запросу владельца («палитра
