# FR-055: Слои, вёрстка и UI kit — этап U4 PRD-0009 (kit v1 + DebugOverlay + витрина)

- **CR ID:** FR-055
- **Статус:** выполнено (U4)
- **Дата:** 2026-09-22
- **Приказ владельца:** «нужно реализовать Продолжай U4 и выведи мне информацию о том какие UI элементы мы уже переносим, какие остаются к переносу»
- **Связанные:** PRD-0009 (§8 F-8/F-10, §13 U4, §15 G6), FR-051 (каркас), FR-052 (U2), FR-053 (U3 пилоты), FR-054 (U5)

## 1. Проблема

PoC PRD-0009 закрыт этапами U0–U3/U5, но из дорожной карты остался не заказанный
владельцем этап **U4**: кит-виджеты (F-8), DebugOverlay (F-10), витрина-галерея,
перенос пилотов на кит. Гейт **G6** (F9-оверлей) — единственный незакрытый пункт
DoD §15. Поверхности сегодня верстают сырыми примитивами: каждый потребитель
вручную подбирает отступы/радиусы/цвета состояний — правила дизайн-системы не
зафиксированы кодом, а отладка слоёв недоступна без чтения исходников.

## 2. Решение (этап U4)

1. **UI kit v1 (F-8)** в `canvas-ui::kit` — чистая модель виджетов поверх
   примитивов U3: `Panel`, `Button`, `IconButton`, `Dropdown`, `Chip`,
   `Toast`, `Tooltip`, `Modal`. Контракты (PRD §8 F-8):
   - цвета — только слоты палитры-среза (`KitPalette` из слотов `ThemeColors`
     v2, включая слоты состояний FR-053) — маппинг в `canvas-render` (крейт
     уже зависит от `canvas-ui`; обратной зависимости нет — G7);
   - отступы/радиусы — только spacing/radius-scale токенов;
   - слой/модальность — только из реестра (кит не рисует сам);
   - текст — только через `TextMeasurer` (F-6), усечение — `ellipsis`;
   - `canvas_ui::anim` — `animate_bool`/`animate_value` (линейная
     интерполяция с dt; L3 из карты переносов Приложения А FR-051);
   - паттерн Popup/Tooltip «якорь + flip при нехватке места + delay»
     (L3 из карты переносов).
2. **DebugOverlay (F-10)** — `canvas_app::debug_overlay`: по готовому
   `UiFrame` строит рамки hit-rect'ов по слоям с подписями «слой/поверхность»
   (и имя элемента), имя поверхности под курсором, подсветку пересечений
   интерактивных rect'ов ОДНОГО слоя (повторное использование
   `UiFrame::overlaps_within_layer` — F-11). Тогл — **F9** (натив) и
   `?ui=debug` (web, параметр `canvas-web::url_params`). Полоса `UiLayer::Debug`
   (L8) — рисуется последней полосой кадра; модель чистая — headless-тесты.
3. **Витрина-галерея** — поверхность `kit_gallery` (Modals/Block, реестр U2):
   компоненты кита × состояния (Normal/Hover/Pressed/Disabled/Selected) ×
   RU/EN × тёмная/светлая тема. Вход — пункт меню «?» «О интерфейсе»
   (Q5, вариант (a): доступна всегда, полезна для баг-репортов и приёмки;
   стоимость нулевая после U4). Esc/backdrop/✕ — закрытие (контракт Block).
4. **Перенос пилотов на кит** (§13 U4): контейнеры/кнопки/чипы пилотов U3
   (what-if бар, галерея схем) переходят на виджеты кита там, где маппинг 1:1
   (панель-контейнер, чип-пилюля, кнопки футера) — значения стилей из тех же
   слотов: ноль визуального скачка (I-1 FR-046).
5. **Линт**: витрина добавлена каноническим состоянием G4-линта (кит покрыт
   линтом — результат этапа U4 по §13).

## 3. Не входит

- Scissor-бакеты (F-5) и замер wasm-прироста — переносятся на следующую
  web-сборку (G7-остаток, как зафиксировано в PRD-0009 §15 G7); в этом
  этапе только фиксация в docs.
- TextInput кита (text_edit), retained-скролл — v2/за пределами PoC (non-goal).
- Онбординг — не дорабатывается (решение владельца на U5, пользовательских
  изменений нет).

## 5. Риски

- R-4 (регресс z-тестов): пилоты мигрируются на те же слоты-значения —
  дифф визуального порядка отсутствует; z-тесты и G4 — на каждом шаге.
- R-6 (порог входа): витрина = живой образец кита; `docs/ui-kit.md`
  дополняется разделом «Кит-виджеты».
- Налезания в витрине — те же правила G4 (одна полоса — без пересечений
  интерактивных rect'ов разных поверхностей; внутри поверхности — осознанная
  композиция, проверяемая линтом кадра).
