# FR-025: Построчные точки выхода на нодах с расчётами + фича-флаг в настройках

- **Статус:** выявлено
- **Тип:** FR (Feature Request)
- **Приоритет:** важно
- **Владелец:** агент (анализ)
- **Источник:** сообщение пользователя (сессия 2026-09-17): «для нод с расчётами нужно добавлять точку выхода к каждой строке с расчётом и к строке с финальным значением, этот функционал надо поставить на фича-флаг в меню настроек».
- **Связанные задачи:** FR-013 (Numi-движок, построчные результаты), FR-014 (value-рёбра, `$in`/`$1..$N`), FR-015 (queueing), FR-018 (шаблонные ноды, футер результата), CR-003 (зона портов), CR-002 (хэндлы перепривязки), SPEC.md §5.1 (`.canvas`: `edges`), §7 (поток значений)
- **Создан:** 2026-09-17
- **Обновлён:** 2026-09-17 (создан, статус `выявлено`)
- **Документ-шаблон:** `docs/change-requests/cr-template.md`

## Описание (What)

Нода с расчётами — это Numi-лист (FR-013): несколько формульных строк
(`rps = 1000`, `latency = 50 ms`, `cpu = …`) с результатами у правого края
каждой строки и финальным значением ноды (последняя формульная строка).
Сегодня value-связь (FR-014) можно протянуть только от ноды целиком — она
унесёт **одно** значение ноды (результат последней формульной строки,
`flow.rs::propagate`). Промежуточные строки расчёта (`rps`, `latency`)
утащить в другую ноду нельзя: значение теряется на границе ноды.

Требуется **построчная точка выхода**: у каждой формульной строки — свой
выходной порт на правом краю ноды (на вертикальном уровне строки
результата), включая строку финального значения; drag от такого порта
создаёт value-ребро, несущее значение **именно этой строки**. У шаблонных
нод (FR-018) точка выхода ставится у футера результата (FR-023) — их
формула и есть финальное значение. Функционал — за **фича-флагом** в меню
настроек (по умолчанию выключен): флаг меняет и рендер портов, и
hit-тест, и семантику создаваемых рёбер; при выключенном флаге поведение
в точности текущее.

## Анализ (Root Cause — чего нет в коде)

Построчных выходов нет ни в модели, ни в потоке, ни в UI — это новая
функция. Существующие точки опоры:

- **Порты ноды — только стороны.** `port_at` (`crates/canvas-core/src/edgegeom.rs:605`)
  возвращает `Side` по ближайшему из четырёх центров сторон
  (`port_point(node, side)`); зон захвата — `Settings::port_zone_px`
  (CR-003). Построчных портов нет: hit-тест не знает о строках.
- **Ребро не знает строку-исток.** `Edge` (`crates/canvas-core/src/model.rs:416`):
  `from_node`/`from_side`/`to_node`/`to_side` + `extra`; `flow_kind` — в
  `canvasdesk.flow.kind` (`model.rs:469`). Поля уровня строки нет.
- **Поток считает ноду целиком.** `propagate` (`crates/canvas-core/src/flow.rs:219`):
  для заметки значение — последняя вычислимая строка
  (`eval_lines_in(&text, &env)…last()`, `flow.rs:263-271`);
  `inbound_slots` (`flow.rs:284`) берёт `outputs[from_node]` —
  по node-id, без разбора по строкам.
- **Построчные результаты уже есть — рендер и core.**
  `ExprLineResults = HashMap<String, Vec<Option<ExprOutcome>>>`
  (`crates/canvas-core/src/expr.rs:59`) — значения и ошибки каждой строки;
  рендер привязывает бейдж результата к ряду строки
  (`crates/canvas-render/src/text.rs:1801-1856`: блок тела с
  `source_line`, `row_y = body_origin.y + block.offset[1] + …`) — та же
  вертикаль нужна порту. `App.expr_line_results` (`main.rs:406`) —
  живой снимок на кадр.
- **Старт drag связи — от порта-стороны.** `on_left_button`
  (`crates/canvas-app/src/main.rs:6157-6179`): `port_at` →
  `EdgeDrag::New { from_node, from_side, value_flow }` (Shift — value);
  дальше `finish_edge_drag` создаёт `Edge`. Для строки нужен третий
  вариант истока.
- **Фича-флаг — готовый паттерн.** `Settings` (`crates/canvas-core/src/settings.rs:148`)
  — serde-default поля + строка в `SETTINGS_ROWS`
  (`crates/canvas-app/src/lib.rs:108`) + ветка `apply_settings_row`
  (`main.rs:4391`). Фокус-режим (T23) добавлялся точно так же.
- **Футер результата шаблонной ноды** (FR-023) — единственная
  «финальная» строка шаблонной ноды; порт шаблонной ноды — у футера.

## Требуемые изменения (Changes)

### 1. Настройка-флаг

- `Settings` (`settings.rs`): поле `pub line_ports: bool` (дефолт `false`,
  `#[serde(default)]` совместим со старыми конфигами); тест round-trip и
  `field_names_snake_case` дополняются.
- Строка панели: `SettingsRow::LinePorts` в `SETTINGS_ROWS` + ветка в
  `apply_settings_row` (инверсия флага; пересчёт hit-зон не нужен —
  рендер/hit-тест читают флаг на кадре). Подпись: «Точки выхода строк: вкл/выкл».
- В пользовательской документации — раздел о построчных выходах
  (`user-docs/calculations.md`).

### 2. Геометрия построчных портов (чистый модуль)

- Новая чистая функция в `canvas-core` (рядом с `edgegeom`) или
  `canvas-app::ui`: `line_port_rows(node, line_results) -> Vec<(usize, [f32;2])>`
  — для каждой формульной строки (включая финальную) — world-точка порта:
  правый край ноды (`node.x + node.width`), Y — центр ряда строки (тот же
  расчёт, что у бейджа результата в `text.rs:1816-1821`; для шаблонной
  ноды — центр футера результата FR-023). Источник вертикалей —
  `ExprLineResults` + раскладка тела (единый источник правды с рендером,
  чтобы порт и бейдж результата не разъезжались).
- `line_port_at(node, point, zoom, tolerance, rows) -> Option<usize>` —
  hit-тест точки порта в зоне `port_zone_px` (тот же допуск, что CR-003);
  конфликт со сторонным портом решается приоритетом построчного
  (флаг включён → построчные порты перекрывают правую сторону в пределах
  своих рядов, остальная сторона остаётся узловой).

### 3. Рендер

- `canvas-render` (cards/text-пасс ноды): при включённом флаге — кружки
  портов на правом краю у каждого ряда с результатом (размер/радиус — как
  у узловых портов; hover — подсветка, аффорданс drag). Порты рисуются
  только у строк с результатом или ошибкой (прза — без порта), финальная
  строка — помечается (например, заполненный кружок против полого у
  промежуточных — открытый вопрос).
- Резиновая линия drag от построчного порта — `edgegeom::draft_curve` от
  точки порта (сторона Right).

### 4. Модель ребра и drag

- `Edge` (`model.rs`): `#[serde(rename = "fromLine", skip_serializing_if =
  "Option::is_none")] pub from_line: Option<usize>` — старые `.canvas`
  грузятся, новые сохраняют строку; round-trip тест.
- `EdgeDrag::New` (`lib.rs:325`): поле `from_line: Option<usize>`;
  drag от построчного порта всегда создаёт **value-ребро**
  (`value_flow: true`) — точка выхода расчёта семантически value.
- `finish_edge_drag`: при `Some(from_line)` — запись поля в `Edge`;
  перепривязка хэндлом `from`-конца (CR-002) сохраняет `from_line`, ретаргет
  на другую ноду — сбрасывает (открытый вопрос).

### 5. Поток значений

- `flow.rs`: построчные выходы — `propagate` дополнительно строит
  `line_outputs: HashMap<(String, usize), Option<Value>>` из
  `eval_lines_in` (он уже возвращает построчные `ExprOutcome`; значения
  строк-присваиваний — значение переменной, строк-выражений — их результат).
- `inbound_slots`: слот ребра с `from_line = Some(i)` — значение строки
  `i` источника; ребро без `from_line` — значение ноды (текущее
  поведение). Политика деградации: строка удалена/стала прозой/ошибка —
  слот `Some(None)` (как «источник без значения» сейчас) — открытый
  вопрос: молчание или видимая ошибка в ноде-приёмнике.
- `$in`/`$1..$N` не меняются: нумерация по порядку рёбер; меняется только
  ИСТОЧНИК значения слота. Подсказки FR-021 совместимы без правок.

### 6. Проверка флага на всех путях

- Флаг выключен (дефолт): рендер портов, hit-тест, `EdgeDrag`, схема рёбер
  и поток — в точности текущие; `.canvas` без `fromLine` — без изменений.
- Флаг включён: новые порты и `fromLine`-рёбра; выключение флага обратно —
  существующие `fromLine`-рёбра продолжают работать (деградируют до
  значения ноды в потоке — рендер портов скрыт, семантика потока
  сохраняется по `from_line`-полю).

## Архитектура тестируемости (инварианты FR-025)

1. **Инвариант вертикали:** world-Y порта строки == world-Y ряда бейджа
   результата той же строки (единый расчёт ряда; тест на расхождение).
2. **Инвариант флага:** при `line_ports = false` ни один путь
   (рендер/hit-test/drag/flow) не обращается к построчным портам;
   `line_ports` не меняет значения потока для рёбер без `from_line`.
3. **Инвариант схемы:** `Edge` без `from_line` сериализуется/грузится
   байт-в-байт как раньше; с `from_line` — round-trip.
4. **Инвариант слота:** слот ребра `from_line = Some(i)` == значение
   строки `i` из `eval_lines_in`; удаление строки — `Some(None)`.

## Открытые вопросы дизайна

- **Вид порта финальной строки** — заполненный vs полый кружок, или
  подпись итога; решить на макете.
- **Деградация в потоке** (строка удалена/ошибка): молчаливый `Some(None)`
  (текущее поведение «источник без значения») или видимая диагностика в
  приёмнике. v1 — молчаливо (согласовано с Numi-принципом тишины прозы).
- **Перепривязка from-конца** (CR-002): сохранять `from_line` при
  перетаскивании на другую ноду (индекс может не существовать) — v1:
  сброс `from_line` до узлового значения.
- **MCP**: параметр `fromLine` в `edge_add`/`edge_connect` — v2 (после
  стабилизации UI-пути).
- **Порты на левой стороне** (выход строки «наружу» влево при тесном
  ландшафте) — v1 только правый край (результат справа, Numi-стиль).

## Проверка (Verification)

### Юнит-тесты (core)

- `line_port_rows`: для листа `rps = 1000\nlatency = 50 ms\ncpu = …` —
  порт у каждой формульной строки; прозаических строк нет; финальная
  строка присутствует; у шаблонной ноды — один порт у футера.
- `line_port_at`: попадание в зоне `port_zone_px`, промах вне; конфликт
  со сторонным портом правой стороны — построчный приоритет в пределах ряда.
- `Edge` round-trip: без `from_line` — идентичный JSON; с `from_line` —
  поле сохраняется; битые значения (`fromLine: -1`) — `None`.
- `inbound_slots` с `from_line`: слот == значению строки; строка удалена —
  `Some(None)`; `from_line = None` — значение ноды (старое поведение).
- Инвариант флага: `propagate` при `line_ports` вкл/выкл даёт одинаковые
  `outputs` для рёбер без `from_line`.

### Юнит-тесты (app)

- `Settings` round-trip с `line_ports`; `field_names_snake_case` содержит
  `line_ports`; дефолт — `false`.
- `EdgeDrag::New` с `from_line`: draft_origin — точка построчного порта.

### Ручная приёмка

- Включить флаг → у каждой строки расчёта ноды виден порт; drag от строки
  `rps` в ноду-калькулятор → в приёмнике `$in` даёт `1000 rps`; drag от
  финальной строки — итоговый результат.
- Выключить флаг → порты исчезают, созданные ранее построчные связи
  работают (значения строк), новые связи — только узловые.
- Старый `.canvas` без `fromLine` грузится и считается как раньше.
