## Описание
Тело ноды (FR-061) не до конца совпадает с прототипом `ux-node-body-fill.html`: нет подписей секций («параметры · N» / «расчёт · N»), авто-строки приёмника не имеют пунктирной амбер-хромировки, Σ-строка ведомости («Σ <имя>») не выводится после расчётных строк, футер результата — без метки «ИТОГ», бейджи каскада — голый текст вместо пилюль (отложено в этап E для kit-Row, но не перенесено в тело ноды). Параллельно — дефекты подгонки высоты: ноды без футера результата никогда не подгоняются (ранний выход в `ensure_reserve_at`), консервативная оценка уровня 1 не учитывает строку заголовка блока-ведомости, тогглы блока/описания не запускают refit, раскрытие описания длиннее клампа не измеряется вовсе. Выявлено агентом сверкой плана владельца с кодом и прототипом.

## Анализ
- **Дедупликация описания (шаг 2 плана).** Q3 (FR-061, решение владельца 2026-09-23 «desc→манифест→проза») ввёл проза-фолбэк зоны описания, но абзац продолжает рендериться и в теле — двойной показ. Этап D фиксировал это заранее: «проза-фолбэк НЕ применён — дублировал бы первый абзац тела»; после Q3 супрессия так и не появилась. Переписывание текста ноды неприемлемо (сдвиг `formula_lines`/`source_line`/`spill`/порт-привязок — индексная привязка к строкам, I-1/I-3). Механика — по прецеденту свёрнутого блока (`text.rs` body_items, `continue` по source_line): супрессия СТРОК абзаца при сборке сегментов, индексы не трогаются. Условие супрессии — `desc == first_prose_paragraph(body_text)` (чистая деривация в общем стеке `with_body_stack`: измерение и рендер супрессируют одинаково, I-2 без расширения контрактов; заодно покрывает случай `canvasdesk.desc`, дословно равного абзацу — двойной показ тоже исчезает).
- **Высота нод без футера.** `scene.rs:874` — ранний выход `if !self.node_shows_result_footer(index) { return; }`: ноды с построчными результатами (обычный Numi-лист) и ноды без результатов вовсе никогда не проходят refit — длинный текст вылезает за низ карточки. Причина раннего выхода: оценка/мера включают резерв футера `RESULT_LINE_HEIGHT + 2.0` — для ноды без футера это дало бы пустой хвост. Фикс: футер-флаг в запросе резерва — резерв футера добавляется только когда футер показывается.
- **Оценка уровня 1 без строки заголовка блока.** `estimated_result_reserve_height` считает только строки текста; `body_items` вставляет заголовок блока-ведомости («▾ расчёт · N строк») отдельным рядом — оценка занижена на 1 ряд, консервативный гейт пропускает (`estimate ≤ height`), уровень 2 не запускается, контент не влезает. Фикс: `block_header_plan` переносится в `canvas_core::expr` (общая чистая функция) и учитывается в оценке (+1 ряд).
- **Тогглы без refit.** `handle_body_hit_click` (app.rs) тогглит `block_collapsed`/`desc_expanded`, но не вызывает `ensure_reserve_at`: разворот блока/описания растёт контент — до следующего пересчёта вылезание. Фикс: refit сразу после тоггла. Для раскрытого описания уровень 2 обязан измерять полное описание — `MeasuredReserveFn` расширяется флагом `desc_expanded` (кламп — только дефолт).
- **Пилюли бейджей.** D-14: «бейдж — текст без пилюли, пилюля отложена в этап E (kit-Row)» — kit-Row пилюлю получил (`ROW_BADGE_PAD_H`, `RowStyle::badge_fill/badge_border`), тело ноды — нет (`shape_row_cell` — голый текст). Прототип .badge: капсула с фоном 9 % и рамкой 50 % цвета. Пайплайн карт поддерживает радиус и рамку (`CardInstance.params[0]`/`border`, cards.wgsl) — `BodyQuadKind::BadgePill*` с производными заливкой/рамкой от цвета текста бейджа.
- **Зазор колонок.** Прототип .row `gap:7px`, план владельца «GUIDE_GAP 6→8». `TABLE_GUIDE_GAP` — общий токен кита (kit.rs/kit_ui.rs/app.rs + parity-тесты), менять глобально нельзя (изменил бы панель FR-044 и витрину). Вводится узловой токен `TABLE_NODE_GUIDE_GAP = 8.0`: `row_grid::GUIDE_GAP` перепривязывается на него (row_grid — каркас именно тела ноды), кит не затронут.
- **Диагноз шага 3 плана не подтвердился.** «sans-ветка в pass_a» отсутствует — `pass_a` замеряет моно (`text.rs:2989`, `MONO_FAMILY`). Реальное расхождение: `canvas-ui::measure::shape_measure` жёстко `Weight::MEDIUM`, рендер моно-ячеек — `mono_attrs` (400). Сегодня это компенсируется отсутствием Medium-лица у Noto Sans Mono (CSS-подбор даёт Regular), но паритет должен быть явным: вес выбирается по семейству (моно/наклонное моно → 400, остальное → MEDIUM — паритет `sans_attrs`/`mono_attrs`).
- **Маркеры портов (::before/::after) уже реализованы** — построчные точки выхода FR-025 и параметр-якоря FR-050 рисуют точки у рядов; дубль не нужен.
- **ⓘ в прототипе отсутствует** — из шага 6 плана исключён (источник ⓘ — FR-045, иная зона).

## Проверка
- `first_prose_paragraph_span`: абзац через пустую строку/фенс; абзац после формул; отсутствие абзаца; байт-паритет `first_prose_paragraph`.
- Супрессия: тело не содержит ряд с текстом абзаца; `formula_lines`/порты не сдвинуты; measure == render (существующий паритет-тест стека расширяется случаем desc-абзаца); сцена: оценка не двойнóй счёт.
- Высота: нода без футера растёт под тело (без пустого резерва футера); нода с заголовком блока получает +1 ряд уже на уровне 1; тоггл раскрытия описания длиннее клампа растит высоту сразу; свёртывание не усаживает (I-6).
- Пилюли: `pill_colors` — детерминированные фон/рамка от цвета текста; ширина колонки бейджей включает 2·PAD_H (тест прохода A); детерминизм прохода A сохранён.
- Гейты: `cargo fmt --all --check`; `CARGO_INCREMENTAL=0 cargo clippy --workspace --all-targets -- -D warnings`; `CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0 cargo test --workspace`; `bash scripts/wasm_gate.sh --check`; `bash scripts/mcp_wasm_gate.sh --check`.
- Онбординг/пользовательская документация: вопрос владельцу по завершении (правило AGENTS.md) — дефекты высоты меняют поведение карточек, шаг онбординга не затрагивается.
