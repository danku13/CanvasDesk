# FR-095: Виртуальная клавиатура web/тач — скрытый input-шим, coarse-гейт, visualViewport

- **Статус:** выполнено
- **Тип:** FR (дефект мобильного ввода → фича виртуальной клавиатуры)
- **Приоритет:** критично
- **Владелец:** агент (сессия 2026-10-03)
- **Источник:** аудит мобильной адаптации 2026-10-03: «на мобильных устройствах работает только html оверлей» (след FR-092) — тач-ввод заработал (FR-092/093), но текст на телефоне ввести негде
- **Связанные задачи:** FR-092 (тач-ввод), FR-093 (двойной тап), wasm-port §5 (текстовый ввод), CR-014 (dvh/тач-цели DOM)

## Описание

После FR-092/093 на телефоне работали тап/драг/пинч и создание заметки двойным
тапом, но **ввод текста был невозможен в принципе**: канвас не editable-элемент —
мобильный браузер не поднимает виртуальную клавиатуру. Существующий мост
beforeinput (`ime.rs`, wasm-аудит 2026-09-25) слушает document, но события
не рождаются: нет фокусируемого элемента, который браузер считает полем ввода.

Решение — скрытый `<input>`-шим в canvas-web + три контура управления:

1. **Шим** (`install_shim`): `1×1, opacity 0, fixed`, `pointer-events: none`,
   `autocapitalize/autocomplete off, spellcheck false`, `enterkeyhint="enter"`.
   Листенеры шима: keydown/keyup форвардятся синтетическим KeyboardEvent на
   канвас (winit-листенер получает их синхронно, в том же тике — стрелки,
   Enter, Esc доходят до App), beforeinput дедуплицируется с keydown
   (существующий механизм — окно 120 мс).
2. **Состояние** (`App::text_input_active`): редактор заметки, открытая панель
   поиска, клавиатурный фокус палитры, поле подмены окна проверки — те же
   приёмники, что у `insert_committed_text`. Синхронизация app→web — в хуке
   `TourAwareApp::drain_and_emit` после каждого события цикла (без новых
   мостов: App остаётся платформенно-нейтральным).
3. **Coarse-гейт** (`canvas_core::web_bridge::POINTER_COARSE`, источник —
   `matchMedia("(pointer: coarse)")` в `touch_platform::install`): на десктопе
   шим не фокусируется вовсе — поведение web-десктопа бит-в-бит прежнее
   (winit-канвас продолжает получать физическую клавиатуру).

Фокус-тайминг: переход false→true — программный `focus({preventScroll:true})`
(Android); iOS Safari программный фокус вне жеста клавиатуру не поднимает —
дополнительный capture-путь `pointerdown/touchstart` на канвасе фокусирует шим
синхронно, пока текстовый режим активен. Тап, только открывающий редактор,
добирает клавиатуру следующим тапом (известное ограничение iOS, см. Приёмка).

Перекрытие клавиатурой: листенеры visualViewport (resize/scroll) шлют
`AppEvent::VisualViewport { bottom_inset }` (инсет = innerHeight −
(vv.height + vv.offsetTop), кламп ≥ 0); App (`on_visual_viewport`) пангует
камеру активного редактора чистой функцией `keyboard_shift_up` (низ ноды
остаётся над инсетом с зазором 12 лог. px; инсет ≥ вьюпорта — низ к верхнему
краю; дедуп по полю `visual_viewport_inset` — сдвиг только при изменении).

## Влияние

| Объект | Что сломано | Где |
|---|---|---|
| canvas-web | нет фокусируемого элемента — клавиатура не поднимается, текст на телефоне ввести нельзя | `crates/canvas-web/src/ime.rs` |
| canvas-app | состояние «текстовый ввод активен» не доезжает до web-слоя | `canvas-app/src/app.rs` (`text_input_active`), `canvas-web/src/tour_aware_app.rs` |
| canvas-web | клавиатура перекрывает низ экрана — курсор редактора скрыт | `ime.rs` (visualViewport), `app.rs` (`keyboard_shift_up`, `on_visual_viewport`) |

## Приёмка

- Юнит-тесты: `keyboard_shift_up` (пан по переполнению, границы зазора,
  инсет 0/отрицательный/≥ вьюпорта, вырожденный вьюпорт), мост web_bridge
  (coarse roundtrip).
- Гейты: fmt, clippy -D warnings (натив + wasm32), test --workspace,
  wasm_gate --check.
- Ручной сценарий (телефон): двойной тап по заметке → клавиатура поднимается
  (iOS — вторым тапом), кириллица/латиница вводятся, Backspace/стрелки/Enter
  работают, камера держит курсор над клавиатурой; тап мимо — клавиатура
  прячется; десктопный web — без изменений.

## Известные ограничения

- iOS: клавиатура на тап, открывающий редактор, поднимается со следующего
  тапа (ограничение программного фокуса Safari; capture-путь покрывает все
  последующие тапы).
- Backspace/стрелки идут форвардом keydown шима → синтетика на канвас;
  композиция IME (китайский/японский) через beforeinput — без приоритетной
  поддержки на мобильных раскладках.

## Точки входа

- `crates/canvas-web/src/ime.rs` — шим, coarse-гейт, visualViewport.
- `crates/canvas-web/src/touch_platform.rs` — matchMedia pointer:coarse.
- `crates/canvas-web/src/tour_aware_app.rs` — синхронизация после событий.
- `crates/canvas-app/src/app.rs` — `text_input_active`, `keyboard_shift_up`.
- `crates/canvas-app/src/app/input.rs` — `on_visual_viewport`.
