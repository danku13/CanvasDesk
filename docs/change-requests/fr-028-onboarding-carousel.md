## Описание (What)

У нового пользователя первый экран CanvasDesk — пустой бесконечный канвас
без подсказок: ни навигация (пан/зум), ни заметки двойным кликом, ни формулы
Numi, ни палитра шаблонов не открываются сами. Обучение перекладывалось на
документацию (`user-docs/quick-start.md`), но точка входа в неё для новичка
неочевидна, а «прочитай доки» — барьер, который индустрия давно заменяет
онбордингом внутри продукта.

Требуется: (1) при первом запуске — автоматический онбординг-тур по функциям
сервиса (карточки-карусель поверх канваса); (2) кнопка **«Пропустить»** всегда
доступна — она **откладывает** тур до следующего запуска (не более 3 раз
подряд, после — авто-показ замолкает); (3) полный проход ставит флаг
«пройдено»; (4) **перезапуск в любой момент** — пункт «Пройти онбординг» в
меню помощи кнопки «?» (FR-031). v2 (отдельный коммит) — интерактивный
демо-канвас «сделай сам» с чек-точками.

## Исследование бест-практик (Research)

Источники:

- **Miro first-run tour** — центральная карточка с шагами поверх реального
  холста, «Next / Skip», прогресс-точки; после Skip — тур больше не
  навязывается, но доступен из меню помощи. Работает на чистом тексте: нет
  скриншотов — принцип «один шаг = одна мысль».
- **Figma product tour / Notion checklist** — короткие туры 5–10 шагов;
  Notion добавляет чек-лист «освойте базу» с прогрессом. Для v2 CanvasDesk
  демо-канвас ближе к Figma: показать живую сцену и предложить действия.
- **Nielsen Norman Group «Onboarding»** — пропуск обязан быть видимым на
  каждом шаге (пользователь никогда не должен искать выход); тур короче —
  завершаемость выше: целиться в 8±2 шага, не перечислять всё.
- **Паттерн «nag limit»** (VS Code welcome, Postman) — отложенное приглашение
  возвращается не бесконечно: 2–3 напоминания, затем тишина по авто-показу,
  ручной вход остаётся навсегда. Выбран лимит 3 откладывания.
- **Флаг в конфиге** — `hud_on_start: bool` (`settings.rs:162`, комментарий
  `focus_mode` `settings.rs:152-157` — «старые конфиги без поля грузятся как
  false») — устоявшийся в проекте способ расширения схемы без поломки
  существующих `config.toml`.

Применение к CanvasDesk: карусель — одна центральная карточка (квад +
screen-тексты — паттерн `settings_overlay`), фон слегка затемняется
(паттерн wheel FR-022), никакого интерактива с канвасом в v1 (пан/зум под
оверлеем заблокированы — как у открытой панели настроек).

## Анализ (Root Cause — чего нет в коде)

Онбординга нет — новая функция. Точки опоры:

- **Нет полей состояния.** `Settings` (`settings.rs:148-162`) не хранит факт
  прохождения онбординга; `hud_on_start: bool` (`settings.rs:162`) — образец
  «настройки при старте», но однобитовый: для «отложить ×3» нужен счётчик
  (`u8`) рядом с флагом «пройдено».
- **Нет запуска при старте.** Ближайший прецедент — `App` инициализация читает
  `settings.hud_on_start` один раз (`main.rs:1089`
  `hud_visible: settings.hud_on_start`); туда же встаёт проверка
  `should_show_onboarding`.
- **Нет карусели.** Существующие оверлеи — статические панели (F1 `lib.rs:340`,
  настройки `settings_ui.rs`, палитра `template_ui.rs:81`): нет машины
  состояний «шаг/назад/вперёд/прогресс». Ближайший образец пошагового UI —
  wheel-навигация FR-022 (хаб «назад», глубина, затемнение) и чекбоксы-строки
  `template_ui::PanelRow` — но это не карусель.
- **Нет перезапуска из меню.** Меню помощи «?» появляется в FR-031 — этот FR
  добавляет в него пункт «Пройти онбординг» (действие уже описано там).
- **Сохранение флагов.** `Settings::save(path)` (`settings.rs:239`) —
  существующий хвост сохранения; вызовы после «Готово»/«Пропустить» идут по
  образцу `apply_settings_row` → `settings.save(config_path)`
  (`main.rs:4430-4432` — ветка HudOnStart как образец побочного эффекта с
  сохранением).

## Требуемые изменения (Changes)

### 1. Схема `config.toml` (+2 поля, `#[serde(default)]`)

- `onboarding_done: bool` — дефолт `false`; `true` = пользователь прошёл тур
  до конца (авто-показ выключен навсегда).
- `onboarding_defers: u8` — дефолт `0`; сколько раз подряд тур отложен
  «Пропустить»; кламп при загрузке в `[0, 3]` (битые конфиги не ломают
  приложение — паттерн `port_zone_px` клампа, `settings.rs:166+`).
- Комментарии полей — по образцу `focus_mode` (`settings.rs:152-157`):
  «старые конфиги без поля грузятся как …». Обновить round-trip тест дефолтов
  и `field_names_snake_case` (новые имена в списке).

### 2. Чистый модуль `onboarding_ui.rs` (образец `settings_ui`)

- Контент: `ONBOARDING_STEPS: &[OnboardingStep]` — `OnboardingStep { title,
  body }`, 8 шагов (скоуп владельца — база + расчёты + шаблоны):
  1. **Приветствие + навигация** — пустой холст, Space+drag / средняя кнопка /
     тачпад, зум Ctrl+колесо, миникарта, «всё сохраняется в .canvas»;
  2. **Заметки** — двойной клик по пустому месту, markdown-подмножество,
     цвет палитрой по ПКМ;
  3. **Связи** — drag от края ноды, перепривязка перетаскиванием конца,
     value-связи;
  4. **Группы и отмена** — рамка группы, Ctrl+Z/Ctrl+Y;
  5. **Формулы Numi** — присваивание и `= выражение`, единицы `rps/ms/MB/s`,
     подсказки при вводе;
  6. **Поток значений** — `$in`/`$N` по входящим связям, живой пересчёт;
  7. **Шаблоны** — палитра Ctrl+P, wheel Shift+клик, параметры нод;
  8. **Финал** — «?» — документация и повтор этого тура, F1 — горячие клавиши
     (кнопка «Готово»).
- Логика показа: `should_show_onboarding(settings) -> bool` — чистая:
  `!onboarding_done && onboarding_defers < ONBOARDING_MAX_DEFERS` (константа
  `= 3`).
- Состояние: `OnboardingState { step: usize }` в `App` (за `Option` —
  `None` = тура нет); переходы `next()/prev()/defer()/complete()` — чистые
  методы с клампом шага `0..len-1`.
- Геометрия: `card_rect(viewport) -> [f32; 4]` — центр окна, ширина
  `ONBOARDING_CARD_WIDTH = 460.0`, высота по контенту шага + шапка + футер
  с кнопками; кламп к окну (320×240 — образец теста FR-026); `progress_dots`
  layout и хит-тесты кнопок «Назад / Далее / Пропустить» — чистые, с тестами.

### 3. UI (рендер, паттерн `settings_overlay`)

- Затемнение канваса под карточкой (квад с альфой — паттерн wheel FR-022);
  карточка: заголовок, тело (обычные screen-тексты, без GFM-блоков — тексты
  короткие), прогресс-точки `● ○ ○ …`, футер: «Назад» (кроме 1-го шага),
  «Далее» → на последнем шаге «Готово», «Пропустить» — слева/справа постоянно
  (NN/g: выход виден всегда).

### 4. Ввод и жизненный цикл

- Автозапуск: `App::new` после загрузки настроек —
  `if onboarding_ui::should_show_onboarding(&settings) { onboarding = Some(0) }`
  (место чтения — образец `hud_on_start`, `main.rs:1089`).
- «Далее» на последнем шаге («Готово») → `onboarding_done = true`,
  `settings.save(config_path)`, закрыть.
- «Пропустить» / Esc → `onboarding_defers += 1` (кламп 3), save, закрыть —
  отложено до следующего запуска. После 3-го откладывания
  `should_show_onboarding` = false (тишина), ручной вход остаётся.
- Перезапуск: пункт «Пройти онбординг» в меню «?» (FR-031) →
  `onboarding = Some(0)`; счётчик `defers` не меняется (явное намерение);
  полный проход ручного тура также ставит `done = true`.
- Открытый онбординг блокирует ввод канваса (как открытая панель настроек);
  Esc — единственный клавиатурный выход, двухэтапность не нужна (нет вложенных
  меню).

### 5. V2 — демо-канвас (отдельный коммит, вне объёма v1)

- Финальный шаг v1 («Попробовать») раскрывается в v2 в живой сценарий:
  приложение создаёт демо-сцену (заметка с формулой, вторая нода, value-связь)
  и ведёт по чек-точкам («создай заметку двойным кликом» → выполнено ✓).
- Каркас v1 это предусматривает: `OnboardingStep` не хардкодит «стоп» —
  шаги допускают опциональное действие (`Option<DemoAction>`), чтобы v2 не
  переписывал машину состояний.

## Архитектура тестируемости (инварианты FR-028)

1. **Инвариант триггера (таблица решений):** `should_show_onboarding`:
   `(done=false, defers 0..2) → true`; `(done=false, defers=3) → false`;
   `(done=true, любые defers) → false` — юнит-тест всех комбинаций.
2. **Инвариант откладывания:** «Пропустить»/Esc инкрементируют `defers` ровно
   на 1 (с клампом 3) и сохраняют конфиг; ручной запуск из меню счётчик не
   трогает.
3. **Инвариант завершения:** «Далее» на последнем шаге → `done = true`;
   любой `defer` после `done` невозможен (тур закрыт).
4. **Инвариант карусели:** `step ∈ [0, len-1]` после любого `next/prev`;
   «Назад» на первом шаге отсутствует (hit-тест — None); «Далее»/«Готово»
   меняют подпись только на последнем шаге.
5. **Инвариант схемы:** `config.toml` без новых полей читается (defaults
   `false`/`0`); round-trip дефолтов с новыми полями байт-в-байт стабилен;
   `defers = 99` в битом конфиге клампится к 3.
6. **Инвариант клампа:** карточка целиком внутри окна 320×240 и при любом
   viewport.

## Открытые вопросы дизайна

- **Иллюстрации в карточках** (мини-схемы из квадов: «двойной клик» с точкой и
  курсором) — v2: текст v1 самодостаточен, но схемы повысят ясность.
- **Сброс онбординга** командой/флагом CLI (`--onboarding`) для демо и
  скриншотов — удобно, вне v1.
- **Локализация** — карточки на русском (язык продукта); i18n-каркас вне
  скоупа.
- **Пропуск на 2-м запуске с середины** (продолжить с шага, где бросил) —
  усложнение состояния; v1 всегда с первого шага.
- **Хоткей перезапуска тура** (например `Shift+F1`) — вместе с хоткеем «?»
  FR-031 в v2.

## Проверка (Verification)

### Юнит-тесты (onboarding_ui)

- Таблица решений `should_show_onboarding` (все комбинации `done` × `defers`).
- `next/prev` — кламп шага; `defer` — инкремент и кламп 3; `complete` — флаг.
- `card_rect` — центр окна, внутри 320×240.
- Хит-тесты кнопок: «Назад» отсутствует на первом шаге; «Далее»/«Готово» —
  только на последнем меняет подпись.

### Юнит-тесты (settings)

- Старый `config.toml` (без новых полей) → `onboarding_done == false`,
  `onboarding_defers == 0`.
- Round-trip дефолтов — байт-в-байт с учётом новых полей; порядок полей
  стабилен.
- `defers = 99` → кламп 3; `defers` в `u8` диапазоне.

### Ручная приёмка

- Удалить `config.toml` → запуск → тур открылся на шаге 1; «Пропустить» →
  закрылся; перезапуск → тур снова; ещё два пропуска → после третьего
  перезапуска тур сам не открывается.
- «?» → «Пройти онбординг» → тур с шага 1 в любой момент; прохождение до
  «Готово» → в `config.toml` появились `onboarding_done = true` и актуальный
  `onboarding_defers`; перезапуск — тишина.
- В открытом туре: «Далее» → прогресс-точки сдвигаются; «Назад» возвращает;
  Esc закрывает с откладыванием; канвас под оверлеем не реагирует (клики
  мимо карточки не создают заметки).
