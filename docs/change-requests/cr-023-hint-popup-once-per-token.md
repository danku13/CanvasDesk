## Решения владельца (Q&A)

**Вопрос Q6 (сессия 2026-10-08): «Когда попап подсказок может открыться повторно после принятого автодополнения (пример: "100 rub")?»**

| Вариант | Суть |
|---|---|
| **До смены токена ← выбрано** | После принятия попап не открывается, пока не изменится токен перед кареткой (ввод/удаление символа) |
| До нового события | Повторное открытие только на новых «структурных» событиях: `$`, пробел, `=`, новая строка |
| Никогда авто | После принятия попап не открывается до конца сессии; повторно — только Ctrl+Space |

**Примечание владельца:** «UR-08 — я не понял варианты, поясни».

**Пояснение выбранного варианта (зафиксировано для владельца):** «до смены токена» означает — принятое автодополнение закрыло свою тему: попап сам не возвращается, сколько бы вы ни двигали каретку по строке. Как только вы **меняете текст перед кареткой** (допечатываете или стираете хотя бы один символ) — попап снова может открыться, если для нового токена есть совпадения. Пример: `100 rub|` → приняли `rub` → попап закрыт; перемещение каретки — тишина; ввод следующего символа/пробела — попап оценивает заново. Ctrl+Space остаётся ручным способом открыть подсказки принудительно. Если по ходу приёмки владелец решит, что suppress должен переживать и один ввод символа (вариант «до нового события») — правка одного условия в `sync`.

---

## Описание (What)

После принятия подсказки (Enter/Tab) попап немедленно открывается снова на том же токене: в строке `100 rub` принятие `rub` возвращает попап с той же подсказкой `rub`. Требуется разовое применение: принятое автодополнение не показывает попап повторно, пока не изменится токен перед кареткой.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| `HintPopup` | Suppress-поле «принято на токене X» | FR-021 (контракт дополняется) |
| `accept_hint` / keystroke-путь | Взведение/снятие suppress | `docs/interface-objects/node.md` |
| Esc | Единая семантика «dismiss до смены текста» | FR-021 |

## Анализ (Root Cause)

Полный разбор — UR-001-08. Suppress-состояния нет: `accept_hint` после вставки немедленно перевызывает `update_hints` (`crates/canvas-app/src/app.rs:5699-5722`, вызов `:5717-5721`); замена токена = backspace-семантика + вставка (`crates/canvas-render/src/edit.rs:921-935`), токен перед кареткой = принятый текст (`rub`) → `hint_items("… 100 rub")` находит единицы по префиксу → `sync` открывает попап при любом непустом списке (`crates/canvas-app/src/hints_ui.rs:284-291`, `self.open = !self.items.is_empty()`). Тот же путь при наборе (`app/input.rs:552-567`); Esc сбрасывает только до следующего символа (`input.rs:485-489`). В `HintPopup` (`hints_ui.rs:262-271`) и `SuggestState` (`suggest.rs:383-419`) поля подавления нет.

**Происхождение:** «тихое» решение агента / пробел контракта FR-021 (контракт описывает Enter/Esc, но не повторное открытие).

## Требуемые изменения (Changes)

1. `crates/canvas-app/src/hints_ui.rs:262-311` — в `HintPopup` поле `accepted: Option<(String /*токен*/, String /*вставка*/)>`; в `sync` (`:284-291`): если `accepted` совпадает с текущим токеном/вставкой — `open = false`; сброс `accepted` при отличии токена (смена токена снимает подавление) и в `reset` (`:275-280`).
2. `crates/canvas-app/src/app.rs:5717-5721` — `accept_hint`: после `update_hints()` взвести `accepted` (или не ресинкать вовсе — реализационная деталь, контракт один: попап закрыт до смены токена).
3. `crates/canvas-app/src/app/input.rs:546-567` — keystroke/paste: подавление переживает следующий ввод символа **на том же токене**, снимается при его изменении; `Esc` (`input.rs:485-489`) — dismiss до смены текста (единая семантика с suppress).
4. Тесты: после accept попап закрыт; ввод символа на том же токене — закрыт; ввод пробела/символа, меняющего токен — попап оценивает заново; Ctrl+Space открывает принудительно.
