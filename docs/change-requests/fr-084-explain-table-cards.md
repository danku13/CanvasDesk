## Описание (What)

Второй раунд фидбэка владельца 2026-10-01 по поверхности «Проверка цепочки
расчёта» (окно FR-048, `crates/canvas-app/src/explain_ui.rs`, после
доработки FR-083) — три проблемы со скриншотов:

1. **Дерево прижато к левому-верхнему углу тела окна.** Когда дерево меньше
   доступной области (короткая цепочка на большом мониторе), справа и снизу
   остаётся пустота — центрирования контента нет.
2. **Один узел-источник раскидывается на множество однотипных карточек.**
   Листья дерева — это строки Numi-листа одного исходного узла: на скриншоте
   6 карточек с одинаковым заголовком «Управляемые» и разными значениями
   (kafka=220, redis=150, mongo=270, s3=30, observability=120, scale) —
   выглядит как дублирование одного и того же узла.
3. **Текстовая кнопка «Изменить» залезает на адресный текст карточки** листа
   (узкая карточка, кнопка в правом нижнем углу поверх строки адреса ребра).

Решения AC-1…AC-3 согласованы владельцем 2026-10-01 (раздел «Требуемые
изменения»; для AC-2 владелец выбрал вариант «А — карточка-таблица» из трёх
предложений А/Б/В; Б «стек-сводка с разворотом» и В «глобальный дедуп»
отклонены). Реализация — доработка поверхности FR-048 без изменения его
статуса и контрактов.

## Анализ (Root Cause — чего нет в коде)

- **Центрирования нет.** Рендер рисует контент от фиксированного
  `BODY_PAD` = 16 (`explain_ui.rs:220`): замыкание `local()`
  (`app/explain.rs:709`–`:714`) = `body + BODY_PAD + x*scale + pan`.
  Пан в непереполняющей оси равен 0 — `pan_clamp` (`explain_ui.rs:553`)
  возвращает `0.0`, когда `content ≤ avail` (контент прижат к
  левому-верхнему углу по решению FR-083). Hit-тесты `node_at`
  (`explain_ui.rs:531`) и `edit_at` (`:619`) повторяют ту же формулу —
  центрирующего слагаемого нет ни в рендере, ни во вводе.
- **Дедупликации сестринских листьев нет.** `layout_tree`
  (`explain_ui.rs:392`) строит карточку `CARD_W×CARD_H` (`:227`/`:229`) на
  каждый видимый узел (`:453`–`:459`) без анализа `node_id` соседей. Строки
  Numi-листа одного источника приходят как отдельные узлы `LineageNode`
  (`canvas-core/src/lineage.rs:151`: `node_id` `:153`, `line` `:155` — один
  узел канваса, разные строки) → N карточек с одинаковым `title` и разными
  значениями. Семантика «ромб разворачивается» (прототип v4, тест
  `diamond_expands_without_dedup`, `lineage.rs:1320`) относится к одному
  узлу под разными родителями — к сестринским строкам одного родителя она
  отношения не имеет, и её изменение не требуется.
- **Кнопка «Изменить» рисуется поверх адресной строки.** `edit_rect`
  (`explain_ui.rs:592`–`:602`) ставит кнопку W=54 в правый нижний угол
  карточки (`card[0]+card[2]−(W+PAD)*scale`, PAD=8) — при scale=1 зона
  кнопки по X ≈ [96…150] px карточки; адресная строка via рисуется на
  `rect[1]+58` (`app/explain.rs:1042`–`:1050`) шириной
  `text_w = rect[2]−16` (`:951`, зона по X ≈ [10…152], по Y ≈ [58…68]) —
  зоны пересекаются. При scale < 1 наезд усиливается: шрифт флорится полом
  8 px (`font(px) = (px*scale).max(8.0)`, `app/explain.rs:949`) и текст
  выходит за отведённую ширину, а геометрия кнопки сжимается медленнее.
- **Построчные дельты what-if уже адресуемы.** Ключ карты дельт —
  `(node_id, line)`: `deltas: BTreeMap<(String, Option<usize>), LineageDelta>`
  (`explain_ui.rs:845`), потребление — `app/explain.rs:966`. Внутри одной
  карточки-таблицы каждая строка адресует свою дельту без изменений модели
  (`LineageDelta` — `lineage.rs:964`).
- **Группировка некуда класть в модели — и не нужно.** `TreeLayout`
  (`explain_ui.rs:372`) — `nodes`/`curves`/`bounds`/`levels`; групповая
  карточка-таблица — элемент слоя лейаута, модель `LineageTree`
  (`canvas-core`) остаётся плоским списком узлов.

## Требуемые изменения (Changes)

### AC-1 — центрирование дерева, когда оно меньше тела (согласовано владельцем 2026-10-01)

- Новая чистая функция **`content_origin(body, bounds, scale, pan) -> [f32; 2]`**
  в `explain_ui`: по каждой оси
  - контент помещается (`bounds*scale ≤ avail`) → origin =
    `BODY_PAD + (avail − content)/2` — дерево центрируется целиком по обеим
    осям;
  - контент переполняет → origin = `BODY_PAD + pan` — как сейчас (кламп
    пана `pan_clamp`, прижатие к левому-верхнему углу, стрелки
    переполнения `overflow_arrows` — без изменений).
- **hit=render — одна геометрия:** `local()` рендера
  (`app/explain.rs:709`) и hit-тесты `node_at`/`edit_at`
  (`explain_ui.rs:531`/`:619`; вызовы `app/input.rs:2414`–`:2438`)
  считаются от единого `content_origin` (инвариант детерминизма FR-048;
  пан-драг и колесо — без изменений, origin надстраивается поверх пана).

### AC-2 — карточка-таблица сестринских листьев одного источника (вариант «А», согласован владельцем 2026-10-01)

- Группировка — на слое лейаута **`explain_ui::layout_tree`** (модель
  `LineageTree` в canvas-core не трогается). Сестринские листья — узлы
  `kind == Leaf` с `line: Some`, у которых **одинаковый `node_id`** и
  **один родитель** (строки Numi-листа одного исходного узла) —
  схлопываются в одну карточку-таблицу:
  - заголовок узла (`title`) — один раз в шапке карточки;
  - ниже — строка на каждый лист: адрес via (квалифицированный адрес
    AC-2.1 FR-048: «строка N»/«output: имя» · параметр) + значение
    («kafka = 220 usd» — значение существующим рендером `Value` с
    единицей);
  - what-if дельта — построчно «было → стало (+Δ)» (`whatif_full_delta`,
    FR-017): ключ дельт `(node_id, line)` (`explain_ui.rs:845`) адресует
    каждую строку таблицы без изменений;
  - шаг строки таблицы ~22 px (константа, например `TABLE_ROW_H = 22.0`);
    высота карточки = шапка + строки × шаг; ширина `CARD_W` неизменна.
- Форму группировки в `TreeLayout` фиксирует реализация (например,
  `TableCard { rect, title, rows: Vec<LaidNode> }` рядом с `nodes`/строки
  остаются `LaidNode` с rect'ами своих строк) — контракт: hit-тесты
  продолжают адресовать отдельный лист по его строке-зоне (`node_at`
  возвращает индекс листа), клики/У2-подсветка/hover работают построчно.
- **Кривые приходят на высоту своей строки:** точка входа кривой в
  карточку-таблицу — по высоте её строки (карточка принимает кривые портом
  со стороны родителя; веер от порта родителя — как сейчас); цвет
  `to_leaf` сохраняется.
- Группируются **только чистые листья под одним родителем**: ромбы (тот же
  узел под разными родителями) и не-листья (`Calc`, терминалы) НЕ
  группируются — семантика «ромб разворачивается» (решение прототипа v4,
  тест `diamond_expands_without_dedup`, `lineage.rs:1320`) не меняется.
- Бейдж «+N глубже» и обычные (не-табличные) карточки — без изменений.

### AC-3 — иконка редактирования в защищённой зоне строки (согласовано владельцем 2026-10-01)

- Текстовая кнопка «Изменить» (`EXPLAIN_EDIT`, `edit_rect`
  `explain_ui.rs:592`–`:602`, рендер `app/explain.rs:1088`–`:1121`)
  заменяется на **иконку-карандаш — глиф ✎** (стандарт UX; решение
  владельца: «что проще для вёрстки — вместо текста кнопку с иконкой
  редактирования»). Глиф рисуется существующим шрифтом (текстовый рендер;
  Icon-кит FR-058 не обязателен).
- Иконка — **в конце строки** (строки таблицы; у обычной карточки листа —
  в конце строки значения): фиксированная зона иконки ~18 px
  (константа `EDIT_ICON_ZONE = 18.0`) у правого края строки; ширина текста
  строки = ширина строки − зона иконки — пересечение текста и кнопки
  физически невозможно (устраняет дефект наезда и при scale < 1).
- Иконка только у редактируемых строк (`Leaf` + `line: Some` + значение
  `Ok` — прежний предикат `explain_ui.rs:630`–`:632`); клик — существующий
  механизм inline-подмены what-if (FR-048 X3: `start_edit`,
  `app/input.rs:2422`–`:2431`); hover-подсветка зоны.
- Старая математика `edit_rect` удаляется вместе с тестом-пином
  `edit_rect_stays_inside_card` (`explain_ui.rs:1827`) **осознанно**;
  `edit_at` переходит на зону иконки строки (обход и предикат
  сохраняются — тест `edit_button_targets_editable_leaves`, `:1736`,
  переезжает на новую геометрию). i18n-ключ `EXPLAIN_EDIT`
  (`i18n.rs:145`; RU `:1509`, EN `:2367`) становится неиспользуемым — из
  таблиц не удалять (инвариант полноты FR-040).

### Не делаем (инварианты и границы)

- Ширина карточки `CARD_W` = 158 постоянна; Ltr/Rtl-зеркало раскладки и
  портовые тесты FR-083 сохраняются (таблица растёт вертикально внутри той
  же ширины).
- Бейдж «+N глубже», крошки, футер, режим защиты — без структурных
  изменений; карточки-таблицы совместимы с защитой (те же карточки, тот же
  reveal/масштаб).
- Формат `.canvas` и модель `LineageTree` (`canvas-core/src/lineage.rs`)
  не затрагиваются; группировка — только слой лейаута `explain_ui`.
- Дедупликация ромбов не вводится (ромб разворачивается — решение
  прототипа v4, тест `diamond_expands_without_dedup`).
- Парити-тесты окна FR-083 (80% вьюпорта) и пан-модель (`pan_clamp`,
  `overflow_arrows`, сбросы) не трогаются — AC-1 надстраивает origin

- Другие модалки и main stage не затрагиваются; hit-тесты и рендер — одна

- `canvas-app` — нативный крейт, в wasm-гейт не входит

## Проверка

- Юнит-тесты `explain_ui`:
  - `content_origin`: непереполняющая ось — центр (пин формулы
    `BODY_PAD + (avail − content)/2`); переполняющая — `BODY_PAD + pan`;
    комбинированный случай (одна ось помещается, другая переполняет);
  - группировка `layout_tree`: 6 сестринских листьев одного `node_id` под
    одним родителем → одна таблица (заголовок один, 6 строк в порядке
    рядов); сестринские листья разных `node_id` — не группируются; узел
    под двумя родителями (ромб) — не группируется; `Calc`/терминалы — не
    группируются;
  - кривые: точка входа кривой в таблицу = высота своей строки (пин Y);
  - зоны иконки: зона у правого края строки, ширина текста строки + зона
    ≤ ширина строки (инвариант «пересечение физически невозможно»);
    `edit_at` по зоне иконки строки; предикат редактируемости прежний;
  - hit=render: `node_at`/`edit_at` от того же `content_origin`, что и
    рендер (тест паритета точки рендера и hit-теста);
  - прежние инварианты: `CARD_W`, Ltr/Rtl-зеркало, `pan_clamp`,
    `overflow_arrows` — тесты FR-083 зелёные (правки — только слагаемое
    origin; отражено в Changelog).
- Гейты: `cargo test --workspace`, `cargo clippy --workspace -- -D warnings`,
  `cargo fmt --check`, `scripts/token_lint.sh` (новых цветов не
  планируется — глиф существующими слотами палитры). WASM-проверка не
  применима: `canvas-app` — нативный крейт, в `scripts/wasm_gate.sh` не
  входит; логика выносится в чистые функции `explain_ui` (TDD).
- Ручная приёмка владельца: короткая цепочка (1–2 уровня) на большом
  мониторе — дерево по центру тела окна по обеим осям; модель с
  Numi-источником «Управляемые» (kafka/redis/mongo/s3/observability/scale)
  — одна карточка-таблица: заголовок один раз, шесть строк со значениями;
  what-if по строке — дельта «было → стало (+Δ)» построчно; иконка ✎ не
  пересекает текст, клик открывает inline-подмену; режим защиты — таблицы
  рисуются, подмена работает.
