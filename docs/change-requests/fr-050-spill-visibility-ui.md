## Описание (What)

Постановка из перекрёстной проверки: реализовать FR-029 «в полной мере, чтобы
проливание значений и по связям было максимально наглядным». MCP-контур v1
выполнен (FR-029: `toParam`/`fromOutput`, секция `outputs`, `edges_list`,
`flow_recalc` v2, `graph_apply`); UI-контур, семантика приоритетов значений и
диагностика состояний не специфицированы — 13 расхождений с FR-014/017/025/
032/033/044/045/049 (журнал перекрёстной проверки, 2026-09-22). Владелец
ответил на уточняющие вопросы Q1–Q13; настоящий FR фиксирует принятые решения
(Р-1…Р-4), новое требование «авто-numi-строка приёмника» и оставшиеся вопросы
(Н1–Н10).

Целевые сцены наглядности (критерии «видно без чтения кода»):

1. **Подключил связь — сразу видно.** Value-ребро с проливанием подключено к
   ноде без ожидающего порта → в теле приёмника немедленно появляется новая
   numi-строка с пролитым значением (Р-4).
2. **Видно, ЧЬЁ значение.** Пролитое по связи значение визуально отличается от
   локального/ручного (Р-2 — шрифтовое различение).
3. **Видно, КТО победил.** Приоритет источников значения: what-if >
   проливание > локальный параметр (Р-1); у строки видно, кем установлено
   значение (пролито / what-if / вручную).
4. **Видно, ЧТО сломано и КАК починить.** Значение не подставлено →
   подсветка + тултип «проблема + путь решения» (Р-3).
5. **Видно распространение.** Изменил upstream → каскад обновлений downstream
   наблюдаем на канвасе (предложения — Н9).

## Решения (зафиксированы владельцем, сессия 2026-09-22)

- **Р-1. Приоритет источников значения** (ответ Q2: «what-if перекрывает
  всё»). Порядок силы: **what-if override > проливание по связи (`toParam`) >
  локальное значение параметра**. В `propagate` значение параметра
  собирается каскадом: локальный дефолт → проливание перекрывает → what-if
  подмена перекрывает всё (механизм построчного override FR-017 — поверх,
  runtime-only, инвариант 2 FR-017 сохраняется). Что не изменилось: рёбра без
  `toParam` — позиционные слоты `$1..$N` как в FR-014; «последний побеждает»
  для дубль-рёбер — см. Н4 (блокировка при создании).
- **Р-2. Визуальное различение пролитых значений** (ответ Q9: «нужно, чтобы
  различалось; можно подумать над отличием в рамках шрифта — особый литерал,
  наклонный шрифт или др.»). Значение, пришедшее по связи, отличается от
  локального. Направление — шрифтовое решение: наклонное начертание
  (italic) моно-шрифта значений (Noto Sans Mono Italic / наклонный синтез) и
  /или особый литерал-маркер перед значением; финальный вариант — на макете
  (паттерн проверки на прототипе FR-044 §Решения). Поверхности: строка
  параметра шаблонной ноды, авто-строка приёмника (Р-4), пилюли веера stage,
  группа «Переменные» панели «Как считается». Тултип строки всегда называет
  источник: «пролито: Трафик.peak_rps = 1389 rps».
- **Р-3. Диагностика «не подставлено» — подсветка + тултип** (ответ Q11:
  «да, надо подсвечивать, так же добавить тултип с пояснением по наведению,
  тултип должен говорить в чём проблема и как её можно решить (например,
  "не подставлено значение, подключите ноду с …")»). Unmapped-состояние
  (FR-045 R-3: связь есть, значения нет) подсвечивается (янтарный акцент
  analysis-слоя, пунктир порта/ребра) + тултип при наведении. **Контракт
  тултипа: ровно два пункта — (а) в чём проблема, (б) как её решить.**
  Шаблоны (RU/EN, i18n FR-040): «Значение не подставлено: связь есть, но
  источник не отдал значение (строка-источник удалена / стала прозой /
  колонка отсутствует). Подключите ноду с актуальным значением или исправьте
  строку-источник»; «Параметр rps не получает значение: выход peak_rps
  отсутствует у ноды "Трафик". Перепривяжите связь на существующий выход
  (клик по ребру → перепривязка)». Закрывает расхождение «тихая деградация
  FR-025 (молчаливый `Some(None)`) vs видимый unmapped-статус FR-045» в
  сторону видимого статуса с объяснением; молчаливая деградация остаётся
  только в невизуализируемом ядре потока.
- **Р-4. Авто-numi-строка приёмника** (новое требование владельца,
  2026-09-22). При подключении value-ребра с проливанием данных к ноде без
  ожидающего порта в принимающей ноде автоматически выводится новая numi-строка
  — чтобы сразу было видно, что параметр подтянулся. Задача — наглядный UX.
  Детали семантики и варианты — §Требуемые изменения п.1; вопрос
  «производная vs материализованная» — Н10.

## Требуемые изменения (Changes)

### 1. Авто-строка приёмника (Р-4)

Определение **«ожидающего порта»** — слот приёмника, готовый принять значение:
для шаблонной ноды — параметр, в который уже адресовано ребро (`toParam`-цель,
строка параметра существует); для текстовой ноды — позиционный слот `$1..$N`,
который читается формулой ноды.

Случаи срабатывания (матрица):

| Ребро | Приёмник | Ожидающий порт | Поведение |
|---|---|---|---|
| `toParam` → существующий параметр | шаблонная | да | Существующая строка параметра помечается маркером проливания (Р-2), значение перекрывает локальное (Р-1). Новая строка НЕ создаётся |
| `toParam` → параметра нет | шаблонная | нет | Ошибка `E-PORT-UNKNOWN` (MCP-валидация имён — без изменений FR-029/FR-032); UI-drag не может создать такую связь (§2) |
| value-ребро без `toParam` | текстовая | нет (формула не читает `$N`) | **Авто-строка**: «<Объект>.<Поле> = <значение> <unit>» — короткое имя поля, полный путь в тултипе (Н7), начертание Р-2 |
| value-ребро без `toParam` | шаблонная | нет | **Авто-строка**: «вход $N (<Поле>) = <значение>» + диагностика W-UNUSED-SLOT (FR-032) с тултипом Р-3: «значение пришло, но формула шаблона его не читает — подключите к параметру через toParam» |

Свойства авто-строки:

- **Позиция:** верх тела ноды, зона «Переменные · входящие значения»
  (FR-045 R-4 / PRD-0004 зона C), после последней строки входов.
- **Природа (рекомендация, Н10):** производная (display-level) — вычисляется
  в `recompute_flow` из графа связей, НЕ сериализуется в `.canvas`
  (round-trip байт-в-байт), не попадает в undo как отдельная сущность;
  повторный пересчёт даёт идентичную строку. Ручное редактирование =
  конвертация в локальную строку-параметр (материализация) с семантикой Н1.
- **Жизненный цикл:** появилась при создании ребра; исчезает при удалении
  ребра (если не сконвертирована в ручную); при потере значения источником —
  переходит в unmapped-вид Р-3 (пунктир, тултип «не подставлено»).
- **Значение и единицы:** значение берётся из слота потока (`inbound` с
  `fromLine`/`fromOutput`/узловое); единицы — по правилам Н5.
- **Undo:** один шаг на создание связи (существующий снапшот канваса;
  производная строка не участвует).

### 2. Приёмные порты параметров — UI-механизм `toParam`-связей (Н2)

Сегодня `toParam`-рёбра создаёт только MCP (`edge_create` v2 / `graph_apply`);
UI-drag адресует ноду целиком (расхождение №2 журнала проверки). Требуется
(предварительно «да», подтверждение Н2):

- У шаблонной ноды каждый параметр листа получает **входной якорь** на левом
  краю (вертикаль — уровень строки параметра, зеркально построчным выходам
  FR-025; hit-тест — допуск CR-003).
- Drag от выхода истока (построчный порт FR-025 / `outputs`-порт / порт
  data-ноды FR-045) на якорь параметра = value-ребро с `toParam`.
- Во время drag допустимые параметры подсвечиваются (unit-совместимые —
  ярче, по правилам Н5/E-UNIT); drop мимо якоря — меню выбора параметра
  приёмника либо отмена.
- Для истока-текстовой ноды без `outputs`: drag от построчного порта уже
  несёт `fromLine`; drag от ноды целиком при >1 формульной строки —
  W-AMBIGUOUS-SRC (FR-032), UI предлагает выбор строки.

### 3. Блокировка дубль-входов при создании (Н4)

Сегодня два value-ребра в один `toParam` создаются молча («последний побеждает»
+ warning в `flow_recalc`; строгий `E-DOUBLE-INPUT` — только в
`graph_validate`, постфактум; расхождение №5 журнала). Требуется
(предварительно «да», подтверждение Н4):

- **UI:** drop на занятый параметр → диалог «Заменить источник? Параметр rps
  уже питается от LB.out_gateway» — [Заменить] (старая связь удаляется, новая
  создаётся, один undo-шаг) / [Отмена].
- **MCP:** `edge_create`/`graph_apply[edge_create]` с `toParam`, уже занятым
  другим value-ребром → немедленная ошибка `E-DOUBLE-INPUT` (fail-fast,
  не ждать `graph_validate`); замена — явная пара delete+create в батче.
- Семантика «последний побеждает» остаётся только для легаси-файлов,
  загруженных с дублями ( + warning, как сегодня).

### 4. Приоритеты и маркер источника значения (Р-1, Р-2)

- `flow.rs`: порядок сборки `env.params` — локальные параметры → перекрытие
  `toParam`-проливанием → перекрытие what-if подменой (param-карта
  propagator FR-017). Инвариант: снятие what-if возвращает проливание,
  удаление ребра возвращает локальное значение.
- Отображение: у каждой строки значения — маркер источника: пролито (Р-2
  начертание + тултип «пролито: <Объект>.<Поле> = <значение>», при наличии
  локального — «(локально было: 500 rps)»), what-if (маркер сценария FR-017),
  ручное (обычное начертание).

### 5. Единицы и безразмерные значения (Н5)

- `OutputSpec.unit` и unit параметров остаются опциональными (расхождение №6
  журнала: значения без размерности — абстрактные цифры — легитимны).
- Безразмерное пролитое значение в параметр с единицей — трактуется в
  единицах приёмника (Numi-семантика: «500» в параметр rps = 500 rps);
  тултип показывает приведение.
- Значение с единицей в безразмерный параметр — приходит с единицей и так
  отображается.
- `E-UNIT` срабатывает только при несовместимых размерностях (ms против rps;
  конвертируемые масштабы ms/s — совместимы, как в FR-032).

### 6. Нотация «Объект.Поле» — раскладка длины (Н7, ответ на уточнение Q8)

| Поверхность | Форма | Комментарий |
|---|---|---|
| Тело ноды, канвас (LOD-2, вне stage) | Короткая: «Поле» | Полный путь — тултип (FR-045 R-5) |
| Ребро вне stage: подпись у истока | Значение + единица: «1389 rps» | Реализовано (main stage 3abd0a4) |
| Ребро вне stage: подпись у приёмника | Короткий адрес: «→ rps» | Полный путь — тултип |
| Main stage: пилюли веера | Полный путь + значение: «Трафик.peak_rps · 1389 rps» | FR-044 Р-3 |
| Main stage: панель «Как считается», формулы | Полный путь с подстановкой: «выручка := Заявки.Кол-во · Заявки.Средний_чек» | Display-подстановка (Н8) |
| Коллизия имён объектов | «Имя (2).Поле» | FR-044 Q4 fallback |

### 7. Каскадная наглядность (Н9 — предложения, отбор владельцем)

См. §Открытые вопросы Н9: пульс рёбер downstream при изменении upstream,

## Инварианты тестируемости

1. **Приоритет (Р-1):** параметр с локальным 500 rps, `toParam` приносит
   1389, what-if override 2000 → пересчёт 2000; снятие what-if → 1389;
   удаление ребра → 500.
2. **Авто-строка (Р-4):** подключение value-ребра к ноде без ожидающего порта
   → в теле приёмника ровно одна новая строка с qualified-именем и значением;
   повторный `recompute_flow` — строка идентична; удаление ребра — строка
   исчезла; round-trip `.canvas` байт-в-байт (строка не сериализуется, Н10).
3. **Дубль-входы (Н4):** после успешного создания в `canvas.edges` нет двух
   value-рёбер в один `toParam`; вторая попытка — диалог (UI) / ошибка
   `E-DOUBLE-INPUT` (MCP).
4. **Тултип Р-3:** каждый unmapped-слот имеет тултип с (а) причиной и
   (б) путём решения; полнота RU/EN таблиц — инвариант FR-040.
5. **Различение (Р-2):** строка с пролитым значением визуально отличается от
   локальной (скриншот-эталон пары строк); тултип называет источник.
