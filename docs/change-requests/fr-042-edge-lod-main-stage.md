## Описание (What)

PRD-0002 ставит двухуровневую LOD-модель отображения связей: (1) **LOD-0** — все
рёбра одной пары нод (пучок) рисуются одной агрегированной линией, толщина
которой кодирует число подключенных входов, с бейджем кратности `×N`; (2)
**LOD-1 «main stage»** — модальный режим детализации по клику на агрегированную
линию: в центрированной композиции (≤ 70% вьюпорта) показываются обе ноды
соединения и все рёбра пучка в детальном виде (стороны портов, лейблы,
`fromLine`/`fromOutput`/`toParam`, kind value/control, текущие значения),
остальной канвас затемняется; выход — `Esc` или клик по затемнённому фону.

Настоящий FR — реализационная постановка PRD-0002 (этап E0): глубокий анализ
того, куда main stage встаёт в рендер- и вводном конвейерах приложения, фиксация
решений по открытым вопросам PRD (§11-Q1…Q6) и разбор изменений по крейтам.
Постановку выполнял агент по запросу владельца; реализация — отдельными
коммитами после подтверждения владельцем (этапы E1–E5 PRD).

## Глубокий анализ (Root Cause — чего нет в коде)

### 1. Рендер-конвейер рёбер сегодня

Полный трассировка от модели до кадра (актуальные строки main после FR-038/039/040):

- Модель: плоский список `Canvas.edges: Vec<Edge>` (`crates/canvas-core/src/model.rs:682`);
  несколько рёбер между одной парой нод **разрешены и никак не агрегируются**
  (прецедент — тест «Дубль пары a↔h», `crates/canvas-core/src/focus.rs:130`).
  Ребро несёт: `from_node`/`to_node`, стороны `from_side`/`to_side`, `label`,
  `color`, `style`, `thickness` (`model.rs:416`), kind через `flow_kind()`
  (`model.rs:539` → `FlowKind::Value`/`Control`), построчный/именованный адрес
  значения `from_line`/`from_output`/`to_param` (FR-025/FR-029, `model.rs:447-474`).
- Толщина — **дискретная ручная стилистика**: `EdgeThickness::dot()` возвращает
  1.8/2.5/3.5 world-px (`model.rs:89`) — вес соединения она не кодирует.
- Кадр: `Renderer` строит инстансы рёбер вызовом `build_edge_instances`
  (`crates/canvas-render/src/renderer.rs:908` → `crates/canvas-render/src/cards.rs:891`),
  который идёт по `canvas.edges` линейно и на каждое ребро тесселирует
  полилинию `edge_polyline` (`crates/canvas-core/src/edgegeom.rs:340`,
  `EDGE_RENDER_SEGMENTS = 48`, `cards.rs:625`) в цепочку кружков-«бусин»
  `polyline_dots` (`cards.rs:835`). Диаметр бусины — `EDGE_DOT = 2.5`
  (`cards.rs:627`), у выделенного ребра — `EDGE_DOT_SELECTED = 3.5`
  (`cards.rs:629`, приплюсовывается в `cards.rs:922`). Диаметр — параметр
  инстанса, SDF-шейдер `cards.wgsl` его не ограничивает → **непрерывная
  толщина не требует шейдерных изменений**.
- Рёбра рисуются **до** карточек (диапазон инстансов до zplan-сегментов,
  `renderer.rs:908-917`; комментарий «ПОД карточками»); цвет value-рёбер —
  `FLOW_EDGE_COLOR` (`cards.rs:646`), затемнение фокус-режима — `FocusView`
  (`cards.rs:683`) с `dim_factor()` (`cards.rs:717`) и полом
  `FOCUS_DIM_FLOOR = 0.35` (`cards.rs:669`).
- Лейблы рёбер — screen-space текст с кэшем шейпинга: `EdgeLabel`
  (`crates/canvas-render/src/text.rs:1030`, `shape_edge_label` — `text.rs:1290`),
  позиция — `edge_midpoint` (`edgegeom.rs:377`).
- Хит-тест: `edge_at(canvas, point, avoid)` возвращает индекс ближайшего ребра
  с допуском `EDGE_HIT_TOLERANCE = 6.0` world-px (`edgegeom.rs:668/10`).
  Перепривязка концов — `retarget_edge` (`edgegeom.rs:277`).
- Миникарта строит снапшот с рёбрами «центр → центр» без дедупа:
  `MiniSnapshot.edges: Vec<([f32;2],[f32;2])>` (`crates/canvas-render/src/minimap.rs:116-135`).

**Вывод:** группировки нет нигде — ни в модели, ни в рендере; каждая линия
пучка рисуется и хит-тестится независимо. Точка входа «толщина по весу потока»
(`docs/interface-objects/edge.md` §2) остаётся нереализованной.

### 2. Вводной конвейер: куда встаёт main stage

Каскад `on_left_button` Pressed (`crates/canvas-app/src/app.rs:7755`), порядок
фронтов: windows-активация → guard `space_pressed` → **онбординг** (модален,
`app.rs:7787+`) → **панель поиска** → **wheel-меню** → **меню помощи** →
**док-просмотрщик** → **настройки** → **панель хоткеев** → **диалог T21** →
**hover-палитра** → … → детектор двойного клика (`double_click.register`,
`app.rs:8642`: по пустому месту — `edge_at` → лейбл связи
`begin_editing_edge` (`app.rs:1802`) / новая заметка) → хит-тест нод → drag →
промах по нодам: `edge_at(...).map(Selection::Edge)` (`app.rs:8783`) → рамка
выделения (CR-001). Перепривязка концов (CR-002) — ветка drag с `retarget_edge`
(`app.rs:8889-8900`); на время drag ребро скрыто (`SceneView.hidden_edge`,
`crates/canvas-render/src/renderer.rs:177+`, резиновая линия заменяет его).

ESC-цепочка `on_key` (`app.rs:7273`, цепочка с `app.rs:7506`), порядок выхода:
меню помощи (двухэтапный, FR-027) → док-просмотрщик → раскрытие hover-палитры →
flyout полосы палитры → развёрнутый док палитры → контекстное меню → настройки
(сначала dropdown — FR-026/FR-021) → панель хоткеев → what-if → wheel-меню.

Инвентарь модальностей и главный вывод: **все 7 полноэкранных модальностей**
(онбординг, поиск, wheel, docs, настройки, хоткеи, диалог) глушат канвас
целиком и рисуют только screen-space контент (`FILL_DIM [0,0,0,0.35]` у wheel —
`app.rs:4952`; `[0.02,0.02,0.04,0.45]` — `app.rs:5523`, `app.rs:6891`;
`[0.02,0.02,0.04,0.55]` у онбординга — `app.rs:5691`). **Ни одна не показывает
мировые объекты внутри своей рамки.** Main stage — **новый класс модальности**:
«мировая сцена внутри screen-space rect» — канвас за рамкой виден (затемнён),
а внутри рамки рендерится мировое содержимое (2 ноды + рёбра пучка).

### 3. Ключевое техническое решение: второй проход с виртуальной камерой

Компоновка «мировой контент внутри screen-space рамки» не реализуется
существующими средствами:

- **Scissor-пассов в `canvas-render` нет** (grep `scissor` по
  `crates/canvas-render/src/renderer.rs` пуст); world-проход один, с одной
  камерой — сдвинуть камеру на «остров» нельзя, не потеряв затемнённый фон
  модели.
- Все screen-space примитивы (`FrameOverlay`, `renderer.rs:134`; текст) — квады
  и глифы, ими карточки с их содержимым не нарисуешь.

Решение (минимальное по изменениям, консистентное с архитектурой):

1. **Срез сцены** — при открытии main stage строится временный
   `Canvas`-срез: 2 ноды пучка + рёбра пучка (клон — десятки байт, O(N) рёбер
   пучка). Все существующие билдеры (`build_edge_instances`, билдеры карточек)
   принимают `&Canvas` — работают над срезом без изменений.
2. **Виртуальная камера stage**: после затемняющего квада рендерится второй
   батч инстансов (рёбра среза → карточки среза) с **вторым uniform камеры**,
   чей world→screen трансформ отображает локальную раскладку stage в
   `main_stage_rect`. Изменение точечно: два бинда камеры и два диапазона
   отрисовки в кадре (прецедент сегментации диапазонов — `plan_tail_ranges`,
   `crates/canvas-render/src/zorder.rs:172`). Контент за пределами rect
   отсекается геометрией раскладки (всё содержимое умещается в rect
   инвариантно) + scissor-rect при наличии — вопрос фиксируется на E3
   (см. §Проверка, инвариант 7).
3. **Раскладка stage** — чистые функции в `canvas-core` (тестируемые, wasm):
   `main_stage_rect(viewport)` и веер параллельных рёбер (ниже).

Альтернативы отклонены: (а) пре-проекция инстансов в screen-space на CPU —
дублирует геометрию карточек и ломает их шейдинг; (б) рендер stage в
отдельный render-target с наложением — новый пайплайн без выигрыша для PoC.

### 4. Раскладка параллельных рёбер внутри stage (веер)

Все рёбра пучка между A и B при одинаковых сторонах портов совпали бы в одну
линию (общие якоря). Требуется детерминированный веер: рёбра сортируются
стабильно (по `edge.id` — прецедент `sort_dedup`, `focus.rs:100`), каждое
получает перпендикулярное смещение к оси A→B с равным шагом (шаг ≥ толщины
линии + зазор), фан-центр — на середине оси. Чистая функция
`stage_edge_fan(count, spacing) -> Vec<f32>` (смещения в stage-координатах);
стороны портов и подписи `fromLine`/`toParam` каждого ребра сохраняются — это
и есть содержание main stage.

### 5. Чего нет — сводка

1. Нет `EdgeBundleIndex` (группировки по паре концов) и кэша с инвалидацией.
2. Нет непрерывной толщины (только дискретные 1.8/2.5/3.5).
3. Нет screen-space бейджа кратности у линии (лейблы есть — но это текст
   пользователя, не вычисляемый `×N`).
4. Нет модальности «мировой контент в рамке» (см. §2) и второго бинда камеры.
5. Нет состояния `BundleHover`/`MainStage` в `App` (`app.rs:896`).
6. Нет настройки-выключателя агрегации (раздел «Связи и порты» модалки
   FR-039, `crates/canvas-app/src/settings_ui.rs:199-207`, сейчас 4 строки).

## Решения по открытым вопросам PRD-0002 (§11)

| # | Вопрос | Решение | Обоснование |
|---|---|---|---|
| Q1 | Вес: только рёбра или коннекты с `fromLine`/`toParam` | **PoC: вес = число рёбер пучка** (1 ребро = 1 input-коннект). Учёт строк/спиллов — v2 (F-14) | Предсказуемость (бейдж = число линий, которые видел пользователь), дешёвая O(edges) группировка, не зависит от пересчёта потока (`recompute_flow`) |
| Q2 | Двунаправленные пары (A→B и B→A) | **Два отдельных пучка** — агрегация по упорядоченной паре `(from_node, to_node)` | Сохраняет семантику направления и независимость толщин; совпадает с формулировкой «пучок» в PRD §4 |
| Q3 | Порог агрегации | **N ≥ 2, без настраиваемого порога в PoC**; аварийный выключатель — настройка F-13 | Порог < 2 вырожден; настраиваемый порог — YAGNI до юзабилити-прогонов (PRD §6, E5) |
| Q4 | Blur фона | **Аппроксимация затемнением** (альфа-квад, палитра `[0.02,0.02,0.04,α]`, α 0.55–0.65 по темам — консистентно с оверлеями `app.rs:5691`) | Настоящего blur в кодовой базе нет ни в одном оверлее; wgpu-пасс (даунсэмпл + гаусс) — отдельный ADR, не блокирует PoC |
| Q5 | MCP `bundles_list` | **Вне скоупа**; обсудить как зеркало LOD-0 в CR-013 | Агрегация — рендер-состояние; контракт FR-032/FR-033 не меняется |
| Q6 | Сочетание с полноэкранными оверлеями | **Взаимная исключительность**: открытие любого оверлея (поиск, wheel, docs, настройки, хоткеи, диалог, онбординг, меню помощи) закрывает main stage; main stage открывается только из Normal/BundleHover | Модальность не вкладывается; спасает ESC-каскад от двусмысленности (первая ветка `Esc` при открытом stage — закрытие stage) |

Дополнительно фиксируется (из анализа рисков PRD §12): **двойной клик по
агрегированной линии = main stage** (лейбл-редактор у пучка неопределён —
лейблы индивидуальных рёбер видны в stage); **ПКМ по агрегированной линии =
main stage** (единый вход; палитра применяется к конкретному ребру изнутри
stage — AC-3.2 PRD); **правка модели при открытом stage** невозможна вводом, а
фоновые мутации (MCP `graph_apply`, FR-033) валидируют срез — при потере
валидности stage закрывается автоматически (инвариант 9).

## Требуемые изменения (Changes)

### 1. `canvas-core`: модуль `bundles.rs` — чистая геометрия и индекс

- `pub struct EdgeBundleIndex`: построение из `&Canvas` за O(edges) —
  `HashMap<(from_node, to_node) (упорядоченная пара String), EdgeBundle>`;
  `EdgeBundle { edges: Vec<usize> (индексы, стабильный порядок по `edge.id`),
  weight: usize = edges.len() }`.
  - Доступ: `bundle_of_edge(edge_index) -> Option<&EdgeBundle>` и
    `bundle_key_of_edge(edge_index) -> Option<(&str, &str)>` — маппинг
    результата `edge_at` в «пучок или одиночка».
  - Выбор **доминирующего ребра** (цвет/геометрия агрегированной линии):
    детерминированно — первый по стабильному порядку среди рёбер с наивысшим
    приоритетом класса: явный `color` пользователя → value
    (`flow_kind() == FlowKind::Value`) → прочие (базовый `EDGE_COLOR`).
    Чистая функция `dominant_edge(canvas, bundle) -> usize`.
- `pub fn main_stage_rect(viewport: [f32; 2]) -> Rect` — центрированный rect:
  `w = min(0.7·vw, STAGE_MAX_W)`, `h = min(0.7·vh, STAGE_MAX_H)` с клампом
  внутрь вьюпорта с полем `STAGE_MARGIN` (инвариант: целиком внутри при
  viewport 320×240; обе стороны ≤ 70% соответствующей стороны — satisfies
  «не более 70% экрана» консервативно: площадь ≤ 49% площади окна).
  Константы `MAIN_STAGE_MAX_FRACTION = 0.7`, `STAGE_MAX_W/H`, `STAGE_MARGIN` —
  в `bundles.rs`. Прецедент чистой геометрии с клампом — `modal_layout`
  (FR-039, `settings_ui.rs`).
- `pub fn stage_edge_fan(count: usize, spacing: f32) -> Vec<f32>` —
  симметричные смещения `[−(k−1)/2·s, …, +(k−1)/2·s]` (k = count), детерминизм.
- `pub fn bundle_color(canvas, bundle) -> [f32;4]` — цвет агрегированной
  линии: цвет доминирующего ребра → `FLOW_EDGE_COLOR` (`cards.rs:646`) для
  value → базовый `EDGE_COLOR` (приёмка AC-1.3 PRD).
- Формула толщины: `pub fn bundle_thickness(weight: usize) -> f32 =
  clamp(1.8 + (weight − 1) as f32 · 0.9, 1.8, 8.0)` — монотонная, непрерывная;
  константы рядом с `EDGE_DOT` (значения уточняются на демо E2, PRD AC-1.2).
- Все функции — чистые, без wgpu/IO; юнит-тесты в крейте (см. §Проверка).
  ADR-0008/0011: модуль в `canvas-core`, wasm-гейт собирает и тестирует.

  (`scene.rs:325`) — он и так вызывается после любой мутации топологии
  (документировано в доке метода: «после ЛЮБОЙ мутации формул или топологии»),
  стоимость O(edges) «поверх» пересчёта потока, вне кадра. Отдельные хуки на
  `add_edge`/`remove_edge` (`model.rs:711/717`) не нужны — все мутации идут
  через вызывающий код, завершающийся `recompute_flow`.
- Валидность среза main stage: приложение проверяет на кадре, что все рёбра
  среза живы (см. §4, инвариант 9); кэш сам по себе всегда перестроен
  синхронно с моделью.

### 3. `canvas-render`: LOD-0 и main stage

- **LOD-0**: `SceneView` (`renderer.rs:177`) получает
  `pub bundles: Option<&'a EdgeBundleIndex>` (`None` — агрегация выключена,
  F-13: поведение байт-в-байт прежнее, регресс-щит). В `build_edge_instances`
  (`cards.rs:891`): если пучок N ≥ 2 — рисуется **одна** агрегированная линия
  (полилиния доминирующего ребра через `edge_polyline`), диаметр бусин
  `bundle_thickness(N)`; одиночные рёбра (N = 1) — прежний путь без изменений.
  Выделение ребра пучка (сделанное в stage) подсвечивает агрегированную линию
  бампом `+1.0` (по образцу `EDGE_DOT_SELECTED − EDGE_DOT`, `cards.rs:922`).
- **Hover пучка (BundleHover)**: линия пучка под курсором — бамп диаметра
  `+1.0` и курсор-подсказка; вычисляется приложением на кадр (паттерн
  `hovered`), в кэш не пишется.
- **Бейдж `×N`**: screen-space текст у `edge_midpoint` доминирующего ребра
  (`edgegeom.rs:377`) со смещением перпендикулярно линии; рисуется группой
  текста (`text.rs`, кэш шейпинга по образцу `EdgeLabel`/`shape_edge_label`,
  `text.rs:1030/1290`, синтетический id `"bundle:{from}→{to}"`); при N = 1 не
  рисуется. Контраст — CR-007 (≥ 3:1, обе темы).
- **Main stage (второй проход)**: в кадре после world-прохода и затемняющего
  квада — (1) полноэкранный затемняющий квад `[0.02,0.02,0.04, α]`, α 0.6
  (тёмная) / 0.5 (светлая) — подбор на демо E3 в коридоре 0.55–0.65 (PRD
  §7.5); (2) подложка и рамка stage в screen-space (`FrameOverlay`-путь,
  стиль модалок FR-039: `palette.menu_fill`, радиус, рамка); (3) **второй
  батч мировых инстансов среза** (рёбра среза с веером → карточки обеих нод
  с их превью) под **вторым биндом камеры** (виртуальная камера, viewport =
  `main_stage_rect`, локальная раскладка: нода-исток слева, приёмник справа);
  (4) бейдж `×N` и подпись-подсказка «Esc — закрыть» (i18n-ключ, FR-040).
  Геометрия каркаса — переиспользование `main_stage_rect`; z-порядок мира не
  меняется (рёбра до карточек — `renderer.rs:908-917`).
- **Миникарта**: дедуп рёбер снапшота по паре концов (`minimap.rs:116-135`) —
  пучок → одна линия (чистая функция над `Vec<([f32;2],[f32;2])>`).

### 4. `canvas-app`: машина состояний и ввод

- `App` (`app.rs:896`): поле `pub main_stage: Option<MainStageState>`;
  `MainStageState { key: (String, String), edges: Vec<usize>, slice: Canvas }`
  — строится при открытии (срез §3). Состояния Normal/BundleHover/MainStage
  из PRD §7.1: BundleHover — вычисляемое (hover на кадре), MainStage —
  `main_stage.is_some()`.
- **Открытие** (клик/ПКМ/двойной клик по агрегированной линии):
  в ветке промаха по нодам (`app.rs:8783`) результат `edge_at` маппится через
  индекс: одиночное ребро → `Selection::Edge` (как сегодня); пучок → открытие
  main stage. Двойной клик (`app.rs:8642`): пучок → main stage (НЕ
  `begin_editing_edge`); одиночное ребро → лейбл (как сегодня). ПКМ
  (`on_right_button`, `app.rs:8950`): пучок → main stage; одиночное — палитра
  (`palette.rs:279/544`). Hover-ветка `on_cursor_moved` (`app.rs:9169`) —
  вычисление BundleHover.
- **Ввод внутри stage** (ветка в начале Pressed-каскада — после онбординга,
  до поиска; при открытом stage прочие оверлеи невозможны — решение Q6):
  клик вне `main_stage_rect` → закрыть; клик внутри → хит-тест рёбер среза в
  stage-координатах (обратный трансформ виртуальной камеры + `edge_at` среза с
  допуском `max(EDGE_HIT_TOLERANCE, d/2 + 2.0)`) → `Selection::Edge` живой
  модели (индексы среза хранят оригинальные `edge.id`); колесо/пан/зум/drag —
  глушатся; правка (Del, `begin_editing`) — отключена (PoC — просмотр и
  выделение, non-goals PRD).
- **Выход**: `Esc` — ветка в **начале** ESC-цепочки (`app.rs:7506`, до меню
  помощи) — при открытом stage прочие оверлеи закрыты (Q6), ветка однозначна;
  клик по фону — закрыть. После закрытия выделение ребра сохраняется
  (AC-3.2). Повторный клик по той же линии — снова открывает.
- **Взаимоисключительность (Q6)**: все фронты открытия оверлеев (поиск
  `search.open()`, wheel, docs, `settings_open`, hotkeys, диалог, онбординг)
  перед открытием выполняют `self.main_stage = None`.
- **T23-сочетаемость**: `FocusView` (`cards.rs:683`) получает политику:
  агрегированная линия подсвечена, если **хотя бы одно** ребро пучка в
  `focus.edges` (OR-семантика), иначе затемняется целиком `dim_factor()`.
- **Настройка F-13**: `SettingsRow::EdgeAggregation` (Toggle, по умолчанию
  вкл) в табе «Связи и порты» (`settings_ui.rs:199-207`, 4 → 5 строк;
  `SETTINGS_ROWS` 18 → 19, `settings_ui.rs:127`); поле в
  `Settings` (`canvas-core/src/settings.rs`) — **единственное** расширение
  конфига, обратная совместимость чтения (serde default — как в FR-040);
  гейт агрегации: `settings_ui`-тоггл → `SceneView.bundles: Option<…>`
  (`None` при выкл) + гейт открытия stage. Тексты строки — ключи `i18n`
  (`crates/canvas-app/src/i18n.rs:1062`, RU/EN).
- Undo/redo (FR-006): агрегация и main stage — рендер-состояние; `push_undo`/
  `mark_dirty` не вызываются (`scene.rs:881/849`).

| Мутация | Точка | Эффект |
|---|---|---|
| add/remove ребра, rebind (CR-002) | `recompute_flow` хвост | Перестройка `EdgeBundleIndex`; вес пучка живо обновляет бейдж/толщину (AC-3.3) |
| drag rebind в процессе | `hidden_edge` (CR-002) | Открытие stage во время drag запрещено; открытый stage при старте drag rebind — закрыть |

## Архитектура тестируемости (инварианты FR-042)

1. **Группировка**: пучок = точная упорядоченная пара `(from, to)`; A→B и
   B→A — разные пучки (Q2); висячие рёбра (нет одной из нод) не ломают
   построение и не агрегируются с ничем; `weight = |edges|`.
2. **Детерминизм**: порядок рёбер пучка и выбор доминирующего — стабильны
   (по `edge.id`), повторное построение индекса на той же модели — идентично.
3. **Толщина**: `bundle_thickness` монотонна; `d(1)=1.8`, `d(4)=4.5`,
   `d(8)=8.0` (кап); при N ≥ 2 пользовательская `edgeWidth` ребра внутри
   пучка игнорируется, у N = 1 — учитывается.
4. **Rect**: `main_stage_rect` — обе стороны ≤ 70% соответствующей стороны
   вьюпорта, центрирован, целиком внутри при любых пропорциях (320×240,
   1920×1080, ультраширокий 3440×1440, высокий 1080×2400) и при минимальном
   окне не вырождается.
5. **Выключатель**: `bundles = None` (F-13 off) → количество/параметры
   инстансов рёбер идентичны текущему поведению (регресс-щит, тест-сравнение).
6. **Веер**: `stage_edge_fan` симметричен, шаг ≥ min-зазор, детерминирован.
7. **Клип**: содержимое stage геометрически умещается в `main_stage_rect`
   (раскладка гарантирует); факт отсечения за rect — фиксируется на E3
   (scissor или инвариант раскладки) и покрывается тестом.
8. **Модальность**: при открытом stage клик по фону закрывает и **не**
   доходит до канваса (нода не создана, выделение не сброшено), колесо не
   зумит, `Esc` закрывает; открытие любого оверлея закрывает stage (Q6).
9. **Валидация среза**: удаление любого ребра среза фоном (MCP/undo) → stage
   закрыт на следующем кадре; выделение выжившего ребра корректно.
10. **Локализация**: строка настроек и подсказка stage — только через ключи
    `i18n`; литералов в рендере нет (инвариант 7 FR-039/FR-040).

  внутри окна, ≤ 70% сторон, центрирован).
- `stage_edge_fan`: чёт/нечёт count, симметрия, шаг.

### Юнит-тесты (`canvas-render`)

- `build_edge_instances` с `bundles`: 6 рёбер пары → один набор бусин
  (диапазон длины одной линии), толщина = d(6); N=1 — прежний вывод (сравнение
  с текущим бейзлайном); F-13 off — идентичность бейзлайну (инвариант 5).

- Миникарта: 6 рёбер пары → 1 линия снапшота.

### Интеграционные (`canvas-app`, по образцу `tests/integration_edges.rs`)

- Клик по пучку → stage открыт (срез: 2 ноды + N рёбер), канвас-клик по фону
  закрывает и не создаёт ноду; `Esc` закрывает; выделение ребра из stage
  живёт после закрытия.
- Двойной клик по пучку НЕ открывает лейбл-редактор; по одиночному — открывает
  (регресс `test_edit_edge_label_double_click`).

- `Shift+drag` нового ребра в пару → бейдж/толщина обновились без «распаковки»
  (AC-3.3); drag rebind из stage невозможен (ввод глушен).
- Фокус-режим (T23): агрегированная линия подсвечена при инцидентном ребре в
  фокусе, затемнена иначе.

### Ручная приёмка

- Демо-канвас «2 ноды × 6 value-рёбер»: LOD-0 — одна линия с `×6`, толщина
  заметно больше одиночной; клик → stage ≤ 70% вьюпорта, фон затемнён, обе
  ноды и все рёбра с подписями `fromLine`/`toParam` читаемы; `Esc` и клик по
  фону закрывают (G1–G3 PRD).
- Обе темы: контраст бейджа/затемнения ≥ 3:1 (CR-007); альфа фона по темам.
- Настройка «Агрегация связей» off → канвас выглядит как сегодня.
- Стресс `--stress` (1000 нод / 3000 рёбер): 60 fps на пан/зум (G4), замер в
  worklog.
