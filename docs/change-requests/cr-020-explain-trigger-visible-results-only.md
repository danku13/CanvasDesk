## Решения владельца (Q&A)

**Вопрос Q1: «Как поступить с зоной «Проверка цепочки расчёта» у нод без видимого результата (нода только с параметром `qty = 10`)?»**

| Вариант | Суть |
|---|---|
| Только при цифрах | Зона только там, где есть видимый результат (полоса ИТОГ или построчные значения), hit = видимая зона |
| Оставить везде | Зона у каждой ноды с любым числом, видимый аффорданс везде |
| **Только у расчётов ← выбрано** | Триггер только у полосы «ИТОГ» и построчных результатов; у констант-присваиваний убрать полностью |

**Вопрос Q2: «Что выводить, если в одной ноде несколько значений (построчные результаты)?»**

| Вариант | Суть |
|---|---|
| Один триггер на ноду | Панель открывается со списком значений, выбор → дерево строки |
| **Лупа на строку ← выбрано** | Мини-лупа у каждой строки-результата (предупреждение владельца: при 5+ строках нода шумит — проверить на приёмке) |
| Только итог | Лупа только у полосы ИТОГ, построчные — кликом по цифре |

---

## Описание (What)

У нод без видимого нижнего поля результата (например, нода только с параметром `qty = 10`) присутствует невидимая hit-зона клика «Проверка цепочки расчёта»: клик по последней строке тела открывает explain вместо выделения/драга ноды. Требуется: триггер существует только там, где есть видимый результат (полоса «ИТОГ» или построчные значения), у каждой строки-результата — своя мини-лупа; у констант-присваиваний триггера нет.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| Полоса результата D | Hit-зона/тултип существуют только при видимой полосе или построчных результатах | `docs/prd/prd-0004-node-anatomy-restructure.md` F-6 |
| Построчные результаты | Каждая строка-результат получает собственный триггер-лупу | FR-088 (ревизия), PRD-0007 AC-1.1 |
| Контракт показа | Единый предикат «есть видимый результат» для рендера/hit/тултипа | FR-088 (пересмотрен), PRD-0007 AC-1.1/AC-1.4 |

## Анализ (Root Cause)

Полный разбор — UR-001-03. Три предиката одного триггера разошлись:

- рендер: `text.has_result(index)` **И** `Ok` (`crates/canvas-render/src/renderer.rs:1768,1786`; комментарий «Фикс 2026-10-05», `:1743-1748`);
- hit-зона: только `Ok` (`crates/canvas-app/src/app.rs:8278-8292`, `result_band_root_at`), перехват клика до canvas-pick (`app/input.rs:2839-2848`);
- тултип: только `Ok` (`crates/canvas-app/src/app/explain.rs:1559-1577`).

У `qty = 10`: футер «ИТОГ» подавлен при наличии построчных результатов (`crates/canvas-render/src/text.rs:3270-3291`), но `expr_results = Ok(10)` (присваивание возвращает значение — `expr.rs:1568-1570`; итог — последняя формульная строка — `flow.rs:793-797`) → невидимая hit-зона 16px на `[h−26,h−10]` лежит на последней строке тела. Геометрия зон не совпадает с полосой D (16px против `RESULT_STRIP_H=32`, `[h−26,h−10]` против `[h−32,h]`).

**Происхождение:** «тихое» решение агента — «Фикс 2026-10-05» сузил видимое, не тронув hit/тултип (расхождение с FR-088). Базовое согласование PRD-0007 (AC-1.4) явно включало константы — теперь владелец решение пересматривает этим CR.

## Требуемые изменения (Changes)

1. Единый предикат «нода показывает видимый результат» — зеркало `node_shows_result_footer` (`crates/canvas-scene/src/scene.rs:1397-1410`): `expr_results == Ok` И (`has_result`-футер ИЛИ есть построчные результаты); у шаблонных нод — футер.
2. `crates/canvas-app/src/app.rs:8278-8292` — `result_band_root_at`: гейт новым предикатом; для нод с построчными результатами — адресация `LineageNodeId::line(...)` по конкретной строке (мини-лупа каждой строки).
3. `crates/canvas-app/src/app/explain.rs:1559-1577` — тултип по тому же предикату, анкер к строке.
4. `crates/canvas-render/src/renderer.rs:1764-1816` + `cards.rs:634-652` — рендер мини-луп у строк-результатов (иконка lucide `search`, hover-акцент по образцу FR-088); геометрия зон = видимой.
5. Пиннеры: `crates/canvas-scene/src/tests.rs` (инвариант футера), `crates/canvas-app/tests/integration_explain_x6.rs` — кейсы `qty = 10` (нет триггера), нода с 3 расчётными строками (лупа на каждой).

## Проверка (Verification)

- Нода `qty = 10`: клик по строке `qty = 10` — выделение/драг ноды, explain не открывается, тултип «Проверка цепочки расчёта» не появляется.

- Шаблонная нода с полосой ИТОГ: триггер работает как раньше (FR-088 без регрессий).
- Нода с 5+ строками-результатами: проверить шум луп на приёмке (предупреждение владельца Q2); при необходимости — порог LOD для мини-луп.
- Hit-зона совпадает с видимой геометрией (клик мимо лупы/полосы не открывает explain).
