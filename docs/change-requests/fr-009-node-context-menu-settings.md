# FR-009: Контекстное меню для каждого объекта с его настройками (для нод)

- **Статус:** в работе
- **Тип:** FR (Feature Request)
- **Приоритет:** важно
- **Владелец:** агент (анализ)
- **Источник:** сообщение пользователя (сессия 2026-09-15): «контекстное меню для каждого объекта с его настройками (для нод…)»
- **Связанные задачи:** CR-004 (прозрачность виджет-нод — настройка прозрачности), FR-006 (undo для изменений настроек), FR-003 (дублирование), SPEC.md §8 (ввод), node.md §4 (взаимодействия)
- **Создан:** 2026-09-15
- **Обновлён:** 2026-09-15
- **Документ-шаблон:** `docs/change-requests/cr-template.md`

---

## Описание (What)

Пользователь запросил контекстное меню для **каждого объекта** канваса с **его
собственными настройками**; приоритет указан для нод. Сейчас меню ноды
содержит только палитру цвета и пункт «Сгруппировать» — настройки конкретного
объекта (переименование, путь/URL, размер, поведение по типу) из меню
недоступны или разбросаны по другим жестам (двойной клик, resize за угол).
Требуется единый механизм: ПКМ по объекту → меню, отражающее настройки именно
этого объекта с учётом его типа (`file` / `text` / `link` / `group` / `widget`).
Выявил пользователь.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| `node` (все типы) | Меню ноды получает раздел «Настройки ▸» по типу ноды | `docs/interface-objects/node.md` §4, §7 |
| `edge` | Пункты связи приводятся к тому же шаблону «настройки объекта» | `docs/interface-objects/edge.md` §4 |
| `group` | Настройки группы (подпись, padding, разгруппировать) | `docs/interface-objects/node.md` §2 (тип `group`) |
| `widget` | Настройки виджет-ноды (props, permissions, перезагрузка) | `docs/WIDGETS.md` §3, §6 |
| Undo/автосейв | Каждое изменение настройки — undo-шаг + `mark_dirty` | FR-006, `docs/SPEC.md` §9 |

## Анализ (Root Cause)

Механизм контекстных меню есть — расширять, а не создавать:

- Модель меню: `ContextMenu` + `MenuTarget::{Node, Edge, Canvas}`
  (`crates/canvas-app/src/lib.rs`, модуль `ui`); рендер — `menu_overlay`
  (`crates/canvas-app/src/main.rs:2243-2390`); открытие по ПКМ и диспетчер
  пунктов — ветка `RightPressed` (`main.rs`, сброс `self.menu` в `1327`,
  `1438`, `1480`; обработка выбора — `3283`).
- Пункты меню ноды: `NODE_MENU_ITEMS` (`lib.rs:1037-1057`) — 7 цветов
  (`Color(Some("1"))..Color(None)`) + `Separator` + `Group`. Подписи —
  `node_menu_label` (`lib.rs:1086-1088`). **Никаких других настроек нет.**
- Меню связи: `EDGE_MENU_ITEMS` — стиль/толщина/цвет (`EdgeMenuItem`).
- Меню канваса: `CANVAS_MENU_ITEMS`, включая подменю «Виджеты ▸»
  (`main.rs:3636-3667`) — механика `Submenu`/`SubmenuEntry`
  (`main.rs:2364-2384`) **уже реализована** и переиспользуется для
  «Настройки ▸».
- Настройки, существующие в модели, но недоступные из меню ноды:
  - подпись/переименование — `Node.label`, редактирование через
    `begin_editing` (двойной клик, `main.rs:3754`);
  - размер — только ручной resize за угол (`in_resize_corner`,
    `main.rs:3782-3789`);
  - путь файла (`Node.file`), URL (`link`-ноды), `props`/`permissions`
    виджета (`CanvasdeskExt`, `model.rs`; `permissions_of_node`,
    `widgets.rs:495`) — из меню недоступны;
  - цвет карточки — единственная настройка в меню сегодня.
- Изменения настроек обязаны проходить через snapshot-undo FR-006
  (`begin_pending_undo` / `push_undo`) — как смена цвета из меню сейчас.

## Требуемые изменения (Changes)

1. `lib.rs` (модуль `ui`): расширить `NodeMenuItem` подменю
   `Settings(&'static [SettingsEntry])` или ввести параллельный список
   `NODE_SETTINGS_ITEMS_BY_KIND: fn(NodeKind) -> &[SettingsItem]` —
   настройки по типу ноды:
   - **общие:** переименовать (вход в `begin_editing`), размер «по
     содержимому», прозрачность карточки (синхронизировать с CR-004),
     цвет (существующие пункты переехали внутрь);
   - **`file`:** открыть файл (как двойной клик, `main.rs:3761-3771`),
     открыть содержащую папку (`canvas_shell::desktop::interop`),
     скопировать путь;
   - **`text`:** очистить текст, дублировать (FR-003);
   - **`link`:** править URL (через `begin_editing`, не новый ввод);
   - **`group`:** править подпись, «Разгруппировать» (удаление группы
     без каскада — паттерн `removing_group_keeps_children`,
     `model.rs:540`);
   - **`widget`:** перезагрузить виджет (пересоздать инстанс хоста),
     показать `props` (просмотр/правка — через существующий мост
     `propsChanged`), permissions — read-only список.
2. `main.rs`: диспетчер новых пунктов в ветке выбора меню; каждый пункт —
   последовательность «push_undo → мутация → mark_dirty».
3. Подписи пунктов: расширить `node_menu_label` (или аналог) с отметкой
   текущего значения (`✓`) — по образцу `edge_menu_label` (`lib.rs:1223`).
4. Меню связи и канваса привести к тому же шаблону (единый UX), сохраняя
   текущие пункты без изменений поведения.
5. Хоткеи отдельных настроек — опционально, через FR-004 (оверлей хоткеев).

## Открытые вопросы дизайна

- Состав настроек v1 по типам (минимальный набор выше — предложен агентом).
- «Прозрачность» как пользовательская настройка карточки: зависимость от
  CR-004 (там прозрачность виджет-нод принудительная).
- Z-order («на передний/задний план») — сейчас порядок = индекс в
  `canvas.nodes`; включать ли в v1.

## Проверка (Verification)

- ПКМ по ноде каждого типа (`file`, `text`, `link`, `group`, `widget`) →
  меню содержит «Настройки ▸» с пунктами именно этого типа; старые пункты
  (цвета, «Сгруппировать», «Виджеты ▸» у канваса) работают как раньше.
- Каждая настройка применяется сразу после выбора и видна на канвасе
  (переименование меняет заголовок, путь/URL сохраняются в `.canvas`).
- `Ctrl+Z` отменяет изменение настройки; автосейв срабатывает (§9).
- Подменю открывается/закрывается корректно (механика `Submenu`), клик вне
  меню закрывает его без побочных эффектов.
- Для `widget`: перезагрузка пересоздаёт инстанс (лог хоста), permissions —
  read-only, props-правка доходит до виджета (`propsChanged`).
