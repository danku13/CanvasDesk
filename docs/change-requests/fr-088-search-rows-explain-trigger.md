# FR-088: Адаптивная вёрстка строк поиска, видимая кнопка «Проверка цепочки» в полосе результата

- **Статус:** реализовано
- **Тип:** FR (батч исправлений вёрстки + ревизия UX-триггера)
- **Приоритет:** важно (ежедневные поверхности: Ctrl+F и триггер окна проверки)
- **Владелец:** агент-сессия (Super Z), по запросу владельца
- **Источник:** запрос владельца 2026-10-03: «почини вёрстку вывода полей
  в поиске, сейчас они как будто имеют жёстко заданные размеры, надо
  сделать адаптивную высоту рядов. Так же я не понимаю что за место ты
  выбрал для hover эффекта с тултипом и кнопкой которая активирует вывод
  проверки цепочки расчёта. сейчас вообще не понятно как и где эта кнопка
  находится»
- **Связанные задачи:** FR-014/T14 (панель поиска), FR-068 W3.2
  (search_ui на measured-семействе), PRD-0007 F-1/AC-1.1 (триггер окна
  проверки по полосе результата), FR-085/ревизия b2f6856 (окно проверки),
  FR-ICONS (атлас иконок), ui-kit §4–5 (примитивы и TextMeasurer)
- **Создан:** 2026-10-03
- **Обновлён:** 2026-10-03

## Описание

Два дефекта/пробела, найденных проверкой поверхностей:

1. **Вёрстка строк поиска жёстко задана и не вмещает контент.** Высота
   строки была константой `ROW_HEIGHT = 28`, заголовок и подзаголовок
   рисовались на фиксированных смещениях (+4/+18) при кеглях 13/11:
   двухстрочный контент занимал ~28.3 px — подзаголовок вылезал за фон
   строки (hover/выделение подсвечивали 28 px, а текст висел ниже), строки
   сливались в сплошную «кашу». Переноса длинных подзаголовков не было
   (экранные тексты однострочные, `Wrap::None`), длинный заголовок тихо
   клипился. Кламп по высоте окна тоже отсутствовал — панель росла вниз
   без ограничений.
2. **Триггер окна проверки необнаруживаем.** Единственный видимый аффорданс
   — крошечный «?»-пилл (22×18) у курсора, появлявшийся только при наведении
   ровно на полосу результата «ИТОГ» внизу ноды (PRD-0007 §6.4, hover-only —
   решение владельца). Владелец: «вообще не понятно как и где эта кнопка
   находится» — решение пересмотрено.

## Решение

### 1. Адаптивные строки поиска (search_ui)

- Высота строки — **замер контента** тем же `TextMeasurer`, что и
  раскладка (ui-kit §5: «эвристики запрещены»): заголовок — ellipsis до
  одной строки (`TextMeasurer::ellipsis`), подзаголовок — перенос по
  словам (`TextMeasurer::wrap`). Линейка — дизайн-константы по каталогу
  W3.3: `TITLE_FONT_SIZE 13` / `SUB_FONT_SIZE 11`, `TITLE_LINE_H 17` /
  `SUB_LINE_H 15` (кегль × 1.3, округлено до целых), `ROW_PAD_V 6`,
  `TITLE_SUB_GAP 2`; формула — [`row_height(lines)`]: строка без
  подзаголовка — 29 px, с одной строкой подзаголовка — 46 px.
- Новое поле `PanelLayout::row_texts: Vec<RowText>` — готовый к отрисовке
  текст строки: заголовок после ellipsis, перенесённые строки подзаголовка,
  абсолютные позиции и ширина текстовой зоны (x зависит от класса строки:
  `ROW_TEXT_X 10` у нод, `ROW_TEXT_X_DOCS 30` у доков — зона бейджа «?»).
  Рендер (`overlays::search_overlay`) НЕ дублирует ни замер, ни смещения —
  единый источник геометрии для раскладки, отрисовки и hit-rect'ов реестра
  (row_rects не изменился).
- **Кламп по высоте окна**: видимые строки укладываются в
  `window_h − PANEL_BOTTOM_MARGIN` (минимум одна строка, далее — скролл
  рядами, как раньше); `MAX_VISIBLE_ROWS = 8` остаётся потолком.

### 2. Кнопка «Проверка цепочки» в полосе результата (renderer + app)

- **Постоянная иконка-лупа** (lucide `search`, размер 16, отступ 8 от правого
  края — `cards::explain_button_rect`) в правом конце полосы результата
  каждой ноды с вычисленным итогом (`ExprOutcome::Ok` — та же зона, что
  hit-тест триггера `result_band_root_at`). Покой — приглушённый тон
  `theme.icon` (α ×0.62), hover ноды — акцент `theme.accent`; dim-режим
  фокуса гасит вместе с карточкой. World-хром самодостаточен: набор
  фиксирован (lucide), как и роли шаблонов (sparse `roles`) — от
  `icon_style` UI не зависит.
- **Значение «ИТОГ» не заезжает под кнопку**: правый край значения в футере
  сдвигается на `EXPLAIN_BTN_ZONE = 30` world px при том же условии
  (итог без ошибки); у ошибочных диагности и строк с направляющими чисел
  семантика прежняя (сдвиг после направляющих — `min`-кламп невозможен,
  зона вычитается из итогового right_world).
- **Тултип вместо «?»-пилла**: при наведении на полосу результата над
  кнопкой (якорь — правый край кнопки, world → screen, клампы к вьюпорту)
  рисуется подпись «Проверка цепочки расчёта» (`keys::EXPLAIN_TITLE`,
  RU/EN) — измеренная ширина + 16 px пад, высота 22, стиль панели поиска
  (`menu_fill`, рамка, радиус 6). Клик по полосе (и по кнопке — она внутри
  полосы) открывает окно проверки, как и раньше (F-1/AC-1.1).

## Приёмка

- 5 новых тестов search_ui: перенос подзаголовка (высота =
  `row_height(n)`, позиции строк), ellipsis заголовка, x-смещение
  строк-доков, кламп панели по высоте окна (7 строк на 300 px, минимум
  одна на 80 px), параллельность row_texts/row_rects; обновлены
  координатные тесты прежней фиксированной вёрстки (28 → 29).
- Ревизия владельца 2026-10-02 (b2f6856) не регрессировала: клип окна
  проверки, зум-текст, иконка edit, поле подмены — не тронуты.
- 2348+ workspace-тестов, fmt, clippy `-D warnings`, wasm-check — зелёные.

## Ревизия CR-020 (2026-10-08, волна W2)

Контракт триггера пересмотрен решением владельца (UR-001-03, Q1/Q2):
триггер «Проверка цепочки» существует ТОЛЬКО при видимом результате —
у построчных результатов Numi-листа постоянная мини-лупа строки
(`text.rs::row_explain_hits`, вердикт `row_grid::row_is_explainable`),
у констант-присваиваний («qty = 10») зоны нет вовсе (футер подавлен
построчными результатами — `result_band_root_at` гейтится
`node_shows_result_footer`). Шаблонные ноды — футер FR-088 без изменений.
Детали — CR-020, ревизии AC-1.1/AC-1.4 в PRD-0007.
