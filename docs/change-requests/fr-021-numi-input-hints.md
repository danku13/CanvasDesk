# FR-021: Контекстные подсказки при вводе, когда строка определяется как Numi

- **Статус:** выявлено
- **Тип:** FR (Feature Request)
- **Приоритет:** важно

## Описание (What)

При редактировании заметки пользователь пишет Numi-формулы «вслепую»: имена
функций (`mm1`, `percentile`, `erlang_c`…), токены единиц (`ms`, `rps`),
имена уже заведённых переменных и `$`-ссылки нужно помнить и набирать
целиком, а ошибка всплывает только после ввода — красной диагностикой под
текстом. Требуется **контекстная подсказка (autocomplete)**: пока каретка
стоит на строке, которую Numi-движок распознаёт как вычисляемую
(присваивание `имя = …`, явное `= …` или чистое выражение), рядом с
кареткой показывается popup со списком вариантов, отфильтрованных по
набираемому токену:

- **функции** с сигнатурами (`mm1(λ, μ[, c])`, `sum(...)` …) — по префиксу
  имени;
- **единицы измерения** (`ms`, `sec`, `rps`, `KB`, `%`…) — после числа;
- **переменные ноды** — заведённые присваиваниями выше по тексту;
- **`$`-ссылки**: `$in`/`$1..$N` по фактическим inbound-рёбрам (FR-014) и
  параметры шаблона `$rps`… (FR-018) — после `$`.

Строки, которые движок считает прозой (без присваивания и без чисел/операторов,
молчаливые ошибки FR-013), подсказок **не** вызывают — автодополнение не
должно мешать обычному набору текста. Выбор — `Enter`/`Tab`, закрытие —
`Esc` или уход каретки с Numi-строки; выбор вставляет остаток токена
(функция — с открывающей скобкой).

## Анализ (Root Cause)

Функции автодополнения нет ни в одном слое:

- **`EditingSession`** (`crates/canvas-render/src/edit.rs:356`) хранит буфер,
  каретку и layout, обрабатывает `KeyCommand` через `apply()`
  (`edit.rs:608`) и `insert_text()` (`edit.rs:657`); состояния подсказок в
  нём нет. `map_key` (`edit.rs:281`) транслирует клавиши в `KeyCommand` —
  при открытом popup навигация `Up/Down/Enter/Tab/Esc` должна
  перехватываться приложением **до** передачи `KeyCommand` в сессию.
- **Грамматика и таблицы** живут в `crates/canvas-core/src/expr.rs`:
  `UNIT_TABLE` (`expr.rs:236`) — приватная, список функций зашит в
  `eval_call` (ветка диспетчеризации, включая FR-015 queueing-набор и
  FR-018 `$param`-грамматику). Для подсказок нужен публичный каталог
  (`fn-имя → сигнатура/описание`, `unit-токены`), иначе UI дублирует
  знания движка и расходится с ним при добавлении функций.
- **Род строки** определяется в `eval_lines` (`expr.rs:1251`) неявно:
  присваивание/выражение/проза. Детектору подсказок нужен тот же вердикт —
  публичная чистая функция над одной строкой (префикс строки до каретки),
  чтобы popup открывался/закрывался ровно на тех строках, которые движок
  реально считает.
- **Контекст ноды**: переменные — присваивания текущего текста (левые части
  `=` до каретки, их единицы — из `eval_lines`-результатов при наличии);
  `$in`/`$N` — inbound-слоты value-рёбер (`flow.rs`, `Env::with_inbound` —
  FR-014); `$параметры` — `canvasdesk.template.params` ноды (FR-018,
  `templates.rs:78` `ParamSpec`).
- **Позиция popup**: каретка в screen/world-координатах вычислима из
  layout буфера редактора (`set_layout`, `edit.rs:478`; привязка рядов —
  `LayoutRun.line_i`, используется в editing_line_results). Для v1
  достаточно якорить popup по началу строки каретки (y) и x каретки,
  с клампом к окну — как `wheel_geometry` клампит центр (FR-018 правка).
- **Рендер**: образец оверлея поверх канваса — `search_overlay` и
  `wheel_overlay` (`main.rs:3045`): `Vec<CardInstance>` + `OwnedScreenText`,
  без поворотов; popup подсказок собирается так же по кадру.

## Требуемые изменения (Changes)

1. **`crates/canvas-core/src/expr.rs`** — публичный каталог и детектор:
   - `pub struct FnHint { name, signature, summary }`;
   - `pub fn fn_hints() -> &'static [FnHint]` — все функции движка
     (`sum`, `avg`, `max`, `min`, `percentile`, `mm1`, `mmc`,
     `utilization`, `littles_law`, `erlang_c`…), сигнатуры синхронны
     `eval_call`;
   - `pub fn unit_tokens() -> impl Iterator<Item = &'static str>` — токены
     `UNIT_TABLE` + `%`/`$`;
   - `pub enum NumiLineKind { Assignment { name }, Expression, Prose }`;
   - `pub fn line_kind(line: &str) -> NumiLineKind` — тот же вердикт, что у
     `eval_lines` (учитывая префикс `=`, код-фенсы — по контексту выше).
   - Чистые функции, детерминированные, без I/O — тестируются в core.

2. **`crates/canvas-app/src/hints_ui.rs`** (новый, чистый модуль — образец
   `template_ui.rs`):
   - `pub struct HintItem { kind: Fn|Unit|Var|DollarRef, insert: String,
     label: String, detail: Option<String> }`;
   - `pub fn hint_items(token_prefix: &str, ctx: &HintContext) ->
     Vec<HintItem>` — фильтр по префиксу (без регистра), порядок: переменные
     → `$`-ссылки → функции → единицы; limit ~8;
   - `pub fn token_before_caret(line: &str, caret: usize) -> (String,
     usize)` — токен слева от каретки (для замены хвоста при вставке);
   - `pub struct HintPopup { open, items, selected }` + клавиатурная модель
     (`move_selection`, `accept`);
   - `pub fn popup_layout(anchor: Vec2, window: [f32; 2], count: usize) ->
     [f32; 4]` — кламп к окну;
   - тесты: префиксы `mm` → `mm1`/`mmc`; `50 ` → единицы; `$` → `$in`,
     `$параметры`; переменные выше по тексту; проза — пусто.

3. **`crates/canvas-render/src/edit.rs`** — минимально: публичный доступ к
   позиции каретки (`caret_line_text()` — текст строки каретки до каретки и
   координаты для якоря popup; источник — layout буфера).

4. **`crates/canvas-app/src/main.rs`**:
   - `SceneState` — `hints: HintPopup` (сброс при `begin_editing`/commit);
   - в `on_key` (`main.rs:5006`): если сессия редактирования активна и
     строка каретки — Numi (`expr::line_kind`) — обновлять список подсказок
     по `token_before_caret`; при открытом popup перехватывать
     `Up/Down/Enter/Tab/Esc` до `map_key` (`Enter` — accept и НЕ
     `KeyCommand::Commit`);
   - при вставке — заменить токен-хвост (`insert_text` + смещение каретки),
     один undo-шаг вместе с правкой текста;
   - overlay-сборка по образцу `wheel_overlay`: квад-фон + строки
     (имя + detail серым), hover/выделение.

5. **Документация**: `docs/SPEC.md` §8 (поведение Enter/Esc в popup),
   `docs/interface-objects/node.md` (раздел редактирования),
   `user-docs/calculations.html` — абзац про подсказки (после реализации).

## Архитектура тестируемости (инварианты FR-021)

1. **Детектор рода строки = вердикт движка.** Для каждой строки фикстуры
   `eval_lines`-тестов `line_kind()` совпадает с тем, что движок посчитал
   (Option<ExprOutcome> есть — Numi; ошибка ввода — всё равно Numi; проза —
   Prose). Тест в core на общей фикстуре.
2. **Каталог не расходится с диспетчером.** Тест: для каждой `FnHint.name`
   вызов `parse("name(1)")` парсится (функция известна грамматике); для
   каждого unit-токена `unit_value(1, token)` даёт не-скаляр (или `%`/`$`).
3. **Popup — чистая геометрия.** `popup_layout` клампится к окну, строки не
   вылезают за popup (как wheel-инвариант FR-018 правки).
4. **Клавиатурный контракт.** Тест: popup открыт → `Enter` вставляет и
   НЕ коммитит; popup закрыт → `Enter` коммитит (существующее поведение
   не меняется); `Esc` при открытом popup не откатывает текст.

## Проверка (Verification)

### Юнит-тесты (core)

- `line_kind("rps = 1000")` → Assignment; `line_kind("= 2 + 2")` →
  Expression; `line_kind("2 + 2")` → Expression; `line_kind("встреча в 3")`
  → Prose; `line_kind("")` → Prose.
- `fn_hints()` содержит `mm1`, `mmc`, `utilization`, `littles_law`,
  `erlang_c`, `sum`, `percentile` — и каждый парсится грамматикой.
- `unit_tokens()` содержит `ms`, `sec`, `rps`, `KB`, `%`.

### Юнит-тесты (hints_ui)

- Префикс `mm` → [`mm1(λ, μ[, c])`, `mmc(λ, μ, c)`]; префикс `MM` — то же
  (регистр не важен); пустой токен на Numi-строке → переменные ноды.
- Токен `$` → `$in` (если inbound есть), `$1`..`$N`, `$rps` (параметры
  шаблона); без inbound и шаблона — `$`-подсказок нет.
- `token_before_caret("rps = 10|", …)` → ("10", смещение) — вставка unit
  заменит только число.
- `popup_layout` у края окна — кламп внутрь; 0 элементов — popup не
  открывается.

### Интеграционные тесты (app)

- Открыть заметку `rps = 1000`, каретка в конце; набрать ` w = mm` → popup
  содержит `mm1`; `Enter` → текст `w = mm1(`, заметка НЕ закоммичена;
  повторный `Enter` → commit.
- Прозаическая строка (обычный текст) — popup не открывается ни на одном
  токене.
- `Esc` при открытом popup закрывает только popup, текст не откатывается;
  второй `Esc` — откат правки (старое поведение).

### Ручная приёмка

- В Numi-строке после `=` виден popup с переменными и функциями; после
  числа — единицы; после `$` — входы и параметры шаблона.
- На прозаических строках подсказок нет — набор текста не мешается.
- Popup не выходит за края окна при редактировании ноды у границы экрана.

## Открытые вопросы дизайна

- **Якорь popup** — по каретке (точный) или по строке (дешевле)? v1 — по
  началу строки каретки; v2 — точная позиция каретки из layout буфера.
- **Сниппеты с плейсхолдерами** (`mm1(λ, μ)` с прыжками по аргументам) —
  v1 не делает, вставка `mm1(` + подсказка сигнатуры в detail.
- **Авто-открытие или только по Ctrl+Space?** Решение владельца: v1 —
  авто-открытие только на Numi-строках (проза не трогается); если мешает —
  настройка в `config.toml` (`settings.rs`).
- **Единицы после числа или везде?** v1 — токены единиц подсказываются
  после числа/пробела за числом; в остальных позициях — переменные/функции.
- **Fuzzy-матчинг** — v1 нет (префикс), v2 опционально.
