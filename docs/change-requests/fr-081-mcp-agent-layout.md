# FR-081: MCP-расстановка нод для агента + защита высоты от сжатия

- **Статус:** реализовано
- **Тип:** FR
- **Приоритет:** важно (агентный контур — раскладка схем MCP-агентом)
- **Владелец:** агент-сессия (Super Z), по запросу владельца
- **Источник:** запрос владельца 2026-10-01: «в рамках MCP агент не должен
  сжимать ноды по высоте меньше чем размер их контента, сейчас при
  расстановке нодов агент сжимает ноды… надо улучшить механизм расстановки
  нод именно для агента» (+ два сценария: расстановка «в порядке который
  есть на скриншоте» либо «по смыслу»)
- **Связанные задачи:** FR-005 (MCP node-edit), FR-012 v4 (group_create —
  проверен в рамках этой сессии: инструмент существует, тесты зелёные),
  FR-069/FR-075 (refit-семейство высоты), FR-071 (plan_scheme_layout),
  FR-010 (plan_related_layout), FR-033 (graph_apply), skills v7
- **Создан:** 2026-10-01
- **Обновлён:** 2026-10-01

## Описание

Две проблемы агентного контура MCP:

1. **Сжатие нод.** Все MCP-входы геометрии (`node_resize`, `node_edit`,
   `node_create_note`, `graph_apply`) применяли `height` как задано —
   агент мог сжать ноду ниже её контента (текст/формулы/футер обрезаются
   силуэтом). Поле `fit` в `node_resize` — opt-in (дефолт false), агенты
   его не выставляют; политика «первая встреча — доверяем высоте»
   (`refit_node_to_content_if_changed`, I-6) дальнейшей коррекции не
   делает: «hash тот же, высота другая — доверяем текущей».
2. **Раскладка только по одной ноде.** Единственный инструмент позиций —
   `node_move` (одна нода за вызов): раскладка схемы из N нод = N вызовов
   с ручным подсчётом координат агентом. Готовые движки раскладки
   (`plan_related_layout` FR-010, `plan_scheme_layout` FR-071) в MCP не
   экспортированы.

## Решение

### Часть 1 — пол высоты по контенту (рост-only кламп)

- `measure.rs`: константа `MIN_CONTENT_HEIGHT` поднята на уровень модуля
  (шапка 34 + зазор 4 + ряд тела 20 + паддинг 10 = 68 px); новая чистая
  функция `measured_content_height(width, display, formula_lines, desc,
  desc_expanded, footer_reserve, sigma_name, auto_rows) -> f32` — тот же
  двухуровневый замер (L1-оценка → L2-шейпинг через `measured_reserve`),
  что у `refit_to_measured_content`, но без мутации.
- `scene.rs`: `min_content_height(index)` (входы через `refit_inputs`,
  I-2 measure = render) и `clamp_height_to_content(index)` — рост-only:
  запрошенная высота ВЫШЕ минимума не трогается («воздух» — свобода
  агента), ниже — поднимается до измеренного контента; spatial
  обновляется точечно.
- Точки применения (все MCP-входы геометрии):
  - `node_resize`: кламп после записи width/height (и после
    опционального `fit`); ответ дополнен `height_clamped` и
    `min_height`;
  - `node_edit`: кламп при записи width/height (`size_written`), ПОСЛЕ
    ветки expr — recompute_flow успевает обновить `expr_line_results`,
    замер по свежему контенту (случай «текст + высота одним вызовом»);
  - `node_create_note`: кламп после `recompute_flow`;
  - `graph_apply`: кламп созданных `node_create_note`-нод после
    успешного батча и пересчёта (паритет с одиночным путём).
- Семантика не ломает UI: refit-семейство, I-6 и `content_height_state`
  не тронуты — после MCP-мутации следующий `recompute_flow` обновляет
  состояние по правилу «доверяем текущей высоте».

### Часть 2 — инструмент `nodes_layout_apply` (расстановка для агента)

Один вызов вместо N `node_move`. Два режима:

- **`mode:"grid"` (дефолт)** — «порядок чтения», транскрипция раскладки
  со скриншота: `rows` — массив рядов, каждый ряд — массив id слева
  направо, ряды сверху вниз. Колонки выравниваются по максимальной
  ширине нод колонки, ряды — по максимальной высоте (в рвёных сетках
  выравнивание сохраняется); зазоры `colGap`/`rowGap` (дефолты 80/48,
  синхронно с `LEVEL_GAP` FR-010; допустимо 0..=500 — образец
  `GROUP_PADDING_MAX`); точка `x`,`y` — левый-верх блока (дефолт —
  текущий bbox перечисленных нод: раскладка «на месте»). Группы в
  `rows` отклоняются (рамка не таскается отдельно от детей); рамки
  групп с переехавшими детьми авторасширяются
  (`group_expand_to_children_deep`, FR-012) — grow-only, spatial
  перестраивается. Ответ: `{mode, moved, positions, bbox,
  col_gap, row_gap, groups_resized}`.
- **`mode:"smart"`** — смысловая раскладка ВСЕГО канваса: повторное
  использование `plan_scheme_layout` (FR-071, Sugiyama-lite) —
  семантические кластеры по группам и связности рёбер, слои
  longest-path (поток слева направо), barycenter-порядок (смысловые
  соседи рядом), выравнивание сеткой без «прилипания»; план
  детерминирован и сдвигается так, что bbox канваса сохраняется (или
  к явной точке `x`,`y`). Размеры групп-рамок применяются из плана
  (`group_sizes`). Ответ: `{mode, bbox}`.
- Общий контракт: `fit` (дефолт true) — перед раскладкой высоты всех
  перечисленных (grid) или всех нод кроме групп (smart) клампятся к
  контенту — сжатые ноды не ломают выравнивание; вся валидация ДО
  undo-шага (паттерн `mcp_group_create`); ровно один undo-шаг
  (FR-006); spatial перестраивается целиком (паттерн `node_delete`);
  пересчёт потока не нужен — топология и значения не меняются.

## Тесты (натив + wasm32-wasip1, гейт FR-037)

- `mcp_node_resize_clamps_height_to_content` — сжатие клампится
  (`height_clamped: true`, `min_height` в ответе), «воздух» не
  сжимается, width как задан; минимум при НОВОЙ ширине (перенос).
- `mcp_node_edit_clamps_height_to_content` — кламп при записи размера;
  x/y без размеров — клампа нет.
- `mcp_node_create_note_clamps_height_to_content` — height=30 с длинным
  текстом → ≥ измеренного минимума.
- `mcp_graph_apply_clamps_created_note_height` — паритет батча.
- `mcp_nodes_layout_apply_grid_positions` — выравнивание колонок/рядов,
  зазоры ≥ запрошенных, позиции/bbox в ответе, один undo-шаг.
- `mcp_nodes_layout_apply_grid_fit_clamps_heights` — fit (дефолт) клампит
  высоты до измерения ячеек.
- `mcp_nodes_layout_apply_grid_expands_group` — рамка группы с
  переехавшим ребёнком авторасширяется (`groups_resized`).
- `mcp_nodes_layout_apply_validation_errors` — неизвестный id, дубликат,
  группа в rows, пустой ряд, нет rows, плохой mode, x без y, colGap>500:
  ошибка без мутаций и undo-шагов.
- `mcp_nodes_layout_apply_smart_deterministic_no_overlap` — bbox на
  месте, наложений нет, детерминизм (два одинаковых канваса → одинаковые
  позиции).
- `mcp_nodes_layout_apply_smart_empty_canvas` — пустой канвас → ошибка.

## Инварианты

- **Агент не сжимает ноду ниже контента** — ни один MCP-вход геометрии
  не применяет высоту ниже измеренного минимума (68 px пол).
- **Высота выше минимума — свобода агента** — «воздух» не сжимается
  (в отличие от `fit: true`, который подгоняет высоту точно под
  контент).
- **Один undo-шаг на вызов** — паттерн FR-006 соблюдён; невалидные
  вызовы не мутируют и не копят шаги.
- **skills_sync** — каталог/скиллы/счётчики синхронны реестру
  (контракт-тесты `canvas-mcp`).
