# FR-099: Safe-area web-оболочки + аудит вьюпортов поворотов планшета

- **Статус:** выполнено
- **Тип:** FR (мобильная обсыпка → safe-area + QA-матрица вьюпортов)
- **Приоритет:** средний
- **Владелец:** агент (сессия 2026-10-03)
- **Источник:** аудит мобильной адаптации 2026-10-03: в meta viewport нет `viewport-fit=cover`, DOM-тулбар не учитывает `env(safe-area-inset-*)` — на iPhone в ландшафте notch/жест-бар перекрывает элементы; повороты/сплит-скрин планшета ни разу не тестировались
- **Связанные задачи:** CR-014 (адаптивность оболочки), wasm-port §9 (вне волны 1), W-e (онбординг)

## Описание

**1. Safe-area (DOM-оболочка, `crates/canvas-web/index.html`):**

- meta viewport += `viewport-fit=cover` — страница рисуется под
  notch/жест-бар, а браузер отдаёт инсеты через CSS `env()`.
- Тулбар (`#w6-toolbar`, позиция «левый низ» на <1200px — CR-014):
  `bottom/left` → `max(8px, env(safe-area-inset-bottom/left))` —
  жест-бар/notch не перекрывают кнопки; fallback 8px — браузеры без env().

**GPU-панели** (HUD топ-лево, миникарта право-низ, палитра левый край) —
сознательно за скопом этого FR: env() из CSS в Rust не пробросить без
пробоотвода и нового AppEvent-канала, а на телефонных вьюпортах GPU-панели
не прижаты к самому краю (поля 8–16 px) — перекрытие возможно только в
ландшафте iPhone под notch у HUD. Зафиксировано как известное ограничение;
кандидат в следующую мобильную волну (probe div + `AppEvent::SafeInsets`).

**2. Аудит вьюпортов** (`scripts/web_layout_audit.py`): матрица расширена
телефоном в ландшафте (844×390) и iPad Air (820×1180) — теперь повероты
планшета/телефона покрыты обеими ориентациями (768×1024/1024×768 уже были).
Прогон скрипта требует playwright-стенд (WASM-TESTING.md); в сессии
исполнение не прогонялось — геометрические инварианты панелей покрыты
юнит-тестами layout-функций, аудит добавлен в матрицу для CI/локального
прогона.

**3. Онбординг (W-e «разморозка»):** расследование показало — онбординг
функционален и не заморожен (`should_show_onboarding`: не пройден И
откладываний < 3; карусель, кнопки, кламп карточки к окну). Реальный пробел
был в тач-целях кнопок — закрыт FR-097 (`button_at` coarse-расширение).
Отдельная разморозка не требуется.

## Влияние

| Объект | Что было | Где |
|---|---|---|
| index.html | viewport-fit нет; тулбар под жест-баром iPhone | meta viewport, CSS `#w6-toolbar` |
| web_layout_audit.py | повороты телефона/планшета вне матрицы | `VIEWPORTS` |
| onboarding_ui.rs | тач-цели кнопок (закрыто FR-097) | `button_at` |

## Приёмка

- CSS/мета правки — статические; верификация env()-офсетов — ручной
  прогон на устройстве с notch (iPhone Safari, ландшафт: тулбар выше
  жест-бара).
- Гейты репо: fmt, clippy -D warnings, test --workspace, wasm_gate --check —
  зелёные.
- Ручной сценарий (телефон): ландшафт iPhone — тулбар не под жест-баром;
  повороты портрет↔ландшафт — панели не вылетают за экран (аудит-скрипт).

## Известные ограничения

- GPU-панели не знают о safe-area-инсетах (см. выше) — фиксировать в
  следующей мобильной волне, если ручная приёмка покажет перекрытия HUD.

## Точки входа

- `crates/canvas-web/index.html` — meta viewport, `#w6-toolbar` CSS.
- `scripts/web_layout_audit.py` — матрица вьюпортов.
- `crates/canvas-app/src/onboarding_ui.rs` — `button_at` (FR-097).
