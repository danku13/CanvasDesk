# CR-007: Доступность цветовых тем — авто-контраст текста на окрашенных карточках

- **Статус:** выполнено
- **Обновлён:** 2026-09-16 (аудит реализации)
- **Тип:** CR (Change Request) + аудит доступности (WCAG 2.1)
- **Приоритет:** важно
- **Владелец:** агент (анализ + реализация)
- **Источник:** сообщение пользователя (сессия 2026-09-16): «Сейчас есть проблемы когда ноды светлого цвета при этом там белый текст и он может не читаться»
- **Связанные задачи:** T1 (темы), T7 (карточки/текст), FR-013 (строки результатов на карточках), T8 (цвета связей)
- **Создан:** 2026-09-16
- **Верификация:** скриншоты `docs/assets/cr-007-light.png`, `docs/assets/cr-007-dark.png`; сцена `examples/colors-a11y.canvas`

## Описание (What)

Текст на окрашенных карточках (пресеты JSON Canvas «1..6» и произвольные
`#RRGGBB`) брался из темы без учёта заливки. Следствия:

1. **Пресеты не зависели от темы**: тёмно-приглушённые заливки применялись
   и в светлой теме, где текст тёмный → тёмное-на-тёмном (~2:1).
2. **Светлые hex-заливки** (например `#ffff88`) в тёмной теме получали
   белый текст темы (~1.1:1) — нечитаемо; это и есть reported кейс.
3. **Акценты на карточке того же тона**: синие результаты формул FR-013 и
   красный бейдж ошибки на заливках давали 2.3–4.1:1 при норме WCAG AA 4.5:1.

Требование: читаемость **всех** текстовых элементов на **любой** заливке
в обеих темах.

## Лучшие практики, на которые опираемся

| Практика | Источник | Применение |
|---|---|---|
| Относительная люминанс и коэффициент контраста 4.5:1 (AA) / 7:1 (AAA) | WCAG 2.1 SC 1.4.3 | `contrast.rs`: `relative_luminance`, `contrast_ratio` |
| Auto-contrast (выбор чёрного/белого текста по фону) | Chrome DevTools «contrast auto», Material «on-color» | `pick_ink`, `ThemeColors::ink_candidates` |
| Светло-тонированные карточки на светлом канвасе (пастели + тёмный текст) | Obsidian canvas (light-пресеты), JSON Canvas spec | `PRESET_COLORS_LIGHT` |
| Сохранение оттенка акцента при починке контраста | Material tonal palette (тон без смены hue) | `ensure_contrast`: смешение к экстремуму, не замена цвета |
| Запас над минимумом (комфортная цель ~6:1 вместо ровно 4.5) | Apple HIG «dynamic type/contrast», Deque «beyond AA» | цель поиска `target + 1.5` |

## Решение (How)

### 1. Тема-зависимые палитры пресетов (`cards.rs`)

`PRESET_COLORS` → `PRESET_COLORS_DARK` (прежние тона, без изменения вида)
+ `PRESET_COLORS_LIGHT` (пастели под тёмный текст, ≥ 7:1 с заголовком
светлой темы). Тёмный жёлтый пресет «3» затемнён `[0.45,0.41,0.20] →
[0.42,0.38,0.19]` — единственный из старых, кто не дотягивал до AA
(4.47:1). Связи (`edge.color`) намеренно парсятся **без темы**
(`parse_color_raw`) — тёмные тона видимы на обоих фонах, а изменение
`build_edge_instances` (сигнатура, вызовы) не оправдано.

### 2. Модуль контраста (`canvas-render/src/contrast.rs`)

- `relative_luminance` / `contrast_ratio` — формулы WCAG 2.1 (unit-тесты
  на эталонах: 21:1 чёрный/белый, #767676 ≈ 4.54:1);
- `pick_ink(fill, ink_a, ink_b)` — лучшие из двух «чернил» по контрасту;
- `ensure_contrast(fg, bg, target, ink_a, ink_b)` — трёхступенчатая починка:
  1. контраст ≥ target → цвет не трогается (тема сохраняется);
  2. смешение `fg` к экстремуму с противоположной от фона стороны до цели
     `target + 1.5` (комфортная читаемость, оттенок сохраняется; +0.05
     запас покрывает квантование u8); минимальное смешение ровно до 4.5
     отвергнуто после верификации на стенде — даёт визуально «мутные»
     заголовки на тёмных заливках;
  3. экстремум не спасает (мёртвая зона средне-серых фонов ~#787878) →
     лучшие «чернила» — пара чистых чёрный/белый даёт ≥ 4.58:1 с ЛЮБОЙ
     заливкой (min-max по люминанс фона).

### 3. Точки применения (`theme.rs`, `text.rs`)

`ThemeColors::readable_on_card(color, fill, colored)` — вход починки;
ремап применяется **только к окрашенным нодам** (`named_color` вернул
заливку), неокрашенные карточки рендерятся как раньше. Группы исключены
(их заливка — `theme.group_fill`, а не цвет ноды). Обработаны все тексты
на карточке: заголовок, иконка, GFM-блоки тела (цвета запечены в кэше
`BodyItem.color` — ремап на этапе отрисовки, кэш не трогаем), построчные
результаты FR-013, программный итог, красный бейдж ошибки.

Бонус-фикс: `TextEngine::set_theme` теперь сбрасывает кэш заголовков/тел —
раньше после переключения темы блоки тела оставались в старых цветах.

### 4. Палитра выбора цвета (T7, `canvas-app`)

Свотчи пресетов в меню цвета — по теме (`icon_quads(…, theme)`): свотч
совпадает с тем, чем зальётся карточка.

## Гарантия

Краеугольный тест `theme::tests::readable_on_card_guarantees_aa_contrast_everywhere`:
серая шкала (шаг 4), сетка цветовых шумов 4×4×4, дефолтные заливки и все
пресеты обеих тем × пять типовых цветов текста — результат всегда ≥ 4.5:1.
`presets_meet_contrast_with_theme_title`: тёмные пресеты ≥ AA с
`theme.title`, светлые пастели ≥ AAA (7:1).

## Что не входит (осознанно)

- Миникарта (`NODE_COLOR_*`) — абстрактные точки-индикаторы, не текст.
- Цвета связей — декоративные линии, парсятся без темы (см. выше).
- Лейблы связей — рисуются на собственной подложке темы.
- Эги-панели (egui) — отдельная система, не в этом CR.

## Верификация на живом стенде

Стенд по `docs/DEMO.md` (Xvfb + lavapipe), сцена `examples/colors-a11y.canvas`:
6 пресетов, светлый/тёмный/средне-серый hex, дефолт; формулы, ссылки,
код, ошибка. Скриншоты обеих тем в `docs/assets/cr-007-{light,dark}.png`:
везде читаемо; кейс «светлая нода + белый текст» воспроизводится только
до фикса (светлый hex в тёмной теме теперь с тёмным текстом).
