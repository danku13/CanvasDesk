# FR-073 — Расталкивание при драге (drag push-apart) с сейф-зонами

**Статус:** выполнено (2026-09-25, сессия агента)
**Приоритет:** высокий (UX-поведение канваса, согласовано с владельцем 2026-09-25)
**Прототип:** `docs/prototypes/prototype-unified.html` (ЧАСТЬ X, коммиты 7865019, 3abd1f1) — модель отлажена в headless-браузере на реальных mouse-событиях

## Замысел

При драге ноды сквозь другие ноды они не блокируются и не накладываются, а
«расталкиваются»: уступают дорогу активной ноде и съезжаются обратно к своим
местам, если активная ушла. Если активная остановилась «между» соседями —
вытесненные получают новые якоря (их прежнее место занято). Между границами
любых двух нод всегда остаётся зазор (сейф-зона).

Модель без сил/скоростей (стабильность, детерминизм): только позиционные
коррекции со сглаживанием — pure-функция шага над позициями. Переносится в
canvas-core один-в-один из прототипа.

### Физика шага (порядок фиксирован)

1. **Возврат к якорям** — lerp `ret` (доля за шаг) для не-активных нод.
2. **Ореол активной** — выталкивание пассивных из AABB активной,
   надутого на `halo + gap/2`; пассивные — на `gap/2` (сейф-зона).
   Мягкая доля `push_frac` + жёсткий дожим до границы (стена непроницаема
   при удержании). Опциональное предиктивное упреждение по скорости курсора.
3. **Парная фаза** — `iters` итераций взаимного расталкивания пассивных
   (мягкая, доля `pair_frac`; транзиент < gap под давлением допустим).
4. **Финальный дожим ореола** — полное выталкивание до границы: парная
   фаза не должна пробивать сейф-зону активной.

### Якоря

- На старте drag: якоря всех нод = текущие позиции (поглощает любые
  внешние сдвиги между драгами — автораскладка, MCP и т.п.).
- На drop: активная закрепляется где бросили; ноды, чей якорь накрыт
  ореолом активной, получают новый якорь на вытесненной позиции
  (дополнительно разрешённый против чужих сейф-зон); остальные
  съезжаются обратно (кадровый тик пружины + keep-alive кадров).

## Точки входа

- `canvas-core/src/drag_push.rs` — новый zero-dep модуль:
  `DragPushParams`, `DragPushState`, `step`, `commit_drop`; реэкспорт в `lib.rs`.
- `canvas-core/src/settings.rs` — поля `drag_push_*` (`#[serde(default)]`,
  обратная совместимость старых config.toml), пресеты-циклы, клампы в
  `Settings::normalize`.
- `canvas-app` — хуки: `App::drag_push: DragPushState`; vel от
  `on_cursor_moved`; кадровый тик в `RedrawRequested` + keep-alive;
  `commit_drop` на отпускании; spatial index через `scene.move_node`.
- `canvas-app/src/settings_ui.rs` — новый таб «Драг» (5 строк);
  `i18n.rs` — ключи ru/en.
- `canvas-web/src/app_spawn.rs` — клампы конфига через `Settings::normalize`
  (паритет wasm ↔ натив).

## Настройки (персистентность)

Через существующий `App::persist_settings` → `config.toml` (натив) /
localStorage `canvasdesk.config` (wasm). Поля: мастер-тумблер, пресеты
сейф-зазора и ореола, упреждение, перезакрепление якорей. Тонкие константы
(`ret`, `push_frac`, `pair_frac`, `iters`) — поля `Settings` без UI-строк
(редактируются config.toml, клампятся при загрузке).

## Вне скоупа

- Edge×edge пересечения и роутинг при расталкивании (существующий edgegeom
  перерисовывает связи по новым позициям как при обычном драге).
- Совместная работа с `snap_collision` (FR-038, п.15): оба режима не
  конфликтуют (collision клампит активную, push двигает пассивных), но
  вместе смыслового синергизма не дают.

## Дополнение (2026-09-25): группы прозрачны для физики

Проверка поведения через wasm (headless-Chromium + SwiftShader, реальные
mouse-события Playwright, оракулы `?log=debug`) выявила дефект: группы-рамки
(FR-012) выталкивались ореолом активной ноды и участвовали в парной фазе.
Репродукция: драг ноды «a» в рамку группы сдвинул группу на 404px, якоря
детей перезакрепились за пределами рамки.

Решение: ноды `node.kind() == Group` полностью прозрачны для физики:

- **не пассивные** — пружина возврата, ореол активных, парная фаза и
  финальный дожим рамку не двигают;
- **не тела** — рамка не выталкивает соседей и не участвует в разрешении
  сейф-зазора при перезакреплении якорей. Мотивация: дети геометрически
  лежат ВНУТРИ рамки — участвуй группа как тело, «ребёнок против своей
  группы» толкался бы вечно; занесение ноды поверх группы — жест вставки
  FR-012, а не коллизия;
- якоря групп не перезакрепляются; драг самой группы (группа + дети =
  активные) не меняется: соседние ноды по-прежнему вытесняются ореолом.

Тесты: `group_frame_is_not_pushed`, `pair_phase_ignores_groups`,
`commit_drop_keeps_group_anchor` (canvas-core, 11 юнит-тестов модуля).
Браузерный дым `scripts/wasm_groups_test.py`: moved-кадры содержат только
ноды, якорь группы не изменился, 0 ошибок страницы (SMOKE OK).
