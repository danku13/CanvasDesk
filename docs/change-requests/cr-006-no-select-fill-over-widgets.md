# CR-006: Нажатие ЛКМ поверх виджета не должно показывать полупрозрачную заливку

- **Статус:** выявлено
- **Тип:** CR (Change Request)
- **Приоритет:** важно
- **Владелец:** агент (анализ)
- **Источник:** сообщение пользователя (сессия 2026-09-15): «при нажатии на ЛКМ поверх виджетов не должна появляться полупрозрачная заливка (сейчас это выглядит так)»
- **Связанные задачи:** CR-001 (рамка выделения — источник заливки), CR-004 (прозрачность виджет-нод), FR-009 (меню по ПКМ), WIDGETS.md §8 (airspace, клик по контенту), SPEC.md §8 (ввод)
- **Создан:** 2026-09-15
- **Обновлён:** 2026-09-15
- **Документ-шаблон:** `docs/change-requests/cr-template.md`

---

## Описание (What)

Пользователь сообщил: при нажатии ЛКМ поверх виджетов появляется
полупрозрачная заливка — её быть не должно. Требуемое поведение: нажатие
левой кнопки мыши по области виджета не создаёт никаких визуальных
полупрозрачных оверлеев поверх виджета (рамок выделения с заливкой,
подсветок-«прокрашиваний»); виджет не мигает сменой режимов рендера.
Выявил пользователь.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| `widget` | ЛКМ по контенту — без canvas-оверлеев и заливок | `docs/WIDGETS.md` §8.1, §8.5 |
| Рамка выделения (CR-001) | Не стартует с контента виджет-ноды | `docs/change-requests/cr-001-selection-multi.md` |
| `node` (выделение) | Виджет-нода выделяется только через хром (заголовок/рамка) | `docs/interface-objects/node.md` §4 |
| Фокус (T23) | Семя фокуса от виджета — не затемняет сцену при клике по контенту (open question) | `docs/plans/T23-focus-highlight.md` |
| Airspace (П7) | Поведение live→snapshot при меню/поиске не меняется | `docs/WIDGETS.md` §8.1 |

## Анализ (Root Cause)

Маршрутизация ЛКМ по виджет-ноде в текущем коде:

- **Живой виджет:** контент накрыт дочерним `WS_CHILD` HWND WebView2
  (`crates/canvas-widgets/src/host/mod.rs:8-9, 431-451`) — ввод уходит в
  WebView2, канвас нажатие не видит. Хром (заголовок 28 px, рамка 8 px —
  `crates/canvas-widgets/src/layout.rs:10-12`) — канвасу; контракт —
  `WIDGETS.md` §8.5 «клик по контенту не выделяет ноду».
- **Snapshot/placeholder-режим:** виджет-нода для канваса — обычная нода:
  `selective_hit` → `select_node_hit`
  (`crates/canvas-app/src/lib.rs:1187-1220`) **не исключает** виджет-ноды →
  клик выделяет ноду (рамка `cards.wgsl:96-97`) и начинает drag
  (`main.rs:3800-3834`).
- **Полупрозрачная заливка в коде** — рамка выделения CR-001:
  `SELECT_RECT_FILL = [0.396, 0.612, 0.969, 0.08]`
  (`crates/canvas-app/src/lib.rs:458`), рисуется поверх сцены
  (`main.rs:5258-5268`), стартует при ЛКМ **с пустого места**
  (`main.rs:3839-3845`); при её активности все live-виджеты принудительно
  уходят в снапшот (`widget_overlay_active`, `main.rs:5291-5309`).
- **Кандидаты наблюдаемой «заливки»** (точный механизм фиксируется
  инструментацией при реализации):
  1. Рамка выделения/подсветка выделением при клике по snapshot-виджету
     (см. выше) — противоречит контракту §8.5 в снапшот-режиме.
  2. Визуальный скачок live→snapshot при начале canvas-оверлеев ( airspace,
     `main.rs:5291-5309`) — контент «гаснет» в кадре, воспринимается как
     заливка/затемнение.
  3. Режим фокуса T23 (`focus_mode`, `main.rs:2413-2444`): выделение
     виджет-ноды делает её семенем — вся остальная сцена затемняется до
     `FOCUS_DIM_FLOOR = 0.35` (`cards.rs:240`).
- Примечание: готовый хит-тест зон `layout::hit_test` → `WidgetHit::
  {Content, Header, Frame, Miss}` (`layout.rs:174-199`) **не используется**
  в маршрутизации ввода канваса — он и есть механизм исправления.

## Требуемые изменения (Changes)

1. `main.rs` (Pressed-ветка): перед диспетчеризацией клика по виджет-ноде
   применять `canvas_widgets::layout::hit_test` (`layout.rs:186-199`):
   - `WidgetHit::Content` → клик уходит виджету (в live — уже так; в
     snapshot — не выделать ноду, не стартовать `select_rect`, не начинать
     drag);
   - `WidgetHit::Header`/`Frame` → прежнее поведение канваса (выделение,
     drag, resize, порты).
2. Гарантия «никаких заливок поверх контента»: при клике, начавшемся с
   `Content`, не рисовать `SELECT_RECT_FILL`-квад поверх области виджета и
   не включать `widget_overlay_active`-гашение из-за самого клика
   (`select_rect` в этой точке не создаётся — п. 1).
3. Проверить T23-фокус: семя фокуса от клика по `Content` виджета не
   включается (затемнение сцены не запускается); от хрома — как у обычных
   нод (open question — подтвердить с владельцем).
4. ПКМ-меню и взаимодействие с хромом не меняются; airspace-гашение при
   меню/поиске/диалогах (П7) остаётся как есть — оно не от ЛКМ по виджету.
5. Трассировка: tracing-событие при `Content`-клике в snapshot-режиме
   (на время приёмки) — подтвердить, что ветка больше не создаёт оверлеев.

## Открытые вопросы дизайна

- Должен ли одиночный клик по контенту snapshot-виджета переводить его в
  live (быстрый просмотр)? Предложение v1: нет — только зум/хром.
- Согласовать с CR-004: рамка выделения по контуру — единственный
  разрешённый отклик, и только от хрома.

## Проверка (Verification)

- ЛКМ (нажатие и отпускание без движения) по контенту часов/стикера/
  календаря в live и в snapshot: никакой полупрозрачной заливки, рамки,
  затемнения сцены; виджет не мигает сменой режимов.
- Drag, начатый с контента виджета, не перемещает ноду и не рисует рамку
  выделения (контент принадлежит виджету).
- Drag за заголовок (0–28 px) и рамку (8 px) — двигает/ресайзит как раньше;
  выделение по хрому работает (рамка без заливки).
- Рамка выделения CR-001 с пустого места работает как раньше (регрессия
  CR-001 не сломана); виджеты под ней по-прежнему гасятся в снапшот (П7).
- `focus_mode` (клавиша F): клик по контенту виджета не запускает
  затемнение сцены.
