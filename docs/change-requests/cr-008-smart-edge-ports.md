# CR-008: Умные порты связей — кратчайший путь и авто-переприсоединение

- **Статус:** выполнено
- **Тип:** CR (доработка существующего механизма связей)
- **Приоритет:** важно
- **Владелец:** агент (анализ + реализация)
- **Источник:** сообщение пользователя (сессия 2026-09-16): «нужно реализовать умную смену точки подключения ноды к ноде, чтобы при перетаскивании нод или их автораскладке не появлялись перепутанные связи, а связи шли по кратчайшему пути от одного порта к другому»
- **Связанные задачи:** TASKS.md T8 (связи); SPEC.md §5.1; CR-002 (перепривязка концов), CR-003 (зона портов), FR-010 (авто-раскладка), FR-014 (value-рёбра)
- **Создан:** 2026-09-16
- **Обновлён:** 2026-09-16 (аудит реализации)

## Описание

Связь хранит стороны подключения (`fromSide`/`toSide`) в момент создания и
больше их не меняет. После перетаскивания нод или авто-раскладки (FR-010)
связь остаётся прицепленной к «старым» портам: линия разворачивается петлёй,
обходит ноду сзади, входит в порт, смотрящий от получателя. Требуется, чтобы
стороны подключения пересчитывались по взаимному положению нод: связь всегда
выходит из ближайшего порта истока и входит в ближайший порт стока
(кратчайший путь), а явный выбор порта пользователем можно закрепить.

## Влияние

| Объект | Что меняется | Где в документации |

| Рендер | Кривая, стрелка, хэндл перепривязки (CR-002), лейблы — по эффективным сторонам | `docs/interface-objects/edge.md` §3 |

## Анализ

- `crates/canvas-core/src/edgegeom.rs:159` — `edge_curve()` использует
  сохранённые `edge.from_side`/`edge.to_side` безусловно; `nearest_side`
  применяется только к `None`-сторонам (файлы без сторон).
- `crates/canvas-core/src/edgegeom.rs:184` — `edge_endpoint()` (хэндл
  перепривязки CR-002) — та же логика.
- `crates/canvas-core/src/model.rs:349` — `Edge::from_side`/`to_side`
  (`Option<Side>`, JSON Canvas `fromSide`/`toSide`); стороны пишутся один
  раз при создании (`create_edge`, `main.rs:6231`) и при `retarget_edge`.
- `crates/canvas-app/src/main.rs:6270` — `apply_related_layout` (FR-010)
  двигает ноды, но связи не пересматривает: порты остаются старыми.
- Отсутствует: функция парного выбора сторон (существующий `nearest_side`
  выбирает сторону каждой ноды независимо — даёт пары вида Left→Left), и
  признак закрепления конца в модели (`Edge.extra`).

## Требуемые изменения

1. **`canvas-core/edgegeom.rs`** — `best_sides(from, to) -> (Side, Side)`:
   перебор 4×4 пар портов, стоимость = расстояние между портами + штраф за
   «спиной» порт (нормаль смотрит от другой ноды) + штраф за одинаковые
   стороны; детерминированный tie-break. `effective_sides(edge, from, to)` —
   склейка: закреплённый конец берёт сохранённую сторону, свободный — сторону
   из `best_sides`. `edge_curve`/`edge_endpoint` переходят на
   `effective_sides`.
2. **`canvas-core/model.rs`** — `Edge::port_pins() -> (bool, bool)` /
   `set_port_pin(end, pin)` / `clear_port_pins()`: расширение
   `extra["canvasdesk"]["pin_ports"] = ["from", ...]`; удаление пустых
   контейнеров — по образцу `set_flow_kind` (чистый round-trip).
3. **`canvas-app`** — палитра связи: группа «Порты» (авто/закрепить исток/
   закрепить сток); закрепление фиксирует текущие эффективные стороны в
   `fromSide`/`toSide` (WYSIWYG) + ставит `pin_ports`; действия — undo-шаг.
   Перепривязка конца (CR-002) остаётся явным жестом: пишет сторону целевой
   стороны, состояние пина не меняет.
4. **`canvas-mcp`** — инструмент `edge_ports {id, pin: auto|from|to|both}`.
5. **Рендер/hit-test/MCP-геометрия** — без отдельных триггеров: пересчёт
   происходит в `edge_curve` на каждом кадре (drag, раскладка, загрузка —
   единый путь), полилиния рендера и hit-test совпадают по построению.
6. **Документация** — `edge.md` (§2/§3/§4/§5/§7), `SPEC.md` §5.1
   (`canvasdesk.pin_ports`), этот CR → «выполнено».

## Проверка

- Нода B справа от A: связь A→B выходит из Right, входит в Left; перенести B
  влево за A — связь переприсоединяется к A.Left → B.Right (тест
  `best_sides` + интеграционный).
- B ниже A (доминанта по Y): порты Bottom/Top соответственно.
- Диагональ: доминирующая ось по компонентам между центрами портов.
- Сохранённые `fromSide`/`toSide` не переписываются на диске при
  перетаскивании (auto влияет только на отрисовку); round-trip файла —
  байт-в-байт по сторонам.
- Закрепление конца через палитру/MCP: сторона фиксируется (текущая
  эффективная), записывается в файл; «Авто» снимает все пины.
- MCP `edge_ports`: unknown id → isError.
- Гейты: `cargo fmt --check`, `clippy --workspace --all-targets
  -D warnings`, `cargo test --workspace` — зелёные.
