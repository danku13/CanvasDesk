## Решения владельца (Q&A)

**Вопрос Q3 (сессия 2026-10-08): «Как отображать ноду, где входящие значения уже использованы в формуле (`sum = $1 × $2`)?»** (владелец предупреждён: скрытие входов — зафиксированное решение fr-050 Р-4, потребуется его пересмотр)

| Вариант | Суть |
|---|---|
| **Входы + расчёт ← выбрано** | Входящие значения остаются видимы всегда (компактно), `sum = …` помечается как РАСЧЁТ (маркер ƒ), не как параметр |
| Чип входов | Входы схлопываются в чип «2 входа: qty, price» (раскрывается по клику), расчёт — отдельной строкой |
| Только расчёт | Входы скрыты (как сейчас), но строка расчёта помечается как расчёт с qualified-адресами источников |

---

## Описание (What)

Нода, принявшая 2 входящих значения («Общая сумма корзины»: qty × price), после ввода формулы `sum = $1 x $2` перестаёт показывать входящие значения, а строка расчёта выводится в зоне «ПАРАМЕТРЫ». Требуется: входящие параметры остаются видимы (компактно), а строка с формулой выводится как РАСЧЁТ (маркер ƒ). Выявлено владельцем при ручном тестировании.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| Авто-строки входов (flow) | Создаются всегда, даже когда слот читается формулой (пересмотр fr-050 Р-4) | `docs/change-requests/fr-050-*` |
| Тело ноды (row_grid) | `Assignment` с RHS-входами → `RowKind::Calc` (маркер ƒ), не `Param` | fr-045 R-4 |
| Метки зон | «ПАРАМЕТРЫ · N» считает только реальные параметры | `docs/interface-objects/node.md` |
| Панель stage | Классификация выравнивается с телом (единая точка) | fr-044 Р-4 |

## Анализ (Root Cause)

Полный разбор — UR-001-04. Две независимые причины:

**(A) — согласованное решение, пересматриваемое.** `auto_rows_with_data` (`crates/canvas-core/src/flow.rs:1443-1463`): слот, читаемый формулой (`$N`/`$in`/qualified — сборщик `crates/canvas-core/src/validate.rs:486-568`), не порождает авто-строку (`if read { continue }`, `:1458-1463`). Зафиксировано во fr-050 Р-4 («авто-строка — строка-проекция», fr-050:120-136); зеркало W-UNUSED-SLOT (FR-032). Панель stage входы показывает всегда (`calc_panel_ui.rs:119-151`) — расхождение поверхностей.

**(B) — «тихое» расхождение с fr-045 R-4.** `build_rows` (`crates/canvas-render/src/row_grid.rs:519-531`): `Assignment { name }` → `RowKind::Param` без анализа RHS; `line_kind` проверяет только LHS (`expr.rs:2221-2227`). Строка `sum = $1 x $2` → зона «ПАРАМЕТРЫ · N» (`text.rs:1070-1078`, `:1127-1161`). В панели stage та же строка — «Расчёт · формулы» (`calc_panel_ui.rs:152-163`, `dataref.rs:411-431`). fr-045 R-4 описывает «Расчёт · формулы» как `<имя> := <формула> = <результат>` — тело ноды этому не соответствует.

## Требуемые изменения (Changes)

1. `crates/canvas-core/src/flow.rs:1453-1463` — авто-строки создаются для всех value-входов независимо от читаемости слота (входы видимы всегда); читаемость остаётся только сигналом W-UNUSED-SLOT (валидация не трогается). Обновить пиннеры `flow.rs:3690-3960`, `validate.rs:678-748`, `scene.rs:3613+`; обновить Changelog fr-050 (решение Р-4 пересмотрено CR-021).
2. `crates/canvas-render/src/row_grid.rs:523-531` — классификация: `Assignment` с RHS, ссылающимся на входы (`$N`/`$in`/qualified; готовые данные — `validate::slot_references`, `dataref::formula_displays().operand_edges`) → `RowKind::Calc`; «чистые» присваивания констант (`qty = 10`) остаются `Param`.
3. `crates/canvas-render/src/text.rs:1070-1078` (param_count) и `:1128-1130` (метки зон) — та же поправка.
4. Единая точка классификации «параметр vs расчёт» (сейчас три копии: `row_grid.rs:523`, `text.rs:1075/1130`, `calc_panel_ui.rs:156`/`dataref.rs:413-418`) — тело и панель stage классифицируют одинаково.
5. Компактность входов при росте числа строк (решение Q3 «входы видимы всегда (компактно)»): при 4+ авто-строках — сворачивание с чипом-счётчиком (деталь приёмки; не блокер v1).
6. Геометрия раскладки схем (W3-C1, фикс CJM-регрессии `geometry_clean_after_autogrow`): `crates/canvas-scene/src/scheme_apply.rs` (`presize_text_heights`) — ПЕРЕД умной раскладкой FR-071 каждая text-нода предразмеривается под консервативную оценку финальной высоты (`measure::estimated_result_reserve_height`, уровень 1, слой canvas-scene+canvas-core без canvas-render): манифестные высоты больше не участвуют в шаге сетки, авто-рост после `recompute_flow` больше не выталкивает ноду из ряда в соседа (investment-case: irr 200 → 368 налезал на growth).
