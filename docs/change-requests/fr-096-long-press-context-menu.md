# FR-096: Long-press на таче → контекстное меню (машина жеста + платформенная будилка)

- **Статус:** выполнено
- **Тип:** FR (дефект мобильного ввода → жест долгого нажатия)
- **Приоритет:** важно
- **Владелец:** агент (сессия 2026-10-03)
- **Источник:** аудит мобильной адаптации 2026-10-03; на таче нет ПКМ — контекстное меню ноды/связи/канваса недоступно вовсе (в FR-092/093 явно помечено «за скопом»)
- **Связанные задачи:** FR-092 (машина TouchGesture), FR-093 (двойной тап/press_from_touch), FR-052 (глушение жестов над UI)

## Описание

Контекстное меню — основной маршрут операций над нодой/связью (удалить,
узкие места, пин и пр.); на тач-устройствах эквивалента ПКМ не было.
Решение — стандартный жест canvas-приложений: удержание пальца ~550 мс
без движения открывает меню в точке касания.

Двухуровневая конструкция:

1. **Машина жеста** (`canvas-core/src/touch.rs`, чистая, детерминированная):
   `Action::LongPress([x; 2])` — физ. px точки касания. Константы
   `LONG_PRESS_MS = 550` (больше интервала двойного тапа 500 мс — быстрый
   двойной тап не схлопывается с long-press) и `LONG_PRESS_SLOP = 12` лог. px
   (движение дальше — это уже драг, кандидат снимается). Выдача — один раз
   за жест: через `step` (Move-дрожание после порога) и через
   `poll_long_press(now_ms)` (тик будилки). После выдачи Move подавляется
   до отпускания (меню открыто — случайные драги не нужны), отпускание —
   `Action::Cancel` (не клик). Второй палец/pointercancel отменяют
   кандидата вместе с одиночным жестом (механика Cancel FR-092).
2. **Платформенная будилка** (`canvas-web/src/touch_platform.rs`): палец без
   движения событий касания не рождает — время доставляет платформа.
   canvas-app инкрементирует `web_bridge::TOUCH_PRESS_GEN` на каждом
   `Action::Press`; canvas-web: setInterval 50 мс замечает смену поколения →
   setTimeout(`LONG_PRESS_MS + 25`) → `AppEvent::LongPressPoll` (wasm32-гейт
   на варианте и матч-руке). Решение — за машиной (`poll_long_press`
   защищён: палец поднят/ушёл за slop/второй палец/уже выдано — тишина),
   лишние тики бесплатны, таймеры не отменяются.

Маршрут в App (`on_touch_long_press`, wasm32): тот же, что у десктопной ПКМ —
`on_right_button(Pressed)` в точке касания (меню ноды/связи/параметра или
пустого канваса). Начальное нажатие тача уже прошло мышиный пайплайн FR-092;
цепочка двойного тапа разрывается (`DoubleClick::reset`) — нажатие, открывшее
меню, не сцепляется со следующим тапом в «двойной тап создания заметки».

## Влияние

| Объект | Что отсутствовало | Где |
|---|---|---|
| canvas-core | жест долгого нажатия в машине TouchGesture | `touch.rs` (+ `poll_long_press`) |
| canvas-web | будилка порога для неподвижного пальца | `touch_platform.rs` (новое), `web_bridge.rs` (новое) |
| canvas-app | маршрут LongPress → контекстное меню | `app/handler.rs`, `app/input.rs`, `lib.rs` (`DoubleClick::reset`) |

## Приёмка

- Юнит-тесты машины (натив CI): срабатывание после удержания (ровно на
  пороге, один раз); быстрый тап — нет; движение за slop — нет (жест
  остаётся драгом с клик-семантикой Release); дрожание в пределах допуска
  после порога — LongPress вместо Move, Move после выдачи подавлен,
  отпускание — Cancel; второй палец отменяет кандидата; poll защищён
  после пинча; track привязан к пальцу, начавшему одиночный жест.
- Гейты: fmt, clippy -D warnings (натив + wasm32), test --workspace,
  wasm_gate --check.
- Ручной сценарий (телефон): удержание на ноде → меню ноды; на пустом
  месте → меню канваса; быстрый тап/драг — без меню; после long-press
  следующий одиночный тап не создаёт заметку.

## Точки входа

- `crates/canvas-core/src/touch.rs` — машина, константы, тесты.
- `crates/canvas-core/src/web_bridge.rs` — мост `TOUCH_PRESS_GEN`.
- `crates/canvas-web/src/touch_platform.rs` — будилка (setInterval→setTimeout).
- `crates/canvas-app/src/app/handler.rs` — `AppEvent::LongPressPoll` (wasm32).
- `crates/canvas-app/src/app/input.rs` — `on_touch_long_press`, bump поколения.
