## Решения владельца (Q&A)

**Вопрос (сессия 2026-10-08): «Какой объём фикса звёздочки делать?»**

| Вариант | Суть |
|---|---|
| **Полный фикс ← выбрано** | Не экранировать одиночный `*` в Numi-строках (детект `expr::line_kind`), italic-пару ограничить строкой, expr снимать `\*` для старых заметок |
| Минимальный | Только expr снимает `\*` — старые заметки считаются, но при наборе `*` снова экранируется |
| Без экранирования везде | Убрать авто-экранирование `*` во всём тексте (настоящие markdown-курсивы в прозе сломаются) |

---

## Описание (What)

В Numi-строке знак умножения `*` «неадекватно отрабатывает»: при вводе `sum = 10 * 2` появляется красная ошибка, значение не считается; владелец вынужден писать `x` вместо `*` (репродуктор: `sum = $1 x $2`). Требуется, чтобы `*` работал в Numi-строках без экранирования. Выявлено владельцем при ручном тестировании.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| Редактор заметки / канонизация markdown | `*` не экранируется на Numi-строках; italic-парность не переходит `\n` | `docs/interface-objects/node.md` (редактирование) |
| Numi-движок | Снятие `\*` при парсе (совместимость старых заметок) | `docs/change-requests/fr-013-text-node-numi-expr.md` |
| Пользовательская документация | Контракт `user-docs/calculations.md:42` («Умножение — звёздочкой») начинает выполняться фактически | `user-docs/calculations.html` |

## Анализ (Root Cause)

Полный разбор — UR-001-01. Кратко:

1. Движок поддерживает `*` полностью (`Tok::Star` expr.rs:1024-1029; `BinOp::Mul` expr.rs:1341-1390; тесты expr.rs:3675-3732). Ломает канонизация.
2. `escape_mask` (`crates/canvas-render/src/markdown.rs:427-441`, строка 432) экранирует **каждый одиночный `*` безусловно** — «тихое» решение коммита d434c41 (фикс для `=`), с предупреждением в комментарии (markdown.rs:421-426), что экранирование ломает expr-парсер.
3. Expr снимает только `\=` (`expr.rs:1593`) → лексер падает на `\`: «неподдерживаемый символ» (`expr.rs:1160-1167`); ошибка видима уже при наборе (live-результаты по `session.text()`).
4. Вторично: парный italic-тоггл ищет закрывающий `*` через `\n` (`markdown.rs:44-46, 86-101`) — `*` в разных строках теряются при рендере.

## Требуемые изменения (Changes)

1. `crates/canvas-render/src/markdown.rs:427-441` — маска экранирования построчная; на Numi-строках (детект `canvas_core::expr::line_kind`, уже импортируется в text.rs/edit.rs) одиночный `*` не экранируется; пары `**` можно экранировать только в прозе.
2. `crates/canvas-render/src/markdown.rs:44-46, 86-101` — `has_marker_ahead`/парный тоггл italic не пересекают `\n` (симметрично с `==`, если применимо).
3. `crates/canvas-core/src/expr.rs:1593` — `source.replace("\\*", "*")` рядом с `\=` (оживление уже сохранённых заметок); то же в `line_kind` (`expr.rs:2211`).
4. Тесты: round-trip `sum = 10 * 2` (набор → коммит → значение 20), кейс из `live_typing_flow_owner_sheets` дополнить строкой с `*`; markdown-тест прозы `a*b` вне Numi-строк сохраняет экранирование.
