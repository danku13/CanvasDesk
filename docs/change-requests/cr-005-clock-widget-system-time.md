# CR-005: Виджет часов не отображает время (должно браться из системы)

- **Статус:** в работе
- **Тип:** CR (Change Request)
- **Приоритет:** критично

- **Источник:** сообщение пользователя (сессия 2026-09-15): «виджет часов не отображает часы. должен брать время из системы»
- **Связанные задачи:** TASKS.md T20–T22 (движок виджетов M5), SPEC.md §7.6, WIDGETS.md §7 (LOD), §10 (отладка), CR-004 (прозрачность), CR-006 (ввод)

## Описание (What)

Пользователь сообщил: виджет «Часы» не отображает часы; время должно браться
из системных часов ОС. Вместо тикающего времени пользователь видит
либо пустую/статичную карточку, либо заглушку. Требуемый результат: часы
показывают актуальное системное время (ЧЧ:ММ:СС + дата) всегда, когда
виджет-нода видима на канвасе, — как в live-режиме, так и в снапшот-режиме.

## Влияние (Impact)

| Объект | Что сломано | Где в документации |
|---|---|---|
| Виджет `com.canvasdesk.clock` | Время не отображается / не обновляется | `docs/WIDGETS.md` §7 (LOD), §10 (симптомы) |
| LOD-конвейер виджетов | Подозреваемые фазы: live-переход, захват/refresh снапшота | `docs/SPEC.md` §7.6 |

| Лог хоста | Нет явного маркера причины «часы не тикают» | `docs/WIDGETS.md` §10 (маркеры) |

## Анализ (Root Cause)

JS-логика виджета **корректна по коду** — дефект на стороне хост-пайплайна:

- `assets/widgets/clock/app.js:19-28` — `render()` берёт системное время
  `new Date()` (часы/минуты/секунды + дата `ru-RU`); `tickLoop` (30-34) —
  `setInterval(render, 1000)`; `onVisibility` (43-45) — таймер гасится в
  снапшоте и возобновляется в live. Заглушка до первого рендера —
  статичный текст «--:--:--» (`assets/widgets/clock/index.html:31`).
- Следовательно «нет часов» = виджет либо не рендерится вовсе, либо
  рендерится застывшим. Кандидаты в порядке правдоподобия:
  1. **Рантайм WebView2 недоступен** → `Target::Placeholder`
     (`crates/canvas-widgets/src/lod.rs:143-155`, `59-63`) — серая карточка
     с именем вместо контента; типовой симптом из `WIDGETS.md` §10
     («Установился, но серый плейсхолдер — нет рантайма WebView2 Evergreen»).
  2. **Виджет не входит в live** — зум < `LIVE_ENTER_ZOOM = 0.27`
     (`lod.rs:11`, гистерезис `198-208`), перекрыт оверлеем (`overlaid`),
     лимит 6 live исчерпан (`lod.rs:15`, LRU-план `105-195`) — пользователь
     видит снапшот; если снапшот не захвачен/не обновляется — видна
     заглушка «--:--:--». Refresh снапшота требует suspended + visible +
     не overlaid + zoom ≥ 0.25 + интервал 5 с (`lod.rs:181-185`).
  3. **Снапшот захвач до первого `render()`** — финальный `CapturePreview`
     при уходе из live (`lod.rs:70-73`) может зафиксировать «--:--:--»,
     если страница ещё не отрисовала время; без refresh пользователь видит
     заглушку сколь угодно долго.
- Диагностика на машине пользователя обязательна: лог хоста
  (`RUST_LOG=debug`, маркеры `WIDGETS.md` §10: «встроенный виджет
  материализован», ошибки создания child HWND в
  `crates/canvas-widgets/src/host/mod.rs:451`).

## Требуемые изменения (Changes)

1. **Диагностика (первый шаг):** tracing-инструментация переходов LOD по
   виджет-нодам — строка `node_id, was→target, причина` (zoom, overlaid,
   package_ok, runtime_ok) при каждом изменении; маркер при захвате
   снапшота (размер, тик). Цель — воспроизводимая причина на машине
   владельца.
2. **Инвариант «часы всегда актуальны»:** для виджетов с «живыми» данными
   (часы) — гарантировать, что снапшот не старше `SNAPSHOT_REFRESH_SECS`
   (`lod.rs:21`) при видимой ноде; убедиться, что первый снапшот
   захватывается **после** первого `render()` страницы (например,
   захват по `ready` + один кадр, а не мгновенно).
3. **Рассмотреть (open question):** хост при `init`/`visibility(true)`
   передаёт текущее системное время хоста в params моста (host→widget,
   расширение `WIDGETS.md` §4) — виджет стартует с верного времени и
   сверяется, защита от «замороженных» интервалов WebView2.
4. Если причина — отсутствие рантайма WebView2: placeholder уже корректен,
   в HUD/toast при добавлении виджета показывать понятное сообщение
   (усиление `WIDGETS.md` §10), CR закрывается обоснованием среды.

## Проверка (Verification)

- На машине с WebView2 Evergreen: виджет часов показывает ЧЧ:ММ:СС и дату,
  совпадающие с системными часами (допуск ±1 с), тикают каждую секунду.
- Зум вниз (выход из live, `LIVE_EXIT_ZOOM = 0.23`) и обратно: снапшот
  не «замирает» дольше 5 с; после возврата в live время продолжает тикать.
- Открытие меню/поиска/диалога поверх виджета (airspace): после закрытия
  время актуально, не сбрасывается на «--:--:--».
- Перезапуск приложения: первый кадр виджета — с актуальным временем
  (не заглушка).
- Лог хоста содержит причину каждого перехода live/snapshot/placeholder.
