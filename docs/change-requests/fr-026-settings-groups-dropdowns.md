## Описание (What)

Панель настроек (кнопка ⚙ / `Ctrl+,`) — плоский список из 8 строк:
настройки разных областей (сетка, связи, поведение окна) перемешаны, а
многозначные настройки переключаются **циклом по клику** («Вид сетки:
линии → точки», «Угол кнопки: 4 клика на оборот», «Зона портов: 5
пресетов»). Пользователь не видит полный набор значений настройки и не
видит логической структуры: с ростом числа настроек (FR-025 добавит
`line_ports`) плоский список деградирует.

Требуется: (1) **группы** — логические секции с заголовками («Канвас»,
«Связи и порты», «Приложение»), визуально отделённые; (2) **выпадающие
меню** — клик по многозначной строке открывает список всех значений с
отметкой текущего (выбор кликом), вместо слепого цикла. Булевы настройки
остаются переключателями по клику (цикл из двух значений — это тумблер,
меню избыточно). Схема `config.toml` не меняется — это реорганизация UI.

## Исследование бест-практик (Research)

Источники:

- macOS System Settings / VS Code Settings UI: настройки группируются по
  областям с заголовками секций; многозначные настройки — нативные
  dropdown/select со списком всех значений и галочкой/подсветкой текущего.
- HIG (Apple Human Interface Guidelines) «Pop-Up Buttons»: закрытое
  состояние показывает ТЕКУЩЕЕ значение на самой строке; открытие — по
  клику на строку; список появляется рядом (ниже), клампится к границам;
  выбор — клик или клавиатура (↑/↓ + Enter); закрытие — Esc/клик вне.
- Miro/Figma preferences: секции с небольшими заголовками-капсами и
  увеличенным межсекционным отступом; строки внутри секции — единая
  сетка (одинаковая высота, одинаковый отступ), hover-подсветка
  кликабельных строк.

Применение к CanvasDesk: панель сохраняет текущий паттерн (screen-space
оверлей, строки-циклы для булевых), секции — заголовки-капсы с отступом;
многозначные строки — попап-меню по образцу контекстного меню
(`ContextMenu.submenu` — готовый in-repo паттерн колонки с пунктами).

## Анализ (Root Cause — чего нет в коде)

Групп и dropdown'ов нет — новая организация UI. Точки опоры:

- **Плоский список.** `SETTINGS_ROWS: [SettingsRow; 8]`
  (`crates/canvas-app/src/lib.rs:108`) — порядок отображения;
  высота панели `panel_height()` (`lib.rs:214-219`) = заголовок +
  8 строк + подсказка; hit-тест `panel_row_at` (`lib.rs:237-248`) —
  индекс по вертикали. Ни секций, ни их заголовков.
- **Цикл по клику.** `apply_settings_row` (`crates/canvas-app/src/main.rs:4391-4436`):
  каждая многозначная настройка — `.next()` по значению
  (`Corner::next`, `GridStyle::next`, `GridDensity::next`,
  `next_port_zone`); полного списка значений UI не показывает.
- **Рендер — строки-лейблы.** `settings_overlay` (`main.rs:4440-4610`):
  `row.label(&self.settings)` в одной колонке; hover — по строке.
- **Готовый паттерн попапа-колонки.** Контекстное меню и подменю:
  `ContextMenu.submenu: Option<Submenu>`, `submenu_rect`,
  `submenu_item_at` (`crates/canvas-app/src/lib.rs:265-291,1073-1080`) —
  screen-space колонка с пунктами и hit-тестом; клавиатурные попапы —
  `hints_ui::popup_layout` (FR-021, кламп к окну).
- **Рост списка уже начался.** FR-025 добавит `SettingsRow::LinePorts`
  (девятая строка) — без группировки панель станет нечитаемой.

## Требуемые изменения (Changes)

### 1. Чистый модуль `settings_ui.rs` (образец `hints_ui`/`template_ui`)

- Модель групп: `SETTINGS_GROUPS: &[SettingsGroup]` — `SettingsGroup {
  title: &'static str, rows: &[SettingsRow] }`. Распределение (v1):
  - **«Канвас»**: Grid, GridStyle, GridDensity;
  - **«Связи и порты»**: EdgesAvoid, PortZone, FocusMode, LinePorts (FR-025);
  - **«Приложение»**: ButtonCorner, HudOnStart.
  Тема остаётся кнопкой у ⚙ (вне панели) — как сейчас.
- Вид строки: `row_kind(SettingsRow) -> RowKind` — `Toggle` (булевы:
  Grid, EdgesAvoid, FocusMode, HudOnStart, LinePorts) или `Dropdown`
  (многозначные: ButtonCorner, GridStyle, GridDensity, PortZone).
- Меню значений: `dropdown_options(SettingsRow, &Settings) ->
  Vec<(String /*значение*/, bool /*текущее*/)>` — полный список
  значений настройки с отметкой текущего (источники — существующие
  `label()`/`PORT_ZONE_PRESETS`/циклы `.next()`; сами циклы остаются
  для тестов инвариантов).
- Состояние: `DropdownState { open_row: Option<usize>, items: Vec<…>,
  selected: usize }` в `App`; сброс при закрытии панели.
- Геометрия: `panel_layout(viewport, corner) -> PanelLayout` — позиции
  заголовков и строк (высота панели = текущая формула + заголовки секций
  + межсекционные отступы); `dropdown_layout(panel, row, count,
  viewport) -> [f32; 4]` — колонка меню у строки (ниже, при нехватке —
  выше), кламп к окну (паттерн `hints_ui::popup_layout`).
- Hit-тесты: `row_at(layout, point) -> Option<(group, row)>`,
  `dropdown_item_at(state, layout, point) -> Option<usize>` — чистые,
  с тестами.

### 2. Рендер (`settings_overlay`)

- Заголовки секций: капс-текст меньшим кеглем (`palette.icon`),
  межсекционный отступ; строки — как сейчас (hover-подсветка), у
  dropdown-строк справа — аффорданс `▾`.
- Выпадающее меню — поверх панели (screen-space, паттерн подменю
  контекстного меню): подложка `palette.menu_fill`, строка пунктов,
  текущее значение — галочка/акцент; hover-подсветка пункта.

### 3. Ввод (`on_click`, клавиатура)

- Клик по булевой строке — как сейчас (`apply_settings_row`, тумблер).
- Клик по dropdown-строке — открыть меню (не менять значение); клик по
  пункту — применить значение (обёртки `set_corner`/`set_grid_style`/… —
  те же побочные эффекты, что в ветках `apply_settings_row`:
  `renderer.set_grid_dots`, `set_grid_steps` и т.д.) и закрыть; клик вне
  меню/строки — закрыть меню (панель остаётся открытой).
- `Esc` при открытом меню — закрыть ТОЛЬКО меню (повторный `Esc` —
  закрыть панель; семантика как у popup FR-021); `↑/↓` + `Enter` в
  открытом меню — выбор с клавиатуры (v1 — желательно, открытый вопрос).
- Файл конфига сохраняется тем же хвостом (`settings.save(config_path)`).

### 4. Совместимость и регрессии

- Схема `config.toml` и все поля — без изменений; существующие тесты
  `settings.rs` не трогаются.
- `panel_row_at`/`panel_height` заменяются на layout-версии; старые
  функции удаляются вместе с их тестами (обновление тестов `lib.rs`).
- Переключение угла кнопки (`ButtonCorner`) в dropdown-меню переносит
  панель вместе с кнопкой — меню закрывается при перепривязке панели
  (состояние привязано к строке, а не к экранной точке).

## Архитектура тестируемости (инварианты FR-026)

1. **Инвариант полноты:** union строк всех групп == `SETTINGS_ROWS`
   (ни одна настройка не потеряна и не задублирована).
2. **Инвариант значений:** `dropdown_options` содержит текущее значение
   каждой настройки ровно один раз; выбор пункта эквивалентен
   соответствующему числу `.next()` (значения совпадают с циклами).
3. **Инвариант клампа:** меню при любом `viewport` и любом угле панели
   целиком внутри окна (`dropdown_layout` — тест на 4 угла + узкие окна).
4. **Инвариант булевых:** `RowKind::Toggle` для всех `bool`-полей
   `Settings`; dropdown для остальных.

## Открытые вопросы дизайна

- **Свёртываемость групп** (v1 — нет): заголовки всегда видны; свёртка
  секций с сохранением в `config.toml` — v2 (новые поля состояния UI).
- **Клавиатура dropdown** (↑/↓/Enter) — v1 желательно; если мешает — v2.
- **Ширина меню** — по самому длинному пункту с клампом к ширине панели
  (решить на макете).
- **Позиция панели при смене угла** — открытое меню закрывается
  (v1); сохранение открытого меню у новой позиции — v2.
- **Поиск по настройкам** (VS Code-стиль) — вне скоупа этого FR.

## Проверка (Verification)

### Юнит-тесты (settings_ui)

- Полнота групп: union rows == `SETTINGS_ROWS`, порядок стабилен.
- `dropdown_options`: для ButtonCorner — 4 угла (текущий помечен),
  GridStyle — 2, GridDensity — 3, PortZone — 5 пресетов; для тумблеров —
  None/пусто.
- Эквивалентность выбора циклу: выбор пункта `i` == `k` нажатий `.next()`
  (значение и лейбл совпадают).
- `dropdown_layout`: кламп к окну на 4 углах панели и узком окне
  (320×240); меню не перекрывает свою строку целиком (видно её верх).
- Hit-тесты: `row_at` по заголовку секции — None; `dropdown_item_at`
  вне меню — None.

### Юнит-тесты (app/settings)

- Схема `config.toml` не изменилась: round-trip дефолтов байт-в-байт с
  текущей версией; `field_names_snake_case` — прежний набор полей.
- Сброс состояния: закрытие панели сбрасывает `DropdownState`.

### Ручная приёмка

- Панель показывает три секции с заголовками; тумблеры переключаются
  кликом; «Угол кнопки» открывает список 4 углов, текущий отмечен;
  выбор «нижний левый» — панель и кнопка переезжают, меню закрыто.
- «Зона портов» — список 5 пресетов; выбор применяет значение и радиус
  портов меняется (рендер читает настройки).
- Меню у нижнего края окна открывается ВЫШЕ строки, не выходя за окно;
  `Esc` закрывает только меню; клик вне — закрывает меню, панель открыта.
