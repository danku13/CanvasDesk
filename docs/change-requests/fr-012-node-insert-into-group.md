# FR-012: Вставка ноды в группу перетаскиванием («втягивание» с расширением группы)

- **Статус:** выполнено
- **Тип:** FR (Feature Request)
- **Приоритет:** важно
- **Владелец:** агент (анализ)
- **Источник:** сообщение пользователя (сессия 2026-09-15): «функция вставки ноды в группу. Группа по умолчанию сама не подвязывает ноду если та ложится поверх неё случайным образом. пользователь переносом ноды на группу инициирует "втягивание" ноды, нода группы должна автоматически расширятся мягко раздвигая остальные ноды вокруг себя»
- **Связанные задачи:** FR-006 (undo), FR-010 (мягкое позиционирование), CR-001 (drag набора), SPEC.md §5.1 (модель), node.md §2 (тип `group`)
- **Создан:** 2026-09-15
- **Обновлён:** 2026-09-16 (аудит реализации)
- **Документ-шаблон:** `docs/change-requests/cr-template.md`

## Описание (What)

Пользователь запросил функцию вставки ноды в группу. Ключевые требования:

1. **Случайное попадание ноды поверх группы не подвязывает её** — группа по
   умолчанию «сама не забирает» ноду, оказавшуюся на ней случайно.
2. **Явный жест «втягивания»:** пользователь перетаскивает ноду на группу —
   этим он инициирует вставку.
3. **Авторасширение группы:** при вставке rect группы автоматически
   расширяется, **мягко раздвигая** остальные ноды вокруг (без резких
   скачков).

## Анализ (Root Cause)

- **Membership сегодня чисто геометрический и неявный:** `group_children`
  (`crates/canvas-core/src/model.rs:445-465`) — «дети = ноды, чей центр
  лежит внутри rect группы»; `translate_group` (`model.rs:425-439`)
  переносит всех геометрических детей вместе с группой. Пользовательское
  намерение нигде не выражается: нода, случайно занесённая поверх группы,
  фактически становится ребёнком — это и есть конфликт с требованием «не
  подвязывать случайно».
- **Контракт v1 зафиксирован** в тестах: `integration_groups.rs:1-8`
  («Дети определяются геометрией (центр внутри rect группы)») — FR-012
  меняет контракт, тесты мигрируют.
- **Жеста drop-на-группу нет:** drag-конвейер — `DragState`
  (`main.rs:3822-3833`) на Pressed, применение на Released
  (`main.rs:3849+`); логики «цель = группа» нет. «Сгруппировать» создаёт
  группу по bbox выделения (`plan_group_around`/`plan_group_at`, `lib.rs`;
  `integration_groups.rs:58-66`), `GROUP_PADDING` — константа `ui`.
- **Расширения группы при добавлении нет:** rect группы статичен после
  создания; анимационные примитивы для «мягкости» есть —
  `ease_out_cubic`, `Flight` (`crates/canvas-render/src/animate.rs:8-79`).

## Требуемые изменения (Changes)

1. **Жест «втягивания»:** во время drag ноды — если центр ноды попадает в
   rect группы (и нода не ребёнок этой группы), подсветить зону группы
   (оверлей по образцу зоны дропа T9, `DROP_GHOST_FILL` — `cards.rs:579`);
   на Released внутри зоны — вставка. Порог намеренности (время удержания
   над группой ≥ ~150 мс ИЛИ перекрытие ≥ половины площади ноды) —
   уточняется реализацией; drag набора (CR-001) вставляет весь набор.
2. **Авторасширение группы:** после вставки rect группы = bbox(дети) +
   `GROUP_PADDING` по всем сторонам; анимация перехода rect'а ~200 мс
   (`ease_out_cubic`).
3. **Мягкое раздвигание:** ноды вне группы, чьи bbox пересекаются с новым
   rect группы, сдвигаются наружу на минимальный вектор разрешения
   пересечения (по осям, без пересечений между собой), с той же анимацией;
   ноды без пересечений не двигаются.
4. **Неявное membership убрать** (требование 1) — один из вариантов
   хранения (решение в анализе реализации):
   - (a) **явный список детей** — расширение ноды группы в `.canvas`
     (образец `CanvasdeskExt`, round-trip сохраняет неизвестные поля);
   - (b) **геометрия + жест:** детьми считаются только ноды, вставленные
     жестом; вышедшая за rect нода перестаёт быть ребёнком.
   Вариант (a) рекомендован: предсказуемость и совместимость с «случайными»
   перемещениями внутри группы.
5. **Обратный жест (минимум v1):** drag ребёнка наружу за rect группы с
   отпусканием вне зоны → удаление из детей (для варианта (b) —
   автоматика).
6. `translate_group` (`model.rs:425-439`) переходит с геометрического
   расчёта на явный список (или гибрид) — инвариант «каждый ребёнок
   сдвигается ровно один раз» сохраняется тестом
   (`model.rs:511`).
7. Undo: один шаг — membership + позиции группы/ноды/раздвинутых соседей
   (FR-006 snapshot — покрывает автоматически).
8. Миграция тестов `integration_groups.rs` под новый контракт + новые
   тесты: втягивание, расширение, раздвигание, «случайное перекрытие не
   подвязывает».

## Открытые вопросы дизайна

- Хранение membership: вариант (a) против (b) — влияет на SPEC §5.1 и
  Obsidian round-trip (у Obsidian Canvas групп нет — дети как отдельные
  ноды совместимы в обоих вариантах).
- Вложенные группы: вставка группы-в-группу — разрешить (v1 да) —
  «вложенные группы считаются обычными нодами» (`model.rs:442-444`).
- Взаимодействие с FR-010: раздвигание соседей — разовая компенсация, не
  постоянный физический движок.

## Проверка (Verification)

- Перетаскивание ноды на группу: зона группы подсвечивается при наведении,
  после отпускания нода — ребёнок (едет вместе с группой по
  `translate_group`), rect группы расширился до bbox+padding с анимацией,
  пересекающиеся соседи мягко разъехались, несвязанные — на месте.
- Случайное перемещение ноды поперёк группы (отпускание НЕ в зоне втягивания
  или без намеренного жеста) — membership группы не изменился (главный
  регресс-тест требования 1).
- Вставка набора (CR-001 drag) — вставляются все ноды набора одним жестом.
- Undo одним шагом возвращает: membership, rect группы, позиции соседей.
- Перенос группы двигает всех явных детей ровно один раз (тест
  `translate_group_moves_children_once` адаптирован).
- Юнит-тесты: расчёт расширения bbox+padding; минимальный вектор
  раздвигания (фиксированная сцена, детерминизм); вложенные группы.
