## Решения владельца (Q&A)

**Вопрос Q8 (сессия 2026-10-08): «Что показывать в тултипе value-коннектора вместо "нода.строкаN"?»**

| Вариант | Суть |
|---|---|
| Резолв имени | «Нода.имя_переменной», fallback «строка N» для безымянных |
| **Имя + значение ← выбрано** | Дополнительно к имени текущее значение: «Цена.price = 100 rub» |
| Имя при создании | Заполнять `fromOutput` при drag и показывать только его |

---

## Описание (What)

Тултип value-коннектора (и входящие подписи нод) показывает `Нода.строка N` вместо `Нода.параметр`, хотя решением ADR-0003 канонический адрес порта — имя. Требуется: в тултипе показывать `Нода.имя_переменной` (резолв имени строки-присваивания через движок) **плюс текущее значение** — формат «Цена.price = 100 rub»; «строка N» — только fallback для безымянных строк.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| Единая точка адреса `dataref` | Резолв имени строки вместо литерала «строка N» | FR-044 (qualified-refs) |
| Тултип построчного порта | Формат «Нода.имя = значение» | `docs/interface-objects/edge.md` |
| Входящие подписи ноды | Тот же резолв | `docs/interface-objects/node.md` |
| Приоритет полей ребра | Привести реализацию к ADR-0003 (имя > индекс) или поправить ADR-0003 | ADR-0003 |
| Drag-создание рёбер (опционально) | Заполнение `fromOutput` именем присваивания | ADR-0003, FR-029 |

## Анализ (Root Cause)

Полный разбор — UR-001-10. Вердикт: причина **(а)** — drag-пути никогда не заполняют `from_output` (`crates/canvas-app/src/app/input.rs:3336`: `let from_line = from_port.and_then(|port| port.line);`; `create_edge` `app.rs:9214-9215`; `create_param_edge` `app.rs:4500-4502`; писатели `from_output` — только MCP `canvas-mcp/src/lib.rs:327-336` и autolink `explain.rs:94`), а display-пути печатают «строка N» напрямую из `from_line`, не резолвя имя: `app.rs:4076-4078`, `app.rs:4122-4128`, `dataref.rs:143-153` (захардкожен литерал `format!("строка {}", line + 1)`). Правильное имя движок уже доставает для тултипа проливания — `spill_source_field` (`flow.rs:1503-1526`, `Assignment { name }` → имя), отсюда расхождение: `Трафик.peak_rps` в одних поверхностях и `Трафик.строка 3` в других на одних и тех же рёбрах. Узкий случай **(б)**: при обоих полях реализация берёт `fromLine` (`model.rs:630-632`, `flow.rs:934`) — **противоречие ADR-0003** («при наличии обоих полей приоритет — у имени», `adr-0003:51-52`); для data-нод (fromLine — индекс строки таблицы, `flow.rs:1007-1013`) показ «строка N» вместо колонки заведомо неверен.

**Происхождение:** неполнота реализации ADR-0003 (drag-механика сознательно оставлена на индексах — «Вариант C») + «тихая» несинхронизация display-слоёв + прямое противоречие кода ADR-0003.

## Требуемые изменения (Changes)

1. `crates/canvas-core/src/dataref.rs:143-153` — `display_ref_for_edge`: при `from_line` резолвить имя строки источника через `NumiLineKind` (тот же вердикт, что `spill_source_field`, `flow.rs:1503-1526`); «строка N» — только fallback для безымянной строки; поле `tooltip` — формат «Нода.имя = значение» (значение — из уже существующего пути `stage_edge_value_text`).
2. `crates/canvas-app/src/app.rs:4076-4079` (лейбл построчного порта) и `:4122-4128` (входящие лейблы) — тот же резолв; убрать победу `from_line` над `from_output`.
3. Приоритет полей: привести `model.rs:630-632`/`flow.rs:934` к ADR-0003 (имя > индекс) **или** зафиксировать поправку в ADR-0003 (решение — при реализации, по умолчанию: имя > индекс, как согласовано в ADR).
4. Опционально (не блокер v1): заполнять `from_output` при drag от строки-присваивания (`input.rs:3336`, `app.rs:9215`, `app.rs:4501`) — устраняет причину в данных, а не только в показе.
5. Тесты: round-trip; репродуктор handtest — рёбра note-11/note-13 → note-12 дают «Кол-во товара.qty», «Цена.price» (значения `10`, `100 rub`); кейс data-ноды (оба поля) — показывается колонка, не строка.
