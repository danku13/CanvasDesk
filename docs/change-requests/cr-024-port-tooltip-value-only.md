## Решения владельца (Q&A)

**Вопрос Q7 (сессия 2026-10-08): «Что показывать на hover у коннектора простой связки (control, без передачи данных)?»**

| Вариант | Суть |
|---|---|
| **Без тултипа ← выбрано** | У контрольной связи тултипа нет вообще; адресная подпись только у value-связей (как в stage-подписях) |
| Нейтральный текст | Подпись «связь» / «link» без `out:` |
| Только при drag | Без тултипа на hover, но при drag с Shift показать «отпустите для потока значений» |

---

## Описание (What)

На hover у порта, из которого drag'ом создаётся обычная (контрольная) связь, показывается тултип `out: <нода>` — дата-семантика на коннекторе без передачи данных, что вводит в заблуждение. Требуется: тултип с адресом (`out: …`) показывается только там, где связь несёт значение; у контрольного порта тултипа нет.

## Влияние (Impact)

| Объект | Что меняется | Где в документации |
|---|---|---|
| Hover-тултип порта | Ветка `PortTarget::Out` гейтится семантикой потока; control — `None` | `docs/interface-objects/edge.md` §тултипы |
| Stage-подписи | Без изменений (гейт уже есть — эталон) | FR-042 |

## Анализ (Root Cause)

Полный разбор — UR-001-09. `port_tooltip_at` (`crates/canvas-app/src/app.rs:4184-4203`) безусловно возвращает `port_label_for(node_index, &PortTarget::Out)` → `STAGE_OUT_LABEL` = `"out: {name}"` (`app.rs:4073-4088`; `i18n.rs:1760` RU / `:2965` EN). Обычный drag от стороннего порта — control-связь (`value_flow = shift_key()`, `app/input.rs:2972-2974`); гейта по `FlowKind` в hover-пути нет (`app/handler.rs:494-502`). Эталон существует: `stage_src_label_lines` (`app/stage.rs:886-889`) — control-подписи нет. Исключение: `PortTarget::Line(None)` (футер шаблонной ноды) — drag с него всегда value (`input.rs:3291`), `out:` оправдан и не трогается.

**Происхождение:** «тихое» решение агента (hover-тултип порта не проходил ревью рода связи; непоследовательность двух реализаций одного правила).

## Требуемые изменения (Changes)

1. `crates/canvas-app/src/app.rs:4189-4203` — в `port_tooltip_at` ветка `PortTarget::Out` для стороннего порта возвращает `None` (control-порт без тултипа); ветка `inbound_label_lines` (value-сторона) сохраняется.
2. `PortTarget::Line(None)` (футер шаблона, `app.rs:4081`) — без изменений.
3. Опционально (вне v1, по решению владельца при реализации): вариант «только при drag» — подсказка «отпустите для потока значений» при Shift+drag (новый i18n-ключ).
4. Тесты: hover стороннего порта — тултипа нет; hover построчного порта value-ноды — подпись есть (UR-001-10 задаёт её формат).
