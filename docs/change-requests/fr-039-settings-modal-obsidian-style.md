- **Приоритет:** важно

## Описание (What)

Панель настроек (кнопка ⚙ / `Ctrl+,`) — узкая (300 px) панель у угла летающей
кнопки: один вертикальный список из трёх групп («Канвас», «Связи и порты»,
«Приложение») с заголовками-капс, 10 строк. Значения вплетены в текст
лейбла («Сетка: вкл»), панель растёт вниз с каждой новой настройкой
(FR-025 добавил 10-ю строку, FR-038 добавит раздел «Snap») и не скроллится.
Визуально это список строк-циклов, а не диалог настроек: нет обзорной
структуры, нет места под описание настройки, при росте списка макет
деградирует.

Требуется переработать меню настроек в стиле **Obsidian** (реорганизация UI,
прецедент — FR-026): (1) **модальное окно по центру экрана** над затемнённым
канвасом вместо панели у угла; (2) **двухпанельный макет** — слева
вертикальная навигация по разделам (иконка + название, активный раздел
подсвечен), справа — содержимое выбранного раздела; (3) **контролы как
в Obsidian** — pill-тумблеры справа от строки, dropdown-кнопки с текущим
значением, селектор темы карточками; (4) закрытие — `Esc` (двухэтапно:
меню → модалка) или клик по затемнению; (5) **адаптивный размер** —
масштабирование от окна с потолками (расчёт на десктопы Full HD и выше;
контрольные точки под планшет/телефон фиксируются константами, адаптив
под них сейчас не делается). Строки настроек получают **приглушённые
описания** под лейблами (v1); все тексты настроек — через таблицу строк
без хардкода (база локализации FR-040). Схема `config.toml` не меняется —
это реорганизация UI. Поиск по настройкам — отклонён владельцем
(2026-09-20): не реализуем.

## Исследование бест-практик (Research)

Источники:

- **Obsidian, диалог Settings**: центрированная модалка над затемнённым
  окном; левая колонка — список разделов (иконка + название; разделы ядра,
  ниже — настройки плагинов), активный раздел подсвечен; правая панель —
  заголовок раздела и строки настроек: слева название (+ приглушённое
  описание), справа контрол — pill-тумблер, dropdown, текстовое поле;
  «Base theme» — две карточки Dark/Light с подсветкой выбранной;
  закрытие — `Esc` или клик по затемнению; раздел запоминается между
  открытиями.
- **VS Code, Settings UI**: строки «название + описание слева, контрол
  справа»; поиск фильтрует строки всех разделов и показывает раздел-источник.
- **Miro/Figma, preferences**: модальные диалоги с левым таб-навигатором;
  pill-тумблеры; единая сетка строк (одинаковая высота и отступ),
  hover-подсветка кликабельных строк.

Применение к CanvasDesk: чистая модель `settings_ui` сохраняется —
`SETTINGS_GROUPS` превращаются в табы, `dropdown_options`/`apply_dropdown_value`
и `DropdownState` переиспользуются без изменений (инвариант «выбор пункта
эквивалентен циклу `.next()`» остаётся); меняются геометрия (панель у угла →
центрированная модалка) и анатомия строки (лейбл-цикл → лейбл + контрол
справа). Паттерны модальных оверлеев уже есть в репо: затемнение + карточка
по центру — онбординг (FR-028), модальный диалог, глушащий ввод, — T21.

## Анализ (Root Cause — чего нет в коде)

Модалки, левой навигации и контролов-тумблеров нет — новая форма UI.
Точки опоры и ограничения текущей реализации:

- **Панель привязана к углу кнопки.** `panel_layout` (`crates/canvas-app/src/settings_ui.rs:362-384`)
  строит rect через `ui::panel_rect` — край окна с отступом
  `SETTINGS_MARGIN` (`crates/canvas-app/src/lib.rs:119-132`). По центру
  экрана ничего не строится; единственные центрированные оверлеи —
  онбординг (`crates/canvas-app/src/app.rs:4939`, затемнение + карточка)
  и модальный диалог T21 (`crates/canvas-app/src/app.rs:8759` — rect по
  центру окна).
- **Высота фиксированной формулой, скролла нет.** `panel_height`
  (`settings_ui.rs:351-358`) = паддинги + шапка + 3 заголовка групп +
  10 строк + подсказка. Список растёт только вниз (FR-025 уже добавил
  `LinePorts`; FR-038 добавит «Snap») — у узкой панели нет запаса ни по
  ширине (описания не поместятся), ни по высоте.
- **Значение внутри лейбла, контрола нет.** `SettingsRow::label`
  (`settings_ui.rs:113-153`) — «Сетка: вкл», «Зона портов: 10 px».
  `RowKind` (`settings_ui.rs:156-176`) различает Toggle/Dropdown, но
  рендер не даёт строке контрола: единственный аффорданс — `▾` справа у
  dropdown-строк (`app.rs:6166-6175`).
- **Левая навигация отсутствует.** `SETTINGS_GROUPS` (`settings_ui.rs:88-110`)
  рендерится заголовками-капс в общем списке (`PanelEntry::Header`,
  `app.rs:6135-6145`); состояния «активный раздел» нет — в `App` только
  `settings_open: bool` + `settings_dropdown: DropdownState`
  (`app.rs:695-698`).
- **Ввод переиспользуется почти целиком.** Клики по панели —
  `app.rs:7178-7231` (приоритет открытого меню, тогглы, открытие dropdown,
  клик мимо панели — закрыть), `Esc` — двухэтапный `app.rs:6605-6615`,
  `Ctrl+,` — `app.rs:6671-6682` (с кириллической «б»), клик по ⚙ —
  `app.rs:7169-7176`. Меняется только геометрия hit-тестов (модалка вместо
  угловой панели). Гейт ввода канваса: `settings_open` глушит клики канваса
  (`app.rs:2885, 8237, 9840`) — сохраняется.
- **Тема живёт вне панели.** Поле `settings.theme` есть
  (`crates/canvas-core/src/settings.rs:158`), переключение — кнопка ☀/🌙
  рядом с ⚙ (`app.rs:5989-6015`); рендер красится через
  `ThemeColors::from_theme` (`app.rs:5960`). Раздел «Внешний вид» — чистая
  надстройка над существующим полем.
- **Dropdown-геометрия завязана на ширину панели.** `dropdown_layout`
  (`settings_ui.rs:404-423`): ширина меню = `PANEL_WIDTH` — при модалке
  ширина якоря станет шириной контрола/контент-панели, параметр уже
  напрашивается.

## Требуемые изменения (Changes)

### 1. Модель табов в `settings_ui.rs` (чистая, образец FR-026)

- `SETTINGS_GROUPS` → `SETTINGS_TABS: &[SettingsTab]` — `SettingsTab {
  title, icon, rows }`. Распределение (v1, 4 раздела):
  - **«Общие»**: ButtonCorner, HudOnStart;
  - **«Канвас»**: Grid, GridStyle, GridDensity, BottleneckOverlay;
  - **«Связи и порты»**: EdgesAvoid, PortZone, LinePorts, FocusMode;
  - **«Внешний вид»**: тема — отдельный вид контента таба (карточки),
    не строка `SettingsRow`.
  Инвариант полноты FR-026 переносится: union строк всех табов ==
  `SETTINGS_ROWS` (тема — вне инварианта, отдельное поле).
  FR-038 дополнит модель пятым разделом «Snap» — модель это допускает.
- `RowKind::Toggle`/`RowKind::Dropdown` — без изменений (все `bool` —
  тумблеры, инвариант булевых FR-026 сохраняется).
- `dropdown_options` / `apply_dropdown_value` / `DropdownState` — без
  изменений (переиспользуются в модалке).
- Геометрия: `modal_layout(viewport, tab) -> ModalLayout` — rect модалки
  по центру окна, **адаптивный размер**: ширина
  `(viewport_w * 0.45).clamp(MODAL_MIN_W, MODAL_MAX_W)`, высота
  `(viewport_h * 0.6).clamp(MODAL_MIN_H, MODAL_MAX_H)` (стартовые
  константы 560/880 × 400/640; финальные пропорции — на макете; Full HD
  1920×1080 → ~864×640), кламп к окну с `SETTINGS_MARGIN`-подобными
  полями — инвариант: модалка целиком в окне при viewport 320×240.
  Контрольные точки будущей адаптации фиксируются константами
  (`MODAL_BP_COMPACT = 1280`, `MODAL_BP_MOBILE = 768` — ширина окна) и
  документируются; поведение ниже точек в v1 НЕ реализуется (планшеты/
  телефоны — будущая адаптация). Rect'ы пунктов левой навигации, rect
  заголовка раздела, rect'ы строк активного таба, rect зоны контента.
  `panel_height`/`panel_layout`/`row_at` (угловые версии) удаляются вместе
  с их тестами — как в FR-026.
- `dropdown_layout`: ширина меню — параметр (сейчас жёстко `PANEL_WIDTH`,
  `settings_ui.rs:409`); в модалке — ширина контрола строки, кламп к окну
  сохраняется (паттерн `hints_ui::popup_layout`).

### 2. Рендер (`settings_overlay`, `app.rs:5953-6190`)

- **Затемнение**: полноэкранный квад поверх канваса под модалкой
  (полупрозрачный чёрный, ~0.4 alpha) — паттерн онбординга (`app.rs:4939`).
  Сцена T23 (`focus_dim`) не трогается.
- **Модалка**: подложка `palette.menu_fill` (тема — `ThemeColors::from_theme`),
  радиус/рамка как у панелей (`params.x = 8`).
- **Левая колонка** (~180 px): пункты «иконка + название» (иконки — из
  существующего набора глифов, без шрифтовых зависимостей); активный
  раздел — акцентная подложка (паттерн hover-подсветки `app.rs:6122-6132`);
  hover — у неактивных. Внизу колонки — подсказка «Ctrl+, — открыть/закрыть»
  (переносится из подвала панели, `app.rs:6179-6190`).
- **Правая панель**: заголовок раздела крупным кеглем (`palette.title`) +
  строки единой сетки: слева лейбл настройки (БЕЗ значения — «Сетка»,
  не «Сетка: вкл») и **описание** приглушённым цветом меньшим кеглем под
  лейблом (высота строки ~44 px, `MODAL_ROW_HEIGHT`; тексты-кандидаты —
  таблица ниже), справа контрол:
  - `Toggle` — pill-тумблер: трек ~34×18 + ручка-квад; включён — акцентный
    цвет, выключен — приглушённый; позиция ручки отражает значение
    (рисуется квадами, как весь UI);
  - `Dropdown` — кнопка со значением + `▾` (значение из
    `dropdown_options` — там текущее уже помечено);
  - «Внешний вид» — две карточки «тёмная»/«светлая» рядом (паттерн
    Obsidian «Base theme»), активная — акцентная рамка; клик — та же
    логика, что у кнопки ☀/🌙 (`settings.theme.next()`-эквивалент
    прямым выбором).

  Тексты описаний — кандидаты (RU; финал при реализации; идут через
  таблицу строк, §5):

  | Настройка | Описание (кандидат) |
  |---|---|
  | Угол кнопки настроек | В каком углу экрана прижата летающая кнопка настроек. |
  | Сетка | Рисовать сетку канваса на заднем плане. |
  | Вид сетки | Сплошные линии или точки в узлах сетки. |
  | Плотность сетки | Шаг сетки: расстояние между линиями/точками. |
  | Связи огибают ноды | Связи обходят посторонние ноды полилинией вместо пересечения. |
  | Зона портов | Радиус захвата порта при протягивании связи (экранные px). |
  | Построчные порты | Отдельный выходной порт у каждой строки Numi-листа. |
  | Узкие места | Рамки и бейджи ρ/W по рассчитанному потоку. |
  | Фокус-режим | Hover/выделение ноды подсвечивает связи и соседей, остальное притемняется. |
  | HUD при старте | Показывать HUD (fps/p95, F3) сразу при запуске. |
  | Тема | Базовая тема интерфейса: тёмная или светлая. |

- Открытое dropdown-меню — над модалкой (screen-space, как сейчас);
  строки под меню не рисуются (куллинг по пересечению rect'ов,
  `app.rs:6150-6155`, — сохранить).
- Hover-подсветка строк и пунктов навигации.

### 3. Состояние и ввод (`app.rs`)

- `App`: + `settings_tab: usize` (индекс активного таба, дефолт 0);
  хранится между открытиями модалки (как в Obsidian), в конфиг не пишется.
- Клик: по пункту навигации — смена таба (+ сброс dropdown); по строке
  `Toggle` — `apply_toggle_row` (как сейчас); по `Dropdown` — открыть
  меню (повторный клик по той же строке — закрыть, `app.rs:7213-7222`);
  по пункту меню — `apply_dropdown_choice` (`app.rs:7185-7200`
  переиспользуется); по карточке темы — применить тему; **клик по
  затемнению (вне rect модалки) — закрыть модалку** (нынешний «клик мимо
  панели — закрыть», `app.rs:7224-7229`, обобщается на модалку).
- `Esc` — двухэтапный без изменений (`app.rs:6605-6615`): меню → модалка.
  `Ctrl+,` — toggle без изменений (`app.rs:6671-6682`). Кнопка ⚙ — toggle
  без изменений (`app.rs:7169-7176`).
- `ButtonCorner` больше не перепривязывает панель (модалка по центру) —
  кейс FR-026 «меню закрывается при смене угла» упрощается: открытый
  dropdown всё равно закрываем (rect строки-якоря сменился).

### 4. Совместимость и регрессии

- Схема `config.toml` и все поля — без изменений; тесты `settings.rs`
  не трогаются (round-trip байт-в-байт).
- Старые тесты `settings_ui` (угловые `panel_layout`/`row_at`/`panel_height`)
  переписываются на модалку; инварианты FR-026 (полнота, эквивалентность
  dropdown циклам, кламп, булевы-тумблеры) — сохраняются в новой геометрии.
- Константы `ui::SETTINGS_*` остаются для кластера кнопок ⚙/☀/?;
  `PANEL_WIDTH` модалкой не используется (новые константы `MODAL_*`).
- Панель хоткеев (F1) рендерится независимо (`app.rs:6041-6088`) —
  сосуществование с модалкой сохраняется.
- Web (`canvas-web`): настройки — общий код `canvas-app`, модалка работает
  и в браузере; кламп на маленьком окне — инвариант (см. проверку).

### 5. Локализуемые тексты настроек (база FR-040)

- Тексты настроек — заголовки табов, лейблы строк, описания, значения
  dropdown («верхний левый», «линии», «частая», «вкл/выкл», пресеты
  портов), подсказка «Ctrl+, — открыть/закрыть» — НЕ хардкодятся в
  `settings_ui.rs` и `settings_overlay`: вводится таблица строк с
  ключами (модуль строк настроек в `canvas-app`, кандидат на слияние с
  общим `i18n` FR-040), API вида `text(key) -> &'static str` (RU сейчас).
- Значения из `canvas-core` (`Corner::label`, `GridStyle::label`,
  `GridDensity::label`, подписи пресетов портов) заменяются ключами
  app-таблицы; core-методы `label()` остаются для тестов/лога — в рендер
  не идут.
- `SettingsRow::label(&self.settings)` перестаёт вплетать значения
  («Сетка: вкл») — значение показывает контрол; сигнатуры `row_kind`/
  `dropdown_options` сохраняются (строки значений — из таблицы).
- Английская таблица, поле `Language` в конфиге и переключатель —
  FR-040. FR-039 гарантирует: ни одного UI-литерала настроек вне
  таблицы.

## Архитектура тестируемости (инварианты FR-039)

1. **Полнота:** union строк всех табов == `SETTINGS_ROWS` — ни одна
   настройка не потеряна и не задублирована; тема — ровно один раздел
   «Внешний вид».
2. **Значения:** `dropdown_options` содержит текущее значение каждой
   настройки ровно один раз; выбор пункта `i` == `k` нажатий `.next()`.
3. **Кламп:** `modal_layout` при viewport 320×240 и больших — модалка
   целиком внутри окна; dropdown любого контрола клампится к окну и не
   перекрывает свою строку целиком.
4. **Навигация:** hit-тест пункта навигации; `row_at` возвращает строки
   только активного таба; клик в зоне контента мимо строк — не смена таба.
5. **Булевы:** все `bool`-поля — `RowKind::Toggle` (pill), остальные —
   `Dropdown`; тема — отдельный вид контента.
6. **Схема:** round-trip дефолтов `config.toml` байт-в-байт с текущей
   версией.
7. **Локализация:** каждый таб и каждая строка имеют ключи лейбла и
   описания в таблице строк; значения непусты (RU); в `settings_ui.rs`/
   `settings_overlay` нет UI-литералов настроек.
8. **Адаптив:** `modal_layout` при 1920×1080 и 1280×720 — размеры в
   границах `[MODAL_MIN_W, MODAL_MAX_W] × [MODAL_MIN_H, MODAL_MAX_H]`;
   кламп 320×240 сохраняется.

## Решения владельца (2026-09-20)

Открытые вопросы закрыты владельцем (сессия 2026-09-20):

- **Поиск по настройкам** — **отклонён**: не реализуем (ни v1, ни v2);
  модалка без поля поиска.
- **Описания строк** — **в v1**: приглушённое описание под лейблом у
  каждой строки; тексты-кандидаты — таблица в §2. Все интерфейсные
  тексты настроек — не хардкод: таблица строк с ключами (база
  локализации FR-040).
- **Размер модалки** — **адаптивный**: масштабирование от окна с
  потолками (расчёт на десктопы Full HD и выше); контрольные точки под
  планшет/телефон зафиксировать константами, адаптив под них сейчас
  не делать.
- **Скролл контента** — как предложено: не нужен в v1 (максимум 4 строки
  на таб); при росте (FR-038 «Snap») — колесо над зоной контента с
  перехватом события (канвас не зумит) — v2.
- **Запоминание активного таба** — как предложено: в памяти `App`
  (переживает закрытие/открытие модалки), в конфиг не пишется.

Новых открытых вопросов нет; изменение решений — через
`История изменений`.

## Проверка (Verification)

### Юнит-тесты (settings_ui)

- Полнота табов: union rows == `SETTINGS_ROWS`, порядок стабилен; тема —
  вне `SETTINGS_ROWS`, ровно один таб её содержит.
- `dropdown_options`: ButtonCorner — 4, GridStyle — 2, GridDensity — 3,
  PortZone — 5 пресетов; текущее помечено; выбор == циклу (переиспользование
  тестов FR-026).
- `modal_layout`: кламп при 320×240 (модалка внутри окна, навигация
  различима), при больших окнах — центр; `row_at` — только строки
  активного таба; `nav_item_at` — пункты, не контент.
- `dropdown_layout` с параметрической шириной: кламп к окну у правого края
  модалки и в узком окне.
- Тексты: полнота таблицы строк — ключи лейбла+описания для всех строк
  и табов, значения непусты (RU); UI-литералы настроек вне таблицы
  отсутствуют.
- Адаптив: `modal_layout(1920×1080)` ≈ 864×640, `modal_layout(1280×720)`
  — в границах MIN/MAX; кламп 320×240 сохраняется.

### Юнит-тесты (app/settings)

- Смена таба: `settings_tab` обновляется, dropdown сброшен; повторное
  открытие модалки восстанавливает последний таб.
- Клик по затемнению закрывает модалку и не доходит до канваса (нода не
  создана); `Esc` — меню → модалка (двухэтапно).

### Ручная приёмка

- `Ctrl+,` — модалка по центру над затемнённым канвасом; ввод под ней
  глушен (клик по канвасу не создаёт ноду, колесо не зумит).
- Левая навигация переключает разделы, активный подсвечен; подсказка
  `Ctrl+,` внизу колонки.
- Тумблеры — pill справа от лейбла, значение видно по позиции/цвету;
  «Зона портов» — dropdown-кнопка со значением, меню с галочкой текущего,
  выбор применяет (радиус портов меняется на рендере).
- «Внешний вид» — две карточки; выбор «светлая» перекрашивает весь UI,
  включая модалку; кнопка ☀/🌙 синхронна с карточками.
- `Esc`: открытое меню закрылось, модалка осталась; второй `Esc` закрыл
  модалку; клик по затемнению закрыл модалку; `Ctrl+,` и ⚙ — toggle.
- Узкое окно (320×240): модалка влезает, меню клампится; web-версия —
  то же поведение.
- Описания видны под лейблами приглушённым кеглем; на Full HD модалка
  ~864×640, при сужении окна плавно уменьшается и клампится (не вылезает).
