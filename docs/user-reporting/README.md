# user-reporting — отчёты владельца об ошибках

Папка — единственное место для **отчётов об ошибках, найденных владельцем**
(ручное тестирование, обратная связь после сессий). Здесь фиксируется
пользовательская формулировка симптома и её разбор до корневой причины.

## Правила папки

1. Один отчёт ручного тестирования (или одно сообщение владельца с набором
   дефектов) — один файл `ur-###-<краткое-название>.md`. Нумерация
   последовательная: `ur-001`, `ur-002`, …
2. Каждый пункт отчёта получает локальный идентификатор `UR-001-N`
   (отчёт — номер, пункт — порядковый внутри отчёта), на который ссылаются
   CR/FR и план доработок.
3. Разбор каждого пункта ведётся до **корневой причины** с адресами
   `файл:строка` и классификацией происхождения:
   - **согласованное решение** — есть документ (ADR/CR/FR/PRD) с решением
     владельца; расхождение означает пересмотр документа новым CR/FR;
   - **«тихое» решение агента** — поведение появилось при реализации без
     отдельного документа и без явного решения владельца;
   - **неполнота реализации** — согласованный контракт не доведён до кода.
4. Если для доработки пункта нужны продуктовые/UX/UI вопросы — они задаются
   в чате сессии, а вопросы и ответы владельца фиксируются в разделе
   «Решения владельца (Q&A)» соответствующего CR/FR и дублируются в отчёте.
5. После разбора на каждую тему создаётся свой документ в
   `docs/change-requests/` (CR — изменение существующего поведения,
   FR — новая функциональность) по шаблону `docs/change-requests/cr-template.md`,
   и добавляется в индекс `docs/change-requests/index-cr-fr.md`.
6. План доработок по отчёту кладётся в `docs/plans/`.
