  проверить что адекватно используется ui-kit и вёрстка»

## Диагностика (воспроизведение на живом сайте Pages)

- Headless-прогон danku13.github.io/CanvasDesk/app (1600×900): автор-бар
  перекрывает заголовок «Шаблоны»; тулбар перекрывает шапку агент-панели;
  чипы обрезаны; иконки строк всплывают; клик по строке — 0 px диффа.
- Код: `PanelLayout` (template_ui.rs) — «все rect'ы `[x,y,w,h]` (конвенция
  `point_in_rect`)»; потребители в overlays.rs/input.rs — `rect_xywh(...)`.
  Поломка внесена до FR-054 и пережила рефакторинги (40add6b и др.),
  т.к. hit==draw ломались СИММЕТРИЧНО (клик мимо нарисованного не заметен).

## Решения

- DOM-хром не убирать и не прятать (нужен для файловых жестов) — СДВИГАТЬ
  из-под углов панелей body-классами из Rust (`App::html_panel_overlap` →
  `TourAwareApp` → `toolbar::set_panel_overlap`, паттерн FR-095
  `text_input_active`); CSS-сдвиги с transition 150ms и клампом min().
- Потребители `PanelLayout` берут rect'ы КАК ЕСТЬ (hit==draw восстановлен).
- Замер чипов — по локализованным display-именам (паритет полосы FR-040 v2);
  радиус чипов/полей/«‹»/карточек — токен `RADIUS_CHIP` (кит-паритет).
- Миникарта: `Renderer::set_minimap_visible(bool)` — приложение гасит её
  покадрово, пока открыта агент-панель (текстура остаётся в кэше).
