# LLM для автодополнения в канвас-приложении: benchmark 11 моделей OpenRouter

*Как мы искали замену локальной fine-tuned модели для inline-подсказок шаблонов — и что из этого вышло.*

---

## TL;DR

Мы прогнали 11 LLM (5 платных, 5 free, 1 внутреннюю) на замороженном eval-сете автодополнения шаблонов бизнес-метрик. Результат: **LLM превосходит гибрид lex+локальная-модель на 57–114%** — с p@1 от 0.468 (baseline) до 1.000 (лучшая paid). Но есть подвох: нелинейная зависимость от масштаба, rate limits на free-tier, и latency, которая убивает inline-UX. В статье — что меряли, что нашли, и какой гибрид выбрали.

---

## Контекст

CanvasDesk — визуальный канвас бизнес-метрик (как Miro для юнит-экономики). Пользователь расставляет ноды-метрики (CAC, LTV, margin), связывает рёбрами значений. Когда он начинает вводить новую ноду, приложение подсказывает подходящий шаблон из каталога.

Существующий движок подсказок — гибрид:
- **lex** (BM25 + char3 + синонимы) — быстрый, локальный, детерминированный
- **mm** (fine-tuned классификатор Laya, sidecar) — медленнее, но «понимает» контекст
- **fusion** — `α·lex + (1−α)·mm`, α=0.85

Baseline: p@1=0.468 на test-сплите. Laya не превосходила lex стабильно (доверительный интервал накрывал ноль). Возник вопрос: **можно ли заменить fine-tuned классификатор на general-purpose LLM через API — и получить прирост без fine-tune?**

## Что делали

### Eval-сет

Замороженный сет из 15 choice-фикстур (подмножество test-сплита 47):
- Контекст ноды: заголовок, переменные канваса, соседи (up/down) с их needs/out
- Каталог: 19 шаблонов с ru/en-описаниями
- Golden: правильный template_id
- Сценарии: C3 (заголовок есть) и C4 (заголовок пустой) — последний сложнее

### Prompt

Один template для всех chat-моделей (без few-shot, без CoT):

```
SYSTEM: Ты — движок автодополнения шаблонов для CanvasDesk.
        Верни JSON: {"choice":"<id>","confidence":0-1,"reasoning":"..."}

USER:   Контекст: {context}
        Каталог: {19 опций}
        Какой шаблон подходит?
```

Параметры: `temperature=0`, `response_format: json_object`.

### System One protocol

Одна модель (`typesafe/jev-1.13`) поддерживает нативный choice-протокол — тот же, что наш существующий Laya-клиент. Запрос:
```json
{"model":"jev-1.13","state":{"document":"..."},
 "questions":{"main":{"type":"choice","criteria":{"id":"desc",...}}}}
```
Ответ: `answers.main.probabilities` — нативный JSON, без парсинга из текста.

### Модели

5 платных (gemma-3-4b, nemotron-nano-30b, nemotron-3.5-lightning, phi-4, glm-5.3-flash, jev-1.13), 5 free (nemotron-super, nemotron-ultra-550b, qwen3.8-27b, gemma-4-26b, inkling), 1 внутренняя (GLM API).

| **lex+Laya (baseline)** | **0.468** | 0.8с | $0 | — |
| nemotron-nano-30b (paid) | 0.467 | 4.2с | $0.044 | ⚠️ = baseline |
| nemotron-3.5-lightning (paid) | 0.600 | 20.4с | $0.036 | ⚠️ медленно |
| phi-4 (paid) | 0.667 | 2.0с | $0.049 | ✓ |
| **jev-1.13 (System One)** | **0.733** | **0.46с** | $0.070 | ⚡ уникальна |
| **nemotron-super:free** | **0.800** | 2.6с | **$0** | 🏆 free |

| **glm-5.3-flash (paid)** | **1.000** | 10.5с | $0.121 | 🏆 идеал |

### Главные находки

**1. Нелинейная зависимость от масштаба.** Малые модели (4B–30B) не превосходят baseline. Качество скачкообразно растёт на 120B+. При этом цена/качество не коррелируют: бесплатный super (120B) даёт +71% к baseline, а платный nano (30B) — 0%.

**2. Free-tier нестабилен.** qwen3.8-27b дал 100% на 7 успешных из 15 (53% rate-limited). gemma-4-26b — 100% geo-blocked. ultra-550b — 33% потерь (503 overloaded). Только `nemotron-super:free` отработал стабильно (15/15, 0 rate limits).

**3. System One protocol — игра-чейнджер для интеграции.** `jev-1.13` — единственная модель с нативным choice-протоколом. Latency 0.46с (в 5× быстрее всех), нативные probabilities (без JSON-парсинга), и **тот же протокол что наш существующий Laya-клиент** — интеграция = замена endpoint, fusion без изменений.

**4. Latency vs quality — trade-off.** Лучшая по качеству (glm-5.3-flash, p@1=1.0) имеет 10.5с latency — слишком медленно для inline-UX без prefetch. Лучшая по скорости (jev-1.13, 0.46с) имеет p@1=0.733 — ниже, но приемлемо с fallback.

## Что выбрали

### Для inline-UX (приоритет latency)

**Гибрид: jev-1.13 primary + glm-5.3-flash fallback + lex safety-net**

- `jev-1.13` на каждый запрос (0.46с, p@1=0.733)
- При `confidence < 0.5` — повторный запрос к `glm-5.3-flash` (p@1=1.0, 10.5с)
- При ошибке/таймауте — fallback на lex (p@1=0.404, мгновенно)
- Стоимость: ~$0.08/1000 запросов

### Для batch/offline (приоритет качества)

`glm-5.3-flash` — p@1=1.000, $0.121/1000. Подходит для генерации embeddings, авто-категоризации.

### Для zero-cost MVP

`nemotron-super:free` + lex fallback. p@1=0.800, $0, но risk rate limits.

## Подводные камни

### 1. WASM не зовёт API напрямую

CanvasDesk компилируется в wasm для web. API-ключ в public bundle = утечка. Решение: backend-proxy (desktop — sidecar, web — cloud function).

### 2. Latency убивает inline-UX

10.5с (glm-5.3-flash) — неприемлемо без prefetch. Решение: запрос при фокусе ноды, lex-подсказка мгновенно, LLM-уточнение позже. `jev-1.13` (0.46с) решает эту проблему — можно звать на каждый keystroke.

### 3. Недетерминизм ломает golden-тесты

LLM с `temperature=0` всё равно не 100% детерминирована. Решение: отключать LLM-mm в CI, проверять только lex.

### 4. Hallucinations

LLM может вернуть template_id не из каталога. Валидация: `choice ∈ catalog`, иначе fallback на lex.

## Выводы

1. **LLM работает как mm-source.** +57–114% к baseline без fine-tune.
2. **Масштаб имеет значение.** Меньше 120B — не интересно.
3. **Free-tier нестабилен.** Только `nemotron-super:free` выдержал 15 запросов без rate limits.
4. **System One protocol — недооценён.** `jev-1.13` с latency 0.46с и нативным choice-форматом — идеален для inline-UX, интегрируется без переделок.
5. **Гибрид побеждает.** Один источник не покрывает все сценарии. jev-1.13 для скорости, glm-5.3-flash для качества, lex для надёжности.
