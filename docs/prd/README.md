# PRD — каталог требований продукта (`docs/prd/`)

PRD (Product Requirements Document) — документ требований продукта: **проблема → цели → пользователи и CJM → user stories → решение → non-goals → roadmap**. PRD отвечает на вопросы «**что и зачем**»; реализационный FR (`docs/change-requests/`) — на вопросы «**где и как**» в коде. Двухуровневая схема: PRD не меняется при каждой правке реализации, FR ведёт исполнение.

## Правила ведения каталога

1. **Файл и номер.** Имя — `prd-<NNNN>-<краткое-название>.md` (kebab-case). Номер — последовательный за максимальным существующим (переиспользование номеров запрещено; история задвоений уже была — см. ADR-0007). Заголовок документа: `# PRD-<NNNN>: <название>`.
2. **Шаблон обязателен.** Новый PRD создаётся копированием [`TEMPLATE.md`](TEMPLATE.html) с заполнением всех разделов. Каноническая структура — 17 разделов; допустимы локальные перестановки (например, «Терминология» рядом с «Контекстом»), но обязательный набор: Контекст с ссылками `file.rs:line` (§2), измеримые цели (§3), user stories + acceptance criteria (§5), **CJM (§6)**, решение с диаграммой и отвергнутыми вариантами (§7), F-таблица (§8), non-goals (§10), DoD (§15), источники истины (§17).
3. **CJM обязателен (§6 шаблона).** Два уровня: краткий (шаги: этап → действие → поверхность) и детальный (мысли, эмоции по шкале −2…+2, боли, **точки отвала**, возможности). Каждая точка отвала трассируется в требование/метрику/риск (§6.3) — точка отвала без митигации считается декоративной и снимается с документа.
4. **Статусная модель.** `черновик → в анализе → в работе (FR создан) → выполнено / отклонено`. Каждое изменение статуса и содержания — строка в «Истории изменений» (§16) и актуализация поля «Обновлён».
5. **Связь с реализацией.** При старте работ по PRD заводится FR-документ в `docs/change-requests/` (следующий свободный номер, шаблон `cr-template.md`) со ссылкой на PRD в поле «Источник». Тяжёлые/нативные зависимости и решения, меняющие правила архитектуры, — через ADR **до** реализации (`docs/adr/`, правило ADR-0001 и AGENTS.md).
6. **Фактура обязательна.** Контекст (§2) и решение (§7) ссылаются на конкретный код (`path/file.rs:line`) и документы; цели (§3) — измеримы; DoD (§15) — чек-лист с гейтами (`cargo test/clippy/fmt`, `scripts/wasm_gate.sh`, round-trip).
7. **Коммит.** Один PRD — один коммит по conventional commits (`docs(prd): …`); индекс в этом файле и `docs/index.md` обновляется тем же коммитом.

## Связи между PRD

- **PRD-0001 + PRD-0003** — полный цикл: импортированная топология архитектуры (0003) получает реальные вводные из данных (0001) и превращается в исполняемую мат.модель.
- **PRD-0002 + PRD-0003** — импортированные графы бывают плотными; агрегация пучков (0002) делает их читаемыми.
