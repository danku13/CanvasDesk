# ИИ в WASM-версии CanvasDesk — что доступно пользователю и как это проверить

> **Рамка документа:** пользовательский ИИ-функционал именно web-сборки (canvas-web,
> wasm32-unknown-unknown), **кроме MCP** (MCP-агентная композиция — отдельный трек,
> ADR-0004/0009/0010/0012). Для каждой функции — фактическое состояние в коде,
> отличие от desktop-сборки и пошаговый сценарий проверки в браузере.
>
> **Состояние кода:** `main`, коммит `6ad9e5a` (2026-10-09). Документ отражает
> фактическое поведение сборки, а не планы: где функционал заглушен — это указано
> явно, с маркерами `FR-LLM-*` для поиска по коду.
>
> Связанные документы: [PRD-0010](prd/prd-0010-llm-integration-byok-chatgpt.html)
> (продуктовые требования F-1…F-7), [ADR-0011](adr/adr-0011-wasm-build-gate.html)
> (wasm-гейт сборки), [ADR-0016](adr/adr-0016-llm-layer-canvas-llm.html) (LLM-слой),
> [WASM-TESTING.md](WASM-TESTING.html) (рецепт UI-проверки wasm),
> [user-docs/ai-features.md](../user-docs/ai-features.html) (пользовательский гайд,
> desktop-фокус), [BYOK.md](BYOK.html).

## 1. TL;DR — матрица доступности

| # | Функция | В wasm (web) | В desktop | Примечание |
|---|---|---|---|---|
| 1 | **Suggest** — ИИ-строки в попапе шаблонов (FR-021), ghost-ноды, C3-карточки (FR-079) | ✅ работает | ✅ работает | В wasm — только локальный lex-ранжир; Laya/LLM-источники — натив |
| 2 | **Настройки → AI and Models** (9-й таб, 14 строк) | ✅ работает | ✅ работает | Persist: wasm — localStorage, desktop — config.toml |
| 3 | **Статусная AI-панель** (F-7.9): модель/провайдер, тумблеры, cost, ⏸/⚙ | ✅ работает | ✅ работает | Скрыта при всех Off и на окнах < 900px |
| 4 | **Пауза всех AI-функций** (⏸) и дневной cost-лимит | ✅ работает (гейты) | ✅ работает | Сами счётчики cost пока mock — см. п. 4.5 |
| 5 | **ChatGPT OAuth — строка входа** (F-5.8) | ⚠️ UI виден, кнопка задизейблена | ✅ полный флоу (натив + `l1-llm-tls`) | В wasm клик → тост «доступно только в нативной сборке»; бейдж статуса честный |
| 6 | **Agent Panel** (F-4) — чат-панель с tool-calls и preview | ❌ недоступна пользователю | ❌ недоступна | UI в коде, но точек входа (хоткей/меню) ещё нет — `FR-LLM-D-TODO` |
| 7 | **Graph Builder** (F-3) — генерация графа из текста | ❌ недоступен пользователю | ❌ недоступен | Аналогично п. 6 |
| 8 | **Реальные LLM-вызовы** (chat/tool_calling/choice) | ❌ архитектурно нет сети | ⚠️ провайдеры готовы, вызовы в панелях не вживлены | wasm: ADR-0011 (fetch-транспорт F-5.10 не реализован); натив: `// FR-LLM-D-TODO` |
| 9 | **Health-check ключа** («Проверить», `/v1/models`) | ❌ заглушка | ❌ заглушка | `// FR-LLM-FIX-TODO:` — флаг in-memory |
| 10 | **Тур онбординга «AI-функции»** (`#tour=ai-mode`) | ✅ работает | ✅ работает | 4 шага: статусная панель → 9-й таб → privacy → док |
| 11 | **Телеметрия AI-событий** (PostHog opt-in, FR-089) | ✅ работает | ✅ работает | По умолчанию OFF; в wasm — единственный исходящий трафик при включении |

Короткая формула: **в web-сборке пользователю сегодня доступны все «локальные»
части ИИ-UX — настройки, статусная панель, локальный suggest и онбординг; всё,
что требует сети (облачные провайдеры, OAuth-вход, health-check), — честно
заглушено, а панельные фичи (Agent Panel / Graph Builder) ещё не имеют точек
входа ни на одной платформе.**

## 2. Как открыть WASM-версию

Три способа — от простого к воспроизводимому из исходников.

### 2.1 Прод-стенд GitHub Pages (проще всего)

CI `pages-web.yml` на каждый пуш в `main` собирает release-бандл
(`scripts/web_bundle.sh --release`) и публикует его в Pages:

```text
https://danku13.github.io/CanvasDesk/app/
```

Требования к браузеру: Chromium-семейство с включённым **WebGPU** (Chrome/Edge
113+; Safari/Firefox — не целевые платформы рендера, см. ADR-0011 и README).
Рендер канваса — WebGPU; без адаптера приложение сообщит об отсутствии GPU
(в headless/виртуальных средах см. флаги SwiftShader из WASM-TESTING.md §4).

### 2.2 Локальный дев-сервер (`trunk serve`)

```bash
git clone https://github.com/danku13/CanvasDesk.git && cd CanvasDesk
# инструменты: trunk 0.21.14, wasm-bindgen-cli 0.2.127 (версия = Cargo.lock)
cd crates/canvas-web && trunk serve   # → http://127.0.0.1:8080
```

`trunk` сам скачает wasm-bindgen-cli нужной версии; при 404 —
`cargo install wasm-bindgen-cli --version 0.2.127 --locked`.

### 2.3 Ручная сборка без trunk (как в WASM-TESTING.md §3)

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cargo build -p canvas-web --target wasm32-unknown-unknown
wasm-bindgen --target web --out-dir target/dist \
    target/wasm32-unknown-unknown/debug/canvas_web.wasm
cp crates/canvas-web/index.html target/dist/
scripts/wasm_ui_test.sh --no-build   # стенд + Chromium-сценарий (L2)
```

Release-бандл, идентичный Pages: `scripts/web_bundle.sh --dist _site/app`.

## 3. Почему ИИ в wasm устроен иначе, чем в desktop

Понимание этих трёх правил объясняет всю матрицу из §1 и поведение UI при
проверке — без него любое расхождение с desktop выглядит «багом».

**Правило 1 — wasm-гейт: в web-сборке нет сетевых зависимостей вообще**
(ADR-0011, FR-036). `canvas-app` собирается с `default features = []`: крейты
`canvas-llm`/`canvas-suggest` включают транспорт (`ureq`) только за фичами
`l1-llm` / `l1-llm-tls` / `l1-laya`, которые canvas-web не активирует. Отсюда в wasm: (а) типы настроек и весь UI ИИ компилируются и работают; (б) фабрика
провайдеров `llm_factory::build_feature_provider` — stub, всегда возвращает
`None`; (в) ни один запрос из браузера напрямую к api.openai.com/OpenRouter
кодом не отправляется. Единственный исходящий трафик — телеметрия PostHog,
если пользователь явно включил её (FR-089).

**Правило 2 — suggest в wasm живёт на локальном движке.** Ранжирование
подсказок (`canvas-suggest`: lex/bm25/fusion-конвейер) выполняется синхронно
на UI-треде (`app.rs`: ветка `#[cfg(target_arch = "wasm32")]` →
`suggest::rank(..., None)`) — воркер-поток FR-064 на wasm не компилируется.
Последний аргумент `None` — отсутствие «удалённого источника»: Laya-sidecar
(натив, `l1-laya`) и LLM mm-source (натив, `l1-llm`) в web-сборку не входят.
Практическое следствие: подсказки в браузере работают всегда, офлайн,
мгновенно (< 1 мс на каталоге 62 опций), но это лексическое ранжирование,
а не семантика LLM, и кастомные варианты нод от LLM не генерируются.

**Правило 3 — хранение в браузере: localStorage вместо файлов.** Настройки
(тот же TOML-текст `config.toml`) сохраняются в `localStorage` (FR-040 v2).
Отсюда два отличия от desktop, важных для приватности: BYOK-ключ лежит в
localStorage открытым текстом (не в OS keychain), а файла `oauth_tokens.json`
(0600) с OAuth-токенами в web нет вообще — токен-стор в wasm не реализован
(OPFS — TODO дизайн-дока §4.4), что и делает вход ChatGPT в браузере
невозможным даже при деплое cloud-proxy.

## 4. Детальный разбор по функциям

### 4.1 Suggest (FR-079) — работает полностью, на локальном движке

Пользователь видит три поверхности suggest, и все три доступны в браузере:

1. **ИИ-строки в попапе шаблонов (FR-021).** При вводе текста в ноде попап
   подсказок, помимо обычных совпадений каталога, показывает «ИИ-строки» —
   варианты, отранжированные suggest-движком под текущий контекст
   (`suggest_ai_items` в `app.rs`).
2. **Ghost-ноды на канвасе.** При выборе ноды (якорь — выбранная нода,
   редизайн FR-079) рядом появляются полупрозрачные ноды-подсказки;
   принятие вставляет шаблон, отклонение убирает.
3. **C3-карточки** — карточки-подсказки по контексту канваса
   (`SuggestTarget::Cards`).

Ранжирование — чисто локальное: токенизатор + bm25/lex-fusion по каталогу
шаблонов и доменных схем. Порог confidence (`confidence_threshold`, дефолт
0.5) настраивается в 9-м табе и влияет на отсечение подсказок. Журнал S0
(`suggest-log.jsonl`) на web не пишется — файловой системы нет (на desktop
пишется рядом с config.toml).

Чего в wasm **нет**: генерации трёх кастомных вариантов нод от LLM (F-2.7),
семантического ранжирования через LLM mm-source (F-2.1–F-2.6) и
Laya-sidecar — все три источника требуют нативных фич. На desktop после
вживления реальных вызовов те же поверхности заполнятся ответами LLM;
UI-механика при этом не меняется.

### 4.2 Настройки → «AI and Models» (9-й таб) — весь UI доступен

Таб открывается из статусной панели (⚙) или модалки настроек. Строки
(идентификаторы `SettingsRow::Ai*` в `settings_ui.rs`):

| Строка | Что делает | Поведение в wasm |
|---|---|---|
| Провайдер Suggest | BYOK / Ollama / Laya / Off (ChatGPT OAuth недоступен по Q2 — rate limits) | Выбор сохраняется; фактический ранжир — всегда локальный lex |
| Провайдер Graph Builder | ChatGPT OAuth / BYOK / Ollama / Off | Сохраняется; генерация — см. п. 4.4 |
| Провайдер Agent Panel | ChatGPT OAuth / BYOK / Ollama / Off | Сохраняется; панель — см. п. 4.4 |
| Модель Suggest / Graph / Agent | Текстовый ввод, дефолт `glm-5.3-flash` (бенчмарк-пресет) | Сохраняется; список `/v1/models` не подгружается (нет сети) |
| API-ключ (BYOK) | Секрет для OpenRouter/selfhost | Хранится в localStorage открытым текстом (не keychain) |
| Self-host URL + ключ | OpenAI-compatible endpoint в контуре | Сохраняется; health-check — заглушка (п. 4.6) |
| Data residency | Local / Cloud / Self-hosted | Сохраняется; информационная семантика (реальной отправки из wasm нет) |
| Дневной cost-лимит | Слайдер $0.25–$5.00, дефолт $1.00 (F-7.4) | Работает как гейт отправки в панелях (после подключения входов) |
| Confidence-порог suggest | Дефолт 0.5 | Влияет на отсечение локальных подсказок уже сейчас |
| Вход ChatGPT (F-5.8) | OAuth-флоу | Кнопка задизейблена, клик → тост (п. 4.7) |
| Телеметрия AI | PostHog opt-in (FR-089) | Работает: событие `canvasdesk:consent-changed` |

Persist — в localStorage (тот же TOML-формат, что config.toml на desktop),
поэтому **сценарий «перезагрузил страницу — настройки на месте» проходит**.
Сброс — очистить site data для домена.

### 4.3 Статусная AI-панель (F-7.9) — работает

Правый нижний угол, над миникартой, 302px (1:1 с прототипом
`prototype-unified.html`). Состав: точка-индикатор, чип активной модели
(усечение «…» по замеру шрифта), чип провайдера, тумблеры Suggest ✓ /
Graph ✓ / Agent ✓ (клик — вкл/выкл функции, синхронно с 9-м табом),
Session/Day cost с прогресс-баром дневного лимита, кнопка ⏸ (пауза всех
AI-функций) и ⚙ (открыть 9-й таб). Панель **не рисуется**, когда все
провайдеры Off (состояние первого запуска — дефолт `LlmSettings` — все Off)
и когда ширина окна < 900px. Значения Session/Day сейчас заполняются
mock-потоком панелей (п. 4.5), тумблеры и пауза — реальные.

### 4.4 Agent Panel и Graph Builder — UI готов, точек входа ещё нет

Это самое важное отличие **не только от планов, но и от desktop**. Обе панели
существуют в коде как полноценные поверхности: рендер оверлея
(`agent_panel_overlay` / `graph_builder_overlay`), hit-тесты
(`agent_panel_hit` / `graph_builder_hit`), защитные гейты отправки
(пауза → сообщение, провайдер Off → сообщение, лимит исчерпан → сообщение),
фабрика провайдеров с валидацией конфига (F-5.9), mock-поток ответа
(«Планирую…» с tool-calls, preview ghost-нод, Accept/Reject). Однако:

- ни хоткей (Ctrl+I из доков), ни пункт меню, ни другой вход **не подключены**:
  `agent_panel.open` нигде не выставляется в `true` (кроме тестов),
  `agent_panel_hit`/`graph_builder_hit` не вызываются из обработчика ввода;
- реальные LLM-вызовы и `graph_apply` помечены `// FR-LLM-D-TODO:` — даже на
  нативе с фичей `l1-llm-tls` панель сейчас отвечает mock-контентом после
  проверки конфигурации фабрикой.

Следствие для проверки: в текущей сборке пользователь **не может открыть
ни одну из панелей** — это ожидаемое состояние волны интеграции
(Stream D, точки `FR-LLM-D-TODO`), а не дефект wasm. Соответственно,
тосты F-5.9 («BYOK: ключ не задан…», «ChatGPT: вход не выполнен…»)
наблюдаемы только через будущие входы панелей или тесты.

### 4.5 Cost-счётчики — гейты реальные, цифры mock

Дневной лимит (`cost_limit_daily`, дефолт $1.00) реально проверяется в
`agent_send` и `graph_builder_generate`: при `ai_cost_day >= лимит` отправка
отклоняется с сообщением «Дневной лимит исчерпан». Но сами счётчики
`ai_cost_session` / `ai_cost_day` инкрементируются mock-потоком панелей, а не
`canvas_llm::cost::actual_cost` после реального запроса — до вживления
реальных вызовов цифры в статусной панели демонстрационные. В wasm это не
меняет ничего дополнительно (панели всё равно недоступны), на desktop —
важно помнить при приёмке cost-логики.

### 4.6 Health-check («Проверить ключ», selfhost «Проверить») — заглушка

Строка API-ключа и selfhost-строки содержат кнопки проверки, но реального
запроса `GET /v1/models` нет: флаги `ai_key_ok` / `ai_selfhost_ok`
выставляются кликом in-memory и сбрасываются перезагрузкой
(`// FR-LLM-FIX-TODO:`). Это одинаково для wasm и desktop — сетевой
health-check не реализован ни на одной платформе.

### 4.7 ChatGPT OAuth (F-5.8) — честная заглушка в web

Строка «Вход ChatGPT» появляется в 9-м табе, когда Graph Builder или Agent
Panel выбраны как `ChatGPT OAuth`. Бейдж состояния строится из персистентных
флагов (`chatgpt_connected` / `chatgpt_email`), поэтому статус честный:
если конфиг приехал с desktop-сборки, где вход был выполнен, web покажет
«вход выполнен · email», но токенов в браузере нет.

Кнопка «Войти через ChatGPT» в wasm **задизейблена**: клик показывает тост
«OAuth-вход доступен только в нативной сборке с feature l1-llm-tls»
(`AI_OAUTH_UNAVAILABLE`; ветка `#[cfg(any(not(feature = "l1-llm"),
target_arch = "wasm32"))]` в `oauth_button_click`). Это осознанное решение,
а не недоделка UI: web-путь OAuth по F-5.10 (deep-link
`canvasdesk://oauth/callback` + stateless cloud-proxy) требует клиентской
fetch-транспортной части и токен-стора в браузере (OPFS) — **их в коде ещё
нет**. Серверная часть пути готова и протестирована
(`cloud/llm-proxy/`, 45/45 тестов: 302-redirect callback, pass-through
token exchange, CORS-прокси `/v1/models` и `/v1/responses`, rate-limit),
но деплоится отдельно (`wrangler deploy`) и без клиента ничего не меняет
в UI.

Полный OAuth-вход сегодня проверяется только на desktop:
`cargo run -p canvas-app --features l1-llm-tls` (нативный listener
`http://127.0.0.1:{port}/callback`, браузер логина, exchange, токены в
`oauth_tokens.json` 0600, авто-refresh, E2E-смоук fbb7536).

### 4.8 Онбординг и тур «AI-функции» — работает

Web-тур `cd-ai-mode` (`sdk/web-onboarding/src/scenarios/ai-mode.ts`,
URL-фрагмент `#tour=ai-mode`) проводит 4 шага: статусная панель AI
(что показывает, тумблеры, ⏸/⚙) → 9-й таб настроек (per-feature выбор
провайдеров) → privacy-режимы (Local / Cloud / Self-hosted) → ссылка на
полный гайд `user-docs/ai-features.md`. Тур открывается и из онбординга
после экрана выбора AI-режима. На wasm работает без изменений — это чистый
DOM-оверлей поверх канваса.

### 4.9 Приватность в web-сборке — что реально покидает браузер

По умолчанию — **ничего**. Сеть в wasm-сборке отсутствует на уровне
зависимостей (Правило 1), поэтому ни контекст нод, ни ключи, ни подсказки
никуда не отправляются. Исключение одно и явное: включённая пользователем
телеметрия (FR-089) отправляет анонимные продуктовые события (показ/принятие
подсказки, cost-события) в PostHog без PII. BYOK-ключ в localStorage — плата
за отсутствие keychain в браузере; это задокументированное отличие, а не
утечка (ключ никуда не отправляется из wasm-кода).

## 5. Desktop vs Web — сводная таблица отличий

| Аспект | Desktop (`canvasdesk`) | Web (`canvas-web` wasm) |
|---|---|---|
| Сетевой транспорт LLM | `ureq` (+TLS за `l1-llm-tls`) | Отсутствует (ADR-0011); fetch-транспорт F-5.10 — TODO |
| Suggest-источники | lex + Laya sidecar + LLM mm-source (за фичами) | Только lex (sync на UI-треде) |
| Провайдеры из настроек | Реальные (`llm_factory` + `l1-llm`) | Stub: фабрика всегда `None` |
| OAuth ChatGPT | Полный флоу (listener + браузер, токены 0600) | Кнопка дизейбл + тост; web-путь F-5.10 — TODO |
| Health-check | Заглушка (`FR-LLM-FIX-TODO`) | Заглушка |
| Agent Panel / Graph Builder | UI готов, входы не подключены, вызовы mock | То же самое |
| Хранение настроек | `config.toml` (рядом с бинарём) | `localStorage` (TOML-текст) |
| Хранение ключей | OS keychain / файлы с 0600 | localStorage, открытый текст |
| Журнал suggest S0 | `suggest-log.jsonl` | Не пишется |
| Исходящий трафик | По активным провайдерам | Только телеметрия при opt-in |

## 6. Как проверить: пошаговые сценарии

Предусловия для всех сценариев: браузер на Chromium с WebGPU; стенд —
любой из §2 (прод-URL, `trunk serve`, локальная сборка). Каждый сценарий
занимает 1–3 минуты; полный регресс — ~20 минут.

### Сценарий A — первый запуск и статусная панель

1. Открыть стенд в чистом профиле (localStorage пуст).
2. Дождаться загрузки канваса (в dev-сборке до ~90 с; первый кадр ~7 с).
3. Ожидаемо: онбординг; статусная AI-панель **отсутствует** — это корректно,
   дефолт `LlmSettings` — все провайдеры Off (`all_off` → панель скрыта).
4. Открыть настройки → 9-й таб → включить любой провайдер (например,
   Suggest → BYOK).
5. Ожидаемо: панель появилась справа внизу над миникартой; чип модели
   `glm-5.3-flash`, чип провайдера, тумблеры, Session/Day, ⏸, ⚙.

### Сценарий B — настройки AI и persist в localStorage

1. В 9-м табе: для Suggest выбрать BYOK, ввести тестовый ключ
   `sk-test-…`, для Graph Builder выбрать ChatGPT OAuth.
2. Проверить строки: модель `glm-5.3-flash`, residency Local, cost-лимит
   $1.00, confidence 0.5, телеметрия OFF.
3. Перезагрузить страницу (F5).
4. Ожидаемо: все выборы и ключ сохранились (localStorage, TOML-текст);
   статусная панель снова видна (Suggest ≠ Off).
5. Очистить site data → настройки сброшены, панель исчезла (п. A.3).

### Сценарий C — статусная панель: тумблеры, пауза, ⚙

1. Клик по тумблерам Suggest ✓ / Graph ✓ / Agent ✓ — функции
   включаются/выключаются, состояние синхронно с 9-м табом.
2. Выключить все три → панель скрывается (эквивалент `all_off`).
3. Включить обратно, клик ⏸ → индикация паузы (AI-функции на паузе);
   повторный клик (▶) — снятие.
4. Клик ⚙ → открыта модалка настроек на 9-м табе.
5. Сузить окно < 900px → панель скрыта; расширить → вернулась.

### Сценарий D — Suggest: ИИ-строки, ghost-ноды, порог

1. Создать ноду из палитры шаблонов; начать вводить текст в тело/заголовок.
2. Ожидаемо: попап подсказок содержит ИИ-строки (ранжир каталога под
   контекст) — мгновенно, без сетевых задержек.
3. Выбрать ноду на канвасе → рядом ghost-ноды-подсказки (якорь — выбранная
   нода); принять одну (вставка шаблона), остальные отклонить.
4. В 9-м табе поднять confidence-порог до ~0.9 → повторить ввод:
   часть подсказок отсекается порогом.
5. Ожидаемо на всё: подсказки работают при отключённой сети (проверка
   DevTools → Network: ни одного запроса, кроме опционального PostHog).

### Сценарий E — OAuth-строка: честная заглушка

1. В 9-м табе выбрать Graph Builder → ChatGPT OAuth.
2. Ожидаемо: появилась строка «Вход ChatGPT» с бейджем состояния (Idle).
3. Клик «Войти через ChatGPT» → тост «OAuth-вход доступен только в нативной
   сборке с feature l1-llm-tls»; флоу не стартует.
4. (Опционально) Прогнать на desktop конфиг с выполненным входом и
   перенести настройки в браузер → бейдж покажет «вход выполнен · email»,
   но кнопка остаётся недоступной — токенов в браузере нет.

### Сценарий F — онбординг-тур AI (`#tour=ai-mode`)

1. Открыть стенд с фрагментом `#tour=ai-mode` (или пройти AI-режим
   онбординга и нажать «Продолжить»).
2. Ожидаемо: 4 шага тура — статусная панель (таргет `#aistatus`) →
   кнопка ⚙/9-й таб (`#aiGear`) → privacy (`#aiResid`) → финал со ссылкой
   на `user-docs/ai-features.md`; кнопки Далее/Назад/Пропустить работают.

### Сценарий G — cost-гейт (наблюдаемая часть)

1. В 9-м табе выставить дневной лимит в минимум ($0.25).
2. Статусная панель: прогресс-бар Day отражает лимит; Session/Day пока
   mock-значения (п. 4.5) — это ожидаемо.
3. Сам отказ «Дневной лимит исчерпан» триггерится в панелях
   (agent/graph) — наблюдаем после подключения их входов (волна
   `FR-LLM-D-TODO`); в текущей сборке корректность гейта покрывают
   юнит-тесты `agent_panel.rs` / `graph_builder_ui.rs`.

### Сценарий H — телеметрия (единственный исходящий трафик)

1. В 9-м табе включить телеметрию.
2. Ожидаемо: событие `canvasdesk:consent-changed` в DOM (DevTools →
   Elements/Console), PostHog-скрипт активируется без перезагрузки;
   выключение — opt-out обратно.
3. Выключить телеметрию → сетевой активности из приложения нет.

### Сценарий I — регресс-минимум разработчика (L0 + консоль)

```bash
# L0: сборка wasm без сети — гейт ADR-0011 (ловит случайные сетевые депы)
scripts/wasm_gate.sh --check
# эквивалент: cargo check -p canvas-web --target wasm32-unknown-unknown
```

1. Открыть стенд с открытой консолью: ожидаемо `[render] renderer
   инициализирован backend=BrowserWebGpu`; строка
   `[canvas-web compat] лимиты не распознаны…` — норма (шим index.html).
2. Не ожидается: `pageerror`, panic-строки, обращения к `api.openai.com` /
   `openrouter.ai` в Network.
3. Для UI-правок — полный L2-рецепт с пиксельными диффами:
   [WASM-TESTING.md](WASM-TESTING.html) §3–§4.
