# Market Research: Архитекторы (SA / EA / TA)

> Исследование целевой аудитории для CanvasDesk: Solution Architect,
> Enterprise Architect, Technical Architect. Рынки: глобальный + русскоязычный.
> Формат — живая markdown-база знаний: расширяется коммитами, цитаты ведут
> на первоисточники, каждая боль — отдельный документ с гипотезами и планом
> проверки.

## Состав «комитета экспертов»

Документы написаны как вердикты пяти экспертных ролей — так проще видеть,
откуда взято каждое заключение и где роли конфликтуют:

| Роль | Зона ответственности | Ключевой документ |
|---|---|---|
| **Продуктовый стратег** | мета-проблема, продуктовые возможности, приоритизация | [01-executive-summary](01-executive-summary.md) |
| **UX-исследователь** | портреты ролей, ранжирование болей, язык пользователя | `audiences/` (3 файла) |
| **Конкурентный разведчик** | карта рынка, цены, белые пятна | [competitive-analysis](competitive-analysis.md) |
| **Аналитик сообществ** | каналы, цитаты, культурный контекст (Habr, Telegram, Reddit) | [quotes-bank](quotes-bank.md) |
| **Экономист продукта** | платёжеспособность, размер рынка, kill-критерии | [research-plan](research-plan.md) |

## TL;DR для тех, кто не будет читать 25 файлов

1. **Мета-проблема.** Все 9 болей — симптомы одного разрыва: между *намерением
   архитектора* и *реальностью кода/среды/бюджета*. Инструменты закрывают либо
   «намерение» (Confluence, Miro, TOGAF), либо «реальность» (мониторинг, IaC),
   но не шов между ними.
2. **Самая денежная боль** — техдолг и облачные затраты: за них уже платят
   (Stripe: 42% недели разработчика; Ardoq оценивает EA-платформы в
   $50–750K/год), значит бюджет существует. **Самая массовая** — устаревающая
   документация: её называют все, но готовность платить низкая, пока она не
   связана с деньгами.
3. **Конкуренты не решают корень.** Диаграммные редакторы требуют ручного
   труда, EA-платформы — бюрократии и $50K+, diagram-as-code — дисциплины,
   которой нет. Инструменты класса «живая модель, считающая себя сама»
   только рождаются (Multiplayer, scopedocs.ai, InstantDocs, Uxxu) — окно
   возможности открыто, но закроется за 2–3 года. Teardown пяти главных
   вендоров ([competitive/](competitive/README.md)) показал: ни один не
   закрывает ни одной из 9 болей полностью, а Multiplayer уже
   экспериментирует с MCP — наш первый «мостовой» сценарий надо ускорить.
4. **Позиция CanvasDesk** — не «ещё один редактор диаграмм», а *исполняемая
   модель*: Numi-листы и value-flow считают нагрузку, деньги и риски прямо на
   канвасе, а MCP-агент собирает и проверяет модели. Это попадает в белый
   след между категориями C и F (см. competitive-analysis).
5. **Следующий шаг** — не код, а 15–20 глубинных интервью по [research-plan](research-plan.md).
   Цитат в банке достаточно для скрининга, но недостаточно для выводов о
   готовности платить.

## Почему только markdown, без PDF

По требованию владельца репозитория папка не раздувается бинарными файлами.
Все визуальные элементы — Mermaid-диаграммы и markdown-таблицы, которые GitHub
рендерит нативно; растровой графики в отчёте нет, поэтому PDF не добавляет
информации. Если для внешнего питча понадобится PDF-выжимка — она генерируется
из этих файлов по запросу (см. research-plan, фаза 0, задача 0.4).

## Как обновлять базу

- Новая цитата → `quotes-bank.md` + ссылка в профильную боль (обязательно
  указать дату и статус ссылки).
- Уточнение по аудитории → правка файла в `audiences/`, а не README.
- Новая боль → новый файл `pain-points/NN-slug.md` + строка в матрице
  `pain-points/README.md` (нумерация сквозная, старые файлы не переименовывать).
- Смена вывода → не стирать старый вердикт, а дописать с датой: база
  хранит эволюцию понимания (принцип ADR, применённый к research).
