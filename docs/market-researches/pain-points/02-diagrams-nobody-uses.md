# Боль 02: Артефакты строятся «непонятно для кого»

> Суть: архитектурные документы производятся для процесса, а не для
> потребителя — поэтому их никто не открывает, и производство теряет смысл.

**Матрица:** тяжесть 4/5 · распространённость 5/5 · готовность платить 2/5 ·
доказательность: высокая

## 1. Механизм боли

Артефакт архитектора обязан отвечать на чей-то вопрос: «как масштабировать?»,
«почему дорого?», «что сломается, если…». Когда ответ на вопрос не
проектируется заранее, диаграмма рисуется «вообще» — и не отвечает никому.
Такие документы невозможно поддерживать: у обновления нет клиента. Порочный
круг: артефакт бесполезен → его не читают → его не обновляют → следующий
артефакт рисуют ещё более «для галочки».

## 2. Доказательства и цитаты

> «Эти архитекторы делают непонятно для кого», «Я тут в Miro накидал»,
> «Нарисуй там что-нибудь архитектурное, а то мы уже код пишем» — знакомо?
> — Антон Ущаповский, архитектор, «Проблемы ИТ-архитектуры», Habr.
> [habr.com/ru/articles/1009402](https://habr.com/ru/articles/1009402/)

Три реплики в одной строке задают весь спектр: сарказм потребителей,
самоирония производителя, императив менеджера. Статья собрала резонанс —
это не маргинальный опыт.

> «Я тут в Miro накидал» как рабочий стандарт: диаграмма существует, чтобы
> обосновать статус встречи, а не передать знание. Там же (1009402) обсуждается,
> что артефакты пишутся «в стол».

> «C4 diagrams are only useful when teams can actually navigate and maintain
> them. Otherwise, architecture becomes another source of confusion» —
> Uxxu, 06.04.2026. [uxxu.io](https://uxxu.io)

> «The question of "how much documentation should we write?" is popping up
> a lot recently» — Simon Brown (создатель C4), dev.to. Само существование
> вечного вопроса — симптом: писать нечего/некому/непонятно зачем.
> [dev.to/simonbrown](https://dev.to/simonbrown/a-minimal-approach-to-software-architecture-documentation-4k6k)

Академическая рамка: EA-артефакты создаются по шаблону процесса, а не по
запросу потребителя — «ineffective knowledge [management]» среди топ-5 барьеров
EA ([Hillmann, 2025](https://www.scitepress.org)).

## 3. Как решают сегодня

- **«Минимальная документация»** (Simon Brown: только C4 context+containers,
  ADR, и всё) — урезание объёма вместо решения адресности.
- **Doc-as-pull**: пишут только по запросу — работает в сильных командах,
  в остальных превращается в «нечего читать при онбординге».
- **Порталы/Backstage TechDocs** — улучшают поиск готового, не производство.
- **Интерактивные обзоры** (архитектурные ката, design review встречи) —
  замена артефакта разговором; не масштабируется между командами/часовыми
  поясами.

## 4. Разрыв рынка

Ни один инструмент не заставляет ответить на вопросы **«для кого артефакт»
и «какой вопрос он закрывает»** на уровне формата. Редакторам всё равно,
зачем рисуют; платформам — зачем заполняют карточку. Разрыв — в модельных
инструментах, где артефакт по определению *считает что-то полезное для
конкретного адресата*: если диаграмма выполняет расчёт бюджета для CFO —
у неё есть клиент, даты обновления и критерий качества (числа сходятся или нет).

## 5. Следствия для продукта (гипотезы)

- **Г1.** В CanvasDesk каждая группа нод отвечает на *вопрос адресата*
  (инфраструктура → «выдержит ли?», финансы → «окупится ли?»); шаблоны
  уже сгруппированы по адресату (инфраструктура / юнит-экономика / продуктовая
  аналитика) — проверить в интервью, совпадает ли с реальными запросами.
- **Г2.** «Артефакт = отчёт»: кнопка «сгенерировать версию для CFO/лида/нового
  инженера» из одной модели (одна модель — многие представления) —
  это усиливает возможности №1 и №4 из executive summary.
- **Г3.** Метрика использования: нода/модель, к которой не обращались N
  месяцев, помечается как кандидат на удаление — борьба с «информационным
  кладбищем» в самом инструменте.

## 6. Вопросы для интервью

1. Назовите последний архитектурный документ, который вы открыли
   добровольно. Что искали? Нашли?
2. Кого вы считаете потребителем своих артефактов? Когда он их видел
   последний раз?
3. Были ли артефакты, которые вы перестали обновлять? Почему именно они?
4. Если бы один документ вы могли сделать «живым» (считающим себя), — какой?
