# ADR-0002: Композиция сервисных архитектур через поток значений («один шаблон = один расчёт»)

- **Статус:** принято
- **Дата:** 2026-09-17
- **Участники:** владелец (концепция и запрос), агент (оформление)
- **Связанные:** CR-013; FR-014, FR-025, FR-029; ADR-0003, ADR-0004, ADR-0005

## Контекст

Задача владельца: ИИ-агент через MCP-сервер собирает примеры архитектур
(эталон — упрощённый Instagram MVP для service design: нагрузка, пропускная
способность) из абстрактных шаблонов сервисов, при этом значения между
шаблонами должны **перетекать по связям** («проливание»), без ручного
копирования чисел. Концепция: один шаблон = один расчёт — для условного API
Gateway существует математически взаимозависимое N-число внутренних
характеристик (внутренние расчёты), выдающих N основных выходных характеристик,
важных для других сервисов.

Фундамент уже реализован: value-рёбра и DAG-движок (FR-014,
`crates/canvas-core/src/flow.rs`), построчные выходы Numi-листов (FR-025,
`FlowSolutions.lines`), доменные единицы и queueing-функции (FR-015,
`mm1`/`mmc`/`erlang_c`…), библиотека из 45 шаблонов (FR-019/FR-027).

## Драйверы решения

- Никакого ручного копирования значений между нодами: изменение стартового
  допущения (например, DAU) автоматически пересчитывает весь downstream.
- Шаблон — расчётная единица с contract-поверхностью: входы (параметры) и
  выходы (именованные характеристики), машиночитаемые агентом.
- Ацикличность композиции: граф value-потока — DAG (инвариант FR-014).
- Прозрачность: значения всех портов наблюдаемы (UI-бейджи + `flow_recalc`).

## Рассмотренные варианты

### Вариант A: Агент копирует значения (прочитал `flow_recalc` → записал параметр)
- Плюсы: нулевые изменения кода.
- Минусы: антипаттерн по определению задачи — граф «замерзает» в момент
  копирования; изменение upstream не пересчитывает downstream; N×M RPC-вызовов;
  рассинхрон копий.

### Вариант B: Внешний «компоновщик» вне канваса (агент считает всю модель сам и рисует только картинку)
- Плюсы: гибкость агента.
- Минусы: канвас перестаёт быть источником истины; расчёты не воспроизводимы
  другим агентом/человеком; теряются единицы, перегрузки, диагностика движка.

### Вариант C: Поток значений по value-рёбрам (FR-014) + порты значений шаблонов
- Плюсы: живой пересчёт уже есть; единицы и DAG-инварианты уже есть; агент
  только создаёт ноды и связи — всё остальное считает движок.
- Минусы: требует доработки контракта портов (CR-013 G1–G5) — named outputs,
  привязка входа к параметру, MCP-адресация.

## Решение

Композиция архитектур выполняется **исключительно потокам значений**: шаблон —
расчётная единица («один шаблон = один расчёт»), его внутренние характеристики —
строки Numi-листа/параметры, его внешняя поверхность — именованные выходы
(`outputs`) и параметры (`params`); соединение шаблонов — value-рёбра от
выхода истока к параметру приёмника; пересчёт — движок FR-014. Ручное
копирование значений в композиции запрещено концепцией; единственный ручной
ввод — стартовые допущения входных нод.

## Обоснование

Вариант C — единственный, при котором канвас остаётся исполняемой моделью
(источник истины), а агент — только редактором топологии. Все вычислительные
примитивы (DAG, единицы, queueing, построчные выходы) уже в ядре — доработка
контракта портов (FR-029) дешевле, чем поддержка любой внешней модели.

## Последствия

- **Положительные:** воспроизводимость (другой агент пересобирает тот же граф
  и получает те же числа); single source of truth; натуральная поддержка
  what-if (FR-017) поверх той же семантики.
- **Отрицательные / принятые риски:** шаблоны без объявленных `outputs`
  непрозрачны для агента — переходный период, пока библиотека дополняется;
  позиционные входы `$1..$N` остаются для простых заметок (риск хрупкости —
  закрыт ADR-0003 для шаблонных нод).
- **Нейтральные:** связям между шаблонами предписан `kind = value`; control-рёбра
  остаются для топологии без расчёта.

## Валидация

- Эталонный сценарий ADR-0005: агент собирает Instagram MVP через MCP, все
  связи — value-потоки; изменение стартового допущения одним вызовом
  пересчитывает весь downstream (`flow_recalc`); чек-лист CR-013 §Проверка.
- Автотесты потока (`flow.rs`): проливание в параметр, DAG-инвариант, единицы.
