# Architecture Decision Records (ADR)

Каталог архитектурных решений CanvasDesk. Формат и правила ведения —
`docs/adr/adr-template.md`. Один файл = одно решение; нумерация сквозная;
отмена решения — новым ADR (заменяемому ставится статус `заменено`).

## Как читать по задаче «агентная композиция с проливанием значений»

0. Позиционирование продукта и результаты аудита документации — **ADR-0007**
   (pivot: визуальная система математического моделирования).
1. Концепция и требования владельца — `docs/change-requests/cr-013-agent-architecture-composition.md`.
2. Почему композиция = поток значений (и что отвергли) — ADR-0002.
3. Как адресуются порты (имена vs индексы) — ADR-0003.
4. Каким набором MCP-инструментов агент собирает и проверяет граф — ADR-0004.
5. На чём принимается готовность (состав, связи, эталонные числа) — ADR-0005
   (Instagram MVP) и ADR-0006 (пять эталонов: system design, защита бюджета,
   P&L, value chain, unit economics).
6. Первый реализуемый шаг — `docs/change-requests/fr-029-value-ports.md`.

## Как читать по задаче «вычислительный стек математического моделирования и лицензионная чистота (B2B / реестр РФ)»

0. Позиционирование продукта — **ADR-0007** (pivot: визуальная система
   математического моделирования).
1. Детальная архитектура вычислений —
   `docs/architecture/math-computing-stack.md`: текущее состояние ядра (факты
   с код-ссылками), слои L0–L5, реестр отбора библиотек с лицензиями,
   параллельные вычисления, лицензионная политика, соответствие реестру РФ
   (ПП РФ № 1236), дорожная карта M0–M6, риски.
2. Решение и его статус — **ADR-0008** (принято владельцем 2026-09-18;
   продуктовое время этапов — `docs/plans/product-roadmap.md`).
3. Требования сценарности/чувствительности, под которые строится стек —
   ADR-0006 (№1–№5), FR-017 (what-if); существующая доменная математика —
   FR-015 (queueing) и FR-027 (финансы v1).
