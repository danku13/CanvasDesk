# ADR-0005: Эталонный сценарий «Instagram MVP» — acceptance-модель агентной композиции

- **Статус:** принято
- **Дата:** 2026-09-17
- **Участники:** владелец (постановка), агент (методика и расчёты)
- **Связанные:** CR-013; FR-029; ADR-0002, ADR-0004; ADR-0006 (каталог эталонов №1–№5 — настоящий сценарий служит развёрнутым приложением эталона №1 «System design»); `assets/templates/`

## Контекст

Концепция «один шаблон = один расчёт» (ADR-0002) требует воспроизводимого
эталона: минимальной архитектуры, которую ИИ-агент собирает через MCP
исключительно проливанием значений, и по которой принимается готовность
FR-029 и последующих FR (R2/R3 CR-013). Владелец предложил упрощённый MVP
Instagram для service design: нагрузка, пропускная способность.

## Драйверы решения

- Эталон собирается **только** из текущей builtin-библиотеки (45 шаблонов) + текстовых Numi-нод.
- Каждый межсервисный переход — value-ребро с адресацией порта (после FR-029); в переходный период сценарий фиксирует, какой инструмент нужен на каждом хопе.
- Числа эталона проверяемы вручную (формулы приведены), автотесты сверяются с движком.

## Рассмотренные варианты

### Вариант A: Минимальная связка из 3 нод (Трафик → Gateway → БД)
- Плюсы: мгновенно проверяемо.
- Минусы: не покрывает split-трафика (несколько downstream-входов) и асинхронной ветки — главные сложности композиции.

### Вариант B: Полный Instagram (stories, reels, DM, рекомендации)
- Плюсы: реалистичность.
- Минусы: 30+ нод; шум detail'ов перекрывает проверку механики проливания.

### Вариант C: Средний эшелон — 12 нод, 3 ветки (синхронный фид, медиа, асинхронные события)
- Плюсы: покрывает все виды хопов (fan-out по долям, read/write-расщепление, кэш-промахи, очередь) при обозримом размере.
- Минусы: требует допущений о долях (зафиксированы ниже как параметры).

## Решение

Эталон — вариант C: **Instagram MVP, 12 нод**. Состав, цепочки проливания и
эталонные числа зафиксированы в §Состав и §Эталонные значения; декларативный
план сборки (JSON для будущего `graph_apply`) — в CR-013 §Эталонный сценарий.
Сценарий — критерий готовности FR-029 и база рецепта для агентов (R5 CR-013).

## Состав (все шаблоны — из `assets/templates/`)

| # | Нода | Шаблон | Параметры/формула |
|---|---|---|---|
| 1 | Трафик-профиль | текстовая Numi-нода | `dau = 1000000`, `sess = 4`, `req = 12`, `peak = 2.5` → `avg_rps = dau*sess*req / 86400 s`, `peak_rps = avg_rps*peak` |
| 2 | CDN | `com.canvasdesk.cdn` | `hit = 60 %` |
| 3 | Балансировщик | `com.canvasdesk.tcp-lb` | деление origin-трафика по долям |
| 4 | API Gateway | `com.canvasdesk.api-gateway` | `mm1($rps, 1 req/($latency_budget - $auth_overhead))` |
| 5 | Auth | `com.canvasdesk.auth-service` | 15 % трафика |
| 6 | Feed/GraphQL | `com.canvasdesk.graphql` | 60 % трафика |
| 7 | Media | `com.canvasdesk.grpc-service` | 25 % трафика |
| 8 | Кэш | `com.canvasdesk.cache-redis` | `hit = 70 %` |
| 9 | БД master | `com.canvasdesk.db-sql-master` | записи + промахи кэша |
| 10 | БД replica | `com.canvasdesk.db-sql-replica` | разгрузка чтений |
| 11 | Очередь | `com.canvasdesk.queue-kafka` | события фида |
| 12 | Воркеры | `com.canvasdesk.worker` | потребители очереди |

## Цепочки проливания (value-рёбра с адресацией порта)

```
1.peak_rps → 2.rps                       (весь пик через кромку)
2.origin_rps → 3.rps                     (промахи CDN: 40 %)
3.out_gateway → 4.rps                    (fan-out по долям)
3.out_auth → 5.rps
3.out_feed → 6.rps
3.out_media → 7.rps
6.db_qps → 9.qps                         (чтения: 80 % от фида, промахи кэша 30 %)
9.replica_load → 10.qps
7.bandwidth → 11… (медиа-поток)          (запись в хранилище: отдельная нода S3 в v2 эталона)
6.events → 11.produce_rate
11.consume_rate → 12.consumed_rps
```

## Эталонные значения (ручной расчёт)

| Величина | Формула | Значение |
|---|---|---|
| avg_rps | 1e6 · 4 · 12 / 86400 | ≈ 555.6 rps |
| peak_rps | 555.6 · 2.5 | ≈ 1389 rps |
| origin_rps | 1389 · (1 − 0.6) | ≈ 556 rps |
| auth_rps | 556 · 0.15 | ≈ 83 rps |
| feed_rps | 556 · 0.60 | ≈ 333 rps |
| media_rps | 556 · 0.25 | ≈ 139 rps |
| db_read_rps | 333 · 0.8 · (1 − 0.7) | ≈ 80 rps |
| events_rps | 333 (каждый запрос фида = событие) | ≈ 333 rps |

Допуск автосверки — ±1 % (округление в цепочке).

## Последствия

- **Положительные:** единый acceptance для всех FR дорожной карты CR-013;
  сценарий сериализуем в план `graph_apply` и превращается в рецепт агента и
  демонстрационный `.canvas`. Расширенная эталонная база (№2 защита бюджета,
  №3 P&L, №4 value chain, №5 unit economics) — в каталоге ADR-0006.
- **Отрицательные / принятые риски:** допущения (доли 15/60/25, hit-rate) —
  иллюстративные, не паспорт Instagram; менять их вместе с числами таблицы.
- **Нейтральные:** хранилище медиа (`storage-s3`) отнесено к v2 эталона, чтобы
  v1 оставался в рамках 12 нод.

## Валидация

- После FR-029: сборка сценария агентом через MCP; `flow_recalc` — значения
  узлов сходятся с таблицей §Эталонные значения; изменение `dau = 2000000`
  одним вызовом удваивает всю цепочку без правки связей.
- Регресс: сценарий сохраняется в `examples/` как `.canvas` (в момент
  реализации R5) и пересчитывается автотестом движка.
