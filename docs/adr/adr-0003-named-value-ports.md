# ADR-0003: Адресация портов значений — именованные выходы и параметрические входы

- **Статус:** принято
- **Дата:** 2026-09-17
- **Участники:** владелец (концепция), агент (анализ и оформление)
- **Связанные:** CR-013 (G1, G2, G5); FR-025, FR-029; ADR-0002

## Контекст

Чтобы value-ребро могло соединить «выход N характеристик шаблона A» с «входом
шаблона B», концы ребра нуждаются в адресации точнее, чем «нода целиком».
Сегодня есть только `Edge::from_line: Option<usize>` (FR-025) — индекс строки
Numi-листа истока, и позиционные входы `$1..$N` по порядку рёбер
(`crates/canvas-core/src/flow.rs:319-350`). Проблемы: индекс строки нестабилен
при правке текста (строки сдвигаются — связь молча начинает уносить другое
значение); вход без имени не позволяет направить два разных значения в два
разных параметра приёмника; формула шаблона (`mm1($rps, ...)`) вообще не читает
позиционные входы (CR-013 G1).

## Драйверы решения

- Связь переживает редактирование текста нод (перестановка/вставка строк).
- Два и более входа приёмника адресуются независимо и явно.
- Агент узнаёт доступные порты из машиночитаемого контракта (`template_list`),
  не угадывая индексы.
- Обратная совместимость: существующие `.canvas` и рёбра FR-025 продолжают работать.

## Рассмотренные варианты

### Вариант A: Только индексная адресация (развить FR-025: `from_line` + `to_line`)
- Плюсы: минимум изменений модели.
- Минусы: индексы нестабильны при правке текста; «порт» остаётся непоименованным
  — контракт нечитаем для агента; семантика входа по-прежнему зависит от порядка
  рёбер.

### Вариант B: Только именная адресация с миграцией всех рёбер
- Плюсы: чистая модель.
- Минусы: ломает существующие файлы и UI-механику FR-025 (drag от строки даёт
  индекс); заметки без манифеста не имеют имён — нужен fallback всё равно.

### Вариант C: Гибрид — имя как канонический адрес, индекс как деталь реализации
- Плюсы: стабильность при правках; совместимость; именованные выходы доступны
  и шаблонам, и обычным заметкам (имя = идентификатор присваивания в строке).
- Минусы: два механизма резолва (индекс/имя) — больше тестовой поверхности.

## Решение

Канонический адрес порта — **имя**: выход — элемент секции `outputs` снапшота
шаблона (`canvasdesk.template.outputs`, поле ребра `fromOutput`), вход — имя
параметра приёмника (`toParam`). Ребро хранит имена; резолв в индекс строки
выполняется при каждом пересчёте. Ребро FR-025 с `fromLine` (индексом) остаётся
валидным адресом (legacy-режим); при наличии обоих полей приоритет — у имени.
Значение ребра с `toParam` подставляется в окружение как `$<параметр>`,
перекрывая локальное значение параметра («проливание сильнее дефолта»);
позиционные слоты `$1..$N` для рёбер без `toParam` не изменяются.

## Обоснование

Гибрид закрывает все драйверы без ломающих изменений: имена дают стабильность
и машиночитаемый контракт, индекс сохраняет работоспособность существующего UI
и файлов. Правило приоритета (имя > индекс) и правило перекрытия
(`toParam` > локальный параметр) — детерминированы и проверяются тестами.
Альтернатива «переписывать формулу инстанса на `$1`» отвергнута: она разрушает
контракт шаблона (CR-013 G1).

## Последствия

- **Положительные:** связи живут при редактировании текста; агент строит
  композицию по именам из `template_list`; входы приёмника самоописаны
  (`toParam: "rps"`).
- **Отрицательные / принятые риски:** снапшот `outputs` может разойтись с
  манифестом после update шаблона (FR-019 linked-update) — принято: снапшотная
  модель уже используется для `expr`/`icon`/`color`; несколько рёбер в один
  `toParam` в v1 — «последний побеждает» + warning (строгая ошибка — R2 CR-013).
- **Нейтральные:** сериализация расширяется опциональными ключами
  `fromOutput`/`toParam` (старые файлы — байт-в-байт).

## Валидация

- Юнит-тесты: round-trip `fromOutput`/`toParam`; резолв имени после сдвига
  строк; перекрытие параметра; legacy `fromLine` без регрессий (модель
  `model.rs:1299-1335`).
- E2E через MCP (FR-029 §Проверка): `edge_create {fromOutput, toParam, kind:"value"}`
  → `flow_recalc` — downstream видит значение конкретной характеристики.
