# ADR-0006: Каталог эталонных сценариев №1–№5 — system design, защита бюджета, P&L, value chain, unit economics

- **Статус:** принято
- **Дата:** 2026-09-17
- **Участники:** владелец (постановка и состав сценариев), агент (методика, расчёты, оформление)
- **Связанные:** CR-013; FR-014, FR-015, FR-025, FR-029, FR-016, FR-017; ADR-0002, ADR-0004, ADR-0005; `assets/templates/`

## Контекст

ADR-0005 зафиксировал первый эталон (Instagram MVP). Владелец расширил эталонную
базу до пяти сценариев (запрос от 2026-09-17) — по одному на класс задач
сервис-дизайна и продуктовой экономики. Каждый эталон — проверяемая модель:
агент собирает граф через MCP, значения проливаются по связям (ADR-0002),
движок считает числа, таблица эталонных значений служит oracle для приёмки
(FR-029 и дорожной карты CR-013).

Все числа ниже просчитаны по формулам фактической библиотеки: `mm1/mmc` —
Erlang-C (`crates/canvas-core/src/expr/queueing.rs:136-145`: W = P_wait/(cμ−λ) + 1/μ,
ρ = λ/(cμ), ρ ≥ 1 → `Overload`), шаблоны `ue-*`/`pa-*` — по манифестам
`assets/templates/*/template.json`. Допуск автосверки ±1 %.

## Общая структура каталога

| № | Сценарий | Класс задач | Ключевые шаблоны | Что доказывает |
|---|---|---|---|---|
| 1 | System design | архитектура + нагрузка + стоимость + риски | `cdn`, `tcp-lb`, `api-gateway`, `auth-service`, `http-endpoint`, `cache-redis`, `db-sql-master/replica`, `queue-kafka`, `worker` | сквозное проливание нагрузки; ρ-диагностика узких мест; смета |
| 2 | Защита бюджета | рост, деградация, цена бездействия | те же + сценарные Numi-ноды | what-if (FR-017) поверх потока; момент перегрузки; ROI опций |
| 3 | P&L | драйверы → выручка/расходы/маржа | `ue-aov`, `ue-gross-margin`, `ue-contribution-margin` + Numi | связь операционки с деньгами; break-even; чувствительность |
| 4 | Business value chain | цепочка ценности и потери | `pa-funnel-conv`, `pa-retention-d7`, `ue-arppu`, `ue-mrr`, `ue-arr` | каскад эффектов изменений по этапам |
| 5 | Unit economics | экономика единицы | `ue-cac`, `ue-arpu`, `pa-user-churn`, `ue-ltv`, `ue-ltv-cac`, `ue-cac-payback` | границы сходимости экономики |

## Эталон №1: System design — ландшафт, узкие места, стоимость, риски

### Цель

Собрать на одном холсте требования, нагрузки, ограничения, сервисы, очереди, БД
и зависимости; сразу увидеть архитектуру, узкие места (ρ), стоимость
инфраструктуры и риски.

### Состав (входные допущения — нода «Нагрузка»)

`dau = 200000`, `sess_per_user = 3 /day`, `req_per_sess = 10`, `peak_mult = 3`
→ `avg_rps = dau·sess·req / 86400 s = 69.44 rps`, `peak_rps = avg_rps·peak = 208.33 rps`.

| Нода | Шаблон | Параметры (← — проливание) | ρ | W (нода) |
|---|---|---|---|---|
| CDN | `com.canvasdesk.cdn` | `rps ← peak_rps (208.33)`, `cache_hit = 0.90`, `origin_latency = 20 ms` | 0.417 | 34.3 ms |
| Балансировщик | `com.canvasdesk.tcp-lb` | `rps ← CDN.origin (20.83)`, `service_rate = 1200`, `servers = 2` | 0.009 | 0.83 ms |
| API Gateway | `com.canvasdesk.api-gateway` | `rps ← 20.83`, `latency_budget = 5 ms`, `auth_overhead = 2 ms` | 0.063 | 3.20 ms |
| Auth | `com.canvasdesk.auth-service` | `rps ← 30 % трафика (6.25)`, `token_verify = 2 ms` | 0.013 | 2.03 ms |
| Приложение | `com.canvasdesk.http-endpoint` | `rps ← 70 % (14.58)`, `timeout = 0.5 s`, `max_connections = 1000` | 0.007 | 0.50 ms |
| Кэш | `com.canvasdesk.cache-redis` | `qps ← чтения 60`, `hit_rate = 0.85`, `eviction_latency = 0.2 ms` | 0.010 | 0.202 ms |
| БД master | `com.canvasdesk.db-sql-master` | `qps ← промахи 9 + записи 6 (15)`, `query_time = 10 ms`, `replicas = 1` | 0.150 | 11.76 ms |
| БД replica | `com.canvasdesk.db-sql-replica` | `qps ← 9`, `query_time = 10 ms` | 0.09 | 10.99 ms |
| Очередь | `com.canvasdesk.queue-kafka` | `produce_rate ← события 20`, `partitions = 6`, `partition_consume = 400` | 0.008 | 2.52 ms |
| Воркеры | `com.canvasdesk.worker` | `tasks_per_sec ← 20`, `processing_time = 50 ms`, `workers = 4` | 0.250 | 50.34 ms |

Смета (Numi-нода «Стоимость», `$/мес`): CDN 50 + LB 72 (2×36) + GW 36 + Auth 72
(2×36) + App 288 (4×72) + Redis 85 + DB 180 + replica 90 + Kafka 150 + Workers
144 (4×36) = **$1167/мес**.

### Эталонные значения и выводы

- Узкое место №1 — CDN (ρ = 0.417), далее воркеры (0.25) и БД master (0.15).
- Рисков (ρ > 0.8, порог FR-016) нет — ландшафт здоров при текущей нагрузке.
- Сверка движка: W каждой ноды совпадает с колонкой таблицы (Erlang-C).

## Эталон №2: Защита бюджета действующей системы

### Цель

Оцифровать текущий ландшафт (копия эталона №1), смоделировать рост нагрузки,
техдолг, инциденты и деградацию; показать, что будет без инвестиций и что даёт
каждая опция. Формат вывода: «вот модель, вот сценарии, вот цена бездействия».

### Состав

Нода роста (Numi): `growth = 15 %/мес`, `horizon = 12 мес`, `M = 1.15^12 = 5.350`
→ `peak_12 = 208.33 × 5.350 = 1114.6 rps`. Все λ-параметры ландшафта №1
масштабируются проливанием от `peak_12` (те же доли трафика).

Сценарные ветки (what-if, FR-017):

| Ветка | Изменения | ρ на горизонте 12 мес |
|---|---|---|
| C. Бездействие | ничего | CDN **2.23 → Overload** (движок даёт ошибку перегрузки — красная диагностика), воркеры **1.34 → Overload**, БД 0.80 (у порога риска) |
| A. Масштабирование origin | `origin_latency` 20 → 4 ms (μ = 250) | CDN 0.446; цена **+$120/мес** |
| B. Кэш агрессивнее | `cache_hit` 0.90 → 0.97 | CDN 0.669 (λ = 1114.6·0.03); цена **+$85/мес** |
| D. Воркеры ×2 | `workers` 4 → 8 | воркеры 0.669 (107/(8·20)); цена **+$144/мес** |
| E. Реплика БД | `replicas` 1 → 2 | БД 0.402 (80.25/200); цена **+$90/мес** |

### Эталонные значения и выводы

- Момент перегрузки без действий: `1.15^m = 50/20.83 = 2.4` → **m ≈ 6.3 → месяц 7** (CDN).
- Цена бездействия: в часы пика (30 % суточного трафика) конверсия падает на 40 %
  → потери = 10000 заказов × 0.3 × 0.4 × $45 (aov из эталона №3) =
  **$54 000/мес**.
- Пакет A+B+D+E = **$439/мес (0.10 % выручки)** — снимает все перегрузки
  (ρ ≤ 0.67); соотношение «цена пакета / цена бездействия» ≈ **123×**.
- Сверка движка: ветка C — две ноды в состоянии `Overload` (ρ в тексте ошибки:
  2.23 и 1.34); ветки A–E — значения таблицы.

## Эталон №3: P&L — операционные драйверы → прибыль

### Цель

Связать операционные драйверы с выручкой, переменными и постоянными расходами;
прогнать сценарии; увидеть маржинальность, точку безубыточности и
чувствительность к допущениям.

### Состав и цепочки проливания

```
visitors (500000) ──→ orders = visitors × conv (2 %) = 10000
orders ──→ revenue = orders × aov ($45, ue-aov) = $450 000
revenue ──→ variable = COGS 30 % + эквайринг 2.9 % = $148 050
(revenue, variable) ──→ CM = (rev − var)/rev = 0.671 (ue-contribution-margin)
fixed = infra ← $1167 (проливание из эталона №1!) + payroll 140000
        + marketing 60000 + tools 18000 = $219 167
EBITDA = rev·CM − fixed = $82 783;  margin = 18.4 %
break-even: rev_be = fixed/CM = $326 627;  orders_be = 7258; visitors_be = 363 000
```

### Сценарии и чувствительность

| Сценарий | Изменение | EBITDA | Маржа |
|---|---|---|---|
| База | — | $82 783 | 18.4 % |
| Конверсия −20 % | conv 2 % → 1.6 % (orders 8000) | $22 393 | 6.2 % |
| Конверсия +20 % | conv 2.4 % (orders 12000) | $143 173 | 26.5 % |
| AOV ±$5 | чувствительность EBITDA | ±$33 550 | — |

### Эталонные значения

revenue $450 000; variable $148 050; CM 67.1 %; fixed $219 167 (в т.ч. инфра
$1167 — живая связь с эталоном №1); EBITDA $82 783; BE-выручка $326 627;
BE-заказы 7259.

## Эталон №4: Business value chain — от потребности до денег

### Цель

Визуализировать цепочку создания ценности: от потребности клиента до денежного
результата; показать этапы, участников, метрики, потери и эффекты изменений.

### Состав (этапы — цепочка нод, потери считаются на каждом шаге)

```
visits 1 000 000
  → signup ×25 % = 250 000            (потеря 750 000)
  → d7-удержание ×35 % = 87 500       (pa-retention-d7; потеря 162 500)
  → оплата ×4 % = 3 500 платящих      (pa-funnel-conv; потеря 84 000)
  → MRR = платящие × ARPPU $18 = $63 000   (ue-mrr)
  → ARR = MRR × 12 = $756 000          (ue-arr)
```

Сквозная конверсия visits → платящие = 0.25 × 0.35 × 0.04 = **0.35 %**.

### Эффект изменения (главная демонстрация каскада)

Активация 25 % → 30 % (+5 п.п.) одним изменением параметра:
300 000 → 105 000 → **4200 платящих → MRR $75 600 (+$12 600 = +20 %)**,
ARR $907 200. Эффект +20 % на выручке от +5 п.п. на первом этапе виден мгновенно
— весь downstream пересчитывается проливанием, без ручного пересчёта.

### Эталонные значения

3500 платящих; MRR $63 000; ARR $756 000; сквозная конверсия 0.35 %; потери по
этапам 750k / 162.5k / 84k; эффект +5 п.п. активации = +$12 600 MRR.

## Эталон №5: Unit economics — сходится ли экономика единицы

### Цель

Посчитать экономику одного клиента: CAC, LTV, ARPU, маржинальность, срок
окупаемости; понять, при каких допущениях экономика сходится, а при каких — нет.

### Состав и цепочки проливания

```
spend $60 000 ──→ new_customers 3000 ──→ CAC = 60000/3000 = $20      (ue-cac)
MRR $96 000, users 8000 ──→ ARPU = $12                               (ue-arpu)
active_t0 10000, active_t1 9500, new_t1 500 ──→ churn = 10 %/мес     (pa-user-churn)
LTV = ARPU × margin / churn = 12 × 0.8 / 0.1 = $96                   (ue-ltv)
LTV/CAC = 96/20 = 4.8  (порог сходимости ≥ 3)                        (ue-ltv-cac)
Payback = CAC/(ARPU × margin) = 20/9.6 = 2.08 мес                    (ue-cac-payback)
```

### Границы сходимости (сценарии допущений)

| Допущение | LTV | LTV/CAC | Вывод |
|---|---|---|---|
| База (churn 10 %, margin 0.8) | $96 | **4.8** | сходится с запасом |
| Churn 25 %/мес | $38.4 | 1.92 | не сходится |
| Margin 0.6 + churn 15 % | $48 | 2.4 | не сходится |
| Требуемый CAC при базе | LTV/3 = $32 | 3.0 | потолок CAC для сходимости |

### Эталонные значения

CAC $20; ARPU $12; churn 10 %; lifetime 10 мес; LTV $96; LTV/CAC 4.8; payback
2.08 мес; потолок CAC $32.

## Требования платформы (что должны дать FR дорожной карты CR-013)

| Требование | Сценарии | Источник |
|---|---|---|
| Проливание в параметры приёмника (`toParam`) — все межсервисные связи | №1–№5 | FR-029 |
| Адресованные выходы (`fromOutput`) — доли трафика, промахи кэша, этапы воронки | №1, №2, №4 | FR-029 |
| `flow_recalc` v2 (значения + outputs + lines) — oracle для приёмки | все | FR-029 |
| What-if/override сценариев без правки базового графа | №2, №3, №5 | FR-017 |
| Индикаторы риска ρ > 0.8 / Overload на канвасе | №1, №2 | FR-016 |
| Композитные шаблоны (эталон целиком как одна нода-паттерн) | №1–№5 (v2) | CR-013 R4 |

## Валидация

- Автосверка: для каждого эталона — e2e-сборка через MCP (после FR-029) +
  `flow_recalc` — значения узлов и портов совпадают с таблицами (±1 %).
- Регресс-тесты движка: числа эталонов фиксируются юнит-тестами
  (`flow.rs`, `queueing.rs`) — как минимум ключевые строки: Overload 2.23/1.34
  (№2), CM 0.671 и BE-заказы 7259 (№3), каскад +20 % (№4), LTV $96 (№5).
- Ручная приёмка владельцем по чек-листу CR-013 §Проверка.
