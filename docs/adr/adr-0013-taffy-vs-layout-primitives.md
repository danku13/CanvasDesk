# ADR-0013: Taffy против собственных layout-примитивов — судьба V-3 (PRD-0009) и план усиления кита

- **Статус:** предложено (анализ по прямому запросу владельца; утверждение решения — за владельцем)
- **Дата:** 2026-09-23
- **Участники:** владелец (вопрос «почему не taffy, какие выигрыши, как усилить кит»), агент (анализ кода, внешнее исследование taffy 0.14.0, wasm-замер)
- **Связанные:** PRD-0009 §7.2 V-3 / §7.4 / §9.5 / Non-goals (исходное решение и «отложено в v2»), FR-062 (план усиления кита — постановка), FR-060 (волна 2 миграции), FR-061 (этап E kit-Row — потенциальный потребитель усилений), ADR-0008 (лицензионный allowlist), ADR-0011 (wasm-гейт), `docs/ui-kit.md`, `crates/canvas-ui/src/layout.rs` (F-7)

## Контекст

Владелец запросил (сессия 2026-09-23): *«Надо понять почему мы не использовали taffy (dioxusLabs), какие есть выигрыши от использования против актуального плана и как нам усилить свой UI kit»*.

Факты системы на момент запроса:

- Решение по taffy зафиксировано в PRD-0009 (создан 2026-09-22): комбинация **V-4 + V-5 + V-6 + V-7** (слои+реестр, layout-примитивы+измеренный текст+scissor, кит, линты); **V-3 (retained-дерево + taffy) сознательно отложен в v2**, интерфейс примитивов V-5 выбран совместимым со слотами taffy (`layout.rs:7`, `geometry.rs:7`), эскалация возможна без переписывания потребителей; §9.5: «taffy (если v2) — отдельный ADR до реализации». Настоящий ADR исполняет это условие.
- Волна 2 кита частично выполнена: FR-056 (scissor, **+4 020 Б к wasm**), FR-057 (Painter/WidgetState/FocusRing), FR-058 (компоненты v2), FR-059 (миграция волна 1 + витрина); FR-060 (autolink/palette/explain + хвосты app.rs) — в постановке.
- `canvas-ui` — 5 475 строк чистой геометрии без wgpu/winit: `layout.rs` 436 строк (Row/Column{gap, MainAlign, CrossAlign, RowPolicy{Fit,SqueezeTail}}, stack, constrain, pad, Custom), `kit.rs` 2 020 строк (Panel/Button/IconButton/Dropdown/Chip/Toast/Tooltip/Modal/TextField/Switch/Card/Icon/список+скролл), TextMeasurer (cosmic-text), 120 тестов крейта. UI — immediate-mode: пересборка «на кадр», дети примитивов — `Child::fixed(w, h)` (явные размеры).
- Бюджет G7: прирост wasm-бина волны 2 — ≤ 100 КБ (протокол замера FR-056: trunk release, без wasm-opt, до/после).
- ADR-0008: прод-зависимости — только пермиссивные лицензии (MIT проходит), нативных C-зависимостей нет.

Факты о taffy (внешнее исследование, 2026-09-23):

- **taffy 0.14.0** (crates.io, релиз 2026-08-24; MSRV 1.71; MIT; ~13.9 млн загрузок) — layout-движок: CSS **Flexbox**, **CSS Grid**, **Block** (+ float, calc(), content_size) переключаемыми cargo-фичами; `default-features = false` даёт no_std-совместимость (все зависимости — slotmap/smallvec/cssparser/serde — опциональны).
- API — **retained-дерево**: `TaffyTree` (slotmap-узлы), `Style`, `compute_layout(root, AvailableSpace)`, чтение результатов `tree.layout(node)`; размер от контента — measure-функции на узле.
- Продакшн-потребители: **Servo** (веб-движок), **Bevy** (UI игрового движка), **Zed** (GPUI), **Slint**, **Lapce/Floem**, Blitz (Dioxus), iocraft, Takumi. Бенчмарки README: 1 000 узлов (глубина 3) ≈ 329 мкс; 10 000 узлов ≈ 4.3 мс — полный проход; в дереве есть кэш/инкрементальность.
- Лицензия MIT — в allowlist ADR-0008; нативных зависимостей нет; wasm-биндинги — WIP (не требуются: вызов напрямую из Rust).

## Замер цены (wasm, методология G7)

Изолированный стенд: cdylib с минимальным реальным сценарием (колонка: шапка фиксированной высоты + тело `flex_grow` + строка из 6 чипов с gap; полный проход `compute_layout`), `wasm32-unknown-unknown`, release (opt-level 3), **без wasm-opt** — та же методология, что G7-замер FR-056. Базлайн — пустая cdylib тем же профилем.

| Конфигурация | Размер .wasm (raw) | Прирост к базлайну |
|---|---|---|
| Базлайн (пустая cdylib) | 322 Б | — |
| taffy 0.14, фичи `[std, taffy_tree, flexbox]` (минимальный набор) | **111 120 Б** | **≈ 108.5 КБ** |
| taffy 0.14, фичи `[std, taffy_tree, flexbox, grid]` | 385 006 Б (с panic-контуром `unwrap`) / 382 049 Б (без unwrap/panic) | ≈ 376 КБ |
| — тот же бин в gzip | 105 911 Б | ≈ 103 КБ |

Справочно: прирост всего scissor-клиппинга (FR-056) — **+4 020 Б**; G7-остаток волны 2 — **≤ 100 КБ**.

Выводы замера: (1) даже **минимальный** набор taffy (flexbox без grid) занимает ≈ 108.5 КБ — **больше всего G7-остатка волны**; (2) CSS Grid добавляет ≈ +270 КБ (≈ 3.7× бюджета) — не обсуждается в текущем бюджете вовсе; (3) оговорка: изолированный стенд тянет собственные куски std/alloc, в реальном бандле приложения часть кода общая — маржинальная цена ниже, но порядок тот же (вариант без panic-машинерии 382 КБ показывает, что доминирует сам движок, а не панический контур). Команды воспроизведения — в §Валидация.

## Драйверы решения

- **D1. Бюджет G7** — прирост wasm-бина регламентирован (≤100 КБ на волну), замер обязателен.
- **D2. Immediate-mode сохраняется** — пересборка кадра «на кадр»; retained-дерево виджетов — non-goal PRD-0009.
- **D3. Чистая геометрия + headless-TDD** — `canvas-ui` без wgpu/winit, детерминизм, 120 тестов; AGENTS.md (тесты до реализации).
- **D4. Зависимости** — ADR-0008 (MIT допустим), но «0 новых зависимостей PoC» — фактический статус кита; каждая зависимость — цена аудита и R-6 (порог входа агентов).
- **D5. Класс проблем** — фактические дефекты UI-слоя (z-порядок, ввод сквозь попапы, налезания, тихие срезы) решены слоями/реестром/примитивами/линтами; «мощности вёрстки» в списке дефектов не было.
- **D6. Ноль визуального скачка** — миграции идут дословной геометрией (U5-паттерн).
- **D7. Дверь открыта** — интерфейс V-5 совместим со слотами taffy; эскалация не должна требовать переписывания потребителей.
- **D8. Реестр поверхностей не зависит от движка вёрстки** — слои/capture/hit-порядок ортогональны тому, кто считает rect'ы.

## Что даёт taffy против актуального плана (честное сравнение)

| Возможность | layout.rs сегодня | taffy 0.14 | Значение для CanvasDesk |
|---|---|---|---|
| Размер от контента (auto/min/max-content) | нет: `Child::fixed`, ширины из TextMeasurer проводятся вручную | measure-функции на узле дерева | **Главный реальный выигрыш**; закрывается дешевле F-13 (FR-062) без +108 КБ |
| per-child grow/shrink | нет: `Fit`/`SqueezeTail` — политика всего ряда | `flex_grow/shrink/basis` на ребёнке | Второй по ценности; закрывается F-14 (FR-062) |
| Многострочный wrap | нет | `flex_wrap` | Встречается (ряды чипов); закрывается F-15 для известных случаев |
| 2D-сетка | нет (вложенные Row/Column) | CSS Grid (спаны, авто-треки) | Потребность появляется у FR-061 этап E (tabular stage); Grid-lite (F-16) покрывает равные треки; полный Grid — только с taffy (+270 КБ) |
| aspect-ratio / calc() / проценты | `constrain(min, max, desired)` | есть | Потребности на текущих 8–10 панелях нет |
| Инкрементальный релайаут, кэш дерева | нет (полный пересчёт; узлы ≈ 10² на поверхность → десятки мкс) | dirty-кэш в дереве | Выгода требует retained-дерева (D2) — вне плана; при immediate-пересборке дерева на кадр кэш частично теряется |
| Спек-семантика CSS, зрелые алгоритмы | свои примитивы, 15 тестов | спека + Servo/Bevy/Zed/Slint | Зрелость не оспаривается; но CSS-семантика шире нужного, MDN-документация — плюс онбординга |
| Зависимости / wasm | 0 внешних; ~0 КБ | MIT; **+108.5…376 КБ** | Нарушает D1 даже в минимальном наборе |

| Отладка/детерминизм | чистые функции, G4-линты по геометрии | детерминирован, но +1 модель | R-6: агенты получают вторую ментальную модель вёрстки |

## Почему taffy не был использован (реконструкция решения PRD-0009 §7.2/§7.4)

1. **Класс проблем был другой.** Дефекты UI-слоя (§2.1 PRD-0009) — z-порядок, клики сквозь попапы, налезания, тихие срезы — решаются механикой слоёв/реестра/примитивов/линтов (V-4/V-5/V-6/V-7). Immediate-пересборка кадра «фактически работала»; дефицит мощности flexbox/grid в истории дефектов отсутствует.
2. **Цена модели.** Taffy — retained-дерево: перевод 20+ поверхностей несоразмерен PoC; новый рантайм-стиль состояний (diff/patch, node-id) усложняет отладку и ломает «ноль скачка» (D6) на период миграции.
3. **Бюджет G7.** Новая зависимость в wasm-бандле при избыточности flexbox для 8–10 панелей. Замер 2026-09-23 (§выше) переводит это из качественного аргумента в количественный: минимальный набор ≈ весь G7-остаток волны, набор с grid — 3.7× бюджета.
4. **Дверь оставили открытой сознательно.** Интерфейс V-5 выбран совместимым со слотами taffy; §9.5 требовал отдельного ADR до реализации — эскалация остаётся управляемой процедурой, а не переписыванием.

Отдельно: egui (V-2) — другой случай, отвергнут навсегда (двойной текстовый рендер, конфликт PRD-0006, +1–2 МБ); к taffy эти причины не применяются и не применялись.

## Рассмотренные варианты

### Вариант A: подключить taffy как движок вёрстки (заменить/под layout.rs)

- Плюсы: спек-семантика flex/grid; авто-размеры; wrap; инкрементальность; зрелость Servo/Bevy/Zed; MDN-документация.
- Минусы: +108.5 КБ (flexbox-only) — весь G7-остаток волны; +270 КБ за grid; retained-дерево против D2; миграция потребителей/адаптер; вторая модель вёрстки для агентов (R-6); «счастливый путь» уже работает — выигрываем то, чего не просили.

### Вариант B: актуальный план — усилить собственные примитивы (FR-062) ✅ рекомендован

- Плюсы: 0 зависимостей, ~0 КБ wasm; детерминизм/headless сохраняются; интерфейс и потребители не меняются (только добавление — конвенция волны 2); закрывает ~80% списка выигрышей taffy (auto-размеры, flex-факторы, wrap, равная 2D-сетка) ценой ~сотни строк в layout.rs; иниварианты G4/G5-линтов действуют на новые возможности автоматически.
- Минусы: семантику CSS придётся дозировать самому (каждый новый случай — тесты); Grid-lite не покроет неравные треки/спаны; «самописный flexbox растёт» — нужна дисциплина (митигируется постановкой: каждый пункт F-13…F-18 — с тестами и непревышением бюджета).

### Вариант C: гибрид — taffy как опциональный бэкенд за тем же API

- Плюсы: исполняет обещание PRD-0009 «эскалация без переписывания потребителей» буквально: `Row/Column/stack` остаются API, за ними — taffy-бэкенд по cargo-фиче.
- Минусы: семантики не совпадают дословно (`SqueezeTail` (хвост до нулевой ширины, half-open hit) ≠ flex-shrink (min-content пол); `Fit`-переполнение видно линту ≠ flexbox растягивает контейнер) — адаптер либо врёт, либо расходится в edge-случаях; поддержка двух бэкендов × двойные тесты; выигрыш отложен, цена — нет.
- Вердикт: не сейчас. Протокол эскалации (§Решение) сохраняет эту дверь без двойной поддержки.

## Решение

1. **Актуальный план не менять:** завершить волну миграции FR-060 (последние hand-rolled поверхности + финальный замер wasm); кит развивать immediate-mode (V-5/V-6) как есть.
2. **Taffy в текущем горизонте не подключать.** Главные выигрыши (размер от контента, flex-факторы, wrap, равная 2D-сетка) закрываются расширением собственных примитивов по FR-062 без +108 КБ и без retained-дерева.
3. **Усилить кит по FR-062** (постановка приложена): F-13 measured-дети (TextMeasurer внутри раскладки), F-14 flex-факторы (`grow`/`MainAlign::End`), F-15 `RowPolicy::Wrap`, F-16 `grid_cells` (равные треки), F-17 связка FocusRing × WidgetState, F-18 геометрические golden-снапшоты кит-компонентов.
4. **Зафиксировать триггеры эскалации на taffy** (любой из):
   - **T1** — ≥3 поверхностей требуют цепочек «контент-размер», и grep-аудит пар `Child::fixed`+`width_of` превышает ~30 мест (ручная проводка стала доминирующей частью диффов);
   - **T2** — появляется поверхность с неравными треками/спанами 2D-сеток (tabular stage FR-061 этап E, defense-дашборды), которую Grid-lite не выражает;
   - **T3** — суммарный релайаут UI в профиле кадра > ~1 мс или > ~2 000 узлов на кадр;
   - **T4** — потребность в CSS-совместимой семантике (встраивание внешних web-спек дизайна).
5. **Протокол эскалации** (исполняет §9.5 PRD-0009 и D7): (a) минимальный набор фич `[std, taffy_tree, flexbox]` — grid отдельным решением (+270 КБ); (b) интеграция только за существующим API `Row/Column/stack` (потребители не переписываются); (c) замер G7 на реальном бандле до merge — превышение ≤100 КБ требует явного решения владельца о бюджете; (d) зависимость — cargo-фичей, выключенной по умолчанию, чтобы taffy не попадал в wasm без явного включения.

## Обоснование

Решение закрывает запрос владельца количественно, а не мнением: выигрыши taffy перечислены (§сравнение) и делимы — ~80% из них достигается ~сотней строк в `layout.rs` с нулевой ценой в бандле (FR-062), остальные ~20% (полный CSS Grid, инкрементальный релайаут retained-дерева) в текущем масштабе (8–10 панелей, ≈10² узлов на поверхность, immediate-пересборка) не востребованы. Зрелость taffy признаётся — триггеры T1–T4 и протокол эскалации делают возврат к вопросу дешёвым: интерфейс V-5 совместим со слотами taffy (дверь PRD-0009 остаётся открытой). Чем пожертвовали: часть семантики CSS придётся дозировать самостоятельно (митигируется TDD-постановкой FR-062 и G4/G5-линтами).

## Последствия

- **Положительные:** G7-бюджет сохранён (0 КБ против +108.5 КБ); одна модель вёрстки для людей и агентов (R-6); FR-062 усиливает кит к этапу E FR-061 (kit-Row) и будущим поверхностям; решение воспроизводимо (замер + триггеры + протокол).
- **Отрицательные / принятые риски:** собственные примитивы растут вместе с потребностями («самописный flexbox растёт») — митигируется правилом «каждое расширение = тесты + замер + линт-покрытие»; Grid-lite не покроет спаны/неравные треки — появление таких потребностей = триггер T2, а не мотив расширять Grid-lite бесконечно.
- **Нейтральные (инерция):** V-3 не закрывается навсегда — совместимость интерфейса и §9.5 остаются в силе; настоящий ADR заменяет часть вербального аргумента PRD-0009 §7.4 (V-3) количественным, не меняя вердикта.
