# T13. Миникарта — план (параллельная сессия с T14)

ЗАДАЧА: миникарта по SPEC §6.1 / TASKS T13. Сессия идёт параллельно с T14 (поиск);
файловые зоны воркеров не пересекаются. Владелец переупорядочил M3: T11/T12 отложены
на период после релиза v1.0, M3 кодируется как T13+T14.

## 1. Цель и критерии приёмки

- Обзорный кадр сцены 220×140 логических px в правом нижнем углу окна
  (отступ 16 px, полупрозрачный фон, скругление углов).
- Содержимое: упрощённые прямоугольники нод (без текста и текстур, цвет по типу);
  edges линиями 1 px — только если нод < 500, иначе только ноды.
- Белая рамка = текущий viewport. Клик по миникарте → центрирование камеры;
  drag внутри миникарты → панорамирование (world-точка под курсором следует за курсором).
- Обновление не каждый кадр, а по изменению сцены или камеры (грязный флаг).
- Критерий производительности: на 5000 нод растеризация+загрузка миникарты < 2 мс;
  навигация кликом точна (клик в центр ноды на миникарте центрирует камеру по этой ноде).

## 2. Что уже есть (инвентарь)

- `canvas-render/src/renderer.rs` — `Renderer` (владеет surface, проходы grid/cards/
  thumbs/text), `render(camera, scene, hud, editing, overlay) -> FrameStats`;
  `FrameOverlay.screen_instances` — квады в логических px (CardInstance: fill+border+
  скругление). `scale_factor` хранится в Renderer (физ./лог. px).
- `canvas-render/src/thumbs.rs` — паттерн GPU-пайплайна текстурированных квадов
  (instanced quads + выборка из атласа; шейдер `shaders/thumbs.wgsl`).
- `canvas-render/src/camera.rs` — `Camera` (position = world-точка в центре viewport,
  `visible_world_rect(viewport)`, `set_center`/`set_zoom` добавит T14-B).
- `canvas-core/src/model.rs` — `Node` (file/text/group, `broken_link`, rect), `Edge`.
- `canvas-app/src/main.rs` — `App`: `mark_dirty()`/`request_redraw()`-протокол,
  `scene.canvas`, камера, `scale_factor` через `window.scale_factor()`, DPI-смена
  уже пересоздаёт surface (`Renderer::resize`/`set_scale_factor`).

## 3. Архитектура

Три слоя, строго по зонам:

1. **T13-A — `canvas-render/src/minimap.rs` (чистая CPU-модель).**
   `Minimap::capture(canvas, viewport_world, width_px, height_px)` — снимок сцены
   (owned: ноды→AABB+тип, edges→пары центров) + подгонка масштаба (fit content bounds
   с padding 8 px; пустая сцена/одна точка — вырожденные случаи без паники);
   `render() -> MinimapImage { width, height, rgba: Vec<u8> }` — CPU-растеризация
   (фон RGBA с alpha, скругление углов, ноды ≥2×2 px, edges 1 px при нодах < 500,
   белая рамка viewport 2 px); `map_to_world(px) -> world` (hit-test) и
   `world_to_map`. Никакого GPU/wgpu в файле.

2. **T13-B — `canvas-render/src/minimap_pass.rs` + интеграция в `renderer.rs`.**
   GPU-проход: одна текстура RGBA8 (physical-size) + один квад в правом нижнем углу
   в screen-space (физические px, логический размер 220×140 + margin 16).
   Паттерн — как `thumbs.rs` (pipeline, bind group, instanced quad), но без атласа.
   В `Renderer`: поле `minimap: Option<MinimapTexture>`, `pub fn
   set_minimap(&mut self, image: &MinimapImage)` (загрузка через queue; замена при
   смене размера), `pub fn minimap_rect_logical(&self) -> Option<[f32; 4]>` —
   прямоугольник миникарты в логических px для hit-test в приложении (None —
   не задана или окно меньше 220+32 × 140+32 → не рисуем). Квад рисуется последним
   проходом (поверх канваса и оверлеев, до HUD-текста допустимо — углы не
   пересекаются: HUD слева-сверху, миникарта справа-снизу).

3. **T13-C (координатор) — `canvas-app/src/main.rs`.** Пересборка миникарты по
   dirty: изменение модели (`mark_dirty`), камеры (позиция/зум изменились с прошлого
   кадра), resize/DPI-смена. Загрузка через `renderer.set_minimap`. Мышь: если
   курсор в `minimap_rect_logical()` — ЛКМ drag = пан (курсор тянет world-точку),
   клик (без движения) = мгновенное центрирование. Взаимодействие перехватывает
   события ДО камеры/нод.

**Отступление от SPEC §6.1** («minimap pass, offscreen render pass»): контент
миникарты — плоские одноцветные прямоугольники и линии; второй GPU-проход с
full-сценой не окупается. «Offscreen» = CPU-буфер RGBA, загружаемый одной текстурой.
Критерий «< 2 мс на 5000 нод» выполняется с запасом (растеризация ~O(n) за десятки
мкс, загрузка 220×140×4 ≈ 123 КБ). Фиксируется в §8.

**DPI:** буфер растеризуется в физических px (`width_px = round(220 × scale_factor)`),
квад — в физических координатах; при смене `scale_factor` приложение перезадаёт
размер и перезагружает буфер. Логические метрики констант (220/140/16).

## 4. Мэппинг событий → действия

| Событие | Действие |
|---|---|
| `mark_dirty()` сцены (перемещение нод, вставка/удаление) | пересборка `Minimap::capture` + `render` + `set_minimap` |
| Камера пан/зум (изменилась `visible_world_rect`) | обновить только рамку viewport → перерендер буфера (снимок нод можно переиспользовать, но простая полная перерисовка тоже < 2 мс — допускается) |
| Resize / DPI-смена | пересборка с новыми `width_px/height_px` |
| ЛКМ click внутри миникарты | `camera.set_center(minimap.map_to_world(px))` |
| ЛКМ drag внутри миникарты | каждый кадр: world-точка под начальным кликом следует за курсором (эквивалент панорамирования) |
| Окно < 252×172 лог. px | миникарта скрыта (`minimap_rect_logical() → None`) |

## 5. Пошаговый план (TDD)

Контракты (типы, сигнатуры, док-комментарии) засеяны координатором в
`minimap.rs` и `minimap_pass.rs` + `mod`-строки в `lib.rs`. Воркеры реализуют тела
и тесты, НЕ меняя публичных сигнатур и lib.rs.

1. **T13-A** (`minimap.rs`, только этот файл):
   - `Minimap::capture`: сборка `Vec<MinimapNode>` (AABB `node.rect`, тип
     File/FileBroken/Text/Group — broken_link → FileBroken), edges → центры нод
     (пары `[f32;2]`); fit: content bounds = union AABB ∪ viewport_world,
     padding 8 px, масштаб = min(w/content_w, h/content_h), центрирование;
     вырожденность (пусто / нулевая ширина-высота / одна точка / огромные
     координаты ±1e7) — без паники и без NaN.
   - `render`: буфер `width*height*4`, фон полупрозрачный тёмный (alpha ≈ 0.72),
     скругление 8 px (углы за радиусом — alpha 0), ноды — заливка 2×2..N px
     clamp, edges 1 px (только если nodes.len() < 500), рамка viewport 2 px
     белая непрозрачная, clamp в границы буфера.
   - `map_to_world`/`world_to_map` — обратные аффинные, round-trip точность ≤ 1 px.
   - Тесты: см. §6.
2. **T13-B** (`minimap_pass.rs` + `renderer.rs`, только эти два):
   - `quad_rect(...)` (засеяна координатором): размещение квада в физических px
     (право-низ, margin, учёт scale), too-small → None.
   - `MinimapPipeline` (шейдер по образцу `thumbs.wgsl`: одна текстура + uniform
     screen-rect, uv 0..1, сглаживание не нужно — nearest/linear на выбор
     воркера, зафиксировать в комментарии); загрузка `MinimapImage` → текстура
     RGBA8 + bind group; draw в `render()` последним (blending как у thumbs —
     straight alpha по формату surface).
   - `Renderer::set_minimap`, `Renderer::minimap_rect_logical` (+ поле, очистка
     при resize — текстуру можно сохранить). `render()` возвращает FrameStats
     как раньше; минимапный проход не влияет на статистику culling.
   - Тесты чистой математики (§6); GPU-часть — ручная приёмка владельца
     (визуально) + компиляция под windows-msvc `cargo check --target
     x86_64-pc-windows-msvc -p canvas-render --all-targets` для CI-гарантии.
3. **T13-C (координатор, после ревью обоих воркеров):** интеграция в `main.rs`
   по §4, гейты workspace, §8, коммит `feat(render,app): T13 — миникарта`.

## 6. Сводка тестов (юнит, `cargo test -p canvas-render`)

- fit/масштаб: content bounds центрируется, padding соблюдается, round-trip
  world↔map ≤ 1 px на краях и в центре.
- вырожденные: пустая сцена (фон+рамка без нод), одна нода-точка, сцена далеко
  от origin (±1e6), нулевой viewport — без паники/NaN.
- растеризация: пиксель в центре ноды = цвет типа; broken-нода краснее; пиксель
  за скруглением угла — alpha 0; рамка viewport белая; edges видны при 499 нодах
  и отсутствуют при 500+.
- hit-test: клик в центр миникарты → world-центр контента.
- `quad_rect`: 220×140@16 при 1280×720/1.0; физ. px при scale 2.0; окно 200×150 →
  None; кламп к краю окна при узком окне.
- (T13-B, компиляционные) clippy `-D warnings` на windows-таргете.

## 7. Риски, ограничения, фолбэки

- **Производительность:** AABB-обход O(n) при каждом dirty; на 5000 нод — десятки
  мкс. Полная перерастеризация вместо инкрементальной — осознанно (порог SPEC
  2 мс). Если замер покажет больше — кэшировать снимок нод и обновлять только
  рамку (заложено в §4).
- **alpha-канал:** формат surface может не поддерживать alpha — полупрозрачность
  реализуется blending-этапом пайплайна (как у thumbs), не альфой surface.
- **wgpu-несовместимость:** минимапный проход — копия проверенного паттерна
  thumbs; отдельный render pass не нужен (квад рисуется в существующий проход
  после thumbs, если порядок в коде позволяет — иначе отдельный проход;
  решение фиксируется в комментарии).
- **Огромные координаты/NaN в модели:** растеризация клампит, map_to_world
  обрабатывает без паники.
- **Конфликт зон:** T13-B — единственный, кто правит `renderer.rs` (T14 его не
  трогает); `lib.rs` засеян координатором и воркерами не правится.

## 8. Отступления при реализации (сессия T13)

1. **CPU-растреризация вместо GPU offscreen-прохода** (задумано в §3): буфер
   220×140×scale RGBA8 собирается на CPU (T13-A) и загружается одной текстурой
   в существующий проход (T13-B). Отдельный render pass не понадобился — квад
   рисуется в общем проходе после всех сегментов z-порядка и текст-групп.
2. **Обновление по dirty** реализовано через сигнатуру
   (позиция, зум, размер буфера) + dirty_until-автосейва сцены: между правкой
   и автосейвом (2 с) каждый запрошенный кадр пересобирает снимок — так
   перемещения нод видны на миникарте в реальном времени; после сохранения
   кадры не запрашиваются и пересборка прекращается. `Minimap::set_viewport`
   используется при чисто-камерных изменениях (дешевле полного снимка).
3. **Edge-кламп** в буфер ±64 px (искажается только невидимая часть) — защита
   от зависания Брезенхэма на вырожденном масштабе (решение воркера T13-A).
4. **MAX_BUFFER_PX = 4096** — защита от гигантских аллокаций при аномальном
   scale_factor (вне реальных кейсов, прокомментировано).
5. **bytes_per_row без 256-паддинга** при write_texture (отличие от thumbs.rs):
   проверено по исходнику wgpu-core 22.1 — write_texture переупаковывает строки
   сам (провалидировано и закомментировано T13-B).
6. **Шейдер минимапы провалидирован через naga 22** (GPU-адаптера в песочнице
   нет): поймана реальная ошибка WGSL до CI.
7. **Клик и drag объединены**: нажатие внутри миникарты мгновенно центрирует
   камеру (это и есть «клик → центрирование»), при последующем движении
   world-точка следует за курсором («drag рамки → панорамирование»). Двойное
   поведение — без отдельного клик-детектора.
8. **Камера**: `Camera::set_center/set_zoom` (кламп) добавлены координатором в
   camera.rs (засеяны до воркеров; тесты — T14-B) — нужны и миникарте (T13), и
   полёту поиска (T14).
