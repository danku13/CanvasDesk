## 2. Порядок внутри волн (строгий)

### Волна W1 — быстрые победы, малый радиус
1. **A1 (CR-026)** — однострочный блендинг-фикс + дельта-тест; сразу визуальная приёмка зебры/подсветок (факт: после фикса зебра станет чуть ярче авторских α0.08–0.14 — проверить, не перебор).
2. **A2 (CR-019)** — markdown-маска построчная, `\*`-снятие в expr; round-trip-тест с `*`.
3. **A3 (CR-023)** — suppress до смены токена; дополнение контракта FR-021.

### Волна W2 — explain-триггер и тултипы
1. **B1 (CR-020)** — единый предикат «есть видимый результат» (зеркало `node_shows_result_footer`), мини-лупы строк; приёмка шума на 5+ строках (предупреждение владельца).
2. **B2 (CR-024)** — гейт control-порта (полдня, независим).
3. **B3 (CR-025)** — резолв имени строки в `dataref` (единая точка), формат «Нода.имя = значение»; решение противоречия приоритетов с ADR-0003 (по умолчанию: имя > индекс — как в ADR).

### Волна W3 — поток значений и подсказки
1. **C1 (CR-021)** — пересмотр fr-050 Р-4: авто-строки всегда; классификация `Calc` по RHS-входам; единая точка классификации (3 копии → 1); обновление пиннеров.
2. **C2 (CR-022)** — снятие ИИ-мерджа из попапа; уточнение тумблера настроек; пометка C1-триггера в плане FR-079.
3. **C3 (FR-101)** — имена входов в `HintContext` (спиллы + qualified), фикс счётчика `inbound`, новые ветки `hint_items`, i18n.

### Волна W4 — редактор и приёмка
1. **D1 (FR-100)** — по слоям: (а) натив: word-delete/undo/PageUp/Tab/SmartHome + Super-паритет + «не глотать»; (б) web: `preventDefault` в шиме, возврат фокуса, компенсация порядка событий winit-web; (в) смоук web-клавиатуры.
2. **D2** — сквозная приёмка по репродуктору `handtest.canvas` (чек-лист ниже), обновление `user-docs` (calculations/interface/hotkeys), онбординга и `docs/ACCEPTANCE.md`; вопрос онбординга владельцу — по правилу AGENTS.md.

## 3. Чек-лист сквозной приёмки (репродуктор handtest.canvas)

1. `sum = $1 * $2` вводится звёздочкой без экранирования, значение считается (A2).
2. Нода «Общая сумма корзины» показывает 2 входящих строки (qty=10, price=100 rub) и строку расчёта с маркером ƒ (C1).
3. Клик по `qty = 10` — выделение/драг ноды, explain не открывается (B1); у строки-результата `sum` — своя мини-лупа.
4. Ввод `купо` в ноде-приёмнике предлагает `Купон.купон`; ввод `$` — имена и `$N` без ложных номеров (C3); принятие не возвращает попап до смены токена (A3); ИИ-строк «заменит ноду шаблоном» нет (C2).
5. Hover у контрольной связи — без тултипа (B2); hover у value-связи — `Цена.price = 100 rub` (B3).
6. Тёмная тема: выделение текста светло-синее, видимое (~20-30% фактической непрозрачности) (A1).
7. Web: Ctrl+A выделяет текст в редакторе ноды сразу после клика по ноде; Ctrl+Backspace удаляет слово (D1).
8. Round-trip `.canvas` зелёный на всех шагах; гейты fmt/check/clippy/test (натив+wasm32) зелёные.

## 4. Открытые вопросы владельцу

1. **Двухсловные присваивания** («Финальная корзина = …») — сейчас невозможны грамматикой (UR-001, раздел «Открытый вопрос»): нужен ли синтаксис `"имя с пробелом" = значение`? Кандидат в отдельный FR (0.5–1 день на парс+тесты, риск конфликтов с прозой).
2. **C3-карточки FR-079** — остаются как есть (решение Q5 касалось только попапа)? Подтверждение при ревью CR-022.
3. **A1-приёмка** — если зебра/подсветки после блендинг-фикса покажутся ярче желаемого: калибровать зебру под новый факт или снизить её α? Решение на скриншотах.
