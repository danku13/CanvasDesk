# Анализ: что перенести из Archify в CanvasDesk

**Дата:** 28.09.2026
**Автор:** агент-сессия (Super Z)
**Источник:** запрос владельца «проанализировать, что стоит забрать в CanvasDesk из сервиса Archify» (сессия 2026-09-28)
**База:** Archify `github.com/tt-a1i/archify` commit `9e35d2b` (v2.17.0-dev.1, MIT) + CanvasDesk commit `2559859`
**Тип:** технический анализ переноса практик чужого продукта в архитектуру CanvasDesk

---

## 0. Постановка задачи

Владелец просит проанализировать открытый проект Archify и выделить практики,
которые стоит перенести в CanvasDesk. Анализ отвечает на три вопроса:

1. Что представляет собой Archify инженерно (пайплайн, гарантии, артефакт)?
2. Где продукты пересекаются по ценности — какие практики Archify закрывают
   известные гэпы CanvasDesk?
3. Что переносим сейчас, что откладываем и что не переносим вовсе?

Метод: полное чтение обоих репозиториев (структура, контракты, документация,
тесты), сопоставление с реестром разрывов `docs/market-researches/04-cjm-audit-plan.md`
(GAP-01…10) и дорожной картой. Выводы сведены в карту переноса T1–T8 (§3).

## 1. Что такое Archify (инженерный разбор)

Archify — агент-скилл для Cursor/Claude Code/Codex CLI: агент превращает
описание (или скан репозитория) в интерактивную HTML-диаграмму. Продуктовая
ниша — «понять, спланировать и поделиться» визуально. Производственный код
~22 тыс. строк JS (плюс 36 тыс. строк тестов, 118 файлов), среда выполнения —
Node ≥ 18, ноль npm-зависимостей в рантайме.

Пайплайн (генерация → гарантии → артефакт):

| Слой | Механизм | Факт для переноса |
|---|---|---|
| Вход | Типизированный JSON IR, 5 схем (architecture/workflow/sequence/dataflow/lifecycle), ajv draft 2020-12, `additionalProperties: false` | дисциплина «схема = контракт»: неизвестные поля отклоняются, а не игнорируются |
| Гейты | Схема → лэйаут → артефакт (9 проверок: single_svg, orthogonal_arrows, label_route_clearance, relationship_crossings…) | валидация до доставки, а не после; showcase-профиль = все проверки ошибки |
| Репеир-рецепт | Диагностика `{code, severity, subject, evidence, supportedFixes}` — стабильные коды (`composition/*`, `schema/*`, `input/*`), субъект, измеренное доказательство, только поддерживаемые фиксы | агент чинит по рецепту, максимум 2 раунда правок — сходится быстрее, чем по стеку |
| Артефакт | Самодостаточный HTML: 14,9 тыс. строк шаблона, весь CSS/JS/шрифт инлайн, работает офлайн | «portable by default» — файл можно отправить кому угодно |
| Просмотр | Focus, upstream/downstream reach, route probe, lens, radar, главы (meta.views), presentation stage, темы, deep links `#focus=`/`#route=`/`#view=` | интерактивность живёт в артефакте, а не в приложении-источнике |
| Экспорт | PNG/JPEG/WebP, dual-theme SVG, WebM, share-карточки 1200×630 (Share/Route/Reach), Copy PNG в буфер; экспорт каноничен — временные состояния просмотрщика вычищаются | канонический экспорт безTransient-состояний |
| Доверие | Proof Lab — галерея проверенных артефактов с машинными receipts (sha256, счётчик проверок) | «проверено» = машиночитаемо, не на слово |
| Дельта | `compare` — Before/Delta/After два снапшота IR, статусы added/removed/changed + receipt | сравнение версий модели как отдельный продукт-жест |

## 2. Пересечение ценностей: почему перенос осмыслен

Продуктовые формулировки почти рифмуются. CanvasDesk (README): «инструмент для
тех, кто должен одновременно спроектировать систему, посчитать её и защитить
расчёт перед командой, C-level или инвесторами». Archify: «turn anything you
want to understand, plan, or share into an interactive visual».

Разница — в фазе «защитить». Archify отвечает на неё артефактом: самодостаточный
HTML, share-карточки, канонический экспорт. CanvasDesk отвечает живым окном:
режим защиты FR-048 (пошаговое раскрытие цепочки расчёта), main stage FR-042,
таблица сравнения what-if. Живое окно требует присутствия автора; реестр
разрывов фиксирует провал асинхронного случая:

> **GAP-01** (P1, `docs/market-researches/04-cjm-audit-plan.md:308`): «нет
> артефакта для асинхронного показа: защита бюджета вне живой встречи
> невозможна („пришлите это“ → нечего слать)».

Второе пересечение — агентный контур. Оба продукта собираются агентом: Archify
через Skill-контракт + CLI-рецепты, CanvasDesk через MCP (41 инструмент,
`graph_apply` с транзакционным клоном-откатом). Archify делает следующий шаг:
каждая ошибка сопровождается рецептом починки (`supportedFixes`). В CanvasDesk
стабильные коды (`E-CYCLE`, `E-UNIT`, `E-PORT-UNKNOWN`, `E-DOUBLE-INPUT`,
`E-OVERLOAD`, `W-AMBIGUOUS-SRC`, `W-UNUSED-SLOT`) уже есть
(`canvas-core/src/validate.rs`), но без подсказки «как чинить» — агент обязан
знать семантику кода заранее.

Третье пересечение — навигация по ссылке. Archify восстановливает состояние
просмотра из URL (`#focus=<id>&reach=upstream`, `#view=`). В CanvasDeck
`url_params.rs` принимает только `?canvas=`/`?template=` — на конкретную ноду
сослаться нельзя.

Приоритет привязан к реестру гэпов и стоимости реализации в Rust-архитектуре.

| # | Практика Archify | Реализация в CanvasDesk | Закрывает | Статус |
|---|---|---|---|---|
| **T1** | Самодостаточный офлайн-HTML как артефакт («portable by default») | **FR-076**: `canvas-core::export_html` — SVG-снимок канваса + вычисленные значения нод + таблица what-if; кнопка в веб-панели, команда в нативе | **GAP-01 (P1)** | берём в этой сессии |

| **T3** | Стабильные deep links (`#focus=<id>`) | **FR-078**: `?focus=<node-id>` в веб-версии — центрирование камеры на ноде после загрузки | J6 «пришлите это» | берём в этой сессии |

| T6 | `guide`-команда (сценарный рекомендер) | MCP `model_guide`: цель → рекомендуемые шаблоны/схемы | UX агента | отложено: требует корпуса рецептов, аналога `recipes/scenarios.mjs` |
| T7 | Proof Lab (галерея с receipts) | Валидационные receipts 14 эталонных схем в CI | доверие к схемам | отложено: недорого, но не блокер |

### 3.1 Почему T1 = HTML, а не PNG (обоснование)

Рыночный док предлагает PNG-экспорт (`GAP-01`), и PNG остаётся целью T4. Для
первого шага HTML выигрывает по четырём инженерным причинам. Во-первых, текст:
SVG-текст рендерит браузер — не нужен CPU-растер глифов (в нативном стеке
глифы идут через glyphon/wgpu, вне GPU-контекста текст не рисуется; миникарта
`minimap.rs` потому и безнадёжна для надписей). Во-вторых, интерактивность:
тема, hover-подсветка нод, сворачивание таблиц — инлайн-JS без GPU. В-третьих,
значения: what-if таблица «переменная | База | С1 | С2» — нативный HTML-элемент.
В-четвёртых, архитектура: генератор — чистая функция в `canvas-core`
(платформенно-нейтральной, wasm-совместимой), покрывается TDD без GUI-стенда.
Наконец, HTML-артефакт переиспользуется в будущем как обёртка для PNG:
растеризация HTML → PNG в браузере тривиальна (canvas), т.е. T4 строится
поверх T1, а не с нуля.

### 3.2 Границы MVP FR-076 (чтобы скоуп не расползался)

В скоуп: SVG-снимок (ноды-прямоугольники с заголовком/строками, группы,
рёбра с подписями значений), значения формульных строк из последнего
пересчёта, таблица сравнения what-if (если сценарии есть), тема светлая/тёмная,
HTML-экранирование пользовательского текста, офлайн-инлайн CSS/JS.
Вне скоупа: интерактивный редактор, deep links внутри артефакта, WebM,
share-карточки, дельта-сравнение — всё задокументировано как v2+.

## 4. Что не переносим (и почему)

| Практика Archify | Причина отказа |
|---|---|
| Механизм update-check (`check-update.mjs`, манифест на GitHub Pages) | не применим: у CanvasDesk бинарь + веб-деплой; канал обновлений уже есть (GitHub Releases/Pages) |
| 5 типизированных диаграммных схем (architecture/workflow/…) | иная доменная модель: у CanvasDesk единый value-flow DAG, а не типы диаграмм; перенос — подмена продукта |
| Mermaid-маппинг входа | у CanvasDesk нет текстовых DSL-входов; импорт архитектур — отдельная тема PRD-0003 |
| Схема скилла для Claude Code/Codex (SKILL.md + `npx skills add`) | у CanvasDesk уже есть MCP-контур и пакет `skills/` — дублирование канала дистрибуции |
| Веб-сайт/astro, спонсорская инфраструктура, Proof Lab-галерея как маркетинг | вне инженерного контура переноса |

## 5. План волн (эта сессия и дальше)

**Волна 1 (эта сессия):** FR-076 (T1) → FR-077 (T2) → FR-078 (T3). Каждый —
отдельный коммит по конвенции «одна задача = один коммит», с FR-документом в
`docs/change-requests/`, обновлением индекса и статусом.

**Волна 2 (кандидаты после демо-подтверждения GAP-01):** T4 PNG-экспорт
(поверх FR-076: рендер артефакта → canvas → PNG + share-карточка 1200×630),
T5 главы защиты поверх режима FR-048.

**Волна 3 (агентный контур):** T6 `model_guide`, T7 receipts эталонных схем
в CI, T8 дельта-сравнение при созревании PRD-0005.

Гейты волны 1: `cargo test -p canvas-core` (+ затронутых крейтов), `cargo
clippy --workspace -- -D warnings`, `cargo fmt --check`; canvas-core остаётся
платформенно-нейтральным (проверка wasm-check затронутых крейтов). L2
браузерный стенд (`scripts/wasm_ui_test.sh`) в сессии недоступен — по правилам
AGENTS.md фиксируется честно, с инструкцией ручной проверки в FR-документах.
