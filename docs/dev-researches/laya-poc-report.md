## 1. Резюме для решения

**Гейт-вердикт первой волны: RED** — по пререгистрированным порогам §14.1 гипотезы. Zero-shot Laya **не превосходит лексический baseline** на домене CanvasDesk стабильно: на test-сплите лучшее плечо `laya-mm` впереди на +6.4 п.п. (p@1 0.383 vs 0.319), но доверительный интервал разности накрывает ноль (−12.9..+25.6 п.п.), на dev-сплите лексика впереди на −14.1 п.п., а на объединённой выборке (n=139) лексика лидирует: **0.381 против 0.309**. Расхождение сплитов — не дефект методики, а следствие стратификации «контексты одной схемы не пересекают сплиты»: разные схемы дают разную сложность, и при n=47/92 это заметно. Стабильного превосходства нет ни в одном разрезе.

Полная гейт-таблица (§8): p@1 — yellow (на test), MRR@5 0.486 — red (<0.55), ECE show/don't-show 0.673 после t-scaling — red (>0.25), p95 на T4 3082 мс — red (>800), RSS 2.03 ГБ — yellow, покрытие сценариев 2/5 — red. Четыре red из шести метрик.

При этом пилот дал **три важные положительные находки**, без которых вывод был бы неполным. Во-первых, класс моделей работает: `laya-mm` на английских контекстах даёт p@1 0.524 и на сценарии C1 (ввод текста) — 0.60, то есть задача «выбрать шаблон из 20 опций по контексту» решается ненулевым качеством без какого-либо дообучения. Во-вторых, лексический baseline оказался неожиданно силён (0.381 на пуле) — каталог из 62 шаблонов с богатыми ru/en-описаниями почти полностью «выбирается» ключевыми словами, и это меняет оценку ценности RAG-слоя: лексики + синонимов может хватить надолго. В-третьих, весь измерительный прибор (226 фикстур с автоголденом, harness, протокол) построен, заморожен и переиспользуется в фазе 2 как golden-тесты `SuggestEngine` — вложение не сгорает ни при каком исходе.

**Рекомендация (§10):** не встраивать L1 на Laya в фазу 2 как есть; вернуться к роадмапу в конфигурации «фаза 0 + палитра v2, RAG-слой как основной путь L1»; опционально — одна итерация формулировки вопросов v0.2 (правило честности: полный повторный прогон) и/или yellow-ветка fine-tune на построенном eval-сете (Kaggle 2×T4, бесплатно). Решение о финальном вердикте — после второй волны (ручная разметка синтетики владельцем) и замера T3 на ноутбуке владельца (one-shot-пакет приложен).

## 3. Стенд и конфигурация

**Sidecar.** `pip install "laya[serve]==0.3.20"` (torch 2.14.0+cpu; CUDA-wheel не влез в диск контейнера — развёрнут CPU-вариант). Один чекпойнт на инстанс через `LAYA_MODELS` (иначе 3 чекпойнта не влезают в 3.9 ГБ RAM контейнера), `LAYA_THREADS=2`, `LAYA_DEVICE=cpu`, порт 8000. Менеджер жизненного цикла (`scripts/sidecar.py`) поднимает и глушит сервер внутри одного процесса harness — фоновые процессы в среде агента не переживают вызовов оболочки.

**Патч конфигурации (пререгистрирован до измерений).** По плану §4.1 `head_max_len` поднят до 512 у всех трёх чекпойнтов (20 опций × ~16 токенов ≈ 320 + инструкции); у english дополнительно `max_len` 512→1024 — иначе бюджет опций не оставляет места для state. ModernBERT-large энкодер нативно поддерживает 8192 позиций, но чекпойнт обучен при 512 — **это RoPE-экстраполяция за пределы обученной длины, помечена как когорта-риск** для плеча `laya-en`. Оригинальные конфиги сохранены (`report/rl_agent_config.*.orig.json`), sha256 весов — в `sidecar-manifest.json` (en 891102d3…, mm 9d628fd9…, td 4fa56de7…).

**Две ловушки, найденные при отладке (важны для фазы 2):**
1. **Авто-роутинг лениво грузит второй чекпойнт.** Запрос с `model: null` на контексте с ≥5% кириллицы маршрутизируется на multilingual — и Router дограчивает его поверх уже загруженного english (RSS 3.4 ГБ, OOM на слабом железе). Клиент обязан передавать явный `model`.
2. **Температуры весов mm вне диапазона.** При старте сервер пишет `RuntimeWarning: laya: this checkpoint ships invalid temperatures or values outside [0.5, 5]; using choice:11+=0.10 -> 0.5. Treat confidence from the affected entries as uncalibrated.` Это прямое предупреждение авторов о некалиброванности confidence mm-чекпойнта для choice-задач с 11+ опциями — оно материализовалось в наших замерах (§6): у `laya-mm` 55 калибровочных провалов (confidence ≥0.7 при неверном ответе) против 10 у en и 0 у td.

## 6. Калибровка и гейтинг показа (show_suggestion)

**Единый вывод по всем трём чекпойнтам: noul-вопрос v0 не решает задачу «показывать ли подсказку».** Модель консервативна на пустой ноде: контексты с богатым окружением (`[up]/[down]`-секции, переменные) и golden=true получают noul 0.005–0.49 — «не показывать». Точность на test: en 0.20, mm 0.00, td 0.00 (mm и td не дали ни одного true). ECE после t-scaling: 0.61 / 0.67 / 0.69 — red у всех (>0.25). Температуры, подобранные на dev (правило §6.2), не спасают: сдвиг систематический, а не температурный.

Диагноз формулировки: вопрос «Is the context specific enough to suggest?» с дефолтными критериями «the statement holds/does not hold» просит модель оценить специфичность **редактируемого текста**, а продукт хочет «достаточно ли богат окружающий канвас». Пустая нода → «не специфично» → «не показывать», как бы богат ни был канвас. По правилу честности (план §2) переформулировка — это **v0.2 с полным повторным прогоном**, а не подгонка задним числом; в гейт пошли числа v0. Альтернативный путь гейтинга, не требующий noul: порог по confidence choice-ответа (рабочая точка precision ≥0.9 на dev) — рекомендован для v0.2.

Дополнительный фактор: предупреждение авторов о температурах mm (§3) — confidence mm частично некалиброван «по построению»; калибровочный провал mm (55 случаев conf≥0.7 при неверном ответе) следует читать с этой оговоркой.

## 10. Что это значит для продукта

1. **RAG-слой (фаза 1 по гейту green) остаётся правильным базовым путём L1.** Лексический baseline — уже 0.38 p@1 на смешанном домене без единой нейросети; добавление короткого списка синонимов и лёгкого fuzzy (запланированная фаза 0) поднимет его дальше. Экономика решения: эмбеддер как первая ML-зависимость репо всё ещё не оправдан.
2. **Laya не готов к встраиванию zero-shot** — ни по качеству (§5), ни по калибровке (§6), ни по латентности на слабом железе (§7). Если ветка продолжится — только через fine-tune и только с измеримым перегейтом; ставку стоит переоценить после того, как наберутся продуктовые события (план фазы 3: 10–50k).
3. **Гибрид важнее «одного решателя»:** зеркальные расхождения по источникам (§5.2) показывают, что L0+lex и семантическая модель решают непересекающиеся подмножества. Продуктовый вывод — маршрут «лексика сначала, модель для непокрытого хвоста», если хвост когда-нибудь оправдает стоимость.
4. **Калиброванный show/don't-show — нерешённая проблема класса.** Для продукта это значит: в фазе 2 гейтить показ детерминированно (правила + confidence choice-ответа), не полагаясь на noul zero-shot.
5. **Ecosystem-фактор:** llm-free дистрибуция (2 ГБ RSS, 3 с на слабом CPU) — само по себе ограничение для «лёгкого» продукта; mm-чекпойнт вдвое легче и быстрее en/td при лучшем качестве — если продолжать, только mm.

## 12. Архитектура встраивания (если ветка продолжится): «дёшево выпилить — дёшево дорабатывать»

Требование владельца: любая Rust-реализация в репо должна быть дешёвой в удалении при неудаче и дешёвой в доработке при успехе. Blue-print, совместимый с находками пилота:

1. **Изоляция за трейтом.** `trait SuggestEngine { fn suggest(&self, ctx: &SuggestContext) -> Vec<Suggestion>; }` в отдельном крейте `canvas-suggest` (не в 11 существующих). Реализации: `LexEngine` (чистый Rust, фаза 1) и `LayaSidecar` (HTTP-клиент к `laya-serve`). Продукт держит `Vec<Box<dyn SuggestEngine>>` и мержит результаты — гибрид §5.2 строится конфигом, не кодом.
2. **Feature-flag, off by default.** `cargo feature l1-laya` — крейт `canvas-suggest-laya` (клиент sidecar) не компилируется в дефолтной сборке. Удаление ветки = удалить 1 крейт + 1 флаг + конфиг-ключ; ноль изменений в ядре. Это же снимает конфликт с минимализмом ядра (AGENTS.md: без ML-зависимостей — их и нет, только HTTP-клиент к sidecar).
3. **Sidecar, не библиотека.** Процесс `laya-serve` управляется тем же паттерном, что `canvasdesk mcp` (spawn/health/shutdown). Из находок пилота: обязательный явный `model` в каждом запросе (ловушка авто-роутинга §3), один чекпойнт (RAM), health-check + smoke-фикстура при старте (дрейф версий — блокер, план §10).
4. **Дешёвое выключение в рантайме.** Конфиг-ключ `suggest.engine = "lex" | "lex+laya"`, дефолт `lex`. Отсутствие sidecar ≠ ошибка: деградация до lex + L0 молча (продуктовый гейт «не показывай, если не уверен» из §6 — в первой версии детерминированный).
5. **Переиспользование пилота.** Eval-сет (226 фикстур) + harness = golden-тесты `SuggestEngine` в CI: `LexEngine` обязан держать p@1 ≥ лексического baseline'а пилота (0.38 пул) — регресс-гейт фазы 1. Формат фикстур JSONL уже сериализуем тестами без sidecar.
6. **Прецедент правил:** все точки встраивания (update_hints триггер, попап FR-021, graph_apply вставка) уже определены в гипотезе §9.2 и не требуют изменений ядра — L1 «подмешивается» в существующий funnel, что и делает выпиливание дешёвым.

## 13. Ограничения первой волны (читать перед выводами)

- **n мал:** основная метрика 47/92/139 — CI широкие; вывод «не превосходит лексику» устойчив на пуле, но отдельные слайсы (C5 n=1, C2 n=5) не интерпретируемы.

- **Одна волна формата вопросов:** v0 заморожена до прогона; noul-вопрос v0.2 (§6) — отдельная итерация с полным повторным прогоном.

- **T4 — единственный измеренный тир**; T3 ожидает one-shot, T1/T2 — экстраполяции.
- **Нет param_exact_rate** (маппинг параметров не размечен) и **нет Jev-плеча** (решение владельца).
