# Инлайн-редактирование нод без двойного клика (архитектурно-технологический вердикт)

**Дата:** 2026-10-08
**Тип:** анализ + реализуемая UX-модель (click-to-edit)
**Заказчик:** владелец продукта
**Автор:** агент-сессия (Super Z)
**База:** commit `59991c5` (main, после UR-001 W1+W2)
**Источники:** `crates/canvas-render/src/edit.rs`, `crates/canvas-app/src/app.rs`, `crates/canvas-app/src/app/input.rs`, `crates/canvas-web/src/ime.rs`, `docs/interface-objects/node.md`, CR-018, FR-072, FR-092/093/096

## 0. Постановка

Вопрос владельца: **можно ли архитектурно и технологически реализовать инлайн-редактирование нод без перехода в режим редактирования двойным нажатием, и как.**

Ответ: **да, реализуемо малой кровью — и частично уже реализовано.** Ключевой факт: в CanvasDesk «режим редактирования» как отдельное состояние интерфейса отсутствует. `EditingSession` (T7/CR-018) — это не модальный режим, а оверлей-сессия, которая рисует каретку и выделение прямо в теле карточки на общем GPU-кадре (glyphon + cosmic-text `Editor`). Вход в сессию, а не сама правка, привязан к двойному клику. Поэтому задача сводится к замене **триггера входа**, а не к перепроектированию редактора: вся механика (каретка по клику, drag-выделение, IME, WYSIWYG-спаны Numi-строк, commit/cancel, undo) уже работает и покрыта тестами.

Частичный прецедент прямого входа уже принят владельцем и живёт в коде: **CR-018 волна v2** — одиночный клик по строке данных таблицы (Numi-ряд) шаблонной ноды открывает правку с кареткой в точке клика (`row_hit_at` → `begin_editing` → `session.click`, input.rs ~3217–3247). Обобщение этого пути на всё тело text-ноды — эволюция принятого решения, а не новая парадигма.

## 1. Текущее состояние (факты из кода)

### 1.1. Как устроена правка сегодня

| Событие | Действие | Место |
|---|---|---|
| Двойной клик по телу text-ноды | `begin_edit_node` → правка тела или заголовка (по точке: шапка `HEADER_HEIGHT` = 34 px → `NodeTitle`) | input.rs ~3089–3164, app.rs `begin_editing`/`begin_editing_title` |
| Двойной клик по линии связи | `begin_editing_edge` — лейбл (T8) | там же |
| Двойной клик по пустому месту | новая заметка + правка заголовка (`title_then_body`) | там же |
| Двойной клик по файловой ноде (Windows) | открытие файла ассоциацией (правка не начинается) | input.rs ~3145 |
| **Одиночный клик по строке таблицы** | **уже открывает правку с кареткой в точке** (CR-018 v2) | input.rs ~3223–3247 |
| Клик внутри активной сессии | каретка в точку; drag — выделение текста (`editor_dragging`) | input.rs ~2950–2995 |
| Клик вне активной сессии | commit (`finish_editing(true)`) и обычная обработка | input.rs ~2997 |
| Enter / Shift+Enter | commit / новая строка; Esc — откат | `map_key`, edit.rs |
| Тач | двойной тап с расширенным слопом (FR-093), лонг-пресс — контекст-меню (FR-096) | input.rs ~3084 |

Сессия хранится в `App.editing: Option<EditingSession>`; во время сессии карточка рендерится штатным пайплайном, но тело заменяется буфером редактора (`session_area_offset` с учётом CR-018 v1.1 варианта B — стационарные зоны desc/меток рисуются над буфером). Автосейв, undo-снапшот «до» (`begin_pending_undo`), автоподгон высоты (`fit_note_size`) — уже привязаны к жизненному циклу сессии, а не к способу её открытия.

### 1.2. Почему «одиночный клик → правка» раньше не делали: конфликт жестов

Единственный настоящий конфликт — назначение **нажатия-с-перемещением (drag)** на теле ноды:

- сегодня press по ноде стартует `DragState` (перенос ноды/набора), и текстовый drag-выделение вне сессии невозможно;
- если press по телу сразу открывает сессию (как у строки таблицы CR-018), то перенос ноды с тела становится недоступен — а это базовый жест канваса.

Промежуточных состояний два, и они взаимоисключающие на одном жесте:

1. **Notion-модель**: press на тело → сразу каретка; drag по телу → выделение текста; перенос — только за шапку. Чисто, но ломает мышечную память переноса заметок (основной жест канваса) и мульти-drag набора с тела.
2. **tldraw/Sheets-модель**: press на тело стартует drag (как сегодня); **клик** (release без движения за порог) → каретка в точке. Drag по телу — перенос (как сегодня); drag-выделение текста — внутри уже открытой сессии (следующий press после входа). Двойной клик сохраняет прежнюю семантику (идемпотентен: вторая кнопка даблклика просто ставит каретку — ветка «клик внутри активной сессии» отрабатывает раньше).

### 1.3. Выбор модели (защищено в этой сессии)

Принята **модель 2 (tldraw/Sheets)**: она не отбирает ни один существующий жест, добавляя новый («клик = правка»). Модель 1 может быть добавлена поверх позже отдельным решением владельца (достаточно перенести `click_edit`-ветку с release на press и переразметить drag-зоны). Ключевые следствия модели 2:

- **перенос ноды** — drag по телу/шапке, как раньше; наборы (CR-001) не страдают;
- **клик по телу** — вход в правку + каретка в точке клика;
- **клик по шапке** — вход в правку заголовка (FR-072-зона); drag по шапке — перенос;
- **двойной клик** — остаётся рабочим везде (совместимость + файлы/what-if/тач);
- **Ctrl/Shift+клик** — выделение (приоритет над правкой, как сейчас);
- **тач** — одинарный тап НЕ открывает правку (виртуальная клавиатура по случайному тапу — анти-паттерн мобильных канвасов; Miro/Obsidian держат двойной тап) — двойной тап сохранён (FR-093);
- **what-if** — клик по строке расчёта остаётся тостом, override — на двойном клике (Q8 FR-017) — гейт;
- **виджеты/файлы/группы** — правка тела не начинается; группы (label) остаются на двойном клике в v1.

## 2. Технологическая оценка по слоям

| Слой | Что требуется | Статус |
|---|---|---|
| canvas-render/edit.rs | Ничего: `EditingSession::new/new_title`, `click`, `drag`, commit-пути универсальны | готово |
| canvas-app/app.rs | `begin_editing_at(index, world)`: `begin_editing`/`begin_editing_title` + конверсия world→px буфера + `session.click` (та же конверсия, что в CR-018 v2) | +15 строк, единая точка |
| canvas-app/app.rs | Кандидат клика: `click_edit: Option<ClickEditCandidate{index, press_cursor}>` — ставится на press, потребляется на release без движения | +1 поле, машина из 2 состояний |
| canvas-app/input.rs | Press: ставить кандидата на text-нодах (после всех ранних return'ов — порты, resize, row-hit, whatif, модификаторы); Release: потребить кандидата после `finish_interaction_undo` | ~30 строк |
| Курсор | I-beam (`CursorIcon::Text`) над телом/шапкой text-ноды на hover — видовая подсказка редактируемости | ~8 строк в `sync_cursor_icon` |
| Клавиатура | F2 на выделенной text-ноде → `begin_edit_node` (Enter занят mindmap-добавлением, FR-011) | ~6 строк |
| canvas-web/ime.rs | Ничего: скрытый input/IME активируются фактом `editing.is_some()`; на wasm click-to-edit работает тем же кодом (press_from_touch уже различается) | готово |
| Тесты | Чистая функция решения `click_edit_target(...)` (kind/whatif/touch/modifiers/файл) + машина кандидата на stub-App; визуал — wasm/manual | новые |

Риски и их закрытие:

1. **Ложные входы в правку при «клике для выделения»** — принял: клик по тексту и есть вход в правку (это и есть запрошенная модель). Откат — Esc (уже откат к исходному тексту) или клик мимо.
2. **Undo-шаг от пустого drag'а** — существующий паттерн FR-006 закрывает отложенный снапшот только при фактическом изменении (`finish_interaction_undo`), затем сессия ставит свой снапшот — двойного шага нет.
3. **Двойной клик после клика** — вторая кнопка даблклика попадает в ветку «клик внутри активной сессии» (каретка в точку), `double_click.register` не достигается; семантика даблклика для не-текстовых целей (файлы, what-if, пустое место) не тронута.
4. **WASM/тач-платформы** — гейт `press_from_touch` исключает тап-правку; стилус трактуется как тач (v1), решается владельцем позже.

## 3. Что сознательно НЕ входит в v1

- Notion-модель (drag по телу = выделение текста без сессии) — поверх модели 2 по решению владельца.
- Клик-правка для label групп и лейблов связей (остаётся двойной клик) — отдельная итерация, там drag по линии связи = перепривязка, нужен отдельный разбор зон.
- Изменение онбординга/пользовательских доков — по правилу AGENTS.md вопрос задаётся владельцу по завершении.

## 4. Критерии приёмки v1

1. Одиночный клик по телу text-ноды открывает правку с кареткой в точке клика (та же конверсия координат, что CR-018 v2).
2. Одиночный клик по шапке открывает правку заголовка (зона `title_edit_area`).
3. Drag по телу/шапке переносит ноду/набор — без входа в правку.
4. Двойной клик сохраняет прежние ветки: файл (Windows) — открытие, what-if строка — override, пустое место — новая заметка.
5. Ctrl/Shift+клик — выделение без входа в правку; тач — правка только двойным тапом.
6. Esc из сессии откатывает текст (существующее поведение); клик мимо — commit.
7. `cargo test` (app/render/core), clippy -D warnings, fmt — зелёные; wasm-гейт компиляции — зелёный.
