## 3. H9 — lex v2: улучшение одиночки, урок про ансамбль

Ablation на dev (n=92): автосинонимы из каталога `name_ru ↔ name_en ↔ key` — +1.1 п.п. (0.4239); связи через `params` шаблонов — **вредны** (0.3804, −3.3); fuzzy Дамерау-Левенштейна (≤2, длина ≥5) — нулевой эффект (отброшен). Итог lex v2 (только names-синонимы, веса 0.55/0.15): **test p@1 0.4043 (+8.5 п.п. к v1), pool 0.4173 (+3.6)**.

Контринтуитивный результат: **fusion(lex v2, mm) = 0.4255 < fusion(lex v1, mm) = 0.4681** (α=0.95 на dev — гибрид почти отказывается от mm). Причина: v2 чинит те ошибки, которые mm и так чинил сам — улучшение компоненты съедает декорреляцию ошибок ансамбля. Классический вывод теории ансамблей, материализованный на наших данных: **для гибрида важнее разнообразие ошибок, чем абсолютная сила члена**.

Продуктовое следствие: lex v2 — лучший автономный fallback-режим (нет sidecar, нет RAM, <10 мс), например для слабого железа или деградации sidecar. В гибрид — только lex v1.

## 4. H2 — двуязычное обогащение: сдвиг сидит в энкодере

Сериализатор v0.4 (env-флаг, дефолт бит-в-бит совместим): `title` соседей [up]/[down] обогащается латинскими сущностями каталога — вариант A `(en-имя, key)`, вариант B `(en-имя)`. Дырка [node] не обогащается никогда (C3-leak золотого ответа).

Результаты (ru-choice, test n=26): A — 0.2308, B — 0.2308 против 0.269 волны 1. Деградация = 1 фикстура (шум), роста нет. Диагноз: (а) контексты уже несли латиницу — vars, имена переменных в out/needs, ключи категорий; (б) языковой сдвиг mm (en 0.524 / ru 0.269) — свойство предобучения mmBERT, не нехватка лексического моста; (в) ключи шаблонов соседей создают ложных кандидатов-дистракторов. Согласуется с литературой (CSR-L 2026): код-свитчинг лечится обучением на код-свитч-данных, не промптом.

## 5. H3 — дескриптор вставки: сигнал в значениях, не в схеме

Типизированный дескриптор `[paste cols: visitors_a(num), ...; rows 1; header yes]` (≤40 токенов) вместо сырого blob в editing: C2-слайс 2/14 против 3/14. Побочный эффект: none-ответов стало 6 (консерватизм усилился) — короткий структурный текст без числовых значений выглядит «нечитаемым» для энкодера. Значения и единицы в blob несли лексический сигнал (руб/%/имена метрик), который дескриптор уничтожил.

## 6. H4 — материализация none: обоюдоострый меч

Внятное none-описание («выбирай none, если домен вне каталога: bespoke-тексты, свободные заметки, нереализованные идеи») на полном сете: said-none-but-golden 20→14 (почти цель ≤12), но picked-but-none 15→18 и p@1 test 0.383→0.319. None стал «привлекательнее» во всех направлениях — модель чаще выбирает его и когда нужно, и когда не нужно. На 33 новых framework-фикстурах (H4×H1-комбинация) результат побитово идентичен базовому описанию (3/33): **описание none не создаёт способность распознавать вне-каталожные домены — её нужно привносить данными (fine-tune) или правилом (домен-детектор до L1)**.

## 7. H5 — калибровка: Platt чинит ECE, уверенность не гейтится

По восстановленным пробам mm (dev 92 / test 47, main-фильтр): t-scaling упирается в край грида (T=4.0, ECE 0.304), **Platt-скейлинг даёт ECE test 0.0986** (критерий ≤0.15 выполнен; a=−0.018, b=−0.814), isotonic-регрессия переобучается (0.347). Но гейт показа по confidence/margin: потолок precision **0.57–0.60 при покрытии 0.30** — даже при пороге 0.99 уверенности mm ошибается в 40% случаев. Platt-коэффициент a≈0 — формальное доказательство: **уверенность mm zero-shot не несёт информации о правильности**. Продукт-вывод волны 2 подтверждён количественно: гейт показа — детерминированное правило (lex-эвристика: длина контекста + наличие соседей, 0.95 acc), нейро-гейтинг недопустим до fine-tune.

## 8. H1 — решающий перегейт: YELLOW, дыра в framework-доменах

**Расширение сета.** Карвинг 3 framework-схем из репо (CJM B2B SaaS, JTBD SaaS, Service Blueprint SaaS; коммит `f305ec7` владельца): все ноды — info-ноты без формул, по конвенции bespoke-доменов (renovation-estimate в mapping.json волны 1) назначен golden=none. Итог: +33 C4-фикстуры. Сплиты: старые 175 заморожены побитово (rng2-последовательность carve сдвигалась вставкой схем в алфавит — 91 расхождение устранено пост-фиксацией по id), новые схемы детерминированно: cjm→test, jtbd→dev, sb→test (test += 28, dev += 5).

(3) Yellow-ветка gate.yaml: fine-tune головки (H8) с none-примерами → повторный перегейт.

## 9. Что значат результаты волны 3 для продукта

1. **Промпт-уровень исчерпан окончательно.** Пять из шести гипотез волны 3 (few-shot в волне 2; H2, H3, H4-комбинации, H5-гейт здесь) — отрицательные или смешанные. Оставшиеся рычаги: данные (fine-tune H8), композиция (гибрид уже реализован), правила (show-гейт, домен-детектор).
2. **Рекомендуемый конфиг фазы 2 (при положительном решении):** гибрид score-fusion(lex v1, mm; α=0.85, min-max) + show-гейт детерминированным правилом (0.95) + показ только на распознанных расчётных доменах (домен-детектор по категориям схем/шаблонов — framework-канвасы не предлагают шаблоны вообще). Ожидание на расчётных доменах: p@1 ≈ 0.47.
3. **Автономный fallback:** lex v2 (синонимы каталога) — p@1 0.40 без нейросети: для слабого железа и деградаций sidecar.
4. **Путь к green:** только H8 (fine-tune mm с hard negatives + none-примерами, ноутбук авторов на Kaggle 2×T4). Критерий запуска (по программе волны 3): гибрид подтверждён (выполнено: 0.468/новый сет 0.307 при +9.3 п.п.) → H8 оправдан. Референс авторов Laya: 0.362 → 0.766 на их домене.
5. **Калибровка после fine-tune:** Platt обязателен в пайплайне (ECE 0.099); гейт по уверенности пересматривать только после H8.

## 10. Ограничения волны 3

- Разметка синтетики владельцем не получена — B-слайс остался с авто-golden; расширение сета выполнено только карвингом framework-схем (смещение к none-зоне, осознанное).
- Расширенный test смешивает «старый замороженный» и «новый framework» сегменты: сравнение с порогами gate.yaml корректно по построению (пороги не пересматривались), но интерпретация по слайсам обязательна (сделано в §8).
- Прогоны td/en чекпойнтов не выполнялись (H7 вне минимального состава); латентные метрики не перемерялись (инференс идентичен волне 1 по конфигурации; p50/p95 в §1).
- Т3.json (ноутбук владельца) не получен; one-shot-пакет восстановлен из архива и готов к перевыпуску.
