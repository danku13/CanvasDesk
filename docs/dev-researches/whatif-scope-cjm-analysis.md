# What-if сценарии и схемы: CJM и варианты скоупинга (канвас vs схема)

- Дата: 2026-10-07
- Тип: analysis + alternatives
- Автор: агент-сессия (задача владельца от 2026-10-07)
- Коммит-база: 7e54e43 (main)
- Источники: жалоба владельца (текст задачи), FR-017 (`docs/change-requests/`,
  волна B2), FR-064 P2 (freeze/сравнение), PRD-0008 (схемы), ADR-0007,
  `design/use-cases/whatif-bar.md`, код: `canvas-core/src/whatif.rs`,
  `canvas-scene/src/scene.rs` (whatif_*), `canvas-app/src/whatif_ui.rs`,
  `app/overlays.rs`.

## 1. Проблема (голос владельца)

> Я как пользователь проектирую схему, провожу what-if, далее открываю или
> собираю другую схему и мне требуется собрать другие what-if сценарии под
> новую схему.

Дополнительно из задачи: кнопка «Сбросить» должна **полностью** сбрасывать
собранные what-if сценарии — до сессии она чистила только подмены активного
сценария runtime-only (фикс сделан в этой же сессии, коммит d50217a).

## 2. Как устроено сегодня (факты кода)

1. **Носитель сценариев — канвас, не схема.** Сценарии персистентны в
   `canvas.extra["canvasdesk"]["whatif"]` файла `.canvas` (гипотеза Q11 FR-017:
   «сценарии едут с канвасом»). Открытие другого `.canvas` даёт сценарии
   того файла; «утечек» между файлами нет.
2. **Подмены адресуют ноды по id** — `(node_id, line) → expr`. Схема,
     применённая из галереи (FR-049), вставляет ноды с ремапом id
   (`note-N`/`group-N`); ручная сборка — те же text-ноды. Понятия
   «экземпляр схемы» в модели данных нет.
3. **Лимит сценариев — 3** (гипотеза Q5b), автоимя «Сценарий N».
4. **Протухание** (инвариант 5): нода удалена / строка удалена / строка
   стала прозой → подмена помечается ⚠ и тихо пропускается в пересчёте.
   Удаление нод схемы НЕ удаляет сценарии — только маркирует подмены.
5. **До этой сессии из UI нельзя было удалить сценарий** (только MCP
   `whatif_scenario_delete`); «Сброс» не персистился. Оба фикса — в этой
   сессии.

## 3. CJM: «what-if поверх двух схем на одном канвасе»

| # | Шаг | Действие пользователя | Состояние системы | Боль |
|---|---|---|---|---|
| 1 | Проектирование | Собирает схему А (галерея/вручную), связывает value-рёбрами | Ноды A₁…Aₙ | — |
| 2 | Гипотезы | Ctrl+Shift+I → «+» → 2–3 сценария, двойной клик по строкам расчёта → подмены | `whatif.scenarios` канваса: S1, S2 (подмены ссылаются на Aᵢ) | — |
| 3 | Сравнение | «Заморозить», «Сравнить» | freeze-снимки + таблица | — |
| 4 | **Переход к новой работе** | Применяет схему Б из галереи (или чистит область и собирает вручную) | Ноды Б добавились; S1/S2 живут, чипы висят | **Старые сценарии «загромождают» бар; лимит 3 занят** |
| 5 | Новые гипотезы | Хочет S1', S2' под схему Б | «+» падает: «лимит сценариев: не более 3» | **Нужен полный цикл очистки — а его не было** |
| 6 | Очистка (до сессии) | «Сброс» → чистятся только подмены АКТИВНОГО сценария, runtime-only | Файл не меняется; после переоткрытия всё вернётся | **Главный дефект: сброс не сбрасывает** |

Ключевой вывод CJM: точка разрыва — шаг 6. Пользователю нужен
**предсказуемый цикл жизни сценариев**, а не новая вложенная модель данных:
«сделал гипотезы → закончил с ними → почистил → собрал новые».

## 4. Варианты

### A. Привязка сценариев к схеме (scheme context)

Каждый сценарий получает `scheme: Option<SchemeInstanceId>`; нодам,
вставленным `apply_scheme`, ставится маркер экземпляра схемы; бар фильтрует
сценарии по «текущей схеме».

- Плюсы: максимальная гибкость на плотных канвасах; сценарии «переезжают»
  вместе с копируемой схемой.
- Минусы:
  - «Текущая схема» не определена для ручной сборки (большинство кейсов
    владельца — именно ручные); выбор контекста по вьюпорту/выделению —
    новый слой неявного состояния, новые баги «почему я не вижу сценарий».
  - Что делать со сценариями «на весь канвас» (смешанными, глобальными)?
    Нужны правила + UI переключения контекста.
  - Ломает простую ментальную модель «what-if — про канвас»: CJM шагов
    1–3 усложняется выбором контекста ДО создания сценария.
  - Стоимость: модель данных + миграция `.canvas` + галерея + бар + MCP
    (9 инструментов whatif_*) + скиллы + доки — полноценный FR с ADR.
- Вердикт: **правильная цель для плотных multi-scheme канвасов, но не
  ближайший шаг**: сначала нужно, чтобы базовый цикл жизни работал без
  сюрпризов (шаг 6 CJM).

### B. Группы сценариев (scenario sets) на канвасе

Сценарии собираются в именованные «сеты», бар показывает активный сет
переключателем.

- Плюсы: решает лимит 3 (сеты по 3); старые сценарии не мешают (свёрнутый
  сет); не требует разметки нод.
- Минусы: та же неопределённость «какой сет активен» без разметки нод;
  двойная иерархия «сет → сценарий» в UI при 26px-чипах; freeze/сравнение
  пересекаются с сетами по смыслу (заморозка уже выполняет роль «архивного
  набора гипотез»).
- Вердикт: дублирует семантику freeze; отложено.

### C. Явная модель «сценарии глобальны для канваса» + полный цикл жизни

Скоуп сценария = канвас (как сегодня), но каждый шаг цикла жизни сделан
явным и предсказуемым.

- Гарантии модели (простые для пользователя):
  1. Сценарии живут в файле канваса; другой файл — другие сценарии.
  2. Полный сброс («Сброс» + confirm) очищает ВСЕ сценарии/подмены/заморозки
     персистентно, одним Ctrl+Z.
  3. Отдельный сценарий удаляется «✕» чипа (confirm) — партикулярная
     очистка без тотального сброса.
  4. Протухшие подмены видны (⚠) и не ломают пересчёт.
- Плюсы: ноль миграций, ноль новых сущностей, покрывает шаг 6 CJM;
  согласуется с ADR-0007 «канвас = носитель модели» и Q11 FR-017.
- Минусы: на ОДНОМ канвасе с НЕСКОЛЬКИМИ одновременно живущими схемами
  сценарии остаются общими (лимит 3 на всё); «почистить под новую схему» —
  явное действие пользователя, не автоматика.
- Вердикт: **принято для сейчас** (реализовано в этой сессии).

## 5. Решение и реализация (эта сессия)

Принята модель **C** с полной проработкой цикла жизни (см. коммиты сессии):

| Кусок | Статус |
|---|---|
| Полный «Сброс» (confirm-диалог, персистентность, undo) | реализовано |
| Undo/redo восстанавливает заморозки по именам снапшота | реализовано |
| «✕» чипа сценария — удаление одного сценария с confirm | реализовано |
| Вёрстка/i18n бара (замер = отрисовка для всех подписей) | реализовано |
| user-docs + design-док синхронизированы | реализовано |

Осознанное ограничение (зафиксировать в user-docs): **what-if сценарии
глобальны для канваса**; для независимого набора гипотез — отдельный
`.canvas` (это дешёвая операция: файл = модель, ADR-0007).

## 6. Миграционный путь к A (когда станет тесно)

Триггеры (любой из): ≥5 отчётов пользователей о конфликтующих сценариях
на одном канвасе; регулярное использование 2+ больших схем на канвасе;
запросы на «what-if по выделенному фрагменту».

Путь: (1) маркер `scheme_instance` на ноды при apply_scheme (обратимо,
чисто additive в `canvasdesk`-расширение ноды); (2) `scheme: Option<id>` в
сценарии + фильтр бара «База | Схема… | Все»; (3) автоподсказка при
`apply_scheme` на канвас со сценариями («привязать новые сценарии к этой
схеме?»); (4) ADR + FR. Формат `.canvas` обратно совместим (неизвестные
поля сохраняются — правило проекта).
