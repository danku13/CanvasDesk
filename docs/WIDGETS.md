# CanvasDesk Widgets — справочник разработчика

Виджет CanvasDesk — самодостаточный микрофронтенд: папка со статикой
(HTML/JS/CSS, билд любого фреймворка) и манифестом `widget.json`.
Канвас — хост-оркестратор: размещает виджет нодой, управляет жизненным
циклом, изолирует и пробрасывает данные через типизированный мост.

Этот документ — единственный источник истины для авторов виджетов:
прочитав его, новый виджет можно собрать и поставить на канвас за ~30
минут, не открывая исходники хоста. Внутреннее устройство движка —
`docs/plans/M5-widgets.md`; спецификация хоста — SPEC §7.6.

| Быстрый путь | Что это |
|---|---|
| `sdk/widget-template/` | Vite + TypeScript-шаблон: `npm run pack` → готовый пакет |
| `sdk/canvasdesk.ts` | SDK-обёртка над мостом (без зависимостей, 131 строка) |
| `examples/todo-panel/` | офлайн-виджет: props-персистентность + standalone-режим |
| `examples/dashboard/` | сетевой виджет: fetch + permission `network` |
| `assets/widgets/` | встроенные часы/календарь/стикер — vanilla JS на SDK |

---

## 1. Формат пакета

Пакет — обычная папка. Точка входа и метаданные описаны в `widget.json`,
всё остальное — статические файлы, доступные виджету по относительным
путям. Никакого специального формата архива нет: установка = копирование
папки.

```
my-widget/
├── widget.json      # манифест — обязателен, в корне
├── index.html       # entry: разметка + CSP (путь задаётся в манифесте)
├── canvasdesk.js    # SDK для script-тега (если проект без сборщика)
├── app.js           # логика виджета
└── assets/…         # картинки, шрифты — что угодно, лимиты ниже
```

Пакет разворачивается в изолированный виртуальный origin
(`SetVirtualHostNameToFolderMapping`, hostname = id с заменой точек на
дефисы): относительные пути работают, всё вне папки недоступно.
Навигация наружу и новые окна отменяются хостом; remote-виджеты (URL
вместо локальной папки) запрещены архитектурно.

**Лимиты пакета:** до 1000 файлов, до 64 МБ, символические ссылки
пропускаются при копировании. `entry` — относительный путь без `..`,
абсолютных путей, схем и дисков (`C:`); иначе установка отвергается.

## 2. Манифест `widget.json`

```json
{
  "id": "com.example.my-widget",
  "name": "My Widget",
  "version": "1.0.0",
  "entry": "index.html",
  "defaultSize": [360, 240],
  "permissions": []
}
```

| Поле | Тип | Обяз. | Правила |
|---|---|---|---|
| `id` | string | да | 3–64 символа `[a-z0-9.-]`, без `..`, без лидирующих/хвостовой точки и лидирующего дефиса. Имя папки пакета и виртуальный hostname |
| `name` | string | да | непустое, читаемое имя для меню «Виджеты ▸» и диалогов |
| `version` | string | да | 1–32 символа; сравнение — semver-подобная тройка `X.Y.Z` (суффиксы `-beta` игнорируются) |
| `entry` | string | да | относительный путь точки входа внутри пакета (обычно `index.html`) |
| `defaultSize` | `[w, h]` | нет | размер ноды при создании, мировые px; кламп 160..2000; по умолчанию `[320, 200]` |
| `permissions` | string[] | нет | только известные значения (см. §6), по умолчанию `[]` |

Неизвестные поля — не ошибка (forward compatibility): они попадают в
warn-лог установки. Опечатка в `permissions` (например, `fs:reed`) —
ошибка: пакет не установится, опечатка видна сразу.

## 3. Установка, обновление, удаление

**Установка.** Перетащите папку пакета на канвас: появится призрак
«Установить виджет» → отпустите → диалог Да/Нет со списком permissions →
пакет копируется в `~/.canvasdesk/widgets/<id>/`, в точке дропа
создаётся нода. Невалидный манифест — призрак-ошибка и toast, ничего
не копируется.

**Добавление на канвас.** ПКМ по канвасу → «Виджеты ▸» — список
установленных и встроенных пакетов. Нода — обычный участник сцены:
двигается, связывается рёбрами, попадает в мини-карту и поиск.

**Обновление.** Перетащите папку с новой версией (`version` выше) —
хост предложит обновление: файлы заменяются, ноды и props сохраняются.

**Удаление пакета.** «Виджеты ▸ <имя> ▸ Удалить пакет» (с подтверждением).
Ноды пакета становятся «битыми» (серый плейсхолдер). Встроенные виджеты
после ручного удаления возвращаются только с новой версией виджета
(tombstone-механика), при следующих запусках не навязываются.

**Где живут данные.** Пакеты — `~/.canvasdesk/widgets/<id>/`.
`props` и геометрия — в `.canvas`-файле сцены (переживают экспорт/импорт,
включая Obsidian Canvas — как неизвестный тип ноды). Объёмное состояние —
SQLite `~/.canvasdesk/cache.db`, таблица `widget_state(node_id, key, value)`.

## 4. Мост (JSON-RPC поверх postMessage)

Каждое сообщение — одиночный JSON-объект (без переносов) вида
`{"jsonrpc":"2.0","method":…,"params":…}`, запросы дополнительно несут
`"id"`. Хост валидирует схемы всех сообщений: невалидное — drop + warn,
никогда не краш и не паника. Виджет шлёт сообщения через
`window.chrome.webview.postMessage(...)`, получает — в `window`-событии
`message` (всё это уже делает SDK — см. §5).

**host → widget (уведомления):**

| method | params | когда |
|---|---|---|
| `init` | `{ nodeId, props, theme, zoom }` | после `ready`: идентификация + стартовые данные |
| `propsChanged` | `{ props }` | props изменились извне: ваш `setProps` (подтверждение), undo/redo, MCP |
| `visibility` | `{ visible }` | переход live ↔ snapshot (см. §7) |
| `themeChanged` | `{ theme }` | смена темы приложения |

`theme` — `{ dark: boolean, accent: "#RRGGBB" }`.

**widget → host:**

| method | params | permission | семантика |
|---|---|---|---|
| `ready` | — | — | виджет загружен, ждёт `init` |
| `resize` | `{ w, h }` | — | изменить размер ноды (хост клампит 160..2000) |
| `setProps` | `{ props }` | — | сохранить props в `.canvas`; на хосте — undo-шаг с коалесценцией подряд идущих вызовов + автосейв |
| `openFile` | `{ path }` | `shell:open` | открыть файл в ассоциированном приложении |
| `readDir` | `{ path }` + `id` | `fs:read` | листинг allowlist-директории; ответ `{ entries: [{ name, isDir }] }` |
| `toast` | `{ text }` | — | строка в HUD канваса (~3 с) + запись в лог |
| `stateGet` | `{ key }` + `id` | — | ответ `{ value: string \| null }` |
| `stateSet` | `{ key, value }` + `id` | — | ответ `{ ok: true }`; value — строка (JSON для структур) |

**Ответы на запросы** приходят с тем же `id`:
`{"jsonrpc":"2.0","id":…,"result":…}`. Отказ (нет permission, путь вне
allowlist, нет пакета) — `result` вида `{ "error": "пояснение" }`.
Виджет обязан деградировать с понятной ошибкой, не падать.

**props или widget_state?** `props` — настройки и контент, участвующие в
undo и живущие в сцене (экспортируются вместе с ней). `widget_state` —
объёмные/производные данные (кэш, черновики, индексы), привязанные к
ноде, но не к файлу сцены.

## 5. SDK: `sdk/canvasdesk.ts`

Обёртка над мостом: типы, Promise-запросы, подписки. Без зависимостей.
Два способа подключения:

**Со сборщиком (Vite/TS):** скопируйте `canvasdesk.ts` в `src/`:

```ts
import { CanvasDesk, type ThemeInfo } from "./canvasdesk";

CanvasDesk.onTheme(applyTheme);
CanvasDesk.onProps((props) => render(props));
CanvasDesk.init((data) => {
  applyTheme(data.theme);
  render(data.props);
});
CanvasDesk.setProps({ count: 42 });        // уведомление
const entries = await CanvasDesk.readDir("docs"); // запрос → Promise
```

**Без сборщика (vanilla):** положите `canvasdesk.js` (iife-сборка)
рядом с `index.html` — появится глобал `CanvasDesk`:

```html
<script src="canvasdesk.js"></script>
<script src="app.js"></script>
```

| API | Вид | Назначение |
|---|---|---|
| `CanvasDesk.standalone` | `boolean` | true, если моста нет — страница открыта как обычный сайт |
| `CanvasDesk.init(cb)` | — | регистрирует init-колбэк и шлёт `ready`; вызвать один раз при старте |
| `CanvasDesk.onProps(cb)` | — | подписка на `propsChanged` |
| `CanvasDesk.onTheme(cb)` | — | подписка на `themeChanged` |
| `CanvasDesk.onVisibility(cb)` | — | подписка на `visibility` (true = live, false = спим) |
| `CanvasDesk.setProps(props)` | уведомление | персистентность в `.canvas` |
| `CanvasDesk.resize(w, h)` | уведомление | размер ноды |
| `CanvasDesk.toast(text)` | уведомление | HUD-строка канваса |
| `CanvasDesk.openFile(path)` | уведомление | открыть файл (permission `shell:open`) |
| `CanvasDesk.readDir(path)` | `Promise<DirEntry[]>` | листинг (permission `fs:read`) |
| `CanvasDesk.stateGet(key)` | `Promise<string \| null>` | объёмное состояние |
| `CanvasDesk.stateSet(key, value)` | `Promise<void>` | объёмное состояние |

**Standalone-режим («микрофронтенд»).** SDK детектит отсутствие
`window.chrome.webview`: уведомления становятся no-op, запросы
отвергаются ошибкой
`CanvasDesk: мост недоступен (standalone-режим)`. Тот же bundle
открывается обычной страницей (`npm run dev`, двойной клик по
`dist-widget/index.html`) — удобно разрабатывать UI без хоста и
выкладывать «лэнддинг-версию» виджета. Пример фолбэка на `localStorage` —
`examples/todo-panel`.

**Правила хорошего виджета:**
- один `setProps` на завершённое действие пользователя (debounce при
  вводе текста, см. стикер): меньше undo-шагов и запись на диск;
- не полагайтесь на порядок `init` → события: подписки регистрируйте
  до `CanvasDesk.init`;
- любые чужие props разбирайте защитительно (`typeof`-проверки): в
  `.canvas` файл мог быть отредактирован вручную;
- при `onVisibility(false)` гасите таймеры и анимации — экономия CPU
  в снапшоте;
- `resize` — просьба, а не команда: хост клампит размеры.

## 6. Permissions

Разрешения объявляются в манифесте и проверяются на КАЖДЫЙ вызов моста.
Отказ — warn в лог хоста + JSON-RPC-ошибка виджету.

| Permission | Что открывает | Без него |
|---|---|---|
| `canvas:read` | (зарезервировано v1.1) структура канваса в будущих версиях | сейчас ни один метод его не требует |
| `shell:open` | `openFile` — запуск файла в ассоциированном приложении | вызов блокируется, ошибка в ответе |
| `fs:read` | `readDir` — листинг **allowlist-директорий**: папки файловых нод текущей сцены + папка `.canvas`-файла | листинг любых других путей отвергается |
| `network` | внешние `fetch`/XHR: без него ВСЕ внешние WebResourceRequested блокируются пустым 403 | страница получает 403, `fetch` резолвится с `ok: false` |

Принципы: запрашивайте минимум (диалог установки показывает список
пользователю); `network` — opt-in, сознательное решение владельца канваса.

**Сеть требует двух ключей.** Permission `network` открывает дверь на
стороне хоста, но CSP вашей страницы решает, куда именно можно ходить:
добавьте в `index.html` явный `connect-src`:

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'self'; connect-src 'self' https://api.github.com; style-src 'unsafe-inline'">
```

Демонстрация обеих линий защиты — `examples/dashboard`: уберите
`network` из манифеста, пересоберите и обновите пакет — fetch получит
403, виджет покажет панель ошибки с пояснением.

## 7. LOD: жизненный цикл (когда ваш виджет «спит»)

Зум и видимость решают, жив ли WebView2-инстанс:

| Состояние | Условие | Что происходит |
|---|---|---|
| **live** | zoom ≥ 0.27 (вход, гистерезис ±0.02) и нода в viewport и не перекрыта оверлеем | настоящий WebView2 поверх канваса, полный ввод |
| **snapshot** | zoom < 0.23, вне viewport, перекрыта оверлеем или проигран LRU | HWND скрыт, рендер приостановлен (`TrySuspend`); канвас рисует последний снапшот; видимые за лимитом освежаются раз в 5 с |
| **placeholder** | пакет удалён/битый или рантайм WebView2 недоступен | серая карточка с именем |

Лимит live-инстансов — 6 (LRU): 7-й и дальше живут снапшотами. При
переходе виджет получает `visibility: false` — гасите таймеры. Зум
контента клампится 0.25–5.0: дальше контент не растягивается.

Практические следствия: не держите WebSocket-соединения открытыми
в снапшоте; не рассчитывайте, что JS исполняется постоянно; всё, что
должно пережить «сон», храните в props или widget_state.

## 8. Ограничения v1.1

1. **Airspace:** HWND WebView2 поверх канваса — при перекрытии живого
   виджета оверлеем (миникарта, поиск, меню, диалоги, рамка выделения)
   виджет временно прячется в снапшот; сами оверлеи не смещаются.
2. Зум контента клампится 5× (при дальнем — снапшот).
3. Не более 6 live-инстансов одновременно (LRU), остальные — снапшоты
   с refresh 5 с.
4. Снапшот «замораживается» при zoom < 0.25 (без refresh).
5. Клик по контенту не выделяет ноду — выделение за заголовок/рамку
   (drag-зона 28 world-px сверху + рамка 8 world-px).
6. Фокус виджета глушит хоткеи канваса до Esc или клика по канвасу.
7. Remote URL как виджет — запрещён архитектурно, только локальные пакеты.
8. Обновление встроенных после ручного удаления пакета — только с новой
   версией виджета (tombstone).
9. Угол мини-карты — постоянная snapshot-зона (виджеты там всегда «спят»).
10. `canvas:read` зарезервировано и пока ничего не даёт.

## 9. Туториал: от нуля до канваса за 30 минут

Нужны: Node.js 18+ и CanvasDesk (сборка `cargo build --release`,
бинарник `canvasdesk.exe` / `canvasdesk`).

1. **Каркас.** Скопируйте `sdk/widget-template/` в отдельную папку
   (вне репозитория — шаблон самодостаточен), откройте её в терминале.
2. **Идентичность.** В `public/widget.json` поменяйте `id` (например,
   `io.me.first-widget`), `name`, при желании `defaultSize`.
3. **Логика.** Откройте `src/main.ts` — там рабочий демо-счётчик.
   Замените на свою логику: рендер из `data.props`, действия — через
   `CanvasDesk.setProps`. Разметка — `index.html`.
4. **Разработка.** `npm install`, затем `npm run dev` — живая страница
   в браузере: SDK в standalone-режиме, UI крутится без хоста
   (props-запросы — no-op, это видно в подсказке внизу демо).
5. **Типы.** `npm run typecheck` — vite build типов не проверяет.
6. **Сборка.** `npm run pack` → `dist-widget/`: `index.html`,
   `widget.json`, ассеты с относительными путями.
7. **Установка.** Запустите CanvasDesk, раскройте окно канваса и
   перетащите папку `dist-widget` на полотно → «Установить» → Да.
   Виджет появился в точке дропа.
8. **Проверка.** Меню ПКМ «Виджеты ▸» — ваш пакет в списке. Добавьте
   второй инстанс, свяжите ноду ребром с заметкой, перезапустите
   приложение: props пережили рестарт.
9. **Итерации.** Правьте код → `npm run pack` → поднимите `version`
   в манифесте → перетащите `dist-widget` снова → «Обновить».

Дальше по необходимости: permissions (§6), объёмное состояние
(`stateGet`/`stateSet`), тема (`onTheme`) — см. примеры
`examples/todo-panel` и `examples/dashboard`.

## 10. Отладка

**Standalone-режим** — первый эшелон: `npm run dev`, обычные DevTools
браузера (SDK в no-op). Мост не нужен, чтобы верстать и отлаживать логику.

**Виджет в хосте.** DevTools WebView2 не подключаются в v1.1 —
диагностируйте через мост: `CanvasDesk.toast("…")` и `console`-хвосты
не видны, поэтому основные каналы — toast и лог хоста.

**Лог хоста.** По умолчанию уровень `info`
(`RUST_LOG=debug,wgpu_hal=warn,wgpu_core=warn` — детальнее).
Ключевые маркеры по виджетам:

| Маркер (фрагмент) | Смысл |
|---|---|
| `встроенный виджет материализован` | пакет из `assets/widgets` развёрнут при старте |
| `widget-пакет пропущен: невалидный манифест` | в `~/.canvasdesk/widgets` найден пакет с битым `widget.json` — путь и причина рядом |
| `внешняя сеть без permission заблокирована` | виджет ходит в сеть без `network` — uri в записи |
| `readDir отказан` | путь вне allowlist или нет `fs:read` |
| `widget toast` | текст вашего `toast()` |
| `postMessage не доставлен` | инстанс уже уничтожен (нормально при быстрых переключениях LOD) |

**Нагрузочный прогон.** `canvasdesk --stress-widgets 10` — сцена с 10
виджет-нодами для проверки fps и LOD (6 live + 4 snapshot). Полный
список флагов — `canvasdesk --help`.

**Типовые симптомы:**

| Симптом | Вероятная причина |
|---|---|
| Пакет не ставится, toast про манифест | невалидный `id`/`entry`/`defaultSize`/`permissions` — см. §2 |
| Установился, но серый плейсхолдер | пакет удалён/битый или нет рантайма WebView2 Evergreen |
| Сетка есть, JS не работает | inline-`<script>` при CSP `default-src 'self'` — выносите в файлы (тест `builtin_widgets_have_no_inline_scripts`) |
| fetch падает с 403 | нет permission `network` (или GitHub-лимит — см. dashboard) |
| Ассеты 404 | не `base: "./"` в vite-конфиге — абсолютные пути не работают в виртуальном origin |
