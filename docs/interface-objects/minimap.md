# Миникарта (`minimap`) — интерфейсный объект

Документ для последовательного расширения функционала миникарты (`T13`). Фиксирует текущее состояние, интерфейс взаимодействия, ограничения производительности и точки входа для новых фич (навигация, нагрузочные сценарии, интеграция с поиском и связями).

---

## 1. Определение

Миникарта — обзорная визуализация всей сцены (`nodes` из `.canvas`) в правом нижнем углу окна. Размер: `220 × 140` логических пикселей, отступ `16 px`. Рендерится как отдельный проход (`minimap pass`) поверх основного кадра (`SPEC.md` §6.1, §6.3).

**Границы ответственности:**
- `canvas-render`: рендер миникарты (`minimap.rs`, `minimap_pass.rs`); упрощённые прямоугольники без текста и текстур; цвет по типу ноды; рёбра — линии `1 px` (только при < 500 нод).
- `canvas-app`: позиционирование (правый нижний угол), обработка кликов (навигация), drag viewport-прямоугольника (панорамирование).

---

## 2. Визуальная структура миникарты

```
Миникарта (220×140 лог. px, отступ 16 px, скруглённые углы)
├── Фон (тёмный, полупрозрачный)
├── Упрощённые прямоугольники нод (без текста и текстур, цвет по типу)
│   ├── `file` — цвет типа файла (по расширению или иконке)
│   ├── `text` — цвет `node.color` или стандартный
│   ├── `group` — цвет группы (граница с меткой, если метка короткая)
│   └── `widget` — цвет виджета (если виджет установлен)
├── Битые ссылки (`brokenLink`) — красный прямоугольник или красная рамка (по решению рендера)
├── Рёбра (`edges`) — линии 1 px (только при числе нод < 500; при ≥ 500 — не рисуются для производительности)
├── Рамка viewport (белая, прозрачная или с заливкой; движется синхронно с камерой)
└── Навигация (клик в центр ноды → камера центрируется по этой ноде; drag рамки viewport → панорамирование сцены)
```

---

## 3. LOD-стратегия миникарты (`SPEC.md` §6.2, `ACCEPTANCE.md` §5.1)

Миникарта имеет собственную LOD-стратегию (независимую от основной сцены), так как её цель — обзор, а не детализация.

| Условие | Поведение миникарты | Ограничение (`ACCEPTANCE.md` §5.1) | Точка входа для фичи |
|---|---|---|---|
| < 500 нод | Рисуются прямоугольники нод + линии рёбер (`1 px`) | При 500+ нод — рёбра не рисуются для производительности | Оптимизация рендеринга рёбер для больших сцен (динамическое включение рёбер в зависимости от зума или нагрузки) |
| ≥ 500 нод | Только прямоугольники нод (без рёбер) | Визуально связи теряются; навигация по связям через миникарту невозможна в больших сценах | Отображение связей в виде «точек» или «линий с упрощённой геометрией» даже в больших сценах; фильтрация связей (`T23`) |
| Нода вне viewport | Не отображается (culling по `rstar` или по координатам) | Миникарта отражает только видимую или всю сцену? Текущее поведение: отражает всю сцену, но с culling по viewport для рёбер? Уточнить в коде (`minimap_pass.rs`) | Явное отображение всей сцены (без culling) или отображение только видимой части (для больших сцен) |
| Битая ссылка (`brokenLink`) | Красный прямоугольник или красная рамка (по решению рендера) | Красный цвет — это визуальный маркер; не влияет на `.canvas` или на поведение ноды | Динамическое изменение цвета при изменении `brokenLink` (например, пульсация или мигание для новых битых ссылок) |

## 4. Взаимодействия с миникартой (таблица действий)

| Действие | Жест / триггер | Обработчик (текущий) | Ограничение (`ACCEPTANCE.md` §5.1, §9) | Точка входа для фичи |
|---|---|---|---|---|
| Навигация (центр камеры по ноде) | Клик в центр ноды на миникарте | `canvas-app` → обновление `camera_x`, `camera_y` в модели; плавное перемещение камеры (~300 мс, плавное торможение — аналогично `T14`: полёт камеры) | Смещение должно быть не более пары пикселей (`ACCEPTANCE.md` §5.1, п. 5); при систематическом смещении — дефект | Улучшение точности навигации; привязка навигации к центру ноды или к конкретной точке внутри ноды |
| Панорамирование (drag viewport) | Drag рамки viewport внутри миникарты | `canvas-app` → обновление `camera_x`, `camera_y` в реальном времени; точка сцены под курсором следует за курсором без «прыжков» | При сужении окна до минимального размера — миникарта скрывается или «клампится» к углу, не наезжая на содержимое канваса | Улучшение поведения при минимальном размере окна; возможность «закрепить» миникарту в углу или переместить её (будущая фича) |
| Нагрузочный сценарий (`--stress 5000`) | Запуск `canvasdesk.exe --stress 5000` + включение HUD (`F3`) | Миникарта не должна «съедать» кадр; цель: растеризация + загрузка суммарно < 2 мс (`ACCEPTANCE.md` §5.1, п. 7) | При больших сценах (> 500 нод) — рёбра не рисуются; это ограничение для производительности, не для навигации | Оптимизация рендеринга миникарты для очень больших сцен (> 5000 нод); динамическое отключение рендеринга миникарты при сильной нагрузке (`F3`: HUD) |
| Новый пустой канвас | Открытие нового `.canvas` без нод | Миникарта рисует фон + рамку viewport без нод; без паники и артефактов | Миникарта должна работать даже при отсутствии нод (пустая сцена) | Отображение «пустой» миникарты с подсказкой или инструкцией для пользователя (будущая фича) |
| Смена монитора / DPI | Перенос окна между мониторами с разным масштабом (`SPEC.md` §6.5) | Миникарта пересчитывается (`scale_factor` из `winit`); размеры (`220 × 140`) — логические пиксели | Миникарта не должна «ломаться» при смене DPI или монитора (`T15`, п. 7: смена масштаба монитора) | Улучшение поведения миникарты при смене DPI: автоматическое пересоздание `surface` (как для основного рендера) или динамическое изменение размера в логических пикселях |

## 5. Производительность миникарты (`SPEC.md` §6.3, `ACCEPTANCE.md` §5.1)

Миникарта — это дополнительный рендер-проход (`minimap pass`, `SPEC.md` §6.1). Её производительность критична, так как она работает одновременно с основным рендером.

**Целевые метрики (`SPEC.md` §6.3`):**
- 60 fps при панорамировании / зуме на сцене из 5000 нод.
- Миникарта не должна «съедать» кадр: растеризация + загрузка суммарно < 2 мс.
- Память: < 500 МБ на 5000 нод без живых превью (миникарта — часть этой памяти, но её вклад минимален, так как она использует упрощённые прямоугольники, не текстуры).

**Текущие ограничения (`ACCEPTANCE.md` §5.1`):**
- При 500+ нод — рёбра не рисуются (для производительности).
- При минимальном размере окна — миникарта скрывается или «клампится» (чтобы не перекрывать содержимое канваса).
- При смене монитора / DPI — миникарта пересчитывается (без краша или «двойного» масштаба, `T15`, п. 7).

## 6. Состояния миникарты (что влияет на визуал и поведение)

Миникарта не имеет собственного `.canvas`-файла или SQLite-таблицы; её состояние — это временное UI-состояние (`canvas-app`), которое не сериализуется.

| Состояние | Где хранится | Как влияет | Точка входа для фичи |
|---|---|---|---|
| Позиция (`x`, `y` в логических пикселях) | `canvas-app` (UI-state) | Миникарта всегда в правом нижнем углу (`220 × 140`, отступ `16 px`); при минимальном размере окна — «клампится» или скрывается | Возможность перемещать миникарту (drag за заголовок); возможность «закрепить» миникарту в другом углу или с другим размером |
| Размер (`width`, `height`) | `canvas-app` (UI-state) | Фиксированный (`220 × 140`); при смене DPI или монитора — пересчитывается (`scale_factor`) | Динамическое изменение размера миникарты (например, при изменении размера окна или по настройке пользователя) |
| Видимость (`visible` / `hidden`) | `canvas-app` (UI-state) | При минимальном размере окна — скрывается или «клампится»; при нормальном размере — всегда видна (если не скрыта пользователем) | Возможность скрыть / показать миникарту через хоткей или через меню; сохранение состояния видимости в `.canvas` или в SQLite (`sessions`) |
| Рендер рёбер (`edges_visible` / `edges_hidden`) | `canvas-app` или `minimap_pass.rs` (зависит от числа нод < 500 или ≥ 500) | При < 500 нод — рёбра рисуются; при ≥ 500 — не рисуются (для производительности) | Динамическое включение / отключение рёбер в зависимости от нагрузки (`F3`: HUD) или по настройке пользователя; отображение рёбер даже в больших сценах (с упрощённой геометрией) |
| Навигация (клик / drag viewport) | `canvas-app` (UI-state) | Клик в центр ноды → камера центрируется; drag рамки → панорамирование; состояние не сериализуется | Постоянное выделение ноды (или связи) в миникарте; отображение состояния ноды (`brokenLink`, `selected`) в миникарте (например, красная рамка для `brokenLink`) |

## 7. Ограничения и известные проблемы (`ACCEPTANCE.md` §5.1, `TASKS.md` T13)

- При 500+ нод — рёбра (`edges`) не рисуются (для производительности). Это ограничение визуальное, не функциональное: навигация (клик, drag) работает, но связи теряются из виду.
- При минимальном размере окна — миникарта скрывается или «клампится»; это ограничение для предотвращения перекрытия содержимого канваса, но может быть неудобно для пользователя, который хочет видеть миникарту даже в небольшом окне.
- При смене монитора / DPI — миникарта пересчитывается (`scale_factor` из `winit`), но нет явной проверки на «двойной» масштаб или на некорректное отображение рамки viewport (`T15`, п. 7: смена масштаба монитора).
- Нет постоянного выделения ноды или связи в миникарте; выделение (`selected`) — это временное UI-состояние, которое не сериализуется и не отображается в миникарте (кроме `brokenLink` — красный цвет, который отображается).
- Нет фильтрации нод или связей в миникарте (`T14`: поиск — это отдельный интерфейсный объект, не интегрированный с миникартой в текущей версии).

| Фича | Привязка к интерфейсу миникарты | Что нужно изменить | Где документировано как ограничение |
|---|---|---|---|

| Нагрузочная сцена (`T13`, п. 7) | Миникарта + HUD (`F3`) | Проверка производительности: панорамирование держит 60 fps; миникарта не «съедает» кадр (< 2 мс); при нагрузке — динамическое отключение рёбер или миникарты | `ACCEPTANCE.md` §5.1, п. 7: цель — растеризация + загрузка < 2 мс |

| Интеграция с поиском (`T14`) | Миникарта + панель поиска (`Ctrl+F`) | При поиске — выделение найденных нод в миникарте (например, подсветка или изменение цвета); навигация по результатам (`F3`, `Shift+F3`) — миникарта отражает текущую ноду в фокусе | `ACCEPTANCE.md` §5.2 (`T14`): поиск по имени и тексту (`FTS5`); миникарта не интегрирована с поиском в текущей версии |
| Интеграция с связями (`T23`) | Миникарта + связи (`edges`) | При hover на ноду или при выделении связи — подсветка связей в миникарте (например, изменение толщины или цвета линии рёбер); при `brokenLink` — красная рамка для связанных нод | `TASKS.md` T23 (не влит): динамическая подсветка связей |
| Постоянное выделение (`selected`) | Миникарта + ноды (`nodes`) | Сериализация выделения в `.canvas` или в SQLite (`sessions`); отображение выделенных нод в миникарте (например, подсветка или рамка); восстановление выделения при загрузке `.canvas` | `ACCEPTANCE.md` §4.1 (`T8`): выделение связи не сериализуется; аналогично для нод — выделение не сериализуется в текущей версии |
| Динамическое изменение размера миникарты | Миникарта (`width`, `height`) | Возможность изменения размера через настройки или через drag за край миникарты; сохранение размера в `.canvas` или в SQLite (`sessions`) | `SPEC.md` §6.1: миникарта — фиксированный размер (`220 × 140`); нет механизма изменения размера |
| Скрытие / показ миникарты | Миникарта (`visible` / `hidden`) | Возможность скрыть / показать через хоткей или через меню (`T17`: ПКМ-меню); сохранение состояния в `.canvas` или в SQLite (`sessions`) | `ACCEPTANCE.md` §5.1, п. 1: миникарта всегда видна (если не скрыта автоматически при минимальном размере окна) |

## 9. Проверка для каждой будущей фичи миникарты (чек-лист)

- [ ] Новая фича не ломает рендер миникарты (`minimap_pass.rs`) для текущих условий (`< 500` нод с рёбрами, `≥ 500` нод без рёбер).
- [ ] При добавлении новых визуальных элементов (подсветка, рамка, цвет) — учитывается ограничение производительности (`< 2 мс` для миникарты).
- [ ] При изменении поведения миникарты (навигация, панорамирование) — не конфликтует с текущими жестами (`клик` в центр ноды, `drag` viewport).
- [ ] При интеграции миникарты с другими интерфейсными объектами (`поиск`, `связи`, `выделение`) — учитывается, что миникарта — это временное UI-состояние, которое не сериализуется (кроме `brokenLink` — красный цвет, который отображается, так как это состояние `.canvas`).
- [ ] При изменении размера или позиции миникарты — учитывается ограничение (`220 × 140`, отступ `16 px`, правый нижний угол) и поведение при минимальном размере окна (`скрывается` или `клампится`).
- [ ] При добавлении новых фич (например, динамическое включение рёбер или постоянное выделение) — документируется изменение ограничений или поведения миникарты в этом документе (`docs/interface-objects/minimap.md`) и в `docs/ACCEPTANCE.md` (если это влияет на ручную приёмку).
- [ ] Журнал (`tracing`) содержит смысловой маркер для новой фичи (`ACCEPTANCE.md` §12.1` — пример для `T15`–`T17`).
