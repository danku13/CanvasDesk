# Галерея схем (`scheme-gallery`) — интерфейсный объект

Документ по FR-049 (T3 PRD-0008): модальная галерея встроенных шаблонов
готовых схем (ноды + value-связи + Numi-расчёты) и empty-state пустого
канваса. Фиксирует состояние v1, входы, поведение и инварианты.

---

## 1. Определение

Галерея — модальная screen-space панель по центру вьюпорта (паттерн
палитры `template_ui` и модалки настроек FR-039): шапка со счётчиком и
кнопкой «×», поле фильтра, чипы категорий («Все» + уникальные категории
реестра), строки схем (название, описание, «ноды: N, связи: M»),
футер-подсказка. Открытая галерея блокирует ввод канваса; клик мимо
панели закрывает. Empty-state — карточка «Начните с шаблона» по центру
при пустом канвасе (US-1 PRD-0008): кнопки «Открыть галерею» (акцент) и
«Пустой холст» (скрыть до следующего опустошения).

**Границы ответственности:**
- `canvas-core/src/schemes.rs` (чистая модель данных): `SchemeManifest`
  (двуязычные поля, `content.nodes[]/edges[]`), валидатор
  (`SchemeValidationError`), `SchemeRegistry::embedded()` —
  `include_dir!` + `OnceLock`, API `list/get/by_category`.
- `canvas-scene/src/scheme_apply.rs` (чистый инстансер):
  `instantiate_scheme` — ремап id (`note-N`/`group-N`, рёбра `edge-N`),
  bbox → origin, value-рёбра (`FlowKind::Value`).
- `canvas-app/src/scheme_gallery_ui.rs` (чистая раскладка/состояние):
  `SchemeGalleryState`, `rows` (фильтр+категория), `layout` (кламп к
  вьюпорту — инвариант 320×240), hit-тесты, `empty_card_rect`.
- `canvas-app/src/app.rs` (рендер/ввод): оверлеи, клавиатура, клики,
  `apply_scheme` (один undo-шаг → `recompute_flow` → zoom-to-fit → тост).

## 2. Входы (4 моста онбординга, F-6/F-8 PRD-0008)

1. **Empty-state пустого канваса** — кнопка «Открыть галерею».
2. **Меню «?»** (FR-031) — пункт «Галерея схем».
3. **Шаг 7 карусели онбординга** (FR-028) — CTA «Попробовать»
   (`OnboardingStep.action_key`, резервация v1 задействована): тур
   завершается, галерея открывается.
4. **Ctrl+T** — тогл галереи (кириллическая «е» — та же клавиша).

Web-порт: `?template=<id>` — авто-вставка схемы на первом кадре
(`App::set_pending_scheme`); неизвестный id — тост «Схема не найдена»,
канвас не меняется (US-5).

## 3. Поведение

- **Выбор схемы**: клик по строке открывает схему немедленно;
  ↑/↓ + Enter — клавиатурный путь.
- **Открытие** (`apply_scheme`): инстанс в центр вьюпорта, ровно один
  undo-шаг (Ctrl+Z возвращает канвас целиком — G3), zoom-to-fit bbox,
  тост «Схема добавлена».
- **Коллизии id исключены**: ремап через генератор свободных id
  (образец `next_free_id`); value-рёбра ссылаются только на ноды схемы
  (US-3 AC-3.3).
- **Фильтр/категории**: печатаемый символ — подстрочный фильтр по
  названиям/описаниям (RU/EN), чип — тогл категории, Backspace — стирание.
- **Esc** — закрыть галерею; ввод канваса под панелью заблокирован.

## 4. Инварианты

- I-G1: форматы `.canvas` не расширяются — схемы собираются из
  стандартных text/group-нод и value-рёбер; метаданные пакета живут
  только в ресурсах.
- I-G2: 0 I/O в hot path — реестр разбирается один раз (`OnceLock`);
  ассеты компилированы в бинарник (wasm, без сети).
- I-G3: цвета — только слоты `ThemeColors`/пресеты JSON Canvas `1..6`
  (токен-линт PRD-0006); hex в схемах запрещён валидатором.
- I-G4: лимиты пакета ≤ 200 нод / ≤ 400 рёбер; вставка ≤ 50 мс на
  200 нод (G7, release-замер).

## 5. Стартовый набор (6 схем, 4 категории — oracle-тесты + инварианты v2)

Контент v2 (переделка по запросу владельца 2026-09-22, PRD-0008 §7.2.1
«шаблон = витрина фич»): в каждой текстовой ноде — заголовок-объект
(первая проза-строка, основа адресов «Объект.Поле» в main stage) и
пояснение, что за значение и в каких единицах; ≥1 пучок из ≥2 рёбер одной
упорядоченной пары с адресацией истока (клик → main stage, FR-042); ≥1
нода с ≥3 инцидентными value-рёбрами (fan-in/fan-out); адресация значений
(`fromOutput`/`fromLine`/`toParam` — именованные выходы, построчные
истоки, проливание в `$параметр`); цепочка значений 2–4 хопа с ветвлением
(дерево происхождения PRD-0007 получит ветки, а не пару); живость без
красных строк. Инварианты фиксированы автотестами `scheme_apply`
(`every_text_node_is_documented`, `every_scheme_opens_main_stage`,
`every_scheme_has_multi_connected_nodes`, `schemes_cover_addressing_features`,
`schemes_have_deep_value_chains`, `schemes_never_show_red_lines`,
`every_scheme_invites_to_edit`, `capacity_service_triggers_bottleneck_analysis`).
