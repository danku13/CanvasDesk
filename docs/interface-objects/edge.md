# Связь (`edge`) — интерфейсный объект

Документ для последовательного расширения функционала связей между нодами. Фиксирует текущее состояние (`T8`), интерфейс взаимодействия, ограничения и точки входа для новых фич (`T23` и будущих).

---

## 1. Определение

Связь (`edge`) — объект `.canvas`, который соединяет две ноды (`fromNode` → `toNode`). Связи хранятся отдельно от нод (`nodes` vs `edges` в `.canvas`), хотя визуально «привязаны» к портам нод (`fromSide`, `toSide`).

**Ключевое архитектурное решение (`SPEC.md` §5.1`):** удаление ноды **не удаляет автоматически** связи с ней — связи остаются «висящими» (в текущей реализации это может приводить к некорректному рендеру, но не к панике). Это осознанное решение для сохранения контекста; восстановление связи при восстановлении ноды — ручное или через будущий механизм (`T18`, `T23`).

---

## 2. Структура данных (`.canvas`)

```json
{
  "id": "e1",
  "fromNode": "n2",
  "fromSide": "right",
  "toNode": "n1",
  "toSide": "top",
  "label": "блокирует"
}
```

| Поле | Тип | Обязательность | Ограничение | Точка входа для фичи |
|---|---|---|---|---|
| `id` | `string` | Обязательное | Уникально в `.canvas` | Авто-генерация ID по UUID v4 (будущая фича) |
| `fromNode` | `string` (id ноды) | Обязательное | Должна существовать в `nodes`; при удалении ноды — «висящая» связь | Автоматическое удаление или архивирование связей при удалении ноды |
| `fromSide` | `"top"` / `"right"` / `"bottom"` / `"left"` | Обязательное | Фиксированные 4 стороны; порт появляется при hover на ноду | Свободные порты (не привязанные к стороне) или множественные порты на одной стороне |
| `toNode` | `string` (id ноды) | Обязательное | Аналогично `fromNode` | Связь «без ноды» с одной стороны (будущая фича: «к источнику» или «к заметке-контексту» без конкретной ноды) |
| `toSide` | `"top"` / `"right"` / `"bottom"` / `"left"` | Обязательное | Аналогично `fromSide` | ~~Динамическое определение стороны (`auto`)~~ — реализовано в CR-008: авто по умолчанию, `canvasdesk.pin_ports` фиксирует конец |
| `label` | `string` | Опциональное | Редактируется инлайн (двойной клик по линии); пустая строка — связь без текста | Форматирование `label` (gfm, жирный, курсив, ссылки), привязка `label` к внешнему `.md`-файлу |

## 3. Визуальная структура связи (рендер)

```
Связь (кривая Безье + стрелка на конце toNode)
├── Линия (1 px, цвет по умолчанию или по типу связи — в будущем)
├── Стрелка (на конце `toNode`, указывает на порт `toSide`)
├── Текст `label` (по центру линии, читаемый при любом угле)
├── Область клика (~6 px от линии, для выделения и удаления)
└── Выделение (при клике или при hover на ноду-источник / ноду-цель)
```

**Текущее поведение (`SPEC.md` §5.1`):**
- Линия — Безье, перерисовывается при перемещении любой из нод в реальном времени.
- Порты подключения (CR-008): по умолчанию — авто, кратчайший путь между нодами
  (пересчёт при drag/авто-раскладке/загрузке); закреплённый конец
  (`canvasdesk.pin_ports`) следует сохранённой стороне.
- Стрелка — на конце `toNode`, указывает на `toSide`.
- `label` — инлайн-редактируемый; Enter сохраняет, Esc отменяет.
- Клик + Del → удаление связи (без подтверждения).
- Выделение связи → подсветка линии (цвет выделения, не влияет на `.canvas`).

## 4. Взаимодействия со связью (таблица действий)

| Действие | Жест / триггер | Обработчик (текущий) | Ограничение (`ACCEPTANCE.md` §4.1) | Точка входа для фичи |
|---|---|---|---|---|
| Создание | Drag от порта ноды (`hover` → 4 порта видны; зона захвата — CR-003) → отпуск на другой ноде | `canvas-app` event loop → добавление в `.canvas` (`edges`) → автосейв (2 с) | Связь не может быть «без ноды»; отпуск в пустоту — отмена | Связи с «висящим» концом, множественные связи между нодами |
| **Перепривязка (CR-002)** | Клик по линии (выделение; на концах хэндлы) → drag хэндла → отпуск на другой ноде | `retarget_edge`: `fromNode`/`toNode` + сторона обновляются, `id`/`label`/цвет/стиль сохраняются; линия скрыта на время drag (резиновая — от неподвижного конца) | Отпуск в пустоту/на противоположную ноду — отмена без изменений; петли запрещены | Перепривязка обеих сторон одновременно, перетаскивание всей связи |
| Редактирование `label` | Двойной клик по линии связи | Инлайн-редактор поверх линии; Enter сохраняет в `.canvas` | `label` — строка без разметки | Форматирование `label` (gfm, цвет, ссылки) |
| Удаление | Клик (выделение) + Del или через ПКМ-меню связи | Удаление из `.canvas`; связи не удаляются автоматически при удалении ноды | Нет «мягкого» удаления | Мягкое удаление, Ctrl+Z, автокаскад |
| Перемещение ноды с связями | Drag ноды (ЛКМ); при мультивыделении (CR-001) — весь набор | Перерисовка Безье в реальном времени; текст `label` остаётся читаемым; порты связей перепрыгивают на кратчайший путь (CR-008) | При больших сценах рёбра визуально «запутываются» — CR-008 снимает часть случаев | Оптимизация рендера, динамическая подсветка (`T23` — влито) |
| **Порты: закрепление (CR-008)** | ПКМ по связи → палитра → группа «Порты»: «Авто (кратчайший путь)» / «Исток: закрепить» / «Сток: закрепить»; MCP `edge_ports {id, pin}` | Закрепление фиксирует текущую эффективную сторону в `fromSide`/`toSide` (WYSIWYG) и ставит `canvasdesk.pin_ports`; «Авто» снимает пины; undo-шаг (FR-006) | Пин не пишет сторону сам — WYSIWYG-фиксация в палитре/MCP | Закрепление отдельных портов визуально (точки), подсветка закреплённых портов на ноде |
| Выделение связи | Клик в пределах ~6 px от линии | Подсветка линии + хэндлы концов (CR-002) + опциональное выделение связанных нод | Выделение не сериализуется | Постоянное выделение, выделение по фильтру |

## 5. Состояния связи (что влияет на визуал и поведение)

| Состояние | Где хранится | Как влияет | Точка входа для фичи |
|---|---|---|---|
| `label` (текст) | `.canvas` (`edge.label`) | Отображается по центру линии; пустая строка — связь без текста | Форматирование, привязка к `.md`, динамическое изменение `label` по изменению нод |
| `fromSide` / `toSide` (сторона порта) | `.canvas` (`edge.fromSide`, `edge.toSide`) | Закреплённый конец — точка привязки Безье; при перемещении ноды линия следует за портом | Множественные порты на одной стороне |
| Порты: авто/закреплено (CR-008) | `.canvas` (`canvasdesk.pin_ports`: `["from"]`/`["to"]`/`["from","to"]`; отсутствие — оба авто) | Авто-конец: сторона = кратчайший путь из `best_sides` (пересчёт на каждом кадре); закреплённый — сохранённая сторона. «Авто» не переписывает `fromSide`/`toSide` в файле | Подсветка закреплённых портов, глобальный тумблер в настройках |
| Выделение связи (временное) | `canvas-app` (UI-state) | Подсветка линии; опциональное выделение связанных нод | Постоянное выделение в `.canvas`, выделение связей при фильтрации (`T14`) |
| «Висящая» связь (`fromNode` или `toNode` отсутствует в `nodes`) | `.canvas` (`edge.fromNode` / `toNode` ссылается на несуществующую ноду) | Рендер: линия отображается без одной из стрелок; взаимодействие ограничено (нельзя редактировать `label` через двойной клик, так как нет ноды-источника или ноды-цели) | Автоматическое удаление или восстановление связи при удалении / восстановлении ноды; ручное «переподключение» через ПКМ |
| Тип потока (FR-014) | `.canvas` (`canvasdesk.flow.kind`: `"value"` / `"control"`; отсутствие поля — `control`) | `value` — бирюзовая линия (FLOW_EDGE_COLOR, если пользователь не задал цвет), лейбл дополняется значением источника (`label · 1000 rps`); значение доступно в формуле downstream как `$in`/`$1..$N`. `control` — визуальная связь (текущий рендер). Тогл — палитра связи (группа «Поток») или MCP `flow_set_kind`; создание value-ребра — `Shift + drag` от порта. Value-ребро, замыкающее цикл, не создаётся: диалог «Обнаружен цикл …» с предложением control-связи (UI) или isError (MCP) | Поток значений downstream, доменные функции (FR-015), what-if (FR-017) |

## 6. Ограничения и известные проблемы (`ACCEPTANCE.md` §10, `TASKS.md`)

- Связи не удаляются автоматически при удалении ноды (`TASKS.md`: T8 — это осознанное решение для сохранения контекста; восстановление связи при восстановлении ноды — ручное).
- Связи не могут быть «без ноды» с одной стороны (текущая реализация требует `fromNode` и `toNode` в `.canvas`; «висящие» связи возникают только при удалении ноды, не при создании).
- Динамическая подсветка связей (`T23`) — влита (brainstorm-focus); связи подсвечиваются при hover/выделении с «дыханием».
- Перепривязка без удаления — влита (CR-002): хэндлы концов выделенной связи, drag к новой ноде; зона захвата хэндлов — как у портов (CR-003).
- Нет форматирования `label` — `label` — обычная строка, без разметки (`gfm`), цвета или ссылок.
- Рендер связей в больших сценах (> 500 нод) — линии могут «запутываться» визуально; оптимизация (`T13`) частично решает это.

## 7. Точки входа для новых фич (последовательно, без нарушения текущего функционала)

| Фича | Привязка к интерфейсу связи | Что нужно изменить | Где документировано как ограничение |
|---|---|---|---|
| Динамическая подсветка связей (`T23`) | Связи (`edges`): цвет/толщина линии в зависимости от состояния связанных нод или при hover | Новый модуль `highlight.rs` или расширение `edgegeom.rs`; привязка к состоянию ноды (`brokenLink`, `selected`, `hover`) | `TASKS.md` T23 (не влит) |
| Форматирование `label` | `label` связи (`edge.label`) | Расширение инлайн-редактора (`glyphon` + `cosmic-text`) для поддержки `gfm` в `label`; сериализация форматирования в `.canvas` (новое поле или расширение `label`) | `TASKS.md` T7 (форматирование — для текстовых нод; для связей — будущая фича) |
| Связи с «висящим» концом | `fromNode` или `toNode` в `.canvas` | Разрешение создания связи с одной стороны (например, «к заметке-контексту» без конкретной ноды-цели); рендер линии с одной стрелкой или без стрелки | `SPEC.md` §5.1 (текущая структура требует обе ноды) |
| Автоматическое удаление связей при удалении ноды | Связи (`edges`) и ноды (`nodes`) | При удалении ноды — проход по `edges`, удаление связей с `fromNode` или `toNode` = удалённая нода; сохранение в `.canvas` через автосейв | `TASKS.md` T8 (осознанное решение — не удалять автоматически; изменение требует решения) |
| Постоянное выделение связей | `edges` (`.canvas` или UI-state) | Новое поле `selectedEdges` в `.canvas` или в UI-state; сериализация при автосейве; рендер подсветки при загрузке `.canvas` | `ACCEPTANCE.md` §4.1 (выделение связи не сериализуется) |
| Связи как «отношения» с типом | `edges` (`.canvas`) | Новое поле `type` (`"blocks"`, `"depends"`, `"references"`); визуальное различие (цвет, стиль линии: сплошная/пунктирная); фильтрация связей по типу (`T14`) | Будущая фича; не в `TASKS.md` или `SPEC.md`. Частично перекрыто FR-014 (`canvasdesk.flow.kind` value/control) |

## 8. Проверка для каждой будущей фичи связи (чек-лист)

- [ ] Новая фича не ломает сериализацию `.canvas` для других приложений (`JSON Canvas 1.0` — связи (`edges`) — стандартная часть spec; добавление новых полей — через `canvasdesk`-расширение или по конвенции spec).
- [ ] Новое состояние связи либо сериализуется в `.canvas`, либо явно документируется как временное (UI-state).
- [ ] Рендер связи учитывает новые визуальные элементы (цвет, толщина, стиль линии) без конфликта с текущим рендером Безье.
- [ ] При добавлении нового взаимодействия (например, форматирование `label`) — не конфликтует с текущим инлайн-редактированием (`Enter` сохраняет, `Esc` отменяет).
- [ ] При изменении поведения связей при удалении нод — учитывается осознанное решение (`TASKS.md` T8: связи не удаляются автоматически) и документируется как изменение этого решения.
- [ ] Журнал (`tracing`) содержит смысловой маркер для новой фичи (`ACCEPTANCE.md` §12.1` — пример для `T8`–`T17`).
- [ ] Этот документ (`docs/interface-objects/edge.md`) обновлён: добавлен раздел или строка в таблице состояний / взаимодействий.
