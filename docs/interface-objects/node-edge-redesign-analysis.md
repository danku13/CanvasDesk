## 1. Резюме

Жалоба владельца декомпозируется в четыре измеримых дефекта текущей модели
связывания, каждый из которых подтверждается кодом и документацией:

1. **Три независимые системы точек подключения** на одной ноде: 4 симметричных
   side-порта (`build_port_instances`, cards.rs:1229), построчные порты на
   правом крае (FR-025, text.rs:1610), якоря параметров на левом крае шаблонов
   (FR-050 Н2, text.rs:1656). Три визуальных языка, три набора правил видимости,
   три источника hit-теста.
2. **Тип связи скрыт до отпускания**: side-порт без типа создаёт control-ребро;
   value-ребро требует невидуемого модификатора `Shift+drag` (FR-014). Пользователь
   узнаёт, какую связь создал, только постфактум — по цвету линии.
3. **Направление не читается с ноды**: 4 симметричных порта — наследие
   Obsidian-канваса (визуальные связи), но после пивота ADR-0007 продукт —
   dataflow-инструмент, где семантика входа/выхода уже есть (якоря слева,
   построчные справа, `best_sides` CR-008) и противоречит симметрии side-портов.
4. **Двойная запись жестов**: одна и та же операция «связать ноды» достигается
   разными жестами с разной семантикой (drag от side-порта, drag от построчного
   порта, drag до якоря, drop на тело, Shift-модификатор) — choose-меню Н2
   сглаживает, но не устраняет.

Анализ всех use case (§3, 26 кейсов в 4 группах) выводит 12 требований (§4),
из которых сформулированы **три варианта** редизайна (§5):

- **В-А «Двухконтурный порядок»** — консервативный: раздать роли двум системам
  (рейлы расчётных нод + hover-точки контентных), минимальная миграция;
- **В-B «Единый порт-рейл»** — классический node-editor (UE/Blender/n8n):
  одна система типизированных портов, входы слева/выходы справа, всегда видны;
- **В-C «Кромки-зоны»** — контекстный: портов в покое нет, кромки ноды
  кодируют вход/выход, точки раскрываются в drag, семантика — от цели drop.

Рекомендация (§8): **В-C как целевой UX**, с вливанием элементов В-B
(лейблы слотов в L2) и анатомии A–E из PRD-0004 (ортогональна портам);
В-А — как первый миграционный шаг (смерть `Shift+drag`, типизация
сток-точек — можно сделать немедленно, до выбора варианта).

## 2. Текущее состояние (факт-карта)

### 2.1 Три системы точек подключения

| Система | Где | Видимость | Что создаёт | Код |
|---|---|---|---|---|
| **Side-порты** (4 шт.) | середины 4 сторон любой ноды (кроме group) | при hover ноды | drag → control-ребро; `Shift+drag` → value-ребро (нода целиком) | `build_port_instances` cards.rs:1229; диаметр `port_dot_diameter` 10–26 px следует зоне CR-003 |
| **Построчные порты** (FR-025) | правый край, у каждого ряда результата | при включённом флаге `line_ports` (настройки «Связи и порты») | всегда value-ребро с `fromLine`; финальная строка — бирюзовая, промежуточные — серо-голубые | `line_ports` text.rs:1610; hit `line_port_hit` app.rs |
| **Якоря параметров** (FR-050 Н2) | левый край шаблонной ноды, у ряда каждого параметра | маленькие нейтральные кружки всегда (у шаблонов); растут при hover ноды | цель drop для value-drag → ребро с `toParam`; подсветка совместимости единиц Н5 (яркий крупный / тусклый маленький) | `param_ports` text.rs:1656; `build_param_port_instances` cards.rs:1318 |
| Хэндлы концов связи (CR-002) | на концах выделенной связи | при выделении связи | drag хэндла → перепривязка `retarget_edge` | `build_edge_handle_instances` cards.rs:1259 |

### 2.2 Жесты и их семантика (сегодня)

| Жест | Результат | Комментарий |
|---|---|---|
| Drag от side-порта → нода | control-ребро | «простая связка нод» |
| `Shift`+drag от side-порта → нода | value-ребро (нода целиком) | модификатор не имеет никакого визуального аффорданса |
| Drag от построчного порта → якорь параметра | value-ребро `fromLine`+`toParam` (проливание) | требует флага `line_ports` |
| Drag от построчного порта → тело ноды | value-ребро `fromLine` → `$in`/`$1..$N` | drop на тело vs на якорь — тонкая разница |
| Drag от side-порта / построчного → пустота | отмена | ghost-нода не предлагается |
| Drop value-drag на ноду с несколькими параметрами | choice-меню Н2 (выбор параметра) | W-AMBIGUOUS-SRC для drag от текстовой ноды целиком |
| Клик по линии → drag хэндла → нода | перепривязка конца | CR-002 |
| ПКМ по линии | палитра связи: Стиль/Толщина/Цвет/Поток (тогл control↔value)/Порты | |
| Drag ноды с `Ctrl`? — нет; drag ноды | перемещение + живая перестройка рёбер | стороны пересчитываются CR-008 |

### 2.3 Кодировка типов и направлений

- Тип ребра виден только **после** создания: value — бирюза `FLOW_EDGE_COLOR`,
  control — цвет темы; unmapped — янтарный пунктир (Р-3/FR-045).
- Направление читается только **стрелкой** на конце `toNode`.
- Тип порта до соединения не кодируется ничем (PRD-0004 §2.2 п.2 это
  фиксирует как пробел; P2 практики — цвет+форма сокета — не реализованы).
- Слоты входов (`$in`/`$1..$N`/`toParam`) не имеют видимой привязки к рядам
  приёмника (PRD-0004 §2.2 п.3) — частично закрыто авто-строками FR-050 Р-4.

### 2.4 Декомпозиция жалобы владельца

| Фраза владельца | Дефект в модели | Подтверждение |
|---|---|---|
| «не нравится как выглядит их UI» | три визуальных языка точек; hover-эффект «рассыпания» (4 side + N line + M param одновременно); симметрия side-портов спорит с лево-право семантикой якорей | §2.1–2.3 |
| «UX работы со связыванием» | тип скрыт до отпускания; `Shift` невидим; drop на тело vs на якорь — разная семантика без подсказки | §2.2 |
| «отдельные точки для значений и отдельные точки для простых связок» | side-порты (control-мир) и line/param-порты (value-мир) спроектированы тремя разными волнами фич (FR-014 → FR-025 → FR-050) без единого контракта | история фич в §2.1 |

## 5. Три варианта

Общее для всех: анатомия зон A–E из PRD-0004 (хедер-идентичность / тело /
полоса результата D / статусный слой E) — она **ортогональна** модели портов
и вливается в любой вариант; типизация кодируется цветом+формой
(бирюза○ = value, серый▢ = control, янтарь⌇ = unmapped); жесты правки (R-9)
и формат `.canvas` (R-10) не трогаются.

### 5.1 В-А «Двухконтурный порядок» (консервативный)

**Концепция.** Признать, что в продукте два класса нод — «расчётные»
(шаблоны, заметки с формулами) и «контентные» (простые заметки, file) — и
раздать им системы явно, наведя порядок в каждой.

- **Расчётные ноды:** порт-рейлы по PRD-0004 — входы слева (якоря
  параметров/слотов `$in`/`$1..$N`/`toParam` с лейблами на hover), выходы
  справа (узловой, построчные FR-025, именованные FR-029). Порты видимы
  на L1, у построчных — точки у рядов, узловой — у полосы D.
- **Контентные ноды:** ровно 2 hover-точки (лево/право-центр) для
  control-связей; value от контентных невозможен (они не в потоке).
- `Shift+drag` умирает: тип задаётся источником (с какой точки тянул).
- Типизация точек: бирюза○/серый▢.

| Плюсы | Минусы |
|---|---|
| Минимальная миграция (пере-использование FR-025/050-механики) | **Две системы портов остаются** — прямое продолжение жалобы владельца, только «покрашенное» |
| MCP изоморфен уже сегодня (R-6 ✓) | SA видит «инженерные» рейлы на расчётных нодах сразу (R-12 ~) |
| Риск регрессий низкий (hit-механика та же) | Граница классов размыта: заметка с одной формулой — уже расчётная? |

**UC-эффект:** закрывает R-2, R-3, R-6, R-7; R-1 — только внутри класса; R-4/R-12 — частично.

### 5.2 В-B «Единый порт-рейл» (классический node-editor)

**Концепция.** Все ноды — один контракт UE/Blender/n8n: входы слева,
выходы справа, порты всегда видимы (L1+), тип — цвет+форма сокета.
PRD-0004 доведён до конца: рейлы — часть анатомии, а не артефакт связей.

- **Каждая нода** (кроме group): левый рейл входов + правый рейл выходов.
  Control-связи — тоже порты: пара «вход/выход хедера» (▢ у углов хедера A).
- Построчные выходы — точки у рядов результата; входные параметры — точки
  у рядов параметров; лейблы слотов на hover (F-5 PRD-0004).
- Один жест: drag выход→вход. Тип определён парой портов ещё до касания.
- File-нода: только control-пара (или ноль точек — настройка); ссылочные
  связи file→file получают первый-class жест.
- Пучки FR-042: hover агрегата подсвечивает кольца портов концов (уже
  специфицировано R6 FR-044 — ложится идеально).

| Плюсы | Минусы |
|---|---|
| **Одна система** — R-1 ✓ радикально | Шум в покое: 100+ нод × постоянные рейлы (R-4 ✗, лечится LOD: L0 — без портов) |
| Тип и направление — до жеста (R-2/R-3 ✓✓) | Заметки/mindmap выглядят «инженерно» (R-12 под риском: SA-линза §7) |
| Индустриальный стандарт — TA/EA узнают паттерн мгновенно | Самая дорогая миграция: вся геометрия точек, hit, z-порядок, LOD |
| Красиво ложится на main stage/пучки (R-8 ✓) | CR-008 авто-стороны теряют смысл (стороны фиксированы) — ломка пинов (см. Q5) |

**UC-эффект:** R-1, R-2, R-3, R-6, R-8 ✓; R-4 — только LOD-компенсацией; R-12 — под вопросом.

### 5.3 В-C «Кромки-зоны» (контекстные порты)

**Концепция.** Портов как стоящих объектов нет вообще. Кромки ноды —
зоны: **левая кромка = вход, правая = выход** (вертикально — вся кромка).
Конкретные точки раскрываются только в момент взаимодействия:

- **Покой:** чистая карточка, ноль точек (любая плотность сцены — R-4 ✓✓).
- **Hover:** кромки дышат — правая подсвечивается бирюзой (у расчётных —
  выход), левая — нейтрально-серым (вход). У контентных нод обе кромки
  серые (control-мир).
- **Начало drag от кромки:** вдоль неё раскрываются конкретные точки
  (у рядов: построчные/именованные выходы справа; параметры/слоты слева —
  motion-раскрытие ~150 мс, токены motion.json). Тяну за кромку в целом —
  взял «узловой» выход (полоса D).
- **Подлёт к цели:** у цели-ноды раскрываются её входы (зеркально);
  совместимые параметры ярче (Н5 уже реализован — R-8 ✓).
- **Семантика — от цели drop:** на точку параметра → проливание `toParam`;
  на ряд-выход-истока… (исток уже выбран точкой старта); на кромку входа →
  value в `$in`; **на тело ноды → choice-меню Н2** (обобщённое: «просто
  связь / передать значение / выбрать параметр») — один и тот же жест
  покрывает UC-C1–C5 (R-5 ✓✓).
- **Direction:** лево≠право топологически (R-3 ✓); drag «справа налево»
  физически возможен (линия идёт как угодно), но зоны подчёркивают поток.
- Исток-симметрия R-7: у истока после создания — бирюзовая кромка/точка
  + тост Н9-6 уже есть; добавляется мини-бейдж исхода у ряда.

| Плюсы | Минусы |
|---|---|
| Ноль шума в покое — «простота восприятия» владельца буквально | Тип не виден ДО касания кромки (R-2 частично: цвет кромки при hover + Н5-подсветка целей) |
| **Один жест на всё** (R-5 ✓) + choice-меню уже существует (Н2) | Обязательна анимация раскрытия (motion-контракт, риск перфа — митигируется токенами) |
| Контентные ноды не «инженереются» (R-12 ✓) | Обучение жесту: первый drag должен «показать» точки (обучающая подсветка/онбординг-шаг) |
| Миграция средняя: рендер точек уже есть (FR-025/050), меняется модель видимости/жеста | Больше UI-состояний (покой/hover/drag-исток/drag-цель) — тест-матрица шире |

**UC-эффект:** R-4, R-5, R-12, R-8 ✓; R-1 ✓ (одна концепция — «кромка+точка»); R-2/R-3 — на 90% (кромка при hover); R-6 ✓ (точки те же).
