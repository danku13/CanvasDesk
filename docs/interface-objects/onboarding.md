# Онбординг (`onboarding`) — интерфейсный объект

Документ по FR-028: тур по функциям сервиса при первом запуске. Фиксирует
состояние v1 (карточки-карусель), интерфейс взаимодействия, схему конфигурации
и точку расширения v2 (демо-канвас).

---

## 1. Определение

**Действие шага (FR-049):** шаг 7 «Шаблоны нод» несёт
`OnboardingStep.action_key = Some(GALLERY_TRY)` — кнопка «Далее» на этом
шаге становится CTA «Попробовать»: тур завершается (флаг пройден),
открывается галерея схем (`scheme-gallery.md`). Резервация v1
(закомментированное `action`) задействована опциональным полем — машина
состояний не переписана.

Онбординг — модальная карусель из 8 карточек поверх затемнённого канваса
(затемнение — паттерн wheel FR-022). Показывается автоматически при первом
запуске; открытый тур блокирует ввод канваса (клики/хоткеи/ПКМ глотаются),
выход виден всегда — «Пропустить» в правом верхнем углу карточки (NN/g).
Перезапуск в любой момент — меню «?» → «Пройти онбординг» (FR-031).

**Границы ответственности:**
- `canvas-core/src/settings.rs`: поля `onboarding_done: bool` /
  `onboarding_defers: u8` (`#[serde(default)]`, старые конфиги читаются),
  `ONBOARDING_MAX_DEFERS = 3`, кламп при загрузке (паттерн `port_zone_px`).
- `canvas-app/src/onboarding_ui.rs` (чистая модель): `ONBOARDING_STEPS` (8),
  `should_show_onboarding` (таблица решений), `OnboardingState` (next/prev с
  клампом, подпись «Далее»/«Готово»), геометрия карточки/кнопок/точек с
  клампом к окну, hit-тесты.
- `canvas-app/src/main.rs` (рендер/ввод): `onboarding_overlay`, обработка
  кнопок/Esc, `defer_onboarding`/`complete_onboarding` (+save).

## 2. Схема `config.toml` (FR-028)

| Поле | Тип/дефолт | Смысл |
|---|---|---|
| `onboarding_done` | `bool`, `false` | Тур пройден до конца («Готово»): авто-показ выключен навсегда, ручной вход остаётся |
| `onboarding_defers` | `u8`, `0` | Сколько раз подряд тур отложен «Пропустить»/Esc; кламп `[0, 3]` при загрузке |

**Таблица решений авто-показа** (`should_show_onboarding`, юнит-тест всех
комбинаций): `!done && defers < 3 → true`; `defers ≥ 3` при `!done` → `false`
(тишина); `done = true` → `false` при любых defers. Ручный запуск из меню «?»
гейтом не является (явное намерение) и счётчик не инкрементирует.

## 3. Карусель v1 (8 шагов, скоуп — база + расчёты + шаблоны)

1. Приветствие + навигация (пан/зум/миникарта, `.canvas`-файл);
2. Заметки (двойной клик, markdown, цвет);
3. Связи (порты, drag, перепривязка);
4. Группы и отмена (рамка, Ctrl+G, Ctrl+Z/Y);
5. Формулы Numi (присваивание, единицы, подсказки);
6. Поток значений ($in/$N, value-связи, живой пересчёт);
7. Шаблоны (Ctrl+P, wheel Shift+клик, параметры);
8. Финал: «?» — документация и повтор тура, F1 — хоткеи.

Переходы: «Далее» (последний шаг — «Готово»: `done = true` + save);
«Назад» — со 2-го шага; «Пропустить»/Esc — `defers += 1` (кламп 3) + save;
прогресс-точки (текущая — акцент). Клавиатура: только Esc (v1).

## 4. Инварианты (юнит-тесты `onboarding_ui` + `settings`)

- Триггер — таблица решений (все комбинации done × defers);
- Карусель: `step ∈ [0, 7]` после любых next/prev; «Назад» на первом шаге
  отсутствует (hit-тест None); подпись меняется только на последнем шаге;
- Кламп карточки: целиком в окне на любом viewport (включая 320×240), кнопки
  внутри карточки;
- Схема: старый конфиг без полей → done=false/defers=0 (тур показать);
  `defers = 99` → кламп к 3; round-trip дефолтов стабилен.

## 5. v2 — демо-канвас (отдельный FR/коммит, вне объёма v1)

Финальный шаг раскрывается в живой сценарий: демо-сцена (заметка с формулой,
value-связь) и чек-точки «сделай сам» («создай заметку двойным кликом» ✓).
Каркас v1 это предусматривает: шаги допускают опциональное действие
(`Option<DemoAction>` — структура шага уже несёт поля для расширения), машина
состояний не переписывается.
