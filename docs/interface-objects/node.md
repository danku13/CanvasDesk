# Нода (`node`) — интерфейсный объект

Документ для последовательного расширения функционала ноды. Каждый раздел фиксирует: текущее состояние, интерфейс взаимодействия, ограничения и точки входа для новых фич.

---

## 1. Определение

Нода — базовый элемент канваса. Представляет либо файл (`type: "file"`), либо текстовую заметку (`type: "text"`), либо группу (`type: "group"`), либо виджет (`type: "widget"`, M5). Геометрия (x, y, width, height) хранится в `.canvas`-файле (JSON Canvas 1.0) и является источником истины.

**Границы ответственности:**
- Модель (`canvas-core`): структура данных, сериализация, spatial index.
- Рендер (`canvas-render`): визуализация в зависимости от LOD (zoom) и состояния (brokenLink, highlight).
- Shell (`canvas-shell`): тамбнейлы, drag-drop, файловый вотчер, оболочка (ShellExecuteEx) для файловых нод.

## 2. Типы нод (из `docs/SPEC.md` §5.1)

| Тип | Поля в `.canvas` | Источник данных | Жизненный цикл | Точки входа для фич |
|---|---|---|---|---|
| `file` | `id`, `file` (путь), `x`, `y`, `w`, `h`, `previewState` (`thumbnail`/`live`/`none`), `brokenLink`, `color` | Файловая система (Explorer, SMB не поддерживается полноценно) | Создаётся drag-drop (T9) или из ПКМ; удаляется пользователем; при удалении файла — `brokenLink: true`, карточка остаётся | Живое превью (M3, T11), превью PDF/Office (T12), восстановление `brokenLink` по возврату файла (T10, T16) |
| `text` | `id`, `text`, `x`, `y`, `w`, `h`, `color` (`"1"`–`"6"` или `null`), `collapsed` (FR-011), `canvasdesk.expr` (FR-013) | Пользователь (инлайн-редактирование) или ПКМ-меню | Создаётся ПКМ / двойным кликом / из текста; текст редактируется двойным кликом или фокусом | Форматирование (gfm, палитра ПКМ — T7), resize (T7), Numi-формулы (FR-013 — влито), поток значений (FR-014 — влито), синхронизация с внешним `.md` (будущая фича) |
| `group` | `id`, `label`, `x`, `y`, `w`, `h` | Пользователь | Группирует ноды: создание по Ctrl+G из выделения (FR-012), «втягивание» ноды drag-ом на группу с settle-анимацией (FR-012), разгруппирование через палитру | Вложенные группы (будущая фича), сворачивание/разворачивание, фильтрация содержимого |
| `widget` (M5) | `id`, `widgetId`, `props`, `canvasdesk: { widgetId, props }` | Локальный пакет в `%APPDATA%/canvasdesk/widgets/<id>/` | Устанавливается drag папки; рендерится через WebView2; при удалении пакета — нода становится «битой» | SDK (T22, T25), permissions (манифест `widget.json`), bridge (JSON-RPC), прозрачность карточки (CR-004) |

## 3. Визуальная структура ноды (LOD из `SPEC.md` §6.2)

Нода рендерится в несколько слоёв. Каждый слой — отдельная точка входа для расширения.

```
Нода (прямоугольник с тенью и скруглением)
├── Фон (цвет типа или `color` для text; CR-007: авто-контраст текста к заливке)
├── Заголовок / заголовочная полоса (FR-072: имя файла / явный заголовок
│   `canvasdesk.title` / имя шаблона-снапшота / первая строка заметки
│   [legacy-фолбэк] / подпись группы; пустой явный — плейсхолдер «Заголовок»)
├── Тамбнейл / превью / текст (в зависимости от LOD и типа)
├── Строка результата / построчные результаты Numi (FR-013/FR-014; красная при ошибке)
│   └── Триггер «?» (FR-048): у полосы результата D и у каждого построчного
│       результата — hover-пилюля «?»; клик по цифре — фолбэк-триггер (У1);
│       открывает окно проверки цепочки расчёта (explain-панель поверх канваса)
├── Маркер свёрнутой ветки mindmap (FR-011, text-ноды)
├── Рамка выделения (highlight, brokenLink — серая/красная)
├── Порты связей (4: top/right/bottom/left, видны при hover)
└── Контекстное меню (ПКМ → палитра, рендерится поверх, не входит в ноду физически)
```

**LOD по zoom (`SPEC.md` §6.2):**
- `< 0.25`: прямоугольник + иконка типа файла (без текста и текстур).
- `0.25–0.6`: + системный тамбнейл (`IShellItemImageFactory`) + имя файла.
- `0.6–1.5`: + превью содержимого (картинка, первая страница PDF через `pdfium-render`, первые N строк текста).
- `> 1.5`: живое превью с прокруткой (максимум 3 одновременно, только под курсором или в фокусе).

**Для виджета (M5, `SPEC.md` §7.6):** отдельная LOD-стратегия — при `zoom < 0.25` или вне viewport → `snapshot-текстура` (`ICoreWebView2::CapturePreview`); при `zoom ≥ 0.25` и видим → живой WebView2-инстанс.

## 4. Взаимодействия с нодой (таблица действий)

Каждое действие — это интерфейс, который можно расширять, не ломая остальные.

| Действие | Жест / триггер | Обработчик (текущий) | Ограничение (из `SPEC.md`) | Точка входа для фичи |
|---|---|---|---|---|
| Панорамирование ноды | Drag ЛКМ (за тело или заголовок) | `canvas-app` event loop → обновление `x`, `y` в модели → автосейв (2 с); при мультивыделении (CR-001) — весь набор + дети групп; порты связей перепрыгивают на кратчайший путь (CR-008); drag ноды на группу — «втягивание» с settle-анимацией (FR-012); на отпускании — snap-at-release (сетка/guides с ghost-предпросмотром в драге, двойной undo-шаг: drag + snap-коррекция; FR-038) | Во время драга перемещение свободное; привязка (сетка/guides) применяется на отпускании — FR-038, тумблеры раздела «Snap» | Реализовано (FR-038): магнитная раскладка, batch-выравнивание |
| Выделение | ЛКМ (одиночный); `Ctrl`/`Shift`+клик — тогл в набор; drag ЛКМ от пустого места — рамка (CR-001) | Рендер: подсветка рамки каждой; модель: `selected` (primary) + `selected_nodes` (набор, UI-state) | Выделение не сериализуется (источник истины — `.canvas`) | Постоянное выделение (`selected` в `.canvas`), фильтрация по выделению |
| Копирование / вставка / дублирование (FR-003) | `Ctrl+C` / `Ctrl+V` / `Ctrl+D` (кир.: с/м/в) | Внутренний буфер нодов; вставка центром bbox на курсор с новыми id; дубликат +32/+32 | Буфер — внутри приложения (НЕ системный clipboard); вставка связей между копиями — нет (только ноды) | Копирование со связями, вставка из внешних канвасов |
| Вырезание (FR-007) | `Ctrl+X` (кир. «ч») | Копирование в буфер + удаление; `Ctrl+V` — вставка; `Ctrl+Z` возвращает | Без системного буфера | Вставка со связями |
| Группирование (FR-012) | `Ctrl+G` по выделению или палитра → «Сгруппировать» | Группа с bbox по выделению; drag ноды на группу — втягивание (зона подсвечивается, settle-анимация проезда); разгруппирование — палитра группы → «Разгруппировать» | Группа — визуальный контейнер; связям и поиску не мешает | Вложенные группы, сворачивание группы |
| Список горячих клавиш (FR-004) | `F1` | Экранная панель слева по центру (23 записи), Esc — закрыть | Панель не интерактивна (строки без действий) | Интерактивные подсказки со ссылками на разделы документации |
| Редактирование текста (`text`-нода) | Двойной клик по телу или фокус через Tab | Инлайн-редактор (glyphon + cosmic-text) поверх ноды; Enter/Ctrl+Enter сохраняет, Shift+Enter — новая строка, Esc отменяет | Форматирование ограничено gfm (`T7`: `**жирный**`, `*курсив*`, `==подсветка==`, Ctrl+B/I/H) | Расширенная палитра (код, таблицы), совместное редактирование, привязка к `.md`-файлу |
| Редактирование заголовка (FR-072) | Двойной клик по шапке; палитра → «Переименовать» | Однострочный инлайн-редактор в шапке (`EditTarget::NodeTitle`): Enter — коммит, Esc — отмена, форматирования нет. У legacy-ноды prefill — производный заголовок; коммит переносит первую строку (проза, не формула) в явный заголовок — дубли в теле не остаётся. Новая заметка стартует с правки заголовка, Enter открывает тело | Заголовок — чистый текст без markdown; пустой коммит = `Some("")` (плейсхолдер, утечки нет) | Файловые ноды — переименование файла (v2), инлайн-правка имени из Explorer |
| Numi-формулы (FR-013) | Строки `имя = выражение с единицами` в тексте заметки | Построчный парсер (`canvas-core/src/expr.rs`): `rps = 1000`, `latency = 50 ms`, итог — отдельной строкой под текстом; построчные результаты с ошибками — красным | v1 — локальные переменные ноды; поток между нодами — FR-014 | what-if (FR-017) |
| Раскладка связанных (FR-010) | Палитра ноды → группа «Раскладка»: Дерево → / Дерево ↓ / Радиально | `plan_related_layout` + `apply_related_layout`: раскладывает окрестность ноды; связи следуют (CR-008 переприсоединяет порты) | Раскладка — undo-шаг (FR-006) | Силовые алгоритмы, констрейнты |
| Ветвление mindmap (FR-011) | Палитра text-ноды → группа «Ветвление»: Добавить дочернюю / сиблинга / Свернуть-развернуть ветку | `AddChild`/`AddSibling` создают связанные text-ноды; `collapsed` прячет поддерево (из поиска и рендера) | Ветка определяется по первому входящему ребру | Сворачивание по хоткею, анимация |
| Удаление | Del (клавиша) или через палитру | Удаление из `.canvas`-модели; автосейв; связи к удалённой ноде остаются «висящими» (не удаляются автоматически) | Связи не удаляются автоматически — это осознанное решение (`SPEC.md` §5.1: связи — отдельные объекты) | Автоматическое удаление связей при удалении ноды, «мягкое» удаление (архив), восстановление через Ctrl+Z |
| Связь (`edge`) | Drag от порта (hover → 4 порта видны) → отпуск на другой ноде; `Shift + drag` — value-ребро (FR-014); перепривязка — drag за хэндл конца выделенной связи (CR-002) | Создание `edge` в модели; перепривязка — `retarget_edge` (id/лейбл/стиль сохраняются); зона захвата портов — настраивается (CR-003: `port_zone_px` 10–40 px); стороны подключения — авто (CR-008) | Связь не может быть «без ноды»; при перепривязке в пустоту/петлю — отмена | Множественные связи между нодами, динамическая подсветка (T23 — влито как фокус-режим) |
| Построчная точка выхода (FR-025) | Drag от кружка на правом краю заметки у строки с результатом (флаг «Точки выхода строк» в настройках, группа «Связи и порты») | Всегда value-ребро со значением именно этой строки (`Edge.fromLine`); порты видны при включённом флаге (финальная строка — бирюзовая, промежуточные — серо-голубые); приоритет построчного порта над сторонным в пределах ряда; перепривязка from-конца — сброс построчного истока | Только правый край (v1); MCP `fromLine` — v2 | Левые порты, MCP-параметр, визуальная ошибка в приёмнике (v2) |
| Палитра ноды (FR-009) | ПКМ по ноде | Группы: «Цвет» (пресеты 1–6 / Без цвета, мультивыделение — всем), «Раскладка» (FR-010), «Действия» (Переименовать, Дублировать, Сгруппировать; по типу: Открыть файл/папку, Скопировать путь, Очистить текст, Разгруппировать, Перезагрузить виджет, Разрешения виджета…), «Ветвление» (FR-011, text) | Мультивыделение скрывает настройки конкретной ноды | Новые группы действий — `palette.rs` |
| Магнитная раскладка (FR-038) | Drag ноды — ghost snapped-позиции + magenta-направляющие (источники: сетка/сосед); snap на отпускании; стрелки — 1 px, Shift+стрелки — 10 px (nudge поверх снапа, каждый шаг — undo) | Движок `snap.rs` (majority, арбитраж grid-vs-guide по минимальной дельте, equal spacing, collision-кламп) + проход `guides.rs` (нелинейная интенсивность); настройки — таб «Snap» модалки (мастер, сетка, guides, collision, допуск, sub/coarse-пороги); якорь угол/центр — advanced (`config.toml`) | Детерминизм; guides исчезают за допуском и на отпускании; snap — отдельный undo-шаг (п.21) | Нелинейный pull-режим, привязка к маркерам потока |
| Batch-выравнивание (FR-038) | ПКМ по канвасу при N≥3 выделенных → «Выровнять по горизонтали» / «по вертикали» / «Распределить равномерно» | `align_centers`/`distribute_evenly` (`snap.rs`): ось = среднее центров; распределение — равные зазоры между краями, span крайних сохранён; один undo-шаг; группы — по рамкам, дети ведомые | Пункты скрыты при N<3; хоткеи не назначены (кандидат приёмки) | Хоткеи, выравнивание по краям/углам (v2) |
| Фокус на связях (T23) | `F` / пункт меню канваса / настройки | `focus_mode`: hover/выделение ноды подсвечивает её связи и соседей, остальное притемняется | Настройка сохраняется в `config.toml` | Интенсивность затемнения, пульс |
| Двойной клик (`file`-нода) | ЛКМ ×2 | Открытие ассоциированным приложением (`ShellExecuteEx` на Windows; аналоги на других ОС) | Не работает для `text` (только инлайн-редактирование) и для `group` (пока нет поведения) | Двойной клик по `group` → «вход внутрь» (будущая фича), по `widget` → фокус виджета |
| Drag-drop (создание `file`-ноды) | Перетаскивание из файлового менеджера на канвас | Полная реализация на Windows (`IDropTarget`); раскладка сеткой (5 в ряд, шаг = размер карточки + 24 px); папка → рекурсивный обход (глубина 1) | Скрытые и системные файлы — пропускаются (`T9`, §3); на Linux/macOS drag-drop — по плану M7 (T28) | Drag папки с настройкой глубины, drag `.canvas`-файла (импорт) |
| Проверка цепочки цифры (FR-048) | Hover-«?» у полосы результата D / построчного ряда (hover-only — решение владельца); клик по самой цифре — фолбэк-триггер (У1); у константы — панель одного узла (AC-1.4) | Окно проверки цепочки расчёта поверх полноэкранного канваса (паттерн main stage): дерево происхождения до листьев (ядро `lineage.rs`), сессионный кэш + чип «Данные изменены», what-if из дерева, автосвязь, режим защиты; клик по подсвеченной ноде канваса подводит узел дерева (У2); MCP `lineage`/`explain_number` — те же данные для агента | Триггер не глушит редактирование прозы (зоны только у вычисленных цифр); повторный «?» на другую цифру — перестройка (У6); панель ↔ main stage взаимоисключительны (F-10) | Экспорт дерева PNG/PDF (non-goal §10 PRD-0007 — «на будущее»), глубина авто-раскрытия — настройка FR-039 |

## 5. Состояния ноды (что влияет на визуал и поведение)

Каждое состояние — отдельный флаг или поле. При расширении фичи следует добавлять флаг, а не изменять существующие.

| Состояние | Где хранится | Как влияет | Точка входа для фичи |
|---|---|---|---|
| `brokenLink` (`bool`) | `.canvas` (`node.brokenLink`) + SQLite (`thumb_cache`) | Серая рамка; тултип «Файл недоступен: <путь>»; тамбнейл не обновляется; связи сохраняются | Автоматическое восстановление по возврату файла (`T10`, `T16`); ручное «перепривязать» через ПКМ |
| `selected` (временное) | `canvas-app` (UI-state, не в `.canvas`) | Подсветка рамки (цвет выделения) | Постоянное выделение в `.canvas`, выделение по фильтру (`T14`), групповое выделение связей |
| `hover` | `canvas-app` (UI-state) | Порты связей видны; курсор меняется на `pointer` для drag | Дополнительные действия при hover (быстрый превью, тултип с метаданными файла) |
| `previewState` (`thumbnail` / `live` / `none`) | `.canvas` (`node.previewState`) | Управляет LOD-рендером (`SPEC.md` §6.2) | Автоматический переход `thumbnail` → `live` при фокусе или при длительном hover; ручное «закрепить превью» |
| `color` (`text`-нода) | `.canvas` (`node.color`) | Цвет заголовочной полосы или фона; `null` → стандартный (`"1"`–`"6"` из палитры); CR-007: цвет текста выбирается автоматически по контрасту (WCAG AA) на окрашенных карточках | Дополнительные цвета, градиенты, привязка цвета к статусу |
| `collapsed` (FR-011, text) | `.canvas` (`node.collapsed`) | Свёрнутая ветка mindmap: поддерево скрыто из рендера и поиска (hidden_subtree_nodes) | Анимация сворачивания, счётчик скрытых потомков |
| Результат формул (FR-013/FR-014) | runtime (`expr_results`/`flow_results`, НЕ в `.canvas`) | Строка итога под текстом; построчные результаты; входы value-рёбер — `$in`/`$1..$N`; ошибка — красная строка с тултипом | what-if (FR-017) |

## 6. Связи (edges) как часть интерфейса ноды

Порты связей (`fromSide` / `toSide`: `top`, `right`, `bottom`, `left`) — это интерфейсный элемент ноды, хотя сами связи (`edges`) хранятся отдельно в `.canvas`.

**Текущее поведение (`SPEC.md` §5.1, `ACCEPTANCE.md` §4.1):**
- При hover на ноду появляются 4 порта (диаметр кружков следует за зоной захвата — CR-003).
- Drag от порта → резиновая линия (Безье) к курсору; `Shift + drag` — сразу value-ребро (FR-014).
- Отпуск на другой ноде → создаётся `edge` с `fromNode`, `toNode`, `fromSide`, `toSide`, `label` (редактируется инлайн).
- Двойной клик по линии → редактирование `label`.
- Клик + Del → удаление связи.
- При перемещении ноды → рёбра перерисовываются в реальном времени; стороны подключения пересчитываются по кратчайшему пути (CR-008), закреплённые концы (`canvasdesk.pin_ports`) следуют сохранённой стороне.
- Перепривязка без удаления (CR-002): клик по линии выделяет связь (хэндлы-кружки на концах) → drag хэндла на другую ноду → `retarget_edge`; пустота/петля — отмена.
- Палитра связи (ПКМ по линии): Стиль / Толщина / Цвет / Поток (value-control) / Порты (авто-закрепить, CR-008).

**Ограничения (`TASKS.md`: T8):** связи не удаляются при удалении ноды; связи не могут быть «без ноды» с одной стороны; нет множественных связей с разными `label` между одними нодами в текущей реализации (код позволяет, интерфейс не ограничивает явно).

## 9. Известный дефект (2026-09-13): множественное выделение — ИСПРАВЛЕН (CR-001)

**Статус:** исправлено реализацией CR-001 (2026-09-13, см. раздел 10 и
`docs/change-requests/cr-001-selection-multi.md`). Оригинальный анализ
(для истории) ниже.

**Выявлено пользователем:** `Shift` + клик по ноде и `Shift` + `drag` (рамка) не работают для множественного выделения.

**Причина в коде (`crates/canvas-app/src/main.rs`):**
- `SceneState.selected` (`строка 190`) — `Option<Selection>` — только одна нода или одна связь.
- `on_left_button` (`строка 3182`) — `self.scene.selected = Some(Selection::Node(index));` — всегда перезаписывает, без проверки `self.modifiers.shift_key()`.
- `dragging` (`строка 192`) — `(usize, Vec2)` — одна нода + смещение; нет механизма `drag`-рамки для выделения нескольких нод.
- `delete_selected` (`строка 1031`) — удаляет одну ноду или одну связь (`match self.scene.selected` с `Some(Selection::Node(index))` или `Some(Selection::Edge(index))`), не несколько.
- Рендер (`SceneView.selected` — `строка 2339`) — передаёт один `Selection`; `renderer.render` подсвечивает одну ноду или одну связь.

**Влияние:** выделение (`selected`) — временное (`UI-state`, не сериализуется в `.canvas`), работает только для одной ноды или одной связи. Множественное выделение (`Shift` + клик, `Shift` + `drag` рамка, выделение связей при выделении ноды) — не реализовано.

**Документ-доказательство:** `docs/change-requests/cr-001-selection-multi.md` — полный анализ с ссылками на строки кода (`main.rs`: `190`, `3182`, `192`, `1031`, `2339`) и описание необходимых изменений (`SceneState.selected` → `HashSet<usize>` или `Vec<usize>`; `on_left_button` + `Shift`; `drag`-рамка; `delete_selected` для нескольких; рендер для нескольких подсвеченных нод).

**Точка входа для исправления:** раздел 6 (`Точки входа для новых фич`) — «Постоянное выделение (`TASKS.md` T14, §8)» — требует изменения структуры `selected` и рендеринга подсветки.
