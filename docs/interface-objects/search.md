# Панель поиска (`search`) — интерфейсный объект

Документ для последовательного расширения функционала поиска (`T14`). Фиксирует текущее состояние (поиск по имени файла и содержимому через FTS5, панель `Ctrl+F`, анимация полёта камеры), интерфейс взаимодействия, ограничения и точки входа для новых фич (фильтрация, интеграция с миникартой и связями, поиск по виджетам).

---

## 1. Определение

Панель поиска — интерфейсный элемент, который открывается поверх канваса (`Ctrl+F`) и ищет ноды двумя путями:

1. **FTS5-индекс (`search_index` в `~/.canvasdesk/cache.db`)** — файловые ноды (`file`): по имени файла (`display_name`) и по извлечённому содержимому (`text`: txt/md до 256 КиБ; для прочих форматов — только имя файла, T11 отложен). Индекс живёт в worker-потоке (`canvas-shell/src/search.rs`), рендер не блокируется.
2. **In-memory проход по сцене** (`canvas-render/src/search_ui.rs`) — заметки (`text`) по заголовку и тексту и имена всех нод — без FTS (мгновенно, но только по открытым нодам канваса).

**Границы ответственности:**
- `canvas-shell`: FTS5-таблица, worker-поток-владелец `rusqlite::Connection`, извлечение текста, команды `IndexFile`/`RemoveFile`/`ReplaceAll`/`Query`.
- `canvas-app`: панель поиска (`Ctrl+F`), склейка FTS-результатов с in-memory проходом, анимация полёта камеры (`~300 мс`, плавное торможение), управление фокусом.
- `canvas-render`: рендер панели (`search_ui.rs`), подсветка найденных нод (`pulse`, затухание ~1.2 с).

## 2. Структура индекса (фактическая, `canvas-shell/src/search.rs`)

```sql
CREATE VIRTUAL TABLE search_index USING fts5(
  path,           -- путь файла ноды (ключ записи)
  display_name,   -- имя файла для отображения
  text            -- извлечённый текст (txt/md до 256 КиБ; иначе пусто)
);
```

Записи — **только для file-нод** (заметки/группы/виджеты ищутся in-memory, §1). Индекс — пересоздаваемый кэш: ошибка открытия БД — деградация (warn, пустые результаты), не сбой.

| Команда worker-потоку | Когда | Что делает |
|---|---|---|
| `IndexFile { path, display_name }` | Создание file-ноды, изменение пути/файла | DELETE+INSERT записи (FTS5 — rowid-таблица без UNIQUE: `INSERT OR REPLACE` оставляет дубликат — зонд T14-A) |
| `RemoveFile { path }` | Удаление ноды / пропажа файла | Удаление записи |
| `ReplaceAll { entries }` | Загрузка канваса, открытие другого файла | Полная переиндексация набора: upsert всех, удаление лишних |
| `Query { query, limit }` | Ввод запроса (дебаунс 200 мс) | FTS5-матч, ответ `SearchEvent::Ready` (хиты: path + display_name) |

Хиты FTS связываются с нодами канваса по пути (`path_matches` относительно папки канваса); файлы вне `.canvas` в результаты не попадают.

> Историческое проектное описание с колонками `file_path`/`extracted_text`/`node_type`/`node_id` удалено 2026-09-16 — оно не соответствовало реализации (см. §9, «Актуальный статус»).

## 3. Интерфейс панели поиска (`search_ui.rs`, `ACCEPTANCE.md` §5.2)

Панель поиска открывается поверх канваса (`Ctrl+F`) и имеет следующие элементы:

```
Панель поиска (поверх канваса, с фокусом клавиатуры)
├── Поле ввода запроса (текстовое, с дебаунсом 200 мс)
├── Список результатов (ноды, соответствующие запросу)
│   ├── Имя файла / заголовок заметки / метка группы / ID виджета
│   ├── Тип ноды (`file` / `text` / `group` / `widget`)
│   ├── Путь (для `file`-нод) или текст (для `text`-нод) или `label` (для `group`)
│   └── Навигация (клик или `Enter` → камера центрируется; `F3` / `Shift+F3` → цикл по результатам)
├── Управление фокусом (панель перехватывает клавиатуру; `Space`, `Ctrl+F`, `F3` — не работают для канваса при открытой панели)
├── Закрытие (клик вне панели, `Esc`, или повторное `Ctrl+F` — очищает поле запроса)
└── HUD (`F3` при отсутствии результатов — переключает HUD: fps, p95)
```

## 5. Ограничения поиска (фактические, сверено с кодом 2026-09-16)

- **Индексируются только file-ноды** (`FTS5`: имя + содержимое txt/md ≤ 256 КиБ); PDF и прочие бинарные форматы — только по имени файла (T11 отложен); изображения — только по имени.
- **Заметки, группы, виджеты** — in-memory проход по открытой сцене (заголовок/текст/метка), без персистентного индекса: после перезапуска ничего пересоздавать не нужно, но поиск ограничен нодами канваса.
- **Свёрнутые ветки mindmap (FR-011)** — исключены из поиска (`hidden_subtree_nodes`): нода внутри свёрнутой ветки не находится, пока ветка не развёрнута.
- **Фильтрация**: файлы вне `.canvas` в результаты не попадают (склейка FTS-хитов с нодами по пути).
- **Дебаунс** `200 мс` — нет перерисовок на каждый символ.
- **Фокус**: при открытой панели клавиатура перехватывается; при закрытии — возвращается канвасу.
- **Конфликт `F3`**: при наличии результатов — навигация по ним; при отсутствии — переключение HUD (`fps`, `p95`).
- **Отказоустойчивость**: ошибка БД — деградация (warn, пустые результаты), приложение не падает; индекс пересоздаваемый (`ReplaceAll` при загрузке канваса).

## 7. Проверка для каждой будущей фичи поиска (чек-лист)

- [ ] Новая фича не ломает `FTS5`-индекс (`search_index` в SQLite); при изменении структуры индекса (например, добавление нового поля для `widget` или для `edge`) — пересоздание индекса или миграция (`rusqlite` — поддержка `ALTER TABLE` для виртуальных таблиц ограничена; лучше пересоздать индекс).
- [ ] При добавлении нового типа индексации (например, `PDF`, `widget`, `edge`) — учитывается производительность (`< 2 с` для открытия `.canvas` на 1000 нод, `SPEC.md` §6.3`); при больших сценах (`5000` нод) — индексация может быть медленной; динамическое отключение или фоновое обновление — рекомендуется.
- [ ] При изменении поведения панели (`Ctrl+F`, `F3`, `Shift+F3`, `Space`) — не конфликтует с текущими жестами (`ACCEPTANCE.md` §5.2, п. 8: «конфликт приоритета клавиши разрешён корректно»); при изменении — обновление этого документа (`docs/interface-objects/search.md`) и `docs/ACCEPTANCE.md` (если влияет на ручную приёмку, `T14`).
- [ ] При добавлении новых фильтров или новых типов поиска (например, «поиск связей» или «поиск виджетов») — учитывается ограничение (`TASKS.md` T14, §8`: индексация фильтруется путями нод канваса; `widget` — не индексируется; `PDF` — не индексируется); изменение ограничения — явно задокументировано в этом документе (`docs/interface-objects/search.md`) и в `docs/ACCEPTANCE.md` (§10: таблица `12` — ограничения, не являющиеся дефектами).
- [ ] При изменении визуального поведения (например, подсветка результатов в миникарте или в канвас) — учитывается ограничение (`SPEC.md` §6.2`: LOD по zoom; `ACCEPTANCE.md` §5.2`: подсветка `pulse` с затуханием `~1.2 с`); при изменении — не ломает LOD или производительность (`< 2 мс` для миникарты, `SPEC.md` §6.3`).
- [ ] При изменении поведения фокуса или при добавлении новых взаимодействий (например, «закрепить результаты» или «история поиска») — учитывается ограничение (`TASKS.md` T14, §8`: фокус перехватывается панелью; при закрытии — возвращается канвасу); при изменении — проверка на конфликт (`Space`, `Ctrl+F`, `F3`, `Shift+F3`) и обновление этого документа.
- [ ] Журнал (`tracing`) содержит смысловой маркер для новой фичи (`ACCEPTANCE.md` §12.1`: пример для `T15`–`T17`; `TASKS.md` T14 — не имеет отдельных маркеров; при добавлении фичи — добавление маркера в `docs/ACCEPTANCE.md` §12.1 или в `docs/plans/T14-search.md`).

## 9. Актуальный статус (2026-09-16)

Сверка документации с кодом:

- Схема `search_index` в §2 приведена к фактической (`path`/`display_name`/`text`, только file-ноды) — прежнее описание (`file_path`/`extracted_text`/`node_type`/`node_id`) было проектным и не соответствовало реализации.

- Будущие направления (§6) актуальны: PDF/виджеты/изображения, фильтрация связей, история поиска, регулярные выражения.
