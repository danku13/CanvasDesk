# Панель поиска (`search`) — интерфейсный объект

Документ для последовательного расширения функционала поиска (`T14`). Фиксирует текущее состояние (поиск по имени файла и содержимому через FTS5, панель `Ctrl+F`, анимация полёта камеры), интерфейс взаимодействия, ограничения и точки входа для новых фич (фильтрация, интеграция с миникартой и связями, поиск по виджетам).

---

## 1. Определение

Панель поиска — интерфейсный элемент, который открывается поверх канваса (`Ctrl+F`) и позволяет искать ноды (`file`, `text`, `group`, `widget`) по имени файла (`.canvas`: `node.file` или `node.label`) или по содержимому (`node.text` для `text`-нод, текст, извлечённый из файла для `file`-нод через `FTS5`). Поиск работает через SQLite (`rusqlite`) с расширением `FTS5` (`docs/SPEC.md` §5.2, `search_index`).

**Границы ответственности:**
- `canvas-core`: модель данных для индекса (`search_index` в SQLite); сериализация `.canvas` не включает индекс (индекс — пересоздаваемый кэш).
- `canvas-app`: панель поиска (`search_ui.rs`); обработка ввода (`Ctrl+F`); анимация полёта камеры (`~300 мс`, плавное торможение, `T14` §4); управление фокусом (панель перехватывает клавиатуру).
- `canvas-shell`: интеграция с файловой системой (`file`-ноды) для индексации содержимого; `notify` (файловый вотчер) для обновления индекса при изменении файлов (`T10`, `T16`).

## 2. Структура индекса (`docs/SPEC.md` §5.2)

```sql
CREATE VIRTUAL TABLE search_index USING fts5(
  file_path,       -- абсолютный путь файла (для file-ноды)
  display_name,    -- имя файла или label группы / заголовок заметки
  extracted_text,  -- извлечённый текст (для file-нод: первые 256 КиБ; для text-нод: node.text)
  node_type,       -- file / text / group / widget (для фильтрации)
  node_id          -- id ноды в .canvas (для навигации и связи с моделью)
);
```

| Поле индекса | Источник данных | Когда обновляется | Ограничение (`TASKS.md` T14) | Точка входа для фичи |
|---|---|---|---|---|
| `file_path` | `.canvas` (`node.file`) или пусто (для `text`/`group`/`widget`) | При создании / изменении `.canvas`; при переименовании файла (`T10`: `Rename` → обновление `node.file` в `.canvas` и в индексе) | Только для `file`-нод; для `text`/`group`/`widget` — пусто или не используется | Поиск по пути (`file_path`) для `file`-нод; фильтрация по пути (например, «все файлы из папки X»); поиск по `widgetId` для виджетов |
| `display_name` | `.canvas` (`node.file` — имя файла; `node.text` — заголовок или первые символы; `node.label` — метка группы; `node.widgetId` — ID виджета) | При создании / изменении `.canvas`; при изменении текста (`text`-нода) или метки (`group`) | Для `text`-нод — `display_name` = первые символы `node.text` (не полный текст); для `group` — `node.label` (если отсутствует — «Группа» или пусто) | Расширение `display_name` для `text`-нод (полный текст или заголовок); возможность задать `display_name` вручную (`group`) или автоматически (`text`: по первому абзацу или заголовку) |
| `extracted_text` | `.canvas` (`node.text` для `text`; извлечённый текст из файла для `file` — через `FTS5` или через `pdfium-render` / `image` для PDF / изображений; `node.props` или `node.canvasdesk` для `widget` — не индексируется в текущей версии) | При создании / изменении `.canvas`; при изменении содержимого файла (`T10`: `Modify` → обновление `thumb_cache` и `search_index`); при изменении текста (`text`-нода) или свойств (`widget`) | Для `file`-нод: текстовые файлы (`.txt`, `.md`) индексируются полностью (до 256 КиБ); PDF не индексируется по содержимому (`TASKS.md` T11: отложено); изображения (`.jpg`, `.png`) — только по имени файла (не по содержимому); `widget` — не индексируется (`T20`–`T22`: виджеты — в работе) | Индексация PDF (`T11`: `pdfium-render` — извлечение текста из PDF); индексация изображений (OCR или метаданные); индексация виджетов (`widgetId`, `props`, или `entry` — HTML-содержимое) |
| `node_type` | `.canvas` (`node.type`: `file` / `text` / `group` / `widget`) | Не изменяется (тип ноды — фиксированный при создании; изменение типа — это удаление + создание новой ноды) | Тип ноды не изменяется в `.canvas`; «изменение типа» — это удаление старой ноды и создание новой с новым типом | Возможность «конвертации» ноды (например, `file` → `text` или `group` → `widget`) с сохранением `.canvas`-структуры и связей (`edges`) |
| `node_id` | `.canvas` (`node.id`) | Не изменяется (ID ноды — фиксированный; при удалении ноды — `node_id` остаётся в индексе до удаления или обновления индекса) | При удалении ноды (`node.id`) — индекс не обновляется автоматически (индекс — пересоздаваемый кэш; удаление `node.id` из индекса — при следующем пересоздании или при явном обновлении) | Автоматическое удаление `node_id` из индекса при удалении ноды; ручное «перестроение индекса» (например, через меню или через команду); сохранение индекса в SQLite (`search_index`) при удалении ноды (без пересоздания) |

## 3. Интерфейс панели поиска (`search_ui.rs`, `ACCEPTANCE.md` §5.2)

Панель поиска открывается поверх канваса (`Ctrl+F`) и имеет следующие элементы:

```
Панель поиска (поверх канваса, с фокусом клавиатуры)
├── Поле ввода запроса (текстовое, с дебаунсом 200 мс)
├── Список результатов (ноды, соответствующие запросу)
│   ├── Имя файла / заголовок заметки / метка группы / ID виджета
│   ├── Тип ноды (`file` / `text` / `group` / `widget`)
│   ├── Путь (для `file`-нод) или текст (для `text`-нод) или `label` (для `group`)
│   └── Навигация (клик или `Enter` → камера центрируется; `F3` / `Shift+F3` → цикл по результатам)
├── Управление фокусом (панель перехватывает клавиатуру; `Space`, `Ctrl+F`, `F3` — не работают для канваса при открытой панели)
├── Закрытие (клик вне панели, `Esc`, или повторное `Ctrl+F` — очищает поле запроса)
└── HUD (`F3` при отсутствии результатов — переключает HUD: fps, p95)
```

## 5. Ограничения поиска (`TASKS.md` T14, `ACCEPTANCE.md` §5.2, `SPEC.md` §5.2)

- **FTS5 (`docs/SPEC.md` §5.2, `https://www.sqlite.org/fts5.html`):** индекс — виртуальная таблица (`USING fts5`); пересоздание — быстрое, но требует ресурсов (`~2 с` для 5000 нод? Уточнить в `TASKS.md` или `SPEC.md`).
- **Индексация содержимого (`TASKS.md` T14, §6`):** текстовые файлы (`.txt`, `.md`) — полностью (до 256 КиБ); PDF — не индексируется (`TASKS.md` T11: отложено); изображения — не индексируются (`TASKS.md` T11: отложено); `widget` — не индексируется (`TASKS.md` T20–T22: виджеты — в работе).
- **Фильтрация (`TASKS.md` T14, §8`):** индексация фильтруется путями нод канваса (`ACCEPTANCE.md` §5.2, п. 9); файлы вне `.canvas` — не индексируются; новые файлы в наблюдаемой папке — не индексируются автоматически (без `.canvas`-ноды).
- **Дебаунс (`TASKS.md` T14, §6`):** `200 мс` — для предотвращения шквала запросов; при быстром наборе — нет мгновенных ответов на каждый символ.
- **Фокус (`TASKS.md` T14, §8`):** при открытой панели — клавиатура перехватывается; канвас не получает `Space`, другие хоткеи; при закрытии — фокус возвращается канвасу.
- **Конфликт `F3` (`TASKS.md` T14, §8`):** `F3` — навигация по результатам поиска (`ACCEPTANCE.md` §5.2, п. 5); при отсутствии результатов — `F3` переключает HUD (`fps`, `p95`, `ACCEPTANCE.md` §5.2, п. 6); конфликт разрешён корректно (без паники или некорректного поведения).
- **Кириллица (`TASKS.md` T14, §8`):** обязательна во всех запросах; `FTS5` проверялась зондом, но в рантайме — первый настоящий прогон (`ACCEPTANCE.md` §5.2, п. 2–3).

| Индексация изображений (`T11`, `TASKS.md` T14, §8) | `search_index` (`extracted_text` или новое поле для изображений) | `image` (`docs/SPEC.md` §3`: `image` — декод в RGBA) или `OCR` для извлечения текста из изображений; добавление текста или метаданных в индекс; фильтрация по типу (`node_type`) | `TASKS.md` T11 (отложено): «живые превью изображений/текста/PDF» — не реализованы (`ACCEPTANCE.md` §10`) |

| Поиск по регулярным выражениям (`TASKS.md` T14, §8) | `search_index` (`FTS5` поддерживает `MATCH` с `*` или с регулярными выражениями) или расширение `search_ui.rs` (парсинг запроса) | Расширение `search_ui.rs` для поддержки регулярных выражений (`.*`, `[a-z]`, и т.д.); фильтрация через `FTS5` или через пост-обработку (`Python`-стиль или `Rust`-стиль); отображение результатов с подсветкой совпадений | Не в `TASKS.md` или `SPEC.md`; будущая фича (ограничение: `FTS5` — это токенизатор, не регулярный выражение; пост-обработка — возможна, но медленная для больших сцен) |

## 7. Проверка для каждой будущей фичи поиска (чек-лист)

- [ ] Новая фича не ломает `FTS5`-индекс (`search_index` в SQLite); при изменении структуры индекса (например, добавление нового поля для `widget` или для `edge`) — пересоздание индекса или миграция (`rusqlite` — поддержка `ALTER TABLE` для виртуальных таблиц ограничена; лучше пересоздать индекс).
- [ ] При добавлении нового типа индексации (например, `PDF`, `widget`, `edge`) — учитывается производительность (`< 2 с` для открытия `.canvas` на 1000 нод, `SPEC.md` §6.3`); при больших сценах (`5000` нод) — индексация может быть медленной; динамическое отключение или фоновое обновление — рекомендуется.
- [ ] При изменении поведения панели (`Ctrl+F`, `F3`, `Shift+F3`, `Space`) — не конфликтует с текущими жестами (`ACCEPTANCE.md` §5.2, п. 8: «конфликт приоритета клавиши разрешён корректно»); при изменении — обновление этого документа (`docs/interface-objects/search.md`) и `docs/ACCEPTANCE.md` (если влияет на ручную приёмку, `T14`).
- [ ] При добавлении новых фильтров или новых типов поиска (например, «поиск связей» или «поиск виджетов») — учитывается ограничение (`TASKS.md` T14, §8`: индексация фильтруется путями нод канваса; `widget` — не индексируется; `PDF` — не индексируется); изменение ограничения — явно задокументировано в этом документе (`docs/interface-objects/search.md`) и в `docs/ACCEPTANCE.md` (§10: таблица `12` — ограничения, не являющиеся дефектами).
- [ ] При изменении визуального поведения (например, подсветка результатов в миникарте или в канвас) — учитывается ограничение (`SPEC.md` §6.2`: LOD по zoom; `ACCEPTANCE.md` §5.2`: подсветка `pulse` с затуханием `~1.2 с`); при изменении — не ломает LOD или производительность (`< 2 мс` для миникарты, `SPEC.md` §6.3`).
- [ ] При изменении поведения фокуса или при добавлении новых взаимодействий (например, «закрепить результаты» или «история поиска») — учитывается ограничение (`TASKS.md` T14, §8`: фокус перехватывается панелью; при закрытии — возвращается канвасу); при изменении — проверка на конфликт (`Space`, `Ctrl+F`, `F3`, `Shift+F3`) и обновление этого документа.
- [ ] Журнал (`tracing`) содержит смысловой маркер для новой фичи (`ACCEPTANCE.md` §12.1`: пример для `T15`–`T17`; `TASKS.md` T14 — не имеет отдельных маркеров; при добавлении фичи — добавление маркера в `docs/ACCEPTANCE.md` §12.1 или в `docs/plans/T14-search.md`).
