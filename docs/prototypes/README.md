# Прототипы UX

Самодостаточные интерактивные HTML-прототипы для быстрого прототипирования:
открываются напрямую в браузере (двойной клик или перетаскивание файла в
окно), без сборки и зависимостей. Назначение — сверка понимания UX/UI и
быстрые итерации по фидбэку владельца **до** постановки в реализацию.
Прототип не является референсом реализации: стек, структура кода и данные в
нём демонстрационные; расхождения с принятыми решениями фиксируются через
changelog соответствующих PRD/FR.

Так как каталог лежит внутри `docs/`, прототипы попадают на GitHub Pages как
статика и открываются по ссылке с сайта документации, не только локально.

## prototype-mainstage-anatomy.html

Интерактивный прототип «main stage + анатомия ноды» (vanilla JS + Canvas 2D,
одиночный файл ~1330 строк, работает офлайн). Визуализирует вводные R1–R7,
формализованные в [FR-044](../change-requests/fr-044-mainstage-fan-readability-qualified-refs.html)
(всё внутри main stage) и [FR-045](../change-requests/fr-045-node-anatomy-data-source-unmapped-calc-trace.html)
(анатомия ноды, LOD, адресация).

Что демонстрирует:

- **LOD-0 агрегация рёбер** — пучок = упорядоченная пара исток→приёмник;
  толщина `clamp(1.8 + (N−1)·0.9, 1.8, 8.0)`, бейдж «×N», hover-подсветка
  с кольцами портов; тумблер «Агрегация связей» (off — исходные отдельные
  связи, включая янтарный пунктир unmapped-ребра).
- **Main stage** — вход кликом по пучку; рамка ≤ 70% вьюпорта с
  центрированием, затемнение фона (0.6 тёмная / 0.5 светлая тема); веер
  рёбер с квалифицированными подписями «Объект.Поле» (R5); lane-стопка
  пилюль значений с шагом = высота + 8 px в «коридоре» между колонками
  портов истока и приёмника (анти-скученность R7); z-порядок «рёбра →
  подложки → подписи портов → карточки» (R6); чужие входы приёмника —
  мини-карточками источников; выход Esc / клик по фону / ✕; выделение
  связи без правок.
- **Панель «Как считается»** (у приёмника, R4) — две группы: «Переменные ·
  входящие значения» и «Расчёт · формулы»; клик по формуле подсвечивает её
  переменные и рёбра-операнды, клик по переменной — формулы, где она
  участвует; hover по строке — живой превью подсветки; сброс Esc/пустой
  клик.
- **Анатомия ноды A–E** (PRD-0004) — хедер с чипом категории; порт-рейлы
  (value — круг, control — ромб); тело с текстом-описанием (R1) и формулами
  в нотации «Объект.Поле» (R5); полоса результата; статусный слой
  (selection > analysis > broken > hover); LOD-пороги зума 0.6 / 1.5.
- **Ноды входных данных** (R2) — категория «данные», индикатор источника
  (CSV / DAC-DB), value-порт на поле источника; трассировка до слота
  (например, S1.USD → вход «Курсы.USD» ноды «Стоимость»).
- **Состояние «значение не подставлено»** (R3) — пунктирный порт ◌,
  янтарное пунктирное ребро, бейдж в analysis-слое, в stage — зона
  «ВХОДЫ БЕЗ ПРИВЯЗКИ».
- **Служебное** — панель «Что проверяем» (8 пунктов), тур из 7 шагов,
  drawer «решения + открытые вопросы», тёмная/светлая темы, мутация
  «±связь» для проверки пересчёта толщины пучка.

Связанные документы: [PRD-0002](../prd/prd-0002-edge-lod-main-stage.html)
(edge LOD + main stage), [FR-042](../change-requests/fr-042-edge-lod-main-stage.html)
(реализационная постановка main stage), [PRD-0004](../prd/prd-0004-node-anatomy-restructure.html)
(единая анатомия ноды), FR-044/FR-045 (выше). История итераций прототипа —
в `worklog.md` корня репозитория (записи от 2026-09-21, R1–R7).

## ux-review-dialog.html

Интерактивный прототип диалога ревью автосвязи (вопросы У7/У8 из Q8
[PRD-0007](../prd/prd-0007-calc-chain-explain.html)) — vanilla JS, одиночный
файл, работает офлайн. Демонстрирует: группировку предложений по парам
«исток→приёмник» с сортировкой по имени переменной (У7 — отложено владельцем на будущее,
2026-09-22), счётчик предложений в бейдже канваса, массовые действия «Принять все»/
«Отклонить все» с обратимым «Вернуть все» до закрытия диалога (У8 — да,
AC-5.2) и undo-бат (AC-5.3). Решение по У7 — отложено владельцем на будущее;
до отдельного решения поведение прототипа — эталон по умолчанию.

## ux-defense-mode.html

Интерактивный прототип проверки цепочки расчёта цифры и режима защиты
(вопрос У9 из Q8 [PRD-0007](../prd/prd-0007-calc-chain-explain.html)) —
vanilla JS, одиночный файл, работает офлайн. **v4 — У9 закрыт (решение
владельца 2026-09-22: «зачем делить экран на две стороны — канвас должен
идти как в prototype-mainstage-anatomy.html, поверх него может открываться
main stage и/или проверка цепочки расчёта цифры»)**: база прототипа — движок
`prototype-mainstage-anatomy.html` без изменений (полноэкранный канвас:
камера пан/зум, LOD, пучки ×N, main stage с веером связей и панелью
«Как считается»), боковых панелей нет. **Проверка цепочки** — плавающее
окно поверх канваса по паттерну main stage: вход — клик по цифре в полосе
результата ноды (У1) или кнопка в панели управления (AC-6.1); внутри —
**граф узлов-карточек с SVG-ветками** (то же представление, что и раньше),
авто-раскрытие 3 уровня (FR-039), уровень 4 — по клику на бейдж. **Режим
защиты** — состояние того же окна (тумблер в шапке): граф укрупняется до
×1.5 с вписыванием в окно (AC-6.2), проза (`NumiLineKind::Prose`) скрывается,
пошаговое раскрытие уровней от корня — клик по узлу, пробел или «Следующий
уровень» (AC-6.3); «Раскрыть всё» — до уровня 4. Выход — Esc (окно
возвращается к обычному виду), ✕ или клик по фону (полное закрытие); канвас
после выхода — без изменений (AC-6.4). **Main stage** (клик по пучку) —
второй оверлей поверх того же канваса; одновременно открыт один оверлей
(F-10). Дерево демо: «Стоимость.Итог 4 687 200 ₽» — выручка (Количество ·
Средний_чек · Сезон) и план USD (выручка / Курсы.USD), источники — уровень 4;
для остальных нод дерево строится из их trace-строк. Полный сценарий
прогнан в headless-браузере. История итераций: v1 (список) → v2
(дерево-граф) → v3/v3.1 (модальное окно, фикс запуска) → v4 (канвас как в
mainstage-anatomy + оверлеи; попутно закрыт Q1 — поверхность объяснения).

## ux-spill-distinction.html

Макет выбора начертания Р-2 и демонстрация визуализации этапа D
[FR-050](../change-requests/fr-050-spill-visibility-ui.html) — vanilla
JS, одиночный файл, работает офлайн. Полный сценарий прогнан в
headless-браузере (живые mouse-события; ошибок консоли нет). Что
демонстрирует:

- **Р-2 различение пролитых** — выбран вариант «наклонная производная
  моно»: у Noto Sans Mono НЕТ официального italic, GPU-скос глифов
  недоступен (glyphon без per-area трансформ), чужой курсивный моно
  ломает метрики — итог: oblique-производная fontTools (11°, авансы
  сохранены, «CanvasDesk Mono Oblique» без RFN «Noto», OFL). Тумблер
  вариантов A/B/C (наклон / маркер «←» / оба) — для сверки владельцем.
- **Р-4 авто-строка приёмника** — «Трафик.peak_rps = 1388.89 rps»
  вверху тела (зона «Переменные · входящие значения», строка-проекция
  Н10-а); слайдер DAU пересчитывает строку, бейджи и подписи ребра
  (демо-критерий «наглядной проверки» FR-050).
- **Н9-2 тултип источника** — hover по наклонной строке: «Пролито:
  Трафик.peak_rps = 1388.89 rps (локально было: 50 rps). Правка —
  отключить проливание, Ctrl+Z вернёт связь».
- **Прочее этапа D** — строка параметра шаблона «rps ← Трафик ·
  peak_rps» + бейдж эффективного значения; подписи концов ребра
  (значение у истока / «→ rps» у приёмника, Н7); unmapped — янтарный
  пунктир + строка «Курсы.usd = —» с тултипом «проблема + решение»
  (Р-3); what-if — янтарная подмена поверх (Р-1).
