# Прототипы UX

Самодостаточные интерактивные HTML-прототипы для быстрого прототипирования:
открываются напрямую в браузере (двойной клик или перетаскивание файла в
окно), без сборки и зависимостей. Назначение — сверка понимания UX/UI и
быстрые итерации по фидбэку владельца **до** постановки в реализацию.
Прототип не является референсом реализации: стек, структура кода и данные в
нём демонстрационные; расхождения с принятыми решениями фиксируются через
changelog соответствующих PRD/FR.

Так как каталог лежит внутри `docs/`, прототипы попадают на GitHub Pages как
статика и открываются по ссылке с сайта документации, не только локально.

## prototype-unified.html

Единый интерактивный прототип — слияние всех прототипов каталога в одну
сцену (vanilla JS + Canvas 2D, одиночный файл ~3220 строк, работает
офлайн). Приоритет — тело ноды **Н-3 «Адаптивная»** (табличная концепция,
[FR-069](../change-requests/fr-069-node-body-fill-stage-f.md); источник
истины — `ux-node-body-fill.html`). Канон слияния и правила переноса
DOM→канвас — [`DESIGN_RULES.md`](DESIGN_RULES.md) §11.

Что вошло и как склеено:

- **Ядро сцены** — движок `ux-defense-mode.html` (новейшая надстройка над
  mainstage): полноэкранный канвас, камера пан/зум 0.25–3×, LOD-пороги
  0.6/1.5, тёмная/светлая темы; единая демо-сцена ~14 нод собрана из данных
  всех прототипов (Заявки, Стоимость, Отчёт, tcp-lb, API Gateway, Профиль
  нагрузки, Трафик с DAU, Курсы CSV, report-q3.md, Гипотеза…).
- **Тело ноды (Н-3, дефолт)** — табличная раскладка, перенесённая с DOM на
  канвас через собственный TextMeasurer (`ctx.measureText`): пер-нодные
  направляющие val/unit/badge, лестница деградации бейджей (текст →
  ⇄/▸/!), зебра, лидеры min 14, кламп описания 2 строки, блок «▸ расчёт ·
  N строк · Σ…» с превью, несворачиваемая unmapped-диагностика, порог T
  2–6 (дефолт 4), ресайз 280–600, what-if «3▸4»/«67▸50», компакт F-9,
  диагностические вертикали «числа»/«юниты»; тумблер «поточная вёрстка»
  показывает состояние «до» (версия flow).
- **Рёбра** — модель портов `ux-node-edge-redesign.html` (fromPort/toPort
  kind: line/named/param/in/node) поверх камеры ядра; дефолт — В-C
  «Кромки-зона» (hover-glow → press → скольжение по точкам с lock → drop
  на порт/тело → choice-меню / обратный жест), тумблеры В-А/В-B; пучки ×N
  mainstage поверх новой модели; Del-удаление с ресетом параметра; якорь
  скрытого ряда уводит ребро к заголовку блока.
- **Spill-различение** (`ux-spill-distinction.html`) — oblique-строки,
  маркер «←» (тумблер A/B/C), авто-строка Р-4, тултипы Н9-2, слайдер DAU
  с живым пересчётом каскада Трафик→Gateway, подписи концов ребра (Н7).
- **Оверлеи (один одновременно, F-10)** — main stage (веер + пилюли-стопка
  шаг=высота+8 + мини-карточки внеших источников + «ВХОДЫ БЕЗ ПРИВЯЗКИ» +
  «Как считается» с взаимными подсветками формула⇄переменная), окно
  проверки цепочки (граф узлов-карточек из trace, авто-3 уровня,
  frontier-бейджи), режим защиты (×1.5 с вписыванием, скрытие прозы,
  Space/клик пошагово, «Раскрыть всё»), диалог ревью автосвязей
  (12 предложений / 3 группы, массовые действия, «Вернуть все», undo-бат).
- **Оболочка** — пульт (тело/связи/драг/сцена/подсказки/поверхности/AI), тур 14
  шагов с событийным авто-продвижением, drawer решений, hint-строка,
  readout, fit, reset.
- **Esc-лестница (7 ступеней)** — choice-меню → drag → ревью → защита →
  цепочка → stage → selection; «один оверлей одновременно» обеспечен
  взаимными close в точках входа.

### Подсказки FR-079 (вплетено 2026-09-30 — UX-канон для S3)

Флоу inline-автодополнения lex+Laya ([FR-079](../change-requests/fr-079-inline-ai-suggest-engine.md),
стадия S3) — спроектировано по книгам владельца (Drive «Books»: Kumar
«Psychology of UX Design», Podmajersky «Strategic Writing for UX», Dooley
«Friction», Schüll «Addiction by Design», Cababa «Closing the Loop», Duke
«Thinking in Bets», Marsh «UX for Business»); правила —
[`DESIGN_RULES.md`](DESIGN_RULES.md) §12. Входы: двойной клик по ноде (C1),
кнопки пульта «Ввод в ноде»/«Создать шаблон», «Настройки подсказок», «HUD
подсказок». Движок выключен по умолчанию (opt-in, как в продукте до приёмки
S5). Что демонстрируется:

- **C1 — ввод в ноде → попап подсказок**: рамка редактирования + полоса ввода
  с кареткой на канвасе; попап снизу — L0-строки (юниты/функции/переменные
  FR-021) **мгновенно**, секция «⚡ шаблоны каталога» — после debounce 300 мс.
  Гибрид (lex+laya при готовом L1): skeleton-строки занимают ожидание
  (Doherty 400 мс), топ-3 вмерживаются через 300–800 мс с бейджем источника
  (AI — топ-1 с imprint mm, lex — остальные) и «почему» у каждой строки;
  при вводе старые строки не мигают. lex-режим — строки мгновенно, без
  skeleton. Латентность L1 — слайдер пульта; ≥ 850 мс — таймаут: skeleton
  гаснет, честная нота «ИИ не успел за 800 мс», попап остаётся с L0 (тихий
  откат, Zeigarnik закрыт). Принятие: клик или ↑↓+Tab; L0-строка дописывает
  ввод, ИИ-строка **заменяет редактируемую ноду шаблоном** (прецедент
  палитры) — undo одним шагом (Ctrl+Z), включая восстановление рёбер.
- **C3 — карточки «следующие ноды»**: у свежесозданной шаблонной ноды справа,
  максимум 3, поп-ин 150 мс, причина у каждой; клик — вставка рядом; цепочка
  ≤ 2 подряд (goal gradient без навязчивости), закрытие Esc/кликом мимо.
- **C4 — домен-подавление**: тумблер «домен: framework» переводит сцену в
  не-расчётный профиль (CJM/JTBD) — ИИ-строк и карточек нет, молча; вердикт
  виден только в HUD и настройках. Show-гейт: короткий контекст/нет соседей —
  секции ИИ тоже нет; частотный лимит 6 подсказок/мин.
- **Настройки (модаль FR-039-паттерн)**: мастер-тумблер opt-in, движок
  off/lex/lex+laya, блок L1 с явным согласием на догрузку ~650 МБ (прогресс
  загрузки → распаковка → smoke-тест → «готово»), warn «L1 недоступен →
  lex» при тихой деградации, opt-out локального журнала.
- **Dev-HUD (S0)**: конвейер (lex/laya/fusion мс + бюджет 800), вердикты
  гейтов (домен/show-gate/соседи/частота), счётчики показов/принято/
  отклонено/правок-после, журнал событий цветом по типу.
- Телеметрия-мок: события shown/accepted/dismissed/edited/timeout/
  suppressed/rate-limited пишутся в журнал (edited — правка ноды, созданной
  принятием; атрибуция авторства гипотеза §15).

Полный сценарий (13 шагов: opt-in → согласие L1 → скелет→строки → HUD →
замена ноды → карточки → цепочка → лимит → undo → таймаут → framework →
lex → Esc-лестница → сброс) прогнан в headless-браузере — живые клавиатура
и мышь, консоль чистая; VLM-ревью скриншотов обеих тем без замечаний по
вёрстке новых поверхностей.

Полный сценарий прогнан в headless-браузере (пиксельные пробы + VLM-ревью
15 состояний; живые mouse-события на создание связи В-C, DAU-пересчёт,
Del, блочный тоггл, Space-шаги, Esc-лестница, ресайз 384→508). Главный
урок переноса DOM→канвас: направляющие хранятся относительными, каждый
draw-сайт прибавляет `n.x` — иначе значения/юниты улетают за сцену
(правило — DESIGN_RULES §11.4–11.5).

### AI-компоненты LLM-интеграции (вплетено 2026-10-04 — PRD-0010 / ADR-0016)

Пять поверхностей LLM-слоя (ЧАСТЬ AI в файле, README-комментарий в шапке
файла). Пульт → группа «AI · LLM-интеграция (PRD-0010)»: тумблер статусной
панели, «Агент-панель» (Ctrl+I), «Настройки AI», «Онбординг AI», «Демо
лимита» (80% → диалог → 100% → error-состояния → сброс). Что демонстрируется:

- **Статусная панель AI** (правый нижний угол над мок-миникартой 220×140,
  не перекрывает её): активная модель+провайдер, функции-тумблеры
  Suggest/Graph/Agent (клик — вкл/выкл, гейтит ИИ-строки suggest и агент),
  cost Session/Day с прогресс-баром (80% — warn + диалог расширения F-7.4,
  100% — red, LLM-запросы отклоняются), ⚙ → настройки, ⏸ пауза всех AI;
  < 900px прячется (F-7.9), при открытой агент-панели отъезжает влево.
- **Custom-node suggest (Q7, F-2.12…F-2.16)**: в попапе C1 секция
  «⚡ custom-ноды · LLM» → «Сгенерировать 3 custom-варианта»: 3 ghost-ноды
  рядом с редактируемой (не перекрывая её; флип у правого края, подъём над
  попапом), skeleton со spinner → каскадный morph, subtle confidence-бар
  (число — в тултипе, Duke), порог из настроек скрывает слабые (F-2.11 —
  по умолчанию третий вариант conf 0,42 < 0,50 скрыт; ниже порог —
  появится), клик — применение с заменой ноды (undo одним шагом) + тост
  «Сохранить как шаблон» (GitHub issue, mock).
- **Агент-панель** (справа, шторка): чат с историей tool-calls
  (graph_read → node_create → graph_validate, mono-строки), context-aware
  чип (Selected: 1 — … / Context: entire canvas — по реальному выделению),
  cost estimate перед запросом («Запрос ~$0.02 · день …»), быстрые запросы,
  **preview ghost-нодами** на канвасе (Sugiyama-lite цепочка от выделенной
  ноды, тег AGENT PREVIEW, пульс) + Accept/Reject (Q3, F-4.11): Accept
  создаёт ноды/связи одним undo-батом, Reject убирает ghost без изменений;
  rate limit ChatGPT локальным счётчиком (F-7.3), 429/лимит — error-сообщения.
- **Настройки «AI and Models»** (9-й таб, паттерн модали): per-feature
  провайдеры (Suggest — ChatGPT OAuth disabled, Q2), API-ключ с
  «Проверить ключ» (health-check F-1.9), выбор модели (glm-5.3-flash…),
  rate limit counter, слайдеры Cost limit ($1/день) и Confidence threshold
  (0,50), data residency Local/Cloud/Self-hosted с описаниями (Q5),
  self-hosted endpoint (URL+key+проверка), телеметрия opt-in (default OFF).
- **Онбординг AI-режима** (F-8): «Выберите режим AI» — Local only / Cloud /
  Self-hosted карточками, «Подробнее о privacy» (redact, keychain,
  телеметрия), «Продолжить» применяет residency + провайдеры per-feature.
- **Esc-лестница расширена в начале**: онбординг → 80%-диалог → настройки
  AI → preview агента (Reject) → агент-панель → существующая лестница.
  Cost-движок честный: каждый мок-запрос списывает оценку (F-7.10).

Прогнано в headless-браузере: открытие/закрытие всех поверхностей,
полный агент-цикл (запрос → tool-calls → preview → Accept → ноды на
канвасе), custom-цикл (генерация → morph → клик по ghost → замена ноды
+ тост), демо лимита (80% → 100% → error-ghost → сброс), онбординг
(выбор Local → провайдеры), узкое окно 800px (панели прячутся), обе темы,
Esc из фокуса в чате; консоль чистая.

## prototype-mainstage-anatomy.html

Интерактивный прототип «main stage + анатомия ноды» (vanilla JS + Canvas 2D,
одиночный файл ~1330 строк, работает офлайн). Визуализирует вводные R1–R7,
формализованные в [FR-044](../change-requests/fr-044-mainstage-fan-readability-qualified-refs.md)
(всё внутри main stage) и [FR-045](../change-requests/fr-045-node-anatomy-data-source-unmapped-calc-trace.md)
(анатомия ноды, LOD, адресация).

Что демонстрирует:

- **LOD-0 агрегация рёбер** — пучок = упорядоченная пара исток→приёмник;
  толщина `clamp(1.8 + (N−1)·0.9, 1.8, 8.0)`, бейдж «×N», hover-подсветка
  с кольцами портов; тумблер «Агрегация связей» (off — исходные отдельные
  связи, включая янтарный пунктир unmapped-ребра).
- **Main stage** — вход кликом по пучку; рамка ≤ 70% вьюпорта с
  центрированием, затемнение фона (0.6 тёмная / 0.5 светлая тема); веер
  рёбер с квалифицированными подписями «Объект.Поле» (R5); lane-стопка
  пилюль значений с шагом = высота + 8 px в «коридоре» между колонками
  портов истока и приёмника (анти-скученность R7); z-порядок «рёбра →
  подложки → подписи портов → карточки» (R6); чужие входы приёмника —
  мини-карточками источников; выход Esc / клик по фону / ✕; выделение
  связи без правок.
- **Панель «Как считается»** (у приёмника, R4) — две группы: «Переменные ·
  входящие значения» и «Расчёт · формулы»; клик по формуле подсвечивает её
  переменные и рёбра-операнды, клик по переменной — формулы, где она
  участвует; hover по строке — живой превью подсветки; сброс Esc/пустой
  клик.
- **Анатомия ноды A–E** (PRD-0004) — хедер с чипом категории; порт-рейлы
  (value — круг, control — ромб); тело с текстом-описанием (R1) и формулами
  в нотации «Объект.Поле» (R5); полоса результата; статусный слой
  (selection > analysis > broken > hover); LOD-пороги зума 0.6 / 1.5.
- **Ноды входных данных** (R2) — категория «данные», индикатор источника
  (CSV / DAC-DB), value-порт на поле источника; трассировка до слота
  (например, S1.USD → вход «Курсы.USD» ноды «Стоимость»).
- **Состояние «значение не подставлено»** (R3) — пунктирный порт ◌,
  янтарное пунктирное ребро, бейдж в analysis-слое, в stage — зона
  «ВХОДЫ БЕЗ ПРИВЯЗКИ».
- **Служебное** — панель «Что проверяем» (8 пунктов), тур из 7 шагов,
  drawer «решения + открытые вопросы», тёмная/светлая темы, мутация
  «±связь» для проверки пересчёта толщины пучка.

Связанные документы: [PRD-0002](../prd/prd-0002-edge-lod-main-stage.md)
(edge LOD + main stage), [FR-042](../change-requests/fr-042-edge-lod-main-stage.md)
(реализационная постановка main stage), [PRD-0004](../prd/prd-0004-node-anatomy-restructure.md)
(единая анатомия ноды), FR-044/FR-045 (выше). История итераций прототипа —
в `worklog.md` корня репозитория (записи от 2026-09-21, R1–R7).

## ux-defense-mode.html

Интерактивный прототип проверки цепочки расчёта цифры и режима защиты
(вопрос У9 из Q8 [PRD-0007](../prd/prd-0007-calc-chain-explain.md)) —
vanilla JS, одиночный файл, работает офлайн. **v4 — У9 закрыт (решение
владельца 2026-09-22: «зачем делить экран на две стороны — канвас должен
идти как в prototype-mainstage-anatomy.html, поверх него может открываться
main stage и/или проверка цепочки расчёта цифры»)**: база прототипа — движок
`prototype-mainstage-anatomy.html` без изменений (полноэкранный канвас:
камера пан/зум, LOD, пучки ×N, main stage с веером связей и панелью
«Как считается»), боковых панелей нет. **Проверка цепочки** — плавающее
окно поверх канваса по паттерну main stage: вход — клик по цифре в полосе
результата ноды (У1) или кнопка в панели управления (AC-6.1); внутри —
**граф узлов-карточек с SVG-ветками** (то же представление, что и раньше),
авто-раскрытие 3 уровня (FR-039), уровень 4 — по клику на бейдж. **Режим
защиты** — состояние того же окна (тумблер в шапке): граф укрупняется до
×1.5 с вписыванием в окно (AC-6.2), проза (`NumiLineKind::Prose`) скрывается,
пошаговое раскрытие уровней от корня — клик по узлу, пробел или «Следующий
уровень» (AC-6.3); «Раскрыть всё» — до уровня 4. Выход — Esc (окно
возвращается к обычному виду), ✕ или клик по фону (полное закрытие); канвас
после выхода — без изменений (AC-6.4). **Main stage** (клик по пучку) —
второй оверлей поверх того же канваса; одновременно открыт один оверлей
(F-10). Дерево демо: «Стоимость.Итог 4 687 200 ₽» — выручка (Количество ·
Средний_чек · Сезон) и план USD (выручка / Курсы.USD), источники — уровень 4;
для остальных нод дерево строится из их trace-строк. Полный сценарий
прогнан в headless-браузере. История итераций: v1 (список) → v2

## ux-node-edge-redesign.html

Интерактивный прототип трёх вариантов редизайна Node/Edge (пре-PRD анализ

— vanilla JS + Canvas 2D, одиночный файл, работает офлайн. Полный сценарий
прогнан в headless-браузере: hover-кромки, drag от кромки со скольжением по
точкам, drop на тело → choice-меню, drop на якорь параметра, удаление связи
Del — живые mouse-события, ошибок консоли нет. Тумблер В-А / В-B / В-C — для
сверки владельцем до постановки в PRD.

Демо-сцена: расчётная нота (построчные результаты), шаблон-приёмник
(параметры rps/latency с авто-строками проливания), контентная заметка,
file-нода; рёбра всех трёх типов — value (бирюза, чип «rps ← 1 000 rps»),
control (серый), unmapped (янтарный пунктир «не подставлено»). Что
демонстрируют варианты:

- **В-А «Двухконтурный порядок»** — рейлы входов/выходов всегда видны у
  расчётных нод, 2 hover-точки у контентных; тип задаётся точкой старта

- **В-B «Единый порт-рейл»** — UE/Blender/n8n: порты всегда видны на всех
  нодах, входы слева/выходы справа, тип = цвет+форма сокета; наглядно
  демонстрирует шум на плотной сцене.
- **В-C «Кромки-зоны» (рекомендация анализа)** — портов в покое нет; hover
  подсвечивает кромки (право=выход, лево=вход); press на кромку раскрывает
  точки у рядов, **скольжение вдоль кромки выбирает конкретную точку**
  (между рядами — узловой уровень); drop на якорь/кромку — типизированное
  ребро, drop на тело — choice-меню (Н2 обобщён: связь / значение / параметр);
  drag от левой кромки — обратный жест «притянуть источник к $in».

## ux-node-body-fill.html

Интерактивный прототип трёх вариантов **тела ноды** — текстовые описания +
Numi-строки (пре-PRD анализ
[`docs/interface-objects/node-body-layout-analysis.md`](../interface-objects/node-body-layout-analysis.md);
доработка 2026-09-23 — табличная концепция, см.
[`docs/interface-objects/node-tabular-body-analysis.md`](../interface-objects/node-tabular-body-analysis.md))
— vanilla JS + DOM, одиночный файл, работает офлайн. Для сверки «до/после»
рядом опубликован снапшот версии **до** табличной доработки —
[`ux-node-body-fill-flow.html`](ux-node-body-fill-flow.html) (поточная
вёрстка, коммит 204a082): баннер ⇄ в его шапке ведёт обратно к табличной
версии, ссылка «⇄ сравнение» — в подзаголовке шапки табличной. Центральный сценарий —
**тест наполнения**: одна нода (шаблон `com.canvasdesk.tcp-lb`, самый
сложный в библиотеке: 6 параметров + 5 выходов) растёт через уровни
L0 пустая → L1 лёгкая → L2 средняя → L3 максимум, во всех вариантах,
с каскадом Р-1 (проливание `server_rate ← Профиль нагрузки`, what-if
`servers 3▸4` → загрузка 67%→50%, unmapped `Отчёт_q3.медиа_доля`).
Headless-прогон чистый, VLM-ревью скриншотов без замечаний по вёрстке
(`docs/assets/node-body-*.png`). Тумблеры:

- **Наполнение L0…L3** — нода пересобирается на лету: от плейсхолдера до
  11 строк данных + описание + заметка + Σ.
- **Н-1 «Сквозной лист»** — канон Numi: проза и формулы одним потоком,
  идентичность строки шрифтом, значения правым желобом с пунктирными
  лидерами, микро-метки групп.
- **Н-2 «Двухзонная»** — текст-зона сверху + ведомость расчёта блоком
  снизу (группы «входящие / параметры / расчёт», Σ-строка, тёмный фон);
  на L0 блока не существует.
- **Н-3 «Адаптивная» (рекомендация, слайдер порога T 2…6)** — до T строк
  сквозной лист, после — расчёт выносится в блок снизу, описание клампится
  до 2 строк («⋯ целиком ▾»), свёрнутый блок показывает превью
  «▸ расчёт · N строк · Σ …»; диагностика (unmapped) не сворачивается.
- **What-if (FR-017)** и **компакт (F-9)** — состояния каскада и LOD.
- **Табличная концепция (правка 2026-09-23, все варианты)** — строки данных
  таблицей: [имя][=][формула][лидер]|[значение]|[юнит]|[бейдж]. Направляющие
  (колонки) = max-ширина содержимого по всем строкам ноды — **цифры всегда
  прижаты к правому краю своей направляющей, доменные юниты — к своей**;
  полоса D, Σ-строка, свёрнутый заголовок блока и превью — на тех же
  направляющих. Бейджи каскада — отдельной колонкой справа и не сдвигают
  направляющие; тесно → лестница деградации: текстовые бейджи → иконки
  (⇄/▸/!, полный текст в tooltip) → ellipsis формулы; числа/юниты не
  деградируют никогда. **Направляющие — невидимая концепция вёрстки**
  (решение владельца 2026-09-23): на ноде нет ни линий, ни сетки —
  выравнивание читается только по правым краям цифр и юнитов. Тумблер
  «направляющие (диагн.)» выключен по умолчанию и включает пунктирные
  вертикали «числа»/«юниты» исключительно как диагностический оверлей
  вёрстки; тянущийся угол ноды — 280–560 px, живой пересчёт направляющих
  и режима бейджей. Скриншоты `docs/assets/node-tabular-*.png`
  (пересняты без оверлея).
- **Оптимизации восприятия O-1…O-12** — ховер по пункту списка подсвечивает
  соответствующие элементы на ноде (два шрифтовых слоя, лидеры, юниты,
  бейджи каскада, зебра, Σ, пустое состояние…).
- Рёбра: проливание (бирюзовое, к строке параметра) и unmapped (янтарный
  пунктир, к авто-строке) с anchors у рядов — FR-025/FR-050 совместимость
  сохранена во всех вариантах.
