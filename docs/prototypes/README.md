# Прототипы UX

Самодостаточные интерактивные HTML-прототипы для быстрого прототипирования:
открываются напрямую в браузере (двойной клик или перетаскивание файла в
окно), без сборки и зависимостей. Назначение — сверка понимания UX/UI и
быстрые итерации по фидбэку владельца **до** постановки в реализацию.
Прототип не является референсом реализации: стек, структура кода и данные в
нём демонстрационные; расхождения с принятыми решениями фиксируются через
changelog соответствующих PRD/FR.

Так как каталог лежит внутри `docs/`, прототипы попадают на GitHub Pages как
статика и открываются по ссылке с сайта документации, не только локально.

## prototype-mainstage-anatomy.html

Интерактивный прототип «main stage + анатомия ноды» (vanilla JS + Canvas 2D,
одиночный файл ~1330 строк, работает офлайн). Визуализирует вводные R1–R7,
формализованные в [FR-044](../change-requests/fr-044-mainstage-fan-readability-qualified-refs.html)
(всё внутри main stage) и [FR-045](../change-requests/fr-045-node-anatomy-data-source-unmapped-calc-trace.html)
(анатомия ноды, LOD, адресация).

Что демонстрирует:

- **LOD-0 агрегация рёбер** — пучок = упорядоченная пара исток→приёмник;
  толщина `clamp(1.8 + (N−1)·0.9, 1.8, 8.0)`, бейдж «×N», hover-подсветка
  с кольцами портов; тумблер «Агрегация связей» (off — исходные отдельные
  связи, включая янтарный пунктир unmapped-ребра).
- **Main stage** — вход кликом по пучку; рамка ≤ 70% вьюпорта с
  центрированием, затемнение фона (0.6 тёмная / 0.5 светлая тема); веер
  рёбер с квалифицированными подписями «Объект.Поле» (R5); lane-стопка
  пилюль значений с шагом = высота + 8 px в «коридоре» между колонками
  портов истока и приёмника (анти-скученность R7); z-порядок «рёбра →
  подложки → подписи портов → карточки» (R6); чужие входы приёмника —
  мини-карточками источников; выход Esc / клик по фону / ✕; выделение
  связи без правок.
- **Панель «Как считается»** (у приёмника, R4) — две группы: «Переменные ·
  входящие значения» и «Расчёт · формулы»; клик по формуле подсвечивает её
  переменные и рёбра-операнды, клик по переменной — формулы, где она
  участвует; hover по строке — живой превью подсветки; сброс Esc/пустой
  клик.
- **Анатомия ноды A–E** (PRD-0004) — хедер с чипом категории; порт-рейлы
  (value — круг, control — ромб); тело с текстом-описанием (R1) и формулами
  в нотации «Объект.Поле» (R5); полоса результата; статусный слой
  (selection > analysis > broken > hover); LOD-пороги зума 0.6 / 1.5.
- **Ноды входных данных** (R2) — категория «данные», индикатор источника
  (CSV / DAC-DB), value-порт на поле источника; трассировка до слота
  (например, S1.USD → вход «Курсы.USD» ноды «Стоимость»).
- **Состояние «значение не подставлено»** (R3) — пунктирный порт ◌,
  янтарное пунктирное ребро, бейдж в analysis-слое, в stage — зона
  «ВХОДЫ БЕЗ ПРИВЯЗКИ».
- **Служебное** — панель «Что проверяем» (8 пунктов), тур из 7 шагов,
  drawer «решения + открытые вопросы», тёмная/светлая темы, мутация
  «±связь» для проверки пересчёта толщины пучка.

Связанные документы: [PRD-0002](../prd/prd-0002-edge-lod-main-stage.html)
(edge LOD + main stage), [FR-042](../change-requests/fr-042-edge-lod-main-stage.html)
(реализационная постановка main stage), [PRD-0004](../prd/prd-0004-node-anatomy-restructure.html)
(единая анатомия ноды), FR-044/FR-045 (выше). История итераций прототипа —
в `worklog.md` корня репозитория (записи от 2026-09-21, R1–R7).

## ux-review-dialog.html

Интерактивный прототип диалога ревью автосвязи (вопросы У7/У8 из Q8
[PRD-0007](../prd/prd-0007-calc-chain-explain.html)) — vanilla JS, одиночный
файл, работает офлайн. Демонстрирует: группировку предложений по парам
«исток→приёмник» с сортировкой по имени переменной (У7 — под вопросом),
счётчик предложений в бейдже канваса, массовые действия «Принять все»/
«Отклонить все» с обратимым «Вернуть все» до закрытия диалога (У8 — да,
AC-5.2) и undo-бат (AC-5.3). Решение по У7 — после просмотра владельцем.

## ux-defense-mode.html

Интерактивный прототип режима защиты (вопрос У9 из Q8
[PRD-0007](../prd/prd-0007-calc-chain-explain.html)) — vanilla JS, одиночный
файл, работает офлайн. **v3.1 — У9 закрыт (решение владельца 2026-09-22:
«режим защиты — это модальное окно»; v3.1 — фикс: в v3 окно фактически
не открывалось — класс состояния вешался на #app, а CSS-селектор оверлея
его не видел; запуск проверен в headless-браузере)**: запуск одним действием
открывает модальное окно поверх затемнённого канваса; панель на время защиты
прячется (паттерн диалога ревью), снапшот сохраняется. Внутри окна — **тот же
граф узлов-карточек с SVG-ветками, что и в explain-панели** (v2; списочное
представление v1 отклонено): полное дерево компонуется один раз за вход,
шаги раскрытия только включают видимость узлов/веток (позиции стабильны),
граф центрируется и вписывается в окно с укрупнением до ×1.5 (AC-6.2),
появление узлов и веток анимировано. Пошаговое раскрытие уровней от корня —
клик по узлу, пробел или «Следующий уровень» (AC-6.3). Выход — Esc, ✕ или
клик по фону: окно закрывается, панель и подсветка возвращаются полностью
(AC-6.4). Клик по подсвеченной ноде канваса подсвечивает её узел в дереве
(У2 — да).
