# Модели канваса

Исполняемые расчётные модели в формате `.canvas` (JSON Canvas 1.0 + расширения
`canvasdesk.*`). Открываются в CanvasDesk (десктоп) или в
[web-версии](https://danku13.github.io/CanvasDesk/app/).

## E-commerce Capacity Model (`ecommerce-platform.canvas`)

Полный расчётный контур платформы электронной коммерции на нодах CanvasDesk:
шаблонные расчётные ноды + Numi-заметки, соединённые value-связями с адресацией
портов (`fromOutput`/`toParam`, FR-029).

**Зоны** (5 групп):

1. **Спрос и сценарии** — допущения (ручные числа только здесь), режим нагрузки
   (`mult`, точка what-if подмены), трафик (avg/peak), расчётный пик.
2. **Доставка** — CDN → L4-балансировщик → API-шлюз → маршрутизация по сервисам;
   медиа-трафик в S3.
3. **Доменные сервисы** — OMS (заказы, события, платежи), Checkout API, платежи,
   auth, каталог, поиск, корзина, WMS (Эрланг C, штат сборщиков), TMS (закон
   Литтла, курьеры), ERP (синхронизация стока), поддержка (Эрланг C).
4. **Данные и фон** — Kafka, воркеры, Mongo (каталог), SQL master + реплика
   (заказы).
5. **Мощность и стоимость** — планировщики мощности (закон Литтла + запас 30%),
   суммарный флот, egress, стоимость инфраструктуры (`infra-cost`), managed-сервисы,
   итоги.

**What-if сценарии** (вшиты в файл, `canvasdesk.whatif`): «Чёрная пятница ×3» и
«Чёрная пятница ×5» — подмена строки `mult = 1` ноды «Режим»; весь граф
пересчитывается, файл не меняется. Сравнение сценариев — `Ctrl+Shift+I` →
«Сравнить».

**Верификация**: `models/ecommerce-platform-report.md` — числа по трём
сценариям (нагрузка, утилизация ρ по узлам, стоимость, штат), воспроизведены
независимым движком (семантика `flow.rs` + `queueing.rs`).

Отчёт: 39 нод / 51 value-связь; база $2 122/мес → ×3 $4 516 (×2.13) → ×5 $6 910
(×3.26); без масштабирования на ×5 перегружены API-шлюз (156%), checkout (140%),
штат WMS (372%), поддержка (417%).
