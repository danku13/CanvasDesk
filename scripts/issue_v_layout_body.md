## Цель

Устранить класс дефектов вёрстки UI: вертикальное выравнивание текста в контролах (кнопки, чипы, поля, вкладки), высота каретки в полях ввода, разнобой вертикальных отступов. Не точечные фиксы, а системный канон: **Конвенция → Миграция → Гейт** (класс закрыт, только когда есть все три).

## Контекст

Расследование (worklog: UI-LAYOUT-AUDIT-SCREENSHOTS, UI-SYSTEMIC-PLAN) подтвердило 3 корневые причины:

1. **Рендерер не центрует текст по вертикали** — `screen_text_area` ставит `top = origin.y` дословно (`canvas-render/src/text.rs:456`); горизонтальная центровка есть, вертикальной нет нигде.
2. **Кит отдаёт геометрию подписи потребителю** — «Подпись — забота потребителя» (`canvas-ui/src/component/button.rs:650`); 234 вызова `label_center`/`label_left` в 9 файлах переизобретают центровку тремя конвенциями (полный rect / ручная суб-геометрия / магические офсеты +2…+12).
3. **Каретка считается от высоты контрола, а не от метрик шрифта** — 7 формул на 7 площадках (`overlays.rs:52/1654/6904`, `agent_panel.rs:1075`, `kit_ui.rs:4844`, `admin_ui.rs:1339`, `explain.rs:1651`); каретка 26px при кегле 13.
4. Дополнительно: факторы строки разъехались — `ROW_LINE_FRAC = 1.1` (`row.rs:29`) vs `SCREEN_LINE_FACTOR = 1.3` (`measure.rs:30`, `LINE_HEIGHT_FACTOR = 1.3` в `text.rs:118`).

## Канон (целевая конвенция)

- Область подписи однострочного текста = **строковый бокс** (кегль × 1.3), центрированный в rect контрола; топ-анкер — только для осознанных многострочных стеков.
- Каретка — из метрик строки: `h = line_height − 2·pad`, `w = 1.5`, y — общий центр с текстом; единая формула для всех полей.
- Один источник метрики: `LineMetrics` / `SCREEN_LINE_FACTOR`; магические вертикальные офсеты у label-вызовов запрещены.

## Критерий приёмки

- Тексты всех кнопок/чипов/полей/вкладок визуально по центру контролов (±1 px) на всех темах; каретка единой высоты ≈ высоте строки текста во всех полях; текст и каретка стартуют от одной формулы.
- `cargo test --workspace`, clippy, fmt, wasm-gate зелёные; doc_lint без ошибок; затронутые golden-эталоны перезаморожены осознанно.

## Риски

- Каскад правок golden-эталонов — держать в одном коммите миграции.
- Места с ручной компенсацией («уже правильные», онбординг) — мигрировать ВСЁ на helper; смешение конвенций вернёт дефект.
- Суб-пиксель ±1 px на нечётных высотах (snap) — принятый допуск, фиксируется в спеке.
- Осознанно топ-анкерные стеки (about-строки, результаты поиска) — явно оставить топ-анкер.
