# Протокол актуализации скиллов MCP

Скиллы в `skills/` — производная от реестра MCP-инструментов
CanvasDesk. Источник истины — константа `TOOLS` в
`crates/canvas-mcp/src/lib.rs` (её же отдаёт `tools/list` живого
сервера) и семантика инструментов в `crates/canvas-scene/src/mcp.rs`.
При изменении функционала MCP скиллы обновляются В ТОМ ЖЕ коммите —
контракт-тест ловит рассинхрон.

## Контракт-тест skills_sync (crate canvas-mcp)

Тесты `skills_*` в `crates/canvas-mcp/src/lib.rs` встраивают все
markdown-файлы пакета (`include_str!`) и проверяют четыре правила:

1. **Полнота каталога:** каждое имя из `TOOLS` есть в
   `skills/canvasdesk-mcp/references/tools.md`.
2. **Покрытие скиллами:** каждое имя из `TOOLS` упомянуто хотя бы в
   одном `SKILL.md` (не только в каталоге) — новый инструмент обязан
   попасть в зону ответственности одного из скиллов.
3. **Счётчик README:** `skills/README.md` содержит актуальное число
   («N инструмент…»).
4. **Call-позиции валидны:** каждый маркдаун-токен в бэктиках, за
   которым следует `{` (форма вызова `инструмент` {параметры}),
   обязан быть именем инструмента из `TOOLS` либо операцией
   `graph_apply` из списка `CALL_POSITION_OPS` в тесте (сейчас это
   `param_set` — операция батча, не MCP-инструмент). Ловит вызовы
   удалённых/переименованных инструментов.

Прогон: `cargo test -p canvas-mcp skills` (входит в полный гейт
`cargo test` и CI).

## Пошаговый протокол при изменении MCP

1. **Изменили реестр или семантику** (`TOOLS` в canvas-mcp,
   инструментальную логику в canvas-scene/src/mcp.rs, форматы ответов).
2. **Каталог:** обновите `skills/canvasdesk-mcp/references/tools.md` —
   добавьте/исправьте строку инструмента; проверьте группировку
   (разведка/ноды/связи/батч/шаблоны/проверка/what-if).
3. **Зона ответственности:** обновите затронутый `SKILL.md`. Новый
   инструмент должен быть упомянут минимум в одном `SKILL.md`
   (правило 2), в идеале — с сигнатурой вызова и одним-двумя
   примерами. Изменение формата ответа → обновите пример структуры в
   `canvasdesk-model-verify` (flow) или соответствующем скилле.
4. **Счётчик:** поправьте «N инструмент…» в `skills/README.md` и
   версию пакета там же.
5. **CHANGELOG:** запись в `skills/CHANGELOG.md` (версия, дата, что
   изменилось, связанные инструменты).
6. **Гейты:** `cargo test -p canvas-mcp` (skills_sync зелёный),
   затем полный регламент репозитория — fmt, clippy, все тесты,
   `scripts/wasm_gate.sh`, `scripts/mcp_wasm_gate.sh`.

## Особые случаи

- **Переименование/удаление инструмента:** правило 4 поймает вызовы
  по старому имени в call-позиции; прозу и таблицы проверьте
  вручную (`rg "старое_имя" skills/`). Обновите каталог, скиллы и
  CHANGELOG одним коммитом.
- **Новая операция `graph_apply`** (не совпадающая с именем
  инструмента): добавьте её в `CALL_POSITION_OPS` в тесте —
  осознанно, комментарием.
- **Изменение кодов ошибок** (`graph_validate`, операции батча):
  обновите таблицы в `canvasdesk-model-build`/`canvasdesk-model-verify`
  — коды заявлены как стабильный контракт рецепта.
- **Новые схемы/шаблоны в реестрах** (assets/): скиллы не перечисляют
  их поимённо (агент читает `schemes_list`/`template_list` в рантайме);
  обновляйте скиллы только при изменении семантики инструментов.

## Стиль скиллов (поддерживать)

- Язык — русский, имена инструментов/полей — как в реестре (латиницей).
- Вызовы в канонической форме: `инструмент` {параметры} — одно
  написание на пакет (правило 4 его использует).
- Примеры с числами — только канонические эталоны (ADR-0005
  Instagram MVP, схемы галереи) с оракулами ±1 %; числа обновляются
  вместе с тестами сцены.
- Frontmatter: `name` (идентификатор), `description` (триггеры RU+EN),
  `version` (целое, +1 при семантическом изменении скилла).
- Размер `SKILL.md` — до ~250 строк; детали уходят в references/.
